Plot reads a plain Jenkins pipeline's state instead of reporting it as an unreachable host. `jenkins_build_map` asked one verb, and `job list` enumerates a container's CHILDREN: a `WorkflowMultiBranchProject` has one child per branch, so listing it yields the branch→colour map Plot renders, while a plain `WorkflowJob` has no children and the same call yields `null` — not an error, not an empty array — which the `type=="array"` guard turned into `failed`, the word for a host that did not answer. Measured live 2026-09-15 on `Quatico.Webseite/quaweb-website`: `job list quaweb/continuous-deploy` answered `null` while `job view` on that path answered `color blue`, `lastBuild #938 SUCCESS`; the job was healthy, signed in and correctly declared, and `runs` turned the `failed` into `exit 4`, which `build-shell.ts` converts to `unaskable` with `refusal: null`, discarding the one signal a team could retry on. So no declaration could fix it, which is why the config key an earlier plan proposed would have been read correctly over a reader that still returned `null`. `job view` is now asked first and answers both questions in one call: the job's own `_class`, and for a plain job the `color` and `lastBuild` that are its state. THE DECIDING `_class` IS THE CONFIGURED JOB'S OWN — a child's `_class` describes the child, and every child of a multibranch container is itself a `WorkflowJob`, so reading it off the listing would read a healthy multibranch job as plain and break the half that works; that mistake sank an earlier draft and a test now pins it, giving a container's five children `WorkflowJob` and asserting it is still read as multibranch. A plain job keys its map on the job path's last segment, which is what lets the `runs` op's `.map[$branch]` find it and emit a line rather than exiting 4. Exactly two shapes are read, and anything else reports `unknown` — a shape nobody measured — never `failed`; a `FreeStyleProject` has a `color` and would be readable, and is still reported unknown rather than guessed at. An instance naming no job probes no shape, since the root scope has no `_class` of its own and the listing already handles it. The multibranch path is byte-identical, pinned against stdout captured from `origin/main` rather than by a fixture comparison, since byte-identical is a claim about bytes. The jen test stub now tells `job list` from `job view`; it branched on the group alone, so both verbs returned the same array and an implementation calling neither was indistinguishable from one calling both. The five call-budget assertions that filtered on the literal string `'job list'` now count total `jen` invocations, since that filter is blind to a per-branch `job view` storm against Jenkins' declared limit of 60. `run-for-sha` is deliberately untouched: it asks the same multibranch-or-plain question through `curl` against REST and answers per sha, so unifying them is an improvement to a working path rather than a fix to a broken one.
