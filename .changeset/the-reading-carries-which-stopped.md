`/plot-fleet --status` now names which kind of stopped it found, and the board's reading carries it. The script told five machine states apart in prose and handed the board one bit, so four different machines all reached `supervisorState` as `down`. The one that lied is `installed`: it is reached when the unit is on disk **and** a completed `--start` recorded that it finished, and `--stop` removes that marker only after a successful unload — so that state means the supervisor died or was booted out on its own, a crash, a logout or an OS update. It printed *"not installed — no unit on this machine"*, which is false about the machine and hides an unexplained death; an operator told the unit is absent does not open `.plot/logs/registryd.log`, and a supervisor that crashed once crashes again after `--start`. It now gains its own arm that names the death and sends the reader to the log before the restart. `platform: none` reports its state too — its arm returns before `fleet_install_state`'s `case` ever runs, so the state machine could never name the one machine where the board's printed repair is refused by design at REFUSAL 3. The state travels as `install=<state>` **on** the `summary:` line rather than beside it, because that line's presence is what `readSupervisor` tests for `summarised`, and a field on its own line would be absent from exactly the killed runs that most need explaining; an appended `key=value` cannot break a substring test. The exit code is unchanged, 0 loaded and 1 not: `supervisorState` gates on exactly those two values and answers `unknown` for everything else, so encoding the state in the code would render `unknown` from every machine carrying it. `SupervisorRun.install` is optional and an absent field answers `down`, never `unknown` — absent means an older script, never a machine with no state, so a board reading a script that predates the field behaves exactly as it did before; that is the compatibility contract and a test pins it, because answering `unknown` there looks defensive and would silently degrade every such board into *could not ask*. The rule answers `died` where the script says `installed`: the script's word is correct about the unit file and exactly backwards as a fleet's status, and `died` refines `down` rather than replacing a check, so a run that could not be asked or stopped before its summary line is still `unknown` whatever field it carried. The wire schema stays a three-value enum and no renderer exists yet, which is the correct end state here — the board parses with that enum and the client only casts, so widening it would ship a value with nothing behind it. The exit-code lock now drives the real `--status` arm through a `PATH` stub of `uname` and `launchctl` rather than sourcing the script and replacing the functions under test: measured 2026-09-18, the sourced form returns before the argument parsing, so no arm existed to run and `exit $?` was never reached — with that line mutated to answer 7 for every not-loaded state the probe still passed, and only the launchd-guarded case caught it, which returns early on `ubuntu-latest`. Each of the four not-loaded states is now built from the facts that produce it, and `none` is reached by the kernel rather than by withholding a binary, since prepending to `PATH` can only add a command.
