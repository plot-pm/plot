The board's auto-dispatch loop now bounds a pass by the machine's headroom, the way the fleet supervisor already does. Two callers dispatch agents against one machine reading and only one acted on it: `plot-registryd` decides once every 60 s and applies `ceilingFor(headroom)` — `starved → 1`, `tight → 2`, `clear`/`unmeasured` → `Infinity` — while the board decided twelve times a minute and applied no band-aware bound at all. `ceilingFor` was module-private in `rules/fleet-size.ts` with `fleetSize` as its only caller, private by history rather than by design: it reads only `headroom` and answers only a ceiling, so this gives an existing rule its second legitimate caller rather than adding a second rule. **The bound goes after BOTH budget assignments**, which is the part a naive implementation gets wrong — `auto-dispatch.ts` computes `parallelAgents - (liveCount + inFlight.size)` and then, when that is spent, REPLACES it with the free-agent count, the deliberate fall-through that lets the fleet reuse a slot it already holds; a `min` applied only to the first leaves that path unbounded, and it is reached exactly when the fleet is at its cap, which is when a tight machine most needs the bound. Measured: the fall-through offered 3 against a tight ceiling of 2. **`min` only ever lowers**, so the board's own comment forbidding a raised budget still holds (`bug/a-landed-branch-still-holds-a-slot`, 2026-08-25), and `clear` and `unmeasured` both answer `Infinity`, so a healthy or unsampled machine is bounded by exactly what bounded it before — pinned by asserting output byte-identical to a pass that took no reading at all, the gate that proves no healthy machine is slowed. **The operator's override is deliberately not consulted**: `machineOverride` is *"dispatch even while the machine reads `starved`"*, so it stands down the deferral, and a ceiling is not a deferral — *now anyway* still starts work, at the rate the reading bears. That changes the override's starved path from three dispatches to one and is the only route by which `STARVED_CEILING` is reachable from the board, since a plain starved reading returns before the budget is computed; exempting the override would also have exempted `tight`, which never deferred and so was never what the operator overrode. No cross-pass state is introduced — the rejected sibling `the-tight-band-remembers-what-it-started` proposed a ratchet whose reset condition was observed zero times in 102 readings — and `HEADROOM_THRESHOLDS` is untouched and asserted literally, because re-measuring it is a separate plan.
