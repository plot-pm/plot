A branch whose pull-request state could not be fetched is no longer reported as abandoned. `quietKind` read `prState: 'none'` as *the host was asked and reported no pull request*, which is also what an unreachable or unanswered host produced: the board's readings derived the word from `pr ? 'open' : 'none'` over a map that is `null` until a fetch succeeds, so an absence of evidence became evidence of absence. `abandoned` is the most consequential word on a row — it is what tells a person the branch can be deleted. Measured 2026-09-20 on `quatico/quaweb-website`: `prAgeSeconds: null`, seven branches rendered *"commits, no PR ever opened — abandoned"*, and three of them carried pull requests, one open and two draft, while the raw host call answered correctly in 0.4 s. `QuietBranchReadings.prState` gains `'unknown'` — the estate's existing word, the one `HostReach`, `PrSchema.state` and `BriefStateSchema` already use — and `quietKind` answers `'quiet'` for it, below `hasMergedPr` so a merged branch still reads `merged` whether or not the host could be asked, and above `prState === 'none'` so a successful fetch reporting no pull request still reads `abandoned`. The reading gains a word and the verdict does not: `QuietKind` keeps its four words, `quietNote`'s record is untouched and `AgentRowSchema` is unchanged, so nothing crosses the wire that did not before and no old client meets a value it cannot parse. The fact is `entry.prs === null` and it is per ENTRY rather than per branch, so one boolean is read once per pulse and supplies both `prState: 'unknown'` and `prUnknown` — whose own producer asked the strictly narrower question *did the host answer but fail to report this PR's state*, and therefore evaluated false for the whole outage, because a null map yields a null record. It reaches the row's sentence as well as its kind, and both the plan-branch and the loose-branch paths: a fix applied to one leaves the other still saying the false thing, and loose branches are the population most exposed, since they reach the board through the refs and a failed fetch is all that stands between the row and a pull request it cannot see. `everyCase()` gains a dimension rather than a case, 12 records to 16, so a fifth arm cannot be added without a case covering it.
