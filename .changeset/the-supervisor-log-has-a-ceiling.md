The looping supervisor now prints its counted tick summary without the per-branch enumerations, while `--once` keeps printing everything it printed before. `registryd.log` reached 69,776,046 bytes and 1.5 million lines in seven days; `board.log` beside it — same machine, same week, same kind of long-lived daemon — is 16,745 bytes, and the daemon's CPU over 3.5 days is 3 min 52 s. It is not busy, it is verbose. `reportTick` took `(report, write, warn)` and one code path served both callers, while its own comment claimed *"the looping daemon prints the counts on its summary line and stops there"* — behaviour the code it annotated did not implement, so this honours a documented rule rather than inventing a quieter one. **`looping` is a parameter and not module state**, because all nine existing tests call the function directly and a distinction they cannot set is one they cannot pin. **Three emitters re-emit per tick in proportion to something that grows, and all three are fixed or the ceiling leaks.** The held enumeration is the bulk, and only `not-claimable` loses it — a hold over the whole estate's backlog, 165 branches re-enumerated 7,333 times; the other four are holds over the queue, small and churning and what a debugger reads at 3am, and they are **capped rather than exempted** because `whyNotReady` tests `merge-unknown` second, before the claimable split, and `landed` answers `unknown` for every slice when the host cannot be asked — one host outage moves the entire queue into a kept class, 574 slices at the measured peak. The scope is a `Record<QueueHold, 'estate' | 'queue'>` rather than a `hold === 'not-claimable'` test, so a sixth estate-wide hold fails the build instead of defaulting into silence. **`unclaimedLines` is the second re-emitter and an earlier draft missed it**: 38,174 lines and 7,132,536 bytes, 10.26% of the file, with `/private/tmp/plot-baseline` named 2,539 times and one worktree path 6,413, under a comment justifying the volume by claiming the unclaimed trees "were twelve at their worst" — the comment is corrected rather than kept. **The third wrote zero bytes of the 69 MB and is proportional to the REGISTRY**, not the estate: `readRegistry`'s warn fires once per unparseable manifest per tick, forever, and it was found by enumerating every emitter rather than by measuring output. It is capped and not silenced — the other two have their counts on the summary line and this one has a count nowhere else, so dropping it would be the silent skip its own docstring refuses. Ten tests pin the result, each growing ONE input, and they were verified by mutation rather than by passing: unthreading `reportTick` fails four, unthreading `readRegistry` fails only the manifest gate, dropping all five holds fails the over-deletion pair, keeping the four uncapped fails the 574-slice gate alone, and forcing `looping` true fails the `--once` gate alone. **What this promises is exact: the log stops growing with the estate. It does not stop growing** — the residual is a fixed 262 B/tick, 131 MB/year, stated rather than hidden, and a ceiling on the file belongs to `plot-fleetctl.sh`, which owns the unit templates and already prints the log path. No file in this change writes the log. The existing 69 MB file is an operator's to remove on their own disk.
