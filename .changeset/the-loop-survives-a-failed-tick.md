The supervisor survives a tick that throws. Its loop had no error handling at all, so one rejected promise — a failing git command, a host call that throws, a manifest that disappears mid-read — was an unhandled rejection and ended the process. Measured 2026-09-22: the daemon died twice in ninety minutes, both times leaving `registryd.err` EMPTY and the launchd label loaded with no process under it, with `launchctl print` reporting `runs = 1` across both deaths — so `KeepAlive: true` did not restart it and `plot-fleetctl.sh --status` went on reporting `supervisor: running` while the fleet handed over nothing. The tick is now wrapped inside the loop, so recovery is the one the contract already promised: the next iteration re-reads the registry and the desks from disk, exactly as it does after a restart. The failure goes to stderr with the error's own text, because an empty error log is what made the deaths invisible. `--once` still returns non-zero on a failed tick, since an operator runs it to learn whether the daemon works and a swallowed failure would report a healthy one. No partial report is emitted — a tick that threw halfway decided nothing — and the interval is still waited, so a repeating failure cannot spin. The entry point gains a `.catch` for what throws before the loop is reached.
