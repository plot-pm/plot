`/plot-deliver` now refuses a delivery whose phase the parser would not read, instead of reporting a success it did not achieve. Filed as #924 from a real delivery in a project repository: the plan carried BOTH front matter and a `## Status` block, the script wrote `Delivered` into the block, and `plot-plan-meta.sh` went on answering `approved` — it prefers front matter wherever it exists and reads the block only in the `else if` below it. **The write succeeded and the outcome did not**, while the summary line said `phase=flipped`. Reproduced before fixing, on the reporter's exact shape: `flip_phase` returns 0 for having changed something, the Status block reads `Delivered`, and the parser still answers `approved`. The cause is one guard — `flip_phase`'s awk matches only inside `section == "status"`, so on a front-matter plan it edits the block and leaves the front matter untouched. **The failure had no symptom**: awk changed a line, the `mv` landed, the push went through, and only a reader asking the parser — which is every later consumer, the board and the reconcile scan included — saw the old phase. `write_transition` now parses the scratch copy through `plot-plan-meta.sh` **before** the `mv` and refuses where what the parser would read disagrees with what is being written. **The test is what the parser answers, never whether awk changed a line**, because refusing on "nothing flipped" would break every re-run of a correct delivery — a plan already carrying `Delivered` flips nothing and is fine. **It parses the file that arm is about to land** — the phase-only scratch copy where the record is already present, the record-carrying one where it is being written — since parsing the other would check content that never reaches the plan. **Before the `mv`, and the position is the mechanism**: after it is too late twice, because the script's own header documents exit 0 as *"the plan is Delivered on the default branch"*, so refusing there would exit 1 on a run meeting the documented success condition, and `runAutoDeliver` spawns the delivery detached — a non-zero exit is logged to nobody while the plan sits delivered on main. A refusal also never reaches `record_state_receipt`, which would otherwise license a commit of the state that was refused. The refusal names **both** values, the file and the cause, because which format ought to win is a decision this gate deliberately leaves to a person: a message saying only *"delivery failed"* throws away the half a person acts on. A refused run leaves the plan byte-identical and pushes nothing, and a second run on an unrepaired file refuses the same way — `decide_transition` answers `write` rather than `already` there, so it reaches the gate again. **The parser is read and never changed**: `plot-plan-meta.sh` is untouched, front matter keeps precedence, no contract field moves, and its output over all 290 plans hashes identically to `origin/main`. Verified by mutation — removing the gate fails all four refusal tests and leaves both no-regression tests green.
