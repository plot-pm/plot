A finished slice now records the tokens its agent actually used, summed across its whole run rather than sampled from the last turn. Plot could already source the number and had never stated it: `readTranscriptFacts` returns `contextTokens` and `contextSpend`, both snapshots of the newest assistant line, both answering *how full is this agent's window* — and neither answering *what did this slice cost*. `rules/slice-tokens.ts` is a new derivation beside them and not a widening of either, which matters because `output_tokens` is counted here and stays deliberately absent from `CONTEXT_USAGE_FIELDS`: that rule guards a context CEILING, where counting output would charge an agent twice for text arriving as input next turn, while this counts SPEND, where output is generated once and billed once. The four counters are kept APART and a summed fifth field is refused by a `.strict()` schema and pinned by key-set assertions on both the schema and the line as it lands on disk — measured over three real transcripts, cache reads are 98.6%, 99.3% and 99.36% of a naive four-counter total, so a four-field sum is a cache-read count wearing a cost's name, and a slice that re-read a large context cheaply would outrank one that generated heavily; a figure a person can act on needs a price table, which this estate excluded by measurement on 2026-08-29. THE SUBJECT IS THE BRANCH WITHIN A DESK, which overturns the plan's own `$PLOT_SESSION_ID` clause by measurement taken in preflight: 39 of 40 branch desks hold more than one main session and one holds 41 whose largest is 18.2% of the total, because `run_bounded` is re-entered on every correction and continuation and each new session id is a new file — so a session-keyed sum reads one file, omits the rest, and ships a number wrong by a factor of five that looks right. `spend.ts:42-50`'s actual concern is preserved exactly: `agent-*` subagent transcripts still belong to no one and are still excluded. A detached `HEAD` segment is charged to the PRECEDING real branch, one-sided and with no lookahead — structural rather than a simplification, since at the write site the next branch has not been chosen — and a `HEAD` segment with no preceding real branch is charged to no slice at all. The record is written at `seal_declaration`, the only moment that still knows which branch just finished: a worker does not exit between slices, so a sum taken at worker exit would charge every slice the worker ever held to whichever branch it held last, and 3 of the 12 largest worker transcripts already span two branches. It is machine-local under the COMMON git dir's `.plot/state/`, resolved with `--git-common-dir` and never `--show-toplevel`, because in a linked worktree the latter returns the DESK and `plot-reap.sh` runs `git worktree remove --force` over exactly those — a record written to the desk is destroyed by the reap on the machine that measured it, with every gate green. It is written once and never updated, so a second run writes a second record and each line stays a measurement with a timestamp. Every failure records NOTHING rather than a zero, and a reader on a machine holding no record is told *not measured here* — a recorded zero is indistinguishable from a free run, and a sum over one is wrong in the direction nobody checks. Two stated limits rather than solved problems: a colleague's checkout reads nothing, and a worker killed by `Worker bound` never reaches the write site, so a rollup over these records is biased LOW in a direction nobody can see from the records alone.
