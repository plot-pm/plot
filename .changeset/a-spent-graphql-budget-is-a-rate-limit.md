A spent GitHub GraphQL budget reads as a rate limit, not as an unreachable host. The in-process GitHub client now reads a GraphQL error of type `RATE_LIMIT` or code `graphql_rate_limit`, an untyped GraphQL error whose message names a spent rate limit, and a `403` that names one with no `x-ratelimit-remaining` header as `throttled`. Measured 2026-11-19: GraphQL answered `API rate limit already exceeded for user ID …` with REST and auth healthy, and the board said *"the git host could not be reached … This is not a rate limit"*. The fleet scan's branch walk now reads a `failed` refusal by its words (`refusalKindOfWords`), the scan banner names when the budget refills where the reset is known, and the Machine section no longer reads a rate limit as `host could not reach the host`. The Machine fact moved into the domain (`rules/machine-health.ts`): its line names each GitHub bucket the budget record holds (`GitHub GraphQL 0 / 5,000 left · REST 3,812 / 5,000 left`) and a bucket it does not hold as `not recorded`, and a bucket at or under a tenth of its limit turns a healthy machine amber `strained` with a row such as `GitHub GraphQL · 0 / 5,000, resets 13:47 · PR listings wait for the reset`. An unasked host and a real outage list no bucket.
