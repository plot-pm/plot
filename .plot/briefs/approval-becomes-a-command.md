### What to build

`plot-approve.sh` becomes a launcher over a JS entry. The decision stays where it already lives: `transitions/plan.ts` (`approve`, `isRefusal`) and `rules/slice-name.ts` (`unnamedBranches`, `unnamedBranchDetail`). What leaves the shell is everything around those rules: the refusals that run before the merge, the PR merge, the booking worktree, the plan edit, the hold and sprint writes, the commit and push ladder, the in-session log, and the receipts.

The failure it fixes: `plot-approve.sh` has 981 raw lines and 494 code lines. It asks `board/plot-transition.mjs` twice (`--check-slices` at `:353`, the transition at `:653`) and treats a missing bundle at `:349` as permission to carry on: it prints `slice headings went unchecked` and approves. Four awk programs (`flip_phase`, `append_approved_line`, `clear_holds`, `update_sprint_annotation`) hold plan-format rules that `rules/plan-record-edit.ts` already holds for two of them. After #1416 the gate counts every non-launcher row, and `scripts/check-decision-count.sh pr` measures 53 at `1abb66b47`; this slice takes it to 52.

Shape: an entry `packages/board/src/server/entry/approve.ts`, bundled to `skills/plot/scripts/board/plot-approve.mjs` and declared in `packages/board/build.mjs` the way `deliver.ts` and `reap.ts` are. The launcher is `plot-deliver.sh`'s eleven lines with `approve` for `deliver`: resolve `$script_dir/board/plot-approve.mjs`, exit 2 with the same missing-bundle message (file, `update the plot plugin`, `pnpm build:board`), `exec node`. Model the entry on `entry/deliver.ts`, which already performs the same ladder for a different transition. The plan is canonical; this brief is orientation.

### Settled decisions — do not re-derive them

**The launcher keeps the name and the arguments.** `plot-approve.sh [--dry-run] [--who <name>] <slug>`, `-h|--help`, an unknown flag exits **1** with `plot-approve: unknown flag '<flag>'` (not 2: `plot-reap.sh` exits 2, this script never did, and the reconcile suites match it). `plot-controller-gate.sh` and `plot-state-gate.sh` name the `.sh` path, `board/approve.ts:72` spawns it (`APPROVE_SCRIPT`), and the skills call it. `--help` printed `sed -n '2,12p' "$0"` — the launcher has no header to print, so the entry prints its own usage text; keep the first line `Plot helper: perform the MECHANICAL half of approving a plan.`

**The refusals run before the merge, in this order, and write nothing.** Phase, then review channel, then the PR, then the slice headings. The merge is the one irreversible write; a refusal after it leaves the PR merged and the plan at Draft, which the script's own header calls the state never to allow. Port the order, and prove it with a test per refusal that asserts the host saw **no** `pr-merge` call.

**The slice check is asked in-process and has no missing-bundle arm.** The shell asked the bundle `--check-slices` and carried on when the bundle was absent. The entry imports `unnamedBranches` and `unnamedBranchDetail` and cannot be missing them. Do not port the `cannot find … slice headings went unchecked` branch: a rule that cannot be asked refuses, and here it can always be asked. The rule is also asked a second time at write, from the file in the booking worktree (`decide_transition` at `:626`). Keep both: measured 2026-10-02, disabling the early check let the transition approve an unnamed plan outright, because the field line carries no slices and the domain reads an absent reading as unmeasured. Pass the slices with the request.

**The exit code is the reading, not the emptiness.** `plot-host.sh pr-state` exits 0 with `state: NONE` for a branch without a PR, 3 for a refused or failed call (a rate limit included), 4 for a backend with no answer. Only the first is an absence. The entry reaches this through `host.prState`; map its `PortResult` to the same three outcomes and keep the three sentences (`no PR found for branch`, `the host could not be asked`, `the host backend has no answer`). Measured 2026-08-27: an empty answer read as *no PRs* refused four fully-merged plans. Absent is not false.

**The merge and the ready call go through `scripts.host`, as `deliver.ts:316` does for the micro-PR merge.** `ports/host.ts` has no `prMerge` or `prReady`, and adding them is a connector change (account, rate limit, REST versus GraphQL) that belongs to `the-build-pipeline-is-its-own-connector`, not to this slice. Do not call `gh`; `scripts/check-host-cli-callers.sh` refuses a second caller. Keep the order: `pr-ready` first when the PR is a draft (its own `step:` line and its own refusal), then `pr-merge <n> --delete-branch`. A merge commit, never a squash.

**The ladder exists once; do not write it a second time.** `deliver.ts` holds `commitAndPush` (`:275`), `recordStateReceipt` (`:230`), `spendActionReceipt` (`:252`), `gitBlobOid` (`:211`) and a private `runGit` (`:324`). Approve needs all of them. Extract them into a shared module under `entry/` and import it from both entries; a copy is an undeclared duplicate, and `packages/domain/corpus/state-receipt.corpus.test.ts` already pairs the receipt format with the shell's `record_state_receipt` — extend that pair to name the shared module, do not add a third writer. `spendActionReceipt` takes `'deliver' | 'release'` today; widen it to `'approve'`. If extracting changes `deliver.ts`, the existing deliver suites pass unedited.

**No new `spawn` or `execFile` site.** The ratchet *One place reaches a process* (`ci.yml:664`) reads `allowed=11` and counts 11 outside `adapters/` today, so there is **no headroom**: `runGit` in `deliver.ts:329` is one of the 11. The approve entry's git calls (fetch, `diff --cached --quiet`, `add -- <paths>`, `commit -c user.name=<who>`, `push`) go behind the `trees` and `refs` ports. `trees.commit(path, message)` and `trees.push(path, branch)` exist; they set no author and `push` is `-u origin`, so the staged-path check, the staging write and the author-bearing commit are new `trees` operations, written in `trees-git.ts` and `trees-fixture.ts` with tests. Moving `deliver.ts` onto them lets you take `runGit` out and lower `allowed` to 10; that is welcome, and the gate says so itself (`the ratchet can tighten`). The commit author is `-c user.name=<who>` for the booking commit and plain `git commit` for the `Impl: same branch` flow.

**The plan edits are the domain's, not a port of the awk.** `rules/plan-record-edit.ts` exports `flipStatusValue(content, from, to)` and `insertStatusRecord(content, field, record)`. Use them for the phase flip (`Draft`/`Design` → `Approved`) and the `Approved:` record. The awk had bug history that the rule must keep: the flip is scoped to the `## Status` section (a plan quoting a status block in prose must not have its illustration rewritten), the record fills an empty `- **Approved:**` placeholder before it appends, an HTML comment ends the writable region (`test/reconcile/approve-record-outside-comments.test.mjs`, 228 lines, is that specification), a plan with no `## Status` heading is a refusal, and both edits run against copies so a plan that cannot take the record keeps its **old phase** too. If `flipStatusValue` has no `Design` arm or the comment arm, add it to the rule with a unit test; do not carry the awk over.

**The hold and the sprint annotation are two new rules, with unit tests, and their awk is deleted in the same change.** No rule exists for either today (`ls packages/domain/src/rules | grep -i "hold\|annot"` returns nothing; `sprint-tick.ts` is delivery's tick and a different write). Put them in `packages/domain/src/rules/` as arrows. The hold rule removes the entry whose **first field equals** a branch the plan names, by string equality, exactly as `plot-phase-gate.sh:121` reads it: a pattern would release gates the plan never named. An absent `.plot/hold` is the common case and is never an error. The annotation rule keeps the closing `-->` marker split off before any field is touched (measured 2026-09-08: a value pattern that avoids `-->` swallowed the `--` and corrupted the comment; excluding `-` rewrote `bug/a-b` as `feature/new-b`), finds the sprint file by the `[<slug>]` item line and never by filename (the week prefix is written in mixed case), writes `pr` and `branch` and **no `status:`** (gone since 2026-09-08), and treats a plan in no sprint as a no-op.

**The receipt contract is the point of the launcher keeping its name.** Two gates read what this script leaves. `plot-state-gate.sh` refuses a commit that changes a `State:` line unless a state receipt names the value: the entry records `Approved` against the **main repository's** `.plot/state/state-receipts/`, after the plan file is replaced, never before (a receipt written before a failed write licenses a commit of a refused state), and never in the booking worktree (that copy vanishes with the worktree). `plot-controller-gate.sh` refuses the script without an action receipt: the entry spends `.plot/state/action-receipts/approve` **only when the action completes**, never at the gate, so an interrupted run can be repeated on the same licence. Re-running is the documented repair after the merge. A launcher that spends the receipt on entry breaks that repair in the case it exists for.

**The run is idempotent, and each step asks the source it would have written.** PR state `MERGED` skips the merge. The transition answers `already` when the file in the booking worktree already carries phase and record. The hold file, the sprint annotation and `git diff --cached --quiet` answer for themselves. No progress file. A re-run on an approved plan prints `step: nothing to commit — the approval is already recorded on <main>` and exits 0.

**The flows differ and every difference is a test.** `Review: pr` merges the plan PR from `idea/<slug>`. `Impl: same branch` resolves the work branch from `Branch prefixes` (never `idea`), skips the merge (`merged=skipped-same-branch`), records in place in the caller's checkout, commits `plot: approve <slug>` and does **not** push. `Review: in-session` needs `--who`, has **no default**, no plan PR (`pr_number=0`, `merged=skipped-in-session`), refuses under `PLOT_UNATTENDED=1` even with `--who`, and refuses a handle `People` does not declare (the domain's `reviewer-undeclared`, asked through the transition, not re-implemented). `Review: ballot` refuses by name; `NONE` is treated as `pr`; an unrecognised value is refused, never defaulted. The recorded name for `pr` follows `--who`, then `PLOT_APPROVE_WHO`, then `git config user.name`, then `plot`. Do not add `PLOT_APPROVE_WHO` to the in-session path.

**The in-session log is a count, not a receipt.** Append `<date>\t<slug>\t<who>\t<script|board>` to `.plot/state/in-session-approvals.tsv` only after the push landed **in this run**. `nothing-to-commit` and `n/a` append nothing, and a refused or interrupted run appends nothing. `PLOT_APPROVE_ENTRY=board` makes the last column `board`.

**The push ladder keeps its three outcomes.** `plot-push-main.sh` (stays; `deliver.ts` calls it too) classifies `clean`, `bypassed`, `unknown` as landed and `rejected` as the caller's problem. On a rejection the entry pushes the booking branch, opens a micro-PR through `host.prCreate`, and merges it with `--delete-branch`. If that fails the plan must not stay at Draft: print the stranded message (`the approval is committed on '<bookbr>' but could not reach <main>`, with `PR #n IS MERGED` or `the in-session approval IS DECIDED`), print the `summary:` line with `push=rejected`, remove the worktree but keep the branch, and exit 1.

**The booking worktree is `$desk_root/.plot-approve-<slug>.<pid>` on branch `plot/approve-<slug>`, cut with `addBranch` (`-B`).** The desk root comes from `deskRoot` of the **main** checkout, never `--show-toplevel`, which answers a desk inside a desk. Call `plot_exclude_desk_root`'s equivalent before the add so a booking run does not leave `.worktrees/` untracked. The branch is disposable: `removeWithBranch` in cleanup is correct here (it is the booking run's cleanup, which the reaper brief forbids for a different reason).

**The output is the contract.** One `step:` line per step and the closing `summary: merged=… phase=… record=… holds=… sprint=… push=…`. `plot-dispatch.sh`, the board's approve route and four reconcile suites read these words. `--dry-run` prints the `would` lines for its flow, writes nothing, merges nothing and exits 0. These suites are the specification of the port. Do not edit an expectation to make a run pass; a changed line is a finding to report in the PR.

**What stays.** `plot-push-main.sh`, `plot-state-receipt.sh`, `plot-desk-root.sh`, `plot-plan-meta.sh`, `plot-host.sh`, `plot-config.sh` and `plot-tmp.sh` are sourced or run by other scripts. Do not edit them. `plot-state-receipt.sh` is still sourced by `plot-deliver.sh`'s siblings and by the gate; the launcher no longer sources it.
