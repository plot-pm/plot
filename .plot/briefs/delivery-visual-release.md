### The decisions the plan settles — do not re-derive them

**Every colour is a lookup over a domain field, never a test in the component.** `accent`, `PlanLine.state`, `SliceState` and `counts[].key` each map to a class through a constant table, as `YOU_MARKER_CLASS` does. A component that compares a count to zero, tests the word `blocked`, or parses `merged` to pick a colour breaks the rule *Every rendered state is a domain property*. The domain already computes all of these (`headerCountParts`, `mergedWords`, `phaseAccent` landed with *Domain fields*); add no domain field, no reading and no host call.

**`PHASE_ACCENT` holds left-border classes, not chip hues.** `PlanCard.tsx:17` maps `accent` to `border-l-sky-400`, `border-l-green-500` and so on, a card's left edge. The plan says the Phase chip maps `accent` through `PHASE_ACCENT`, and its value-free `export` is on this branch's list. Applied to a chip, those classes draw a left border in a Tailwind palette colour on a token-based chip, which is the palette-class failure this plan removes. Settled call: write a second constant table in the component that maps the same `accent` keys (`neutral`, `Discovery`, `Design`, `Development`, `Testing`, `Released`) to `delivery-hue-*` classes, keeping `PlanCard.tsx` untouched when it is not imported. Choose the hues to match the `PHASE_ACCENT` colours (sky, slate, green, violet, orange; `neutral` takes `delivery-tone-neutral`). If you export `PHASE_ACCENT` anyway, change nothing else in `PlanCard.tsx`. Say in the PR body which you did and why; do not restyle `PlanCard`.

**The strip carries words, not only blocks.** The blocks are `div`s with no text. Keep the per-state count as visible text or as an accessible name with the same wording `data-strip-segment` has today (`2 delivered`), and keep `data-strip-text` and `data-strip-unread`. A strip of coloured boxes passes a render check and fails the design's rule that every dot or colour sits beside its state as words.

**The mockups lose where the spec text disagrees.** The mockups use 10 px for column headers; the plan fixes 11 px for chips and column headers, 13 px for rows and 15 px for section titles. The mockups' abbreviated texts lose to the spec: no abbreviated text where the row has room, and `merged 2 days ago` is `storyDateText`'s output, not `3 d ago`. The mockups step between frame and box (`#0b1020`, `#131a2e`); that step is not reproduced, and no token is added for it.

**Tokens, not hex, and unlayered.** Every colour is a `--card-*` or `--hue-*` token, and the rules live in `styles/delivery-release.css`, which Primitives imports unlayered after `@import "tailwindcss"`. A `dark:` utility or a hex value on a Release element is the failure this plan removes. Keep Tailwind utilities for layout (`flex`, `gap-*`, `min-w-0`); remove the colour, border and background utilities you replace, because a utility and a rule that set one property leave the cascade for the next reader to untangle. Do not add to `index.css` or `delivery.css`; if a class you need is missing from `delivery.css`, define it in `delivery-release.css` and name it in the PR body.

**Class-reading tests.** The plan lists the tests that read a class name (*Tests and Selectors*). Many integration tests read `data-plan-row`, `data-strip-segment`, `data-plan-line` and `data-person-card`; those are attributes and stay. Re-check with `grep -rn "slate-\|emerald-\|sky-\|blue-600\|border-l-" packages/board/test` against the Release block and `ReleasePersonCards` before you remove a class. If a test reads one, move it to a `data-*` attribute in the same PR and say so in the PR body. A test that reads `textContent` of `data-plan-toggle` or `data-plan-line-link` must still read the same string.

**Rules carried over unchanged:** a function you write is an arrow; absent is not false (no `phase` renders no chip, no `merged` renders no relative time, no `pr` renders no PR link, never an empty string in a cell); a cell that cannot hold its text cuts it at the end with an ellipsis and keeps the full text as its `title` (`delivery-truncate`); icons come from `glyphs.ts` only, so add no SVG path.

### Done when

The plan's *Sections* done-when is the specification. CI gates: this branch's browser tests and the existing ones pass, and `delivery-tab-screenshots.browser.test.ts` passes, with no horizontal scroll at 320 px. A reviewer judges that the section matches `delivery-toggle-icons-v2.html` and `plan-slices.html` within the spec's text: the dark theme against the mockup, the light theme by eye against the dark mockup, from the `delivery-screenshots` artifact of the CI run on the PR head.

The assertions that exist because a naive implementation would pass without them:

- **One computed style from `delivery-release.css` on a real Release element, not only the marker rule.** The screenshot test reads `--delivery-section` from `[data-section="release-delivery"]`, which proves the file loads and not that a rule from it beats a Tailwind utility. Assert the computed colour of a Done line's state word (`delivered`) equals `--hue-green`, and a blocked count's colour equals `--hue-red`. A utility left on the element wins silently.
- **The strip has one block per slice.** A plan with 3 delivered and 2 not started renders 5 `delivery-strip-block` elements in that order with the `delivery-state-*` classes; a blocks count taken from the segments' sum, not from `planSliceCount`, passes a one-state fixture and fails a mixed one. A plan whose slices are `unread` renders no block for them and keeps `data-strip-unread`.
- **The Phase column absent and present.** A plan with `phase` renders the chip with that word; a plan with none renders no chip and the Phase cell is empty, not `undefined`. A rule that maps a missing `accent` to a default hue passes the first and paints a chip on the second.
- **The person-card bar and the release bar agree.** One fixture with a `blocked` slice asserts the `blocked` segment of the person card and of the sprint card carry the same class. This catches a surviving local `SEGMENT_CLASS` in `ReleasePersonCards.tsx` that keeps a blocked slice amber.
- **The table at both widths.** At 1280 px the header row (Plan, Phase, Slices, Owner) is visible; at 639 px it is hidden and the cells stack. A rule written only for the wide case passes the 1280 px render and breaks the 320 px check.
