### What to build

Two domain rules and one component (`planReference`, `planIndexOf`, `planRoute`, `planRouteOfDocLink`, `PlanReference`) already exist on `main`, built by the Rule slice, and the tuple/agent rows already render through them, built by the Rows slice. What is still plain text or a raw `planHref`/`rewritePlanLink` call are the **panel-level** surfaces: `PlanCard`, `PlanModal`, `StoryModal`'s plan list and its own doc-link rewriter, `server/board.ts`'s doc-link rewriter, and five `onOpenPlan` callers whose signature is not yet the shared `(file: string) => boolean`. This slice closes that gap, adds the CI gate that proves no new site builds a `/plan/` href outside the rule, and deletes the four now-dead helpers.

### The decisions the plan settles — do not re-derive them

**The open signature is `(file: string) => boolean`, with `onOpenPlanFile` in `App.tsx` as the one real implementation.** Four callers pass the wrong shape today and need to move, each confirmed by reading `App.tsx` directly (not inferred from the plan text):

- `Board.tsx:136` / `Swimlanes.tsx:17` — `onOpenPlan: (card: Card) => void`, wired from `App.tsx:1527` and `:1541` as `onOpenPlan={setOpenPlan}`. Move both component props to `(file: string) => boolean` and wire both call sites to `onOpenPlanFile` directly — the same callback `AgentList` already receives (`App.tsx:1394`). `PlanCard`'s `onOpen` prop stays `(card: Card) => void` (`PlanCard.tsx:311`); `Board.tsx`/`Swimlanes.tsx` wrap it: `onOpen={(card) => onOpenPlan(planHref(card)) && undefined}`-shaped is wrong because `onOpen` has no return — thread the file into a thunk that calls the new `onOpenPlan`, discards its boolean (the anchor it intercepts is `PlanCard`'s own, not this prop's), and still calls `onOpen`'s existing contract. Simplest correct shape: keep `onOpen: (card: Card) => void` passed to `PlanCard` unchanged, and have `Board.tsx`/`Swimlanes.tsx` build it inline from the new `onOpenPlan` (`onOpen={(card) => { onOpenPlan(planRoute ? cardFile(card) : card.path); }}`) — pick whichever reads cleanest once you're in the file, the constraint is only that `PlanCard` itself keeps taking `(card: Card) => void`, because `PlanCard`'s own anchor (see below) needs the whole card for its `handleOpen`, not just a file.
- `SprintModal.tsx:9` — `onOpenPlan?: (slug: string) => void`, wired from `App.tsx:1588-1600` with a hand-rolled slug→card lookup that duplicates what `planIndexOf`/`planReference` already do. **Gap the plan does not spell out:** `SprintModal` receives `cardSlugs: ReadonlySet<string>` (`SprintModal.tsx:11`), not cards or a `PlanIndex` — it cannot build a `planReference` answer (no file, no issues) from a set of slugs alone. This slice must widen that prop to carry what `planReference` needs — pass the `PlanIndex` itself (built once in `App.tsx` from `allCards`) rather than `cardSlugs`, and have `SprintModal` call `planReference({ slug: m.slug }, index)` per member. `cardSlugs` then has no remaining caller in this file; remove it from the props rather than keeping it alongside the index.
- `WorkerLogModal.tsx:108` / `:141` / `:319` and `AgentPanelFacts.tsx:338` — already `(planFile: string) => void`. Only the return type changes, to `boolean`; `App.tsx`'s wiring into `WorkerLogModal` already uses `onOpenPlanFile`-shaped logic in spirit, confirm at the call site rather than assuming.

**`PlanCard` and `PlanModal` headings gain the prefix via `PlanReference`, but their `Open` controls are NOT replaced by it.** `PlanReference` renders its own anchor with its own click-interception (`isPlainPlanClick`) and its own text (prefix + truncated slug) — it is built for a *reference*, not for a card's own `Open` action, which has different text ("Open") and already has its own modifier-aware `handleOpen` (`PlanCard.tsx:351-355`). Do not swap the `Open` anchor for `<PlanReference>`. Instead:
  - `PlanCard.tsx:372-374` (`<div>{card.title}</div>`) and `PlanModal`'s `ariaLabel`/`frameTitle` (`DocModal` props, built at `PlanModal.tsx:39-44`) gain the prefix as *text*, computed from `planReference({ file: card.path, slug: card.slug, issues: card.issues }, index).label` (or equivalently render `<PlanReference answer={...} />` beside/instead of the bare title where a link is also wanted — the plan's own wording, "headings gain the prefix", does not require the heading itself to become a link; `Open` already is one). Pick the simpler of: (a) render `{label}` as plain text in the heading, reusing the already-computed label, or (b) render `<PlanReference>` in place of the bare title so the heading becomes clickable too. The Done-when table does not distinguish, so either satisfies it — note which you chose in the PR body since the Fleet index slice will read this file next.
  - Their `Open` anchors (`PlanCard.tsx:496-497`, `PlanModal.tsx:40-44`) stop calling `planHref(card)` and call `planRoute(card.path)` instead — same output today (`planHref` and `planRoute` compute the identical `/plan/<basename>` string), but `planHref` is deleted by this slice, so every caller must move first or the deletion breaks the build.

**`StoryModal`'s plan list (`:299-312`) is in scope for both the label and the link — it is the one list in that file that is a plan reference.** Replace the raw `<button onClick={() => setViewingPlan(card)}>{card.title}</button>` with `<PlanReference>`: build the index once from `cards` (the prop `StoryModal` already receives in full, per its own comment at `:54-58`), answer `planReference({ file: card.path, slug: card.slug }, index)` per plan, and pass `onOpenPlan={(file) => { const c = cards.find(c => c.path === file); if (!c) return false; setViewingPlan(c); return true; }}`. This is an in-overlay navigation (`setViewingPlan`), not a route change, so it always returns `true` for a card found by file — there is no "fall through to the browser" case here the way there is in `App.tsx`'s top-level `onOpenPlanFile`.

**`StoryModal`'s `rewritePlanLink` (`:12-24`) and `server/board.ts`'s `rewritePlanLinks` (`:3182-3194`) both move to the domain's `planRouteOfDocLink`.** Both are regex-identical to each other and to what `planRouteOfDocLink` (already shipped by the Rule slice, `packages/domain/src/rules/plan-reference.ts:180`) does — confirmed by reading both: same plan-path regex, same story-path regex, same fallback to the original href. Delete both local functions; `StoryModal.tsx:40` and `server/board.ts:3200` call the imported rule instead. This is the one change in `server/board.ts` this plan touches — the plan's Motivation section notes `server/board.ts` was out of scope for PR #2992 but is explicitly in scope here (Approach, "The server's document-link rewriter").

**`planHref` (`lib/plan.ts:13-16`) is deleted only after every caller above has moved to `planRoute`.** Grep for `planHref(` before deleting — `PlanCard.tsx:343`, `PlanModal.tsx:40`, and `StoryModal.tsx:155` (the `viewingPlan` DocModal's `href`, separate from the plan list) are the three call sites found by reading the files directly; do not trust this list over your own grep, since another slice may have touched these files between this brief being written and you picking it up.

**The CI gate, `scripts/check-plan-routes.sh`, does not exist yet — this slice writes it.** Model it on `scripts/check-no-bundle-diff.sh` (grep-based, comments stripped, named exceptions) rather than inventing a new gate shape. It greps `packages/board/src` and `packages/domain/src` for a `/plan/` href built from a template literal or string join, with comments removed, and fails on any site outside `packages/domain/src/rules/plan-reference.ts`. Measured on `origin/main` before this slice (commit `251b2abfc`, per the plan's own measurement) there were 10 such sites; the Rows slice has already removed the `lib/tuple-row.ts` (×3), `lib/agent-rows/rows.tsx` and `lib/plan.ts` ones (re-measure with your own grep once you start — do not trust the count without checking, since the Rows slice already merged and the plan's 10-site count predates it). What remains for this slice to clear: `components/StoryModal.tsx:16`, `App.tsx:952`, `:965`, `:980`, `server/board.ts:3186`. Add the gate's step to `.github/workflows/ci.yml` beside the other `scripts/check-*.sh` steps — `Plan headings say Slices` at `ci.yml:1666-1667` is the nearest sibling to pattern-match against.

**Remove the `` href={`/plan/ ``} allowance from `ROW_NAVIGATION`** at `test/unit/agent-list.test.ts:3398` — this is the test fixture that let the old pre-rule hrefs pass; once every site routes through `planReference`/`planRoute`, the allowance is dead and the gate above would otherwise still pass a reintroduced raw href if this fixture still excuses it.
