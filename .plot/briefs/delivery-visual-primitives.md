### What to build

The Delivery tab does not look like the approved mockups, and the cause is structural, not cosmetic: no section is a card (each group is its own bordered `rounded-lg border` list), no table shows its column headers (`HeaderRow`, `FleetAgentHeader` and the Tickets header are `sr-only`), and colours are Tailwind palette classes written per component, so the tab shares no palette with the Plans tab, which already draws from the `--card-*` and `--hue-*` tokens in `index.css`. This slice lays the foundation once so each Sections branch only writes its own stylesheet: the tokens in both themes, `styles/delivery.css` (the primitives), the six empty per-section stylesheets, the section card and header bar, both group-heading variants, the kind cell, the tab-header columns, visible header rows and row rules, the five-state colour map, the theme contrast test, and the screenshot harness with its CI artifact. Plan *Theme Tokens*, *Primitives* and *Screenshots* are the specification; this brief orients and corrects.

### The decisions the plan settles — do not re-derive them

**Tokens, not hex, defined once for light and once under `prefers-color-scheme: dark`.** The board has no other theme switch: no `data-theme` and no `@custom-variant` under `packages/board/src`. A hex value in a stylesheet or a `dark:` utility on a Delivery element is the failure this slice exists to remove. The light and dark blocks are `index.css:77-121` and `:123-…` today.

**Two token families are added and one is changed, no more.** `--card-rule` (slate-100 light, `rgb(51 65 85 / 0.5)` dark) and `--hue-rose`, `--hue-rose-dot`, `--hue-rose-soft` serve the `design` role chip, because `ChipColour` names `rose` and `index.css` has no rose hue. Light `--card-meta` changes from `oklch(55.4% 0.046 257.417)` (`index.css:87`) to `oklch(53% 0.046 257.417)`, because the old value reads 4.35:1 on `--card-band-strong` and `--card-panel-strong` and the gate asserts 4.5. The token is shared, so the Plans tab's muted text darkens by the same step; Jan Wloka accepted that. The other `dark:` utilities and the `prefers-color-scheme` block in `server/board.ts` stay.

**The imports are unlayered and go directly after `@import "tailwindcss";` (`index.css:1`).** Tailwind 4 puts utilities in `@layer utilities`, and an unlayered rule outranks any layered one, so a section rule beats a utility that sets the same property. Importing them layered, or after other rules, loses silently. The screenshot test asserts one computed style per stylesheet, so a stylesheet the build drops, or a layer that loses, fails CI. A Sections branch never edits `index.css`: that is why the six per-section files exist empty.

**One five-state colour map for every bar and strip.** Delivered `--hue-green-dot`, at a gate `--hue-amber-dot`, being built `--hue-blue-dot`, blocked `--hue-red-dot`, not started `--card-track`. It changes `SprintCard.tsx:5-7` today, which colours a gate sky and a blocked slice amber, the inverse of the mockups. A count in the header takes the same map: `being-built` blue, `working` (a Fleet count, not a slice state) green. A class maps an existing domain field and computes nothing: no component tests a string, a count or a threshold to pick a style.

**The role chip keeps the domain's colour keys.** The mockups colour `approver` teal and `idea` grey; the domain gives `approver` emerald and `idea` sky (`agent-roles.ts:136-145`), and `brief` already holds teal, so the mockups' colours would give two roles one chip. Map each `ChipColour` to `--hue-<colour>-soft` behind `--hue-<colour>` text.

**Where a mockup and the spec text disagree, the spec text wins.** The mockups show the Fleet switches as text on the header card; the spec shows them read-only, so they stay read-only switches. The mockups label the toggle "This sprint"; the spec names it **My sprint**. Column headers and kind cells are 11 px, not the mockups' 10 px, which is the smallest size the board uses. Rows are 13 px.

**A dot always sits beside its state as words.** A dot with no visible word beside it carries `role="img"` and an `aria-label`, as `MachineSection` does at `AgentList.tsx:24`. Icons come from `glyphs.ts` only; add no SVG path.

**The visible header row changes what `innerText` reads, not what `getByRole('columnheader')` reads.** `agents-tab.browser.test.ts` asserts column headers by role, which reads the same shown or hidden. Audit every grid `innerText` read in the integration tests (26 files read `innerText` on 2026-11-18) and fix a test only where it asserted the `sr-only` placement itself. Name each fixed test in the PR body. Below 640 px the header row stays hidden and the cells stack, as `max-sm:grid-cols-1` does today.
