### What to build

`plot-dispatch` creates a worktree, pushes a claim and books a `Started:`
record — then stops. Two steps of the hand-off have been supplied by hand all
evening: **writing the brief** and **starting the agent**. This branch closes
the first one.

Measured: `plot-dispatch.sh` contains **zero** occurrences of the word "brief".

**This file you are reading is itself an instance of the artifact** — it was
written by hand, like every other file in `.plot/briefs/`. That is the gap.

### The architecture decision — the first draft of the plan got it backwards

The plan originally said *"`plot-dispatch` invokes `/plot-implement`"*, meaning
the **script**. That is wrong twice over, and the interrogation killed it:

- **No script in this repo invokes a skill**, and that is the Manifesto's
  direction rather than an omission — *skills interpret and adapt; scripts
  collect and report* (Principle 3).
- **A bash script cannot reach a skill at all.** Skills exist inside an agent
  session; there is no callable surface from a shell.

**The caller is `skills/plot-dispatch/SKILL.md`** — the session-level layer that
already drives `plot-dispatch.sh` through its phases. That is where
interpretation is allowed and another skill is reachable. **`plot-dispatch.sh`
keeps doing exactly what it does today**; do not add a brief-writing step to it.

### Why the brief cannot be generated by a script

This is measurable and it decides the design. `plot-implement`'s brief template
is **8 lines**. The briefs actually written this session run **111–127 lines**,
and the difference is not padding — every added part is a **rejected
alternative**: the obvious approach, plus the measurement that killed it.

> *"`merge-tree` cannot answer this — `plot-dispatch` creates the candidate
> branch, so the comparison reports clean for every candidate, forever."*
>
> *"Do NOT route this through `worktree_rows()`. A local branch with no worktree
> still holds commits nobody can see."*
>
> *"Do not read that diff. Take either side, then rebuild — which side you take
> cannot matter."*

A plan records the decision; the brief records what an implementer would
otherwise **re-derive**. Without it, three agents this session would have
rebuilt mechanisms already disproved — the plan text alone does not stop someone
reaching for `merge-tree`, because the plan's *reasoning* reads as background
rather than as a warning aimed at them.

So the brief is **interpretation**, not extraction. A script filling an 8-line
template would produce something worse than the plan it summarises.

### Three more decisions the plan settles

**One definition of what an implementer needs to know.** A second definition in
the dispatcher would drift from the first the way every duplicated rule in this
repo has: the eligible-note string became a shared constant this session for
exactly that reason, and the artifact merge strategy exists because two copies
of a generated file cannot be reconciled. `plot-implement` already defines the
brief, already reads the plan's recorded `Impl:` answer and already runs the
staleness preflight — call it rather than reimplementing a thinner version.

**The brief lands at `.plot/briefs/<branch>.md`, committed to the default
branch** — where the briefs already live — so a resumed or replaced agent can
read it without the dispatching session.

**A direct `plot-dispatch.sh` call cannot write a brief, but it MUST say one is
missing.** Direct calls are legitimate: `--dry-run` and `--status` are the
normal way to look before leaping, and this session used the bare script five
times. **Refusing to run without a brief would be a gate in the wrong place**;
reporting the gap costs nothing. The summary gains the fact alongside the worker
count — *worktree prepared, no brief, no worker started* — which is exactly what
was missing five times in one evening.

### The template grows to match what briefs actually contain

The 8-line version in `skills/plot-implement/SKILL.md` describes a shape nobody
has used. The real ones carry:

- a *what to build* narrative
- the **settled decisions with their measurements**, framed as warnings
- the assertions a naive test would pass without
- a bookkeeping duty
- a scope guard naming the branches in flight

Write that shape down — **not as a form to fill**, but as the sections a brief
is incomplete without. Read several files in `.plot/briefs/` before you edit the
template; they are the evidence.

### Done when

The plan's `## Done when` list is the specification. The assertions that exist
because a weaker implementation passes without them:

- **A dispatch produces a brief at `.plot/briefs/<branch>.md`**, committed to
  the default branch. Assert it names the plan, the branch and the scope guard —
  the three things a replacement agent cannot work without.
- **The brief comes from `plot-implement`, not from the dispatcher.** Assert
  there is **one** definition: a template string in `plot-dispatch.sh` fails
  this even if its output looks right.
- **The script never invokes a skill.** Assert `plot-dispatch.sh` contains no
  such call — the plan's own first draft proposed exactly that, and it would
  invert the Manifesto's direction as well as being impossible in bash.
- **A direct script call reports the missing brief** rather than refusing.
  Assert `--dry-run` and `--status` still work untouched.
- **`--no-start` still starts nothing, and still writes the brief.** The two are
  independent; conflating them would remove the inspect-first workflow this
  session relied on.

`pnpm run validate` all pass; a changeset is present. macOS bash 3.2 — **no
`declare -A`**.
