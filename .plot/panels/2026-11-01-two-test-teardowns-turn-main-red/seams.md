# Seams juror — Two test teardowns turn main red

Position: amend

The two failures do not share one mechanism, and the plan's Approach ("both fixes are the same shape: a teardown waits for the process it started") is false for both. Leak 1 is a production defect: `parseBlobs` stages through a raw `mkdtempSync`, and the board already has a registry (`packages/board/src/server/stage-dirs.ts`) that removes exactly this kind of directory on SIGTERM, written on 2026-10-15 for the same failure under a different prefix. PR #2992 moved `parseBlobs` into the board server's scan path on 2026-11-01, and the leak started on #2992's own merge commit: 0 of 40 board-integration runs before it, 7 of 44 since. No test starts the parser spawn, so no test can wait for it. Leak 2 is a test defect, but the writer is the continuation's re-parented REPORTER subshell, not the agent, so "wait for the agent to exit" does not close it; the fleet's own `rm-tree.mjs` docstring records that awaiting the waited-for process "did not hold". The CI gate that should catch leak 2's shape counts only `fs.rmSync` and misses the bare `rmSync` import: it sees 2 sites where 94 exist under its own two directories. The slices do not collide textually with any open PR or with the plan walk's last slice, but #3003 (merged 15:47Z) added a second unregistered stage directory (`plot-default-plans-`) on the same poll path, and the plan walk's Removal slice makes `plot-scan-walk.mjs` the only scan path, which carries `parseBlobs` into a third process with no exit handler. Fix the mechanism once in the domain, and the next red main is prevented rather than queued.

## Amendments I require

- A1. Replace the Approach. State two mechanisms: (1) a production process ended by a signal skips `parseBlobs`'s `finally`, fixed in production through the existing stage-directory registry; (2) a test removes a desk while the continuation's re-parented reporter still writes, fixed in the test. Remove "both fixes are the same shape" and the claim that the precedent is a "wait" pattern; the 2026-09-01 precedent is a retrying removal.
- A2. Rewrite slice 1 and Required behaviour 1 against production code. Move `stage-dirs.ts` from `packages/board/src/server/` into `packages/domain/src/adapters/` (it touches fs and process, so it is an adapter; the domain may not import the board), keep `board.ts` on it, and make `parseBlobs` stage through `makeStageDir`/`removeStageDir`. Register `removeStageDirsOnExit()` in each entry that reaches `planStoreRef`: the board server (already), `registryd-main.ts`, and `entry/scan-walk.ts`. Rename the branch to what it builds, for example `bug/the-ref-plan-store-stages-through-the-registry`.
- A3. In the same slice, route `fleet.ts:1614` (`plot-default-plans-`) and `fleet.ts:1792` (`plot-draft-plans-`) through the registry, or name each as out of scope with a reason. A fix that covers one of three members on the same poll path leaves the next red main queued.
- A4. Prove slice 1 deterministically with the precedent already in `packages/board/test/unit/stage-dirs.test.ts:85` (*a SIGTERM mid-build removes the directory, and the process still ends by SIGTERM*): a child node process calls `parseBlobs` with a stub `plot-plan-meta.sh` that blocks, the test waits until the `plot-plan-store-ref-*` directory exists, sends SIGTERM, and asserts the directory is gone and the child ended by SIGTERM. Mutation check: revert `parseBlobs` to raw `mkdtempSync` and the test must fail (my probe shows the directory stays).
- A5. Rewrite slice 2 and Required behaviour 2. The fleetd case (`continuation.test.ts:77`) injects `fakeSpawn`, as its three siblings do, because it asserts only `kind === 'started'`; the test then starts no process. The pid-start-time case (`:158`) keeps its real spawn and removes its desks with `removeTree` from `packages/fleet/test/rm-tree.mjs` (the declared helper whose retry absorbs a reporter's late write). Proof: a spy asserts the fleetd case calls the injected spawn exactly once; for the real-spawn case, state that the retry is the fix and why the reporter cannot recreate the desk (`>>` and `>` into a removed directory fail, the reporter's errors go to `/dev/null`).
- A6. Correct the Motivation facts: seven leaks since #2992's merge (list the jobs), two continuation failures (13:49Z and 15:39Z), the full caller list (Finding 7), and the three browser files (Finding 8). Answer the Open Question in the plan rather than deferring it, because the answer changes the slice from a test change to a production change.
