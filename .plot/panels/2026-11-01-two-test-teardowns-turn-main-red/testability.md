# Testability juror — two-test-teardowns-turn-main-red

Position: amend

Both leaks are real and both are reproducible deterministically, but neither slice as written can be proven, because each slice names the wrong actor. Slice 1 asks a test to wait for spawns before "its teardown removes the `plot-plan-store-ref-*` staging directory": no test removes that directory, the test helper already waits for the whole server tree to exit, and the leak happens inside the board server process when its SIGTERM handler ends it mid-`parseBlobs`. The leak moved across three test files on 2026-11-01, so a per-test wait cannot fix it; the fix belongs in production, where `stage-dirs.ts` already solved the same leak for `plot-board-plans-` in #1802. Slice 2 asks the test to wait for "the agent process" to exit, but the process that writes into the desk after the agent exits is the reporter sibling, which no pid file names. A test that waits on `.plot-worker.pid` still races. The plan also has no "Done when", so nothing checks the fix except one green CI run. The amendments below give each slice a test that fails on main and passes after the fix, with no timing in the assertion.

## Findings

1. **high: slice 1 targets the test, but the leak is in the server process, and a test-side wait cannot remove it.** Evidence: `packages/board/test/helpers.mjs:269-288` (`kill`) already sends SIGSTOP and SIGTERM to the server tree, then waits with `untilGoneSync` and escalates to SIGKILL. `packages/board/src/server/stage-dirs.ts:62-71` removes only the directories made through `makeStageDir`, then raises SIGTERM again. `plan-store-ref.ts:113` calls `mkdtempSync` directly, so its directory is never recorded, and the `finally` at `:149-151` never runs. I checked this by running a probe (scratch `probe.mjs`) that has the shape of `parseBlobs`: `mkdtempSync`, an awaited detached spawn, and `rmSync` in a `finally`. After SIGTERM it left `plot-plan-store-ref-*` behind both without a handler and with the `stage-dirs` re-raise handler (exit 143 both times). The test cannot remove a directory whose exact path only the dead process knew, and CLAUDE.md forbids removal by glob.
2. **high: the leaking test is not one test, and the plan undercounts the failures.** I matched each leak's `holds:` timestamp to the serial vitest file running at that moment. There is one file at a time, because `packages/board/vitest.config.ts` runs `fileParallelism` false for the serial project. Results: run 41303723233 `stuck-rows.browser.test.ts`, 41304794037 `tiny-garden.browser.test.ts`, 41310373655 `dead-fetch.browser.test.ts`, 41314420918 `stuck-rows`, 41319588779 `stuck-rows`, 41322195284 `tiny-garden.browser`, 41323069974 `dead-fetch`. All three files run `startServer` on `fixtures/tiny-garden`. Each leak shows about 4 s before the file ends, which is the `afterAll` kill. On 2026-11-01, 8 of 48 `ci.yml` runs on main failed: 7 on `plot-plan-store-ref-` and 2 on `plot-continue-fleetd-` (41312576926 and 41322195284). The plan names 2 runs.
3. **high: slice 2 waits for the wrong process.** Evidence: `packages/fleet/src/shared/continuation.ts`, the `spawnFn('sh', ['-c', …])` block after `reporterTail`. The agent subshell records `$!` in `.plot-worker.pid`. A sibling reporter, which records no pid, polls `kill -0` every 0.05 s. After the agent is gone, the reporter writes `.plot-worker.exit` when that file is missing, and then appends a `WorkerMonitor` line to `<desk>/.plot-worker.monitor.worker.jsonl`. With `Worker command` = `true` (`continuation.test.ts:97`), the agent exits at once and the reporter writes up to 50 ms later, which is the `ENOTEMPTY` at `continuation.test.ts:74`. A teardown that waits for the agent pid returns before the reporter's write, so slice 2's own wording still races. Both processes are re-parented to init, so the test holds no child handle that it can await.
4. **medium: the plan has no "Done when", and its only evidence of the race is "the next commit ran green".** Under my lens, a green run proves nothing at a 7-in-48 failure rate. The probability of one clean run is about 85 %.
5. **medium: the plan omits the third production caller.** `packages/fleet/src/server/entry/registryd-main.ts:1317,1364,2819` builds `planStoreRef` in fleetd. A `launchctl bootout` or `--stop` of fleetd mid-parse leaves the same directory in the operator's real TMPDIR, where no `owned-run.sh` reports it. `plot-scan-walk.mjs` (`entry/scan-walk.ts:76`) installs no signal handler at all. Only `board/src/server/index.ts:1055` calls `removeStageDirsOnExit`.
6. **low: the claims that are true.** `plan-store-ref.ts:113` is the `mkdtempSync` line. `continuation.test.ts:74` is the `afterEach` `rmSync`. The case name matches the log of job 124894630710. The precedent plan `docs/plans/2026-09-01-a-teardown-does-not-fail-a-suite.md` exists and is Released. That precedent is the weaker match, because a retrying `rmTree` does not stop a live writer. The closer precedent is `fb75fdd31` (#1802), "The board server removes its plot-board-plans- … stage directories on exit and on SIGTERM", which the plan does not cite.
7. **low: Type reads `feature`, but both slices are `bug/` branches and the change fixes defects.**

## Amendments I require

- A1. Rewrite slice 1 as a production fix: `parseBlobs` creates its staging directory through a recorded-stage-directory registry and removes it through that registry. Every entry that can reach `planStoreRef` (board server, `plot-scan-walk.mjs`, `registryd-main`) installs the exit and signal removal. Use one registry per process: move `stage-dirs.ts` into `packages/domain/src/adapters/`, because `process.on` reaches the world, and let the board import it. Two registries would each raise the signal again. This follows the layering rule, because the domain adapter must not import from `packages/board`.
- A2. Slice 1 test, deterministic and red on main: a domain test spawns a node child with a private `TMPDIR`. The child installs the exit handlers and calls `planStoreRef(...).readPlans` with a fake `Refs` that answers fixed blobs, and a script directory whose `plot-plan-meta.sh` stub blocks (for example `exec sleep 60`). The parent waits for the state, a `plot-plan-store-ref-` entry in that `TMPDIR`, not for a time. The parent then sends SIGTERM, awaits `exit`, and asserts that the `TMPDIR` is empty and the exit signal is SIGTERM. Add a second case for `process.exit` mid-parse. Model both on `packages/board/test/unit/stage-dirs.test.ts:84-111`. On main the assertion fails every time (my probe reproduced it 2 of 2), because the stub parser removes the race.
- A3. Add one entry-level proof for each entry, or at least for the board server, since that is what CI hit: `startServer` with `PLOT_SCRIPTS_DIR` pointing at the blocking stub, a request that reaches `planMetasAtDefault`, a wait for the stage entry, then `server.stop()`, and an assertion that the entry is gone. Without this proof, A1 can wire the registry and still miss the one entry that leaked.
- A4. Rewrite slice 2 so that it names the reporter, not the agent, and choose one of two deterministic fixes. (a) Recommended: inject `spawn` with a stub, the way the sibling case at `continuation.test.ts:125-130` already does. The case asserts only `result.kind === 'started'` and the acceptance of a fleetd caller, so it needs no real process, and then nothing writes into the desk. (b) Keep the real spawn, and before removal wait for the reporter's last write: the `WorkerMonitor` line in `.plot-worker.monitor.worker.jsonl`. Use the fleet's existing `test/rm-tree.mjs` removal, not raw `rmSync`. Option (a) is smaller and has no wait to tune. If the case must keep the real spawn, write in the plan why it must.
- A5. Slice 2 proof: (a) needs no reproduction, because the stub spawn removes the writer. Assert that the stub was called once, and that no `.plot-worker.monitor.worker.jsonl` exists after the call. For (b), add a probe case that awaits the agent pid's death, reads the desk listing, then awaits the reporter's line. That case shows that the line arrives after the agent's death, which proves that a wait on the agent pid alone is insufficient.
- A6. Add `## Done when` with checks that do not trust one green run: the A2 and A3 (or A5) tests fail on the parent commit and pass on the branch, which the reviewer checks by running them against `origin/main` with the source change reverted. And no `plot-plan-store-ref-` or `plot-continue-fleetd-` entry appears in the next 30 `ci.yml` runs on main. The baseline is 7 of 48 and 2 of 48 on 2026-11-01, so 30 clean runs reduce the chance that the fix only got lucky to about 1 % for the store-ref leak.
- A7. Correct the Motivation: list all 7 store-ref runs and 2 continuation runs, name the three serial test files and the server process as the place of the leak, list `registryd-main.ts` as a caller, and cite `fb75fdd31`/#1802 as the precedent.
