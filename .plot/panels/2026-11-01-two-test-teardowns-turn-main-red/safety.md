# Safety juror — two-test-teardowns-turn-main-red

Position: amend

The plan reads both failures as a test teardown that does not wait for its process. That holds for slice 2 only partly, and it does not hold for slice 1. The `plot-plan-store-ref-*` leak comes from the board server process itself: `startServer().kill()` already waits for the server and its whole tree to exit, and the server dies by SIGTERM while `parseBlobs` awaits its parser, so the `finally` at `plan-store-ref.ts:149` never runs. The board already has the fix for this exact shape (`stage-dirs.ts`, #1802, for `plot-board-plans-`), and `plan-store-ref.ts` does not use it. So slice 1 is a production change, and the same leak happens on an operator machine every time a board stops mid-scan. Through the safety lens, the production fix has one real hazard the plan must name: if the board's signal installer is reused in fleetd, one SIGTERM ends fleetd at once instead of gracefully (measured below). Slice 2 waits for the wrong process: the last writer into the desk is the unrecorded reporter subshell, not the agent whose pid the desk records. Both slices are small and worth doing; the plan needs the amendments below before approval.

## Findings

1. **high — slice 1 targets the wrong layer; the leak is in the board server, not in a test.** Evidence: the leaked directory's timestamps fall inside a board browser test that starts a real server on `test/fixtures/tiny-garden` every time. Run 41322195284: created 15:44:32.837, inside `tiny-garden.browser.test.ts` (15:44:24.9 to 15:44:36.9). Run 41323069974: created 15:59:24.998, inside `dead-fetch.browser.test.ts`. Runs 41319588779, 41314420918, 41303723233: inside `stuck-rows.browser.test.ts`; 41310373655: `dead-fetch`; 41304794037: `tiny-garden.browser`. The staged files are the tiny-garden plans (`2026-03-01-plant-tomatoes.md` and others). The server calls `planStoreRef` in process at `packages/board/src/server/fleet.ts:2936` (the display scan when no fleet owns it, every few seconds), added by `0846ab0e1` on 2026-11-01 00:15; the first leak on main is run 41303723233 at 11:57 the same day, and run 41251375560 (2026-10-31) has none. `packages/board/test/helpers.mjs:269-288` `kill()` stops, TERMs and waits for the server and its tree (`untilGoneSync`, then `endStragglers`). So no test can "wait for every spawn it starts": the spawn is inside the server, and the test already waits for the server. The server's SIGTERM handler `removeStageDirsOnExit` (`packages/board/src/server/stage-dirs.ts:62-71`, installed at `index.ts:1055`) removes only directories made through `makeStageDir`; `plan-store-ref.ts:113` calls `mkdtempSync` directly. Checked with `gh run view --log-failed` over every failing main CI run of 2026-11-01 and `git grep` over `origin/main`.
2. **high — the leak is not rare and not CI-only.** 7 of the 9 failing `main` CI runs on 2026-11-01 carry exactly one `plot-plan-store-ref-*` entry (41303723233, 41304794037, 41310373655, 41314420918, 41319588779, 41322195284, 41323069974). The plan's Motivation names two. On an operator machine the same path runs on every board stop during a scan: `pnpm board` runs under `node --watch`, so every rebuild restarts the server, and `/plot-board --stop` TERMs it. Each such stop leaves one directory in the operator's `$TMPDIR` until fleetd's hourly `--sweep-temp` removes it after 24 h (`packages/board/src/server/entry/reap.ts:283-300`); with no fleetd running, nothing removes it. The plan's "Board impact: none" and its test-only framing hide this.
3. **high — a production fix that reuses the board's signal installer in fleetd breaks fleetd's graceful stop.** `planStoreRef` also runs in fleetd/registryd (`packages/fleet/src/server/entry/registryd-main.ts:1317`, `:1364`, `:2819`) and through `refs-git.ts:400`. fleetd handles SIGTERM with `stopOnSignals` (`registryd-main.ts:2378-2392`): the first signal requests a stop that ends the current tick, and a second signal calls `exit(143)` at once. `removeStageDirsOnExit` re-raises the signal after its cleanup. I ran a probe (`node` v26.13.0, both listeners in one process, one SIGTERM): the output was `first: graceful stop requested`, `stage-dirs: cleanup, re-raise`, `second signal seen: exit 143 at once`, exit 143. So one SIGTERM (a `launchctl bootout`, `/plot-fleet --stop`) would end fleetd mid-tick and skip "the clock's runs end before the daemon does" (`registryd-main.ts:2876-2880`), with a scan still writing `.plot/state/`. The cleanup also removes the live stage directory under a parse that the graceful path would let finish. In fleetd the `finally` already runs on the first signal, and the second-signal path goes through `process.exit`, so an `exit` listener alone is enough there.
4. **medium — the layering rule decides where the shared stage-dir set lives.** `stage-dirs.ts` is board code; `plan-store-ref.ts` is a domain adapter, and the domain cannot import the board (CLAUDE.md, The Layering Rule). The live set must move to `packages/domain/src/adapters/` (it is already arrow functions and reaches the filesystem, so it is adapter code), with `board.ts:85` importing it from there. The plan says "Neither needs a design decision"; this is one.
5. **medium — slice 2 waits for the wrong process.** `continueOnDesk` (`packages/fleet/src/shared/continuation.ts:1390-1398`) spawns `sh -c` detached; that shell starts an agent subshell (its pid goes to `.plot-worker.pid`) and a reporter subshell whose pid is recorded nowhere. Both are re-parented to pid 1. The reporter polls `kill -0` every 50 ms and, after the agent exits, writes `.plot-worker.exit` (when absent) and `.plot-worker.monitor.worker.jsonl` into the desk (`continuation.ts:1374-1388`). With `Worker command` = `true` (`continuation.test.ts:96`) the agent ends at once and the reporter writes while `afterEach` (`continuation.test.ts:73-75`) runs `rmSync`, which is the `ENOTEMPTY` in the checks log of run 41322195284 (`continuation.test.ts:74:41`). A teardown that waits only for the `.plot-worker.pid` agent still races the reporter. The reporter is in the outer shell's process group (`detached: true` makes the outer `sh` a group leader), so waiting on that group is the correct condition; the test can learn the group id by passing a `spawn` wrapper (`input.spawn`, already used at `continuation.test.ts:139`) that records the real child's pid.
6. **medium — the same race exists in two more describes and one more test file, and the plan names none of them.** `continueOnDesk records the spawned pid's own start time` (`continuation.test.ts:158-176`) SIGKILLs the agent and then removes the desk while the reporter writes `137` into it. Run 41312576926 failed the same `fleetd caller` case and also left `plot-continue-fleetd-repo-*`: the `afterEach` loop threw on the first desk and never removed the second. The same run failed `helper-contracts` with `ENOTEMPTY` on `plot-pushmain-*/w/.git/plot-push-main.lock`, a third teardown race outside this plan.
7. **low — a teardown wait must be bounded and must not kill by a guess.** A wait for a process group with no bound can hang `vitest` past its hook timeout; a fallback `SIGKILL` to a recorded group id after the group is gone can hit a recycled group on an operator machine, where live desks and a board run beside the suite (`CLAUDE.md`, "Wait on your own PID, not a process name"). The existing `untilGoneSync` in `helpers.mjs:104-116` is the shape: bounded, signal 0, by exact id.
8. **low — the plan states facts that are incomplete.** "The callers are `fleet.ts` and `entry/scan-walk.ts`" omits `registryd-main.ts` (three sites) and `refs-git.ts:400`. **Type** reads `feature` for two `bug/` slices. "the leaking test is not yet named" is answerable now (finding 1). `plan-store-ref.ts:113` and the `finally` at `:149-151` are correct as stated.

## Amendments I require

- A1. Rewrite slice 1 as a production fix: `parseBlobs` makes its stage directory through a shared stage-dir set and removes it by the exact path `mkdtempSync` returned, on success, on failure, and when the process exits. Move `stage-dirs.ts` to `packages/domain/src/adapters/` and import it from `board.ts` and `plan-store-ref.ts`. Never remove by glob or prefix.
- A2. Split the installer into an `exit`-only listener and the signal re-raise. The board keeps both (it has no other SIGTERM handler). fleetd/registryd install the `exit` listener only and never a signal listener. State this in the slice, and add a test that one SIGTERM to a process with a `stopOnSignals`-style listener and the stage-dir set installed still stops gracefully (does not exit 143 on the first signal).
- A3. Give slice 1 a deterministic red-then-green proof that does not depend on CI timing: a domain test spawns a child `node` process that calls `readPlansAt` with a private script directory (a copied stub, never a symlink into `skills/plot/scripts/`) whose `plot-plan-meta.sh` writes its own pid and its argument paths to a ready file and then sleeps. The test waits for the ready file, sends SIGTERM to its own child by pid, waits for that child's exit, and asserts the exact stage directory is gone. It then ends the orphaned stub by the pid the stub wrote. Red on `origin/main`, green after.
- A4. Rewrite slice 2's required behaviour: the teardown waits for the outer `sh`'s process group (every process `continueOnDesk` started, the reporter included) to be empty before it removes the desk, captured through an `input.spawn` wrapper around the real `spawn`. Apply it to both real-spawn describes (`accepts a fleetd caller` and `records the spawned pid's own start time`). The wait is bounded (5 s or less, below the hook timeout), uses signal 0 only, and on the bound fails with the group id rather than sending SIGKILL.
- A5. Give slice 2 a deterministic proof: with `Worker command` = `sleep 0.3`, assert that `.plot-worker.exit` is absent when `continueOnDesk` returns and present once the group is empty. That shows a writer outlives the call, independent of scheduling.
- A6. Each `afterEach` removes every recorded directory even when one removal throws (try each, then rethrow the first error), so one failure does not also leak the sibling `-repo-` directory.
- A7. Correct the Motivation: seven runs, not two; the three test files; the board server as the process that creates the directory; all `planStoreRef` callers; Type `bug`; and replace "Board impact: none" with the board server's changed SIGTERM cleanup.
