# Panel — the-inbox-says-what-it-is-showing

**Reconciled: `unanimous` — amend (premise, value)**

Both jurors confirm the reading, the precedent and the byte-for-byte gate. Both
amend for the same reason from opposite directions: **a setup step is read once,
and the screen is read every day.**

## What survives every check

The JQL line is quoted verbatim, `PLOT_JIRA_JQL` is named in no skill and no
README, the cited comment lines are real, and the sibling plan genuinely shipped
the project scope for #850 while leaving the assignee clause alone deliberately.
The plan re-argues no default and changes no byte — and its one hard gate,
asserting the query line unchanged, is genuine.

## The amendment both lenses reach

`value` put the question directly: **would the board saying what it queried beat
a setup sentence the operator reads once and forgets?**

It found the mechanism already shipped. The board distinguishes three inbox
states, and this plan's case — `issueAnswer: 'answered'` with an empty array —
renders a bare `none`, while a credentials failure renders `data-issue-error`
with a note. **`HOST_ANSWER_HINT` is the pattern for exactly this** and is not
applied to the answered-but-empty case.

So the durable remedy exists one line away and is unfiled. The amendment is not
to abandon the setup step — it is cheap and true — but to **name that gap** in
`What this does not do`, so the panel does not record this report as answered by
documentation when the screen still says nothing.

## The merge question was asked and answered against

The plan's own Notes say the two reports *"both show an operator an empty
board"*. `value` read the render path and refuted it: **#930 produces an amber
error line, this produces `none`.** Same feeling, different pixels, different
fix.

They also differ in kind — `docs` against `feature`, one changing no byte and
one changing what the code reads. Merging would drag a docs change into a
release-gated plan.

**Two plans, correctly.** What the pair lacks is not a merge but the third,
unfiled item: the board line that makes them distinguishable on screen.

## A stale sentence in the file the step lands in

`value` found the setup skill already carries a false sentence about the Jira
inbox. **A plan adding a true sentence about the inbox to a file holding a false
one, and not fixing it, has not finished** — the implementer is already in the
file, so the marginal cost is near zero.

## What the lenses had in common

**Both accepted `Type: docs` without testing it.** `value` comes closest,
noting that folding in the board line would make `docs` wrong — and then leaves
the type alone. Neither asked whether a plan whose best answer is a code change
should be typed as documentation at all, which is the question the amendment
raises and does not settle.

That matters beyond bookkeeping: a `docs` plan is live on merge and needs no
release, so typing this one `docs` **decides** that the board line is somebody
else's plan. The type is doing argumentative work here, and nobody examined it.

## The moderator's reading

**Unanimous, and the amendment is small and specific:** name the unfiled board
line, bring the stale sentence into scope, and soften the Notes' claim that both
reports show one screen — the code says otherwise.

**Nothing here moves the plan's phase.**
