## (a) Problem statement

1. **"`continue`, `restart` and `merge` refuse every unattended caller" is true for `restart` only.** `restartWorker` refuses `unattended` (`workflows/dispatch-verbs.ts:194-198`), and both entrances read the environment (`board/src/server/restart.ts:68`, `fleet/src/server/entry/restart-command.ts:89`). `continueBranch` refuses only `unknown-branch` and `no-worktree` (`fleet/src/shared/continue-command.ts:72-90`), and its CLI has no unattended check (`fleet/src/server/entry/continue-command.ts:61-104`). `workflows/merge.ts` and `entry/ask.ts` contain no unattended check: grep for `unattend` returned exit 1. The controller gate checks an unattended caller only at a desk (`gate.ts:651-657`). So the *Caller identity* slice has one refusal to lift, not three.
2. **"`release` refuses every unattended caller" describes no current behaviour.** `workflows/release.ts:239-243` turns the Should-Have prompt into a `PLOT-UNASKED` warning under `unattended` and proceeds. The plan states this as a fact that "still" holds. Sibling #2911 states it as "stays refused" (its *Approach*, line 29). Neither plan builds the refusal, so it falls between the two plans.
3. **"`agentRunCommand` and the `agent-run` port take a role name" is half built already.** `AgentRunRequest.role` exists (`ports/agent-run.ts:47-48`), and the reviewer already passes `role: 'reviewer'` (`entry/review.ts`, the `agentRun.run({... role: 'reviewer' ...})` call after line 438). The command adapter ignores the field: it runs `bash -c '<fragment> "$@"'` (`agent-run-command.ts:63-66`). The field's vocabulary is `worker` plus board roles (`idea`, `brief`, …). Mapping every `role` to `--agent <role>` would start `claude --agent idea`, which does not exist. The plan names no separate field and no allow-list.
4. **The plan names one adapter, but two adapters implement the port.** `agentRunFor` picks `agentRunSdk` when `Agent runner: sdk` is set (`fleet/src/shared/agent-run-for.ts:64-100`), and `worker-loop.ts:2199` uses the SDK adapter. With the plan as written, a role started on the SDK runner silently drops its definition.

## (b) Approach — executed findings that move the design's mechanism

5. **`--agent reviewer` is not found under the reviewer's current flags.** `reviewerCommand` passes `--setting-sources user` (`rules/review-verdict.ts:180-181`). Run (1): `claude -p --agent probe --setting-sources user` answered *"--agent 'probe' not found"*, and the same call with `user,project` loaded the agent. To start the reviewer "through" the runner, slice 1 must add `project` to the setting sources. That also loads the project's `settings.json` hooks and `CLAUDE.md` into a run that is isolated today. Neither the plan nor #2917 names this trade.
6. **The definition's `isolation: worktree` did not apply under `--agent`.** Run (2) printed the scratch repo's own path and `master`, and `git worktree list` showed one tree. The *Isolation* column therefore has to be built by the runner, through `AgentRunRequest.worktree`, as `review.ts` already does with `trees.add`. "read-only" is not a frontmatter isolation value at all; it is a tool list, as `REVIEWER_TOOLS` / `REVIEWER_DENY` show.
7. **A `PreToolUse` hook in the frontmatter did not fire under `--agent`. The same hook in `.claude/settings.json` blocked the call.** Run (3), n=1. If this holds, the plan's core claim fails: "Hooks in each definition are the gates for these rules" cannot hold for a role started as `claude -p --agent <role>`. The gates would have to live in project settings that are scoped to the role, for example through `--settings <file>` per role, or the runner must start the role as a subagent. Slice 1 has to prove that a definition's hook fires before slice 2 writes four definitions that depend on it.
8. **Dead-desk fixer against `worktree` isolation.** A fixer commits to the PR's branch (design table). On a dead desk (#2915), that branch is still checked out in the desk's worktree, and git refuses a second worktree on the same branch. The fixer must run in the desk's worktree, or the desk must be removed first. This is a seam with #2912 and #2915, and none of the three plans names it.

## (d) Open questions

- **OQ1 (how fleetd declares its identity).** For the only refusal that exists (`restart`), the caller is fleetd's own tick, in-process (#2915: "fleetd calls the `restart` controller"). So the identity can be a typed argument at the call site, for example `caller: 'fleetd'` in place of `unattended: boolean` in `RestartReadings` (`dispatch-verbs.ts:134-135`). The two CLI and HTTP entrances keep reading `PLOT_UNATTENDED` and keep refusing. No process boundary exists, so no other process can forge the identity, and no environment variable or marker file is needed. The unblocker's `continue` call also needs no identity, because `continue` has no unattended refusal. Design goal 4 ("an agent never decides what happens next") also argues that fleetd, not the unblocker, should call `continueBranch` with the answer the unblocker returns. #2913 owns that choice.
- **OQ2 (hooks).** This is moot until finding 7 is settled. `check-no-bundle-diff.sh` already covers bundles in CI. A `Stop` hook that runs `./scripts/check-bash32-syntax.sh` fits bash 3.2.
- **OQ3 (copy or template).** `claude --agents <file>` (help text: "with --print the path to a file that holds one") could load the definitions from the plugin without copying them into the repo, and that removes the drift. Whether inline agents honour `hooks` is untested, and the design's reason for `.claude/agents/` is that plugin agents ignore hooks.
- **New:** Which source wins for `model` and `effort`: the charter (`reviewer.json`: opus, high), the `Agent models` config key (`agent-run-for.ts`, `boardAgentModel`), or the definition's frontmatter? Today the reviewer fragment passes `--model` explicitly.
- **New:** Does `maxTurns` in the frontmatter apply under `--agent`? Given findings 6 and 7, it needs the same probe.
- **New:** Does the `agent-run` port grow a field (for example `agent?: string`) instead of overloading `role`?
