# Juror verdict: safety

Position: amend

Evidence: Read the plan, issue #2898 (`gh issue view`), `DESIGN-delivery-loop.md`, the sibling plans #2909–#2917 (grep for identity, runner, exclusion), and at the plan's tree: `adapters/agent-run/agent-run-command.ts`, `adapters/agent-run/agent-run-sdk.ts:423`, `adapters/bounded-run/bounded-run-process.ts:97-160`, `rules/agent-run-env.ts`, `ports/agent-run.ts:47-48`, `rules/review-verdict.ts:157-186`, `board/src/server/entry/review.ts:35-60,405-466,600-630`, `board/src/server/entry/gate.ts:625-700`, `rules/controller-gate.ts`, `workflows/merge.ts`, `workflows/dispatch-verbs.ts:124-200`, `workflows/release.ts:230-250`, `board/src/server/restart.ts:55-80`, `fleet/src/server/entry/restart-command.ts:37-89`, the shipped bundles `plot-continue-command.mjs` and `plot-ask.mjs` (grep for `unattended`), `skills/plot-release/SKILL.md`, `plot-host.sh:563-598` (`commit-status`), `.gitignore`, `claude --help` (2.1.312). Ran: a scratch vitest probe (`juror-2898-safety/probe.test.ts`, run with the domain package's vitest against the plan tree's `src`) that calls `restartWorker` with `unattended: true` and `merge` with a green PR and no default-branch reading. Output: `restart → refused/unattended`; `merge → decided, pr-merge pinned to the head, defaultBranchRead:false`. Did not start any `claude` run, board or fleet command.

## (a) Problem statement

1. **The claim "continue, restart and merge refuse every unattended caller" is wrong for two of three.** Only `restart` refuses: `dispatch-verbs.ts:194-198` (my probe confirmed `reason: "unattended"`), read from `PLOT_UNATTENDED` at `fleet/src/server/entry/restart-command.ts:89` and `board/src/server/restart.ts:68`. `merge` has no caller input at all (`workflows/merge.ts:22-60`; `entry/merge.ts` and `entry/ask.ts` have zero `unattended` hits; the probe decided a merge). `continue` has no unattended refusal either (`board/src/server/continue.ts` zero hits; the `plot-continue-command.mjs` bundle mentions "unattended" only inside the wrapper's exit text). Sibling #2914 already says "The merge controller has no unattended caller today". Consequence for safety: today **any** unattended process, including every desk worker and every future role, can merge through `plot-ask.mjs merge` and can answer a `PLOT-BLOCKED` question through `continue`. The plan describes this as "lift a refusal"; the real work is "add a refusal, then scope the exception".
2. **"`release` still refuses every unattended caller" describes nothing that exists.** `workflows/release.ts:239-244` turns the Should-Have prompt into a warning under `unattended` and proceeds; `plot-release/SKILL.md:141-143` says the same ("PLOT_UNATTENDED answers *may I ask?*… and proceed"). The design binds "`release` stays refused for every unattended caller" (Calls made, line 180). The plan must build that refusal (at the domain release workflow and at the publish/merge of the release PR), and test it, not assume it.
3. **The runner fact is half right.** `AgentRunRequest` already carries `role` (`ports/agent-run.ts:47-48`) and `review.ts:451` passes `role: 'reviewer'`. The plan adds a parameter that exists. More important: there are two runners, not one. `agentRunFor` picks `command` or `sdk` (`fleet/src/shared/agent-run-for.ts:60-100`), and `agent-run-sdk.ts:423` loads `settingSources: ['user','project','local']`. A role started on the SDK runner would get no `--agent` and none of the definition's hooks.
4. **Missing cause: the reviewer is deliberately isolated from the reviewed tree's settings, and `--agent` reverses that.** `reviewerCommand` passes `--setting-sources user` (`review-verdict.ts:179-180`), and `review.ts:50-53` states the reason: "no settings from the reviewed tree". The reviewer's cwd is a detached worktree at the PR head (`review.ts:447,455`). `.claude/agents/reviewer.md` resolved from that cwd is **the PR's own copy**. Either `--setting-sources user` hides project agents and `--agent reviewer` fails or falls back (unverified; I did not start a run), or project agents load and the PR under review supplies its own reviewer prompt, tools and hooks. The second case lets a fixer or a desk worker edit `reviewer.md` in its slice and get `plot/review=success` on that head. That is the anti-goal's shortest path.

## (b) Approach

5. **Definitions must not be read from the tree the role works on.** The same problem holds for the fixer (works on the PR branch) and main-repair (works on a branch off main): each later attempt loads whatever the previous attempt committed to `.claude/agents/*.md` or `.claude/settings.json`. `claude --help` documents `--agents <file>` "with --print the path to a file". fleetd should pass the definitions from a trusted read (the default branch's committed blob at `origin/<default>`, or fleetd's own installed copy), not let the CLI discover them in cwd. Whether `--agents` JSON honours `hooks` and `permissionMode` is unverified and must be the runner slice's first measurement; if it does not, the role keeps `--setting-sources user` plus a `--settings` file fleetd writes outside the tree.
6. **Roles can bypass the ruleset without bypass rights.** `plot-host.sh commit-status <sha> success plot/review …` (`plot-host.sh:563-598`) writes the required status with the GitHub App key that any local process can read from the `Review app` config key. A fixer, unblocker or main-repair with Bash can run it, or run `plot-review.mjs`, and turn the check green. That is a grep-detectable rule, so it belongs in a `PreToolUse` hook in every non-reviewer definition: deny `commit-status`, `plot-review.mjs`, reads of the `Review app` key path, `gh pr merge`, `plot-ask.mjs merge`, and pushes to the default branch. The reviewer itself never writes the status; `review.ts` does after the run, and that stays.
7. **The controller gate does not cover roles in a worktree.** `controllerGateOf` returns `null` for any linked worktree before it checks unpinned merges (`gate.ts:688`, after the doc at `:636-643` "a linked worktree (a desk) is a worker's own call and is allowed"). A fixer or main-repair in `isolation: worktree` therefore may run an unpinned `gh pr merge` or a controller-owned script and the plugin gate allows it. "One merge in flight" then holds only if the role chooses to obey it. The role hooks in finding 6 are the gate that closes this.
8. **One caller identity for "fleetd and the roles it starts" is too wide.** The design's role table gives no role a merge or restart: the unblocker writes "one answer through `continue`", the fixer commits, main-repair opens a PR. If the identity lifts `merge` for every fleetd-started process, a fixer can merge its own PR. The identity should name the caller (`fleetd`, `unblocker`, …) and each controller should allow a list: `merge` and `restart` only for fleetd's own tick; `continue` for fleetd and the unblocker; `release` for none.
9. **An environment variable is forgeable by inheritance, which answers open question 1 against it.** `agentRunEnv` merges the inherited environment (`agent-run-env.ts`, "MERGES, NEVER REPLACES"), `boundedRunProcess` spawns with `{...process.env, ...options.env}` (`bounded-run-process.ts:113`), and the continue bundle spawns the new worker with `{...process.env, …}`. A variable set on a role reaches every desk worker that role's `continue` starts, and a variable set on fleetd reaches every worker fleetd dispatches. A project `.claude/settings.json` `env` key can also set it (`backgroundSwitchRefusal`, `agent-run-env.ts`, exists for exactly that shape). Over HTTP the board reads its **own** environment (`restart.ts:68`), so an env identity never reaches `/api/restart` at all. A single-use token file fleetd writes under `.plot/state/` (mode 0600, naming caller, action, subject and expiry, consumed by the controller) survives these cases; an env var does not.
10. **`memory: local` is a write into the PR tree.** For the fixer the cwd is the PR branch's worktree. A branch cut before the `.gitignore` slice merges has no entry for `.claude/agent-memory-local/`, so a `git add -A` commits it. The memory is also a persistence channel between attempts ("joining the lines passed the gate"). Put the memory directory outside the tree or make the `Stop` hook refuse a commit that touches it.

## (c) Slices

11. The order is wrong for safety. `feature/fleetd-caller-identity` lifts refusals; it must merge **after** the role hooks (finding 6) and must first **add** the missing refusals on `merge`, `continue` and `release` (findings 1, 2). Recommended order: (1) refusals added (merge, continue, release) with the caller-scoped exception list; (2) definitions with hooks, loaded from a trusted source; (3) runner, covering both `command` and `sdk` adapters or refusing roles on `sdk`; (4) adoption.
12. Missing from every plan in the story: a **run record per (role, PR, head)**. `boundedRunProcess` keeps the child in fleetd's group and kills it on `exit` (`bounded-run-process.ts:108-136`), but a `SIGKILL` or OOM of fleetd runs no handler, so the role keeps running while the next fleetd sees no record and starts a second fixer on the same branch. Two ticks in one fleetd hit the same gap if the start is not awaited. "One writer per branch" in the design keys only on the desk's worker (`DESIGN-delivery-loop.md:87`), and a fixer is not a desk worker. The runner slice owns the start, so it should write `<role>-<pr>.run` (pid, pid start time, head, start) and refuse a start while a live record exists. #2913 claims "the rule answers once per question" for the unblocker but names no record either.
13. `isolation: worktree` conflicts with "commits on the PR's branch". Git refuses to check a branch out in a second worktree while the dead desk's worktree still holds it. The fixer must either work in the desk's worktree (and then the desk's `.plot-worker.pid` arm of the gate applies, `gate.ts:657-676`) or the plan must say who removes the desk worktree first. A Claude Code worktree on a new branch would push to the wrong ref or fail.

## (d) Open questions

- **Q1 (identity mechanism):** not an environment variable (finding 9). A file token under `.plot/state/`, written by fleetd per start, naming caller, action and subject, consumed once. Verify the HTTP path reads it from the request, not the board's environment.
- **Q2 (hooks):** "never commit built bundles" is already gated by `scripts/check-no-bundle-diff.sh`; a `PreToolUse` on `git commit` can run it. "Never join lines" has no reliable grep; it stays an instruction, and `check-shell-lines.sh` still catches the shell side. Add the hooks this lens needs and the plan does not list: deny `commit-status`, `plot-review.mjs`, `gh pr merge`, `plot-ask.mjs merge`, a push to the default branch, edits to `.claude/**`, `scripts/check-*.sh` and `.github/workflows/**`.
- **Q3 (copy or template):** a template with a version stamp. Copies drift, and a drifted hook is a missing gate that looks present.
- New: does `claude -p --setting-sources user --agent <role>` find a project agent? One probe settles finding 4 and decides the reviewer's start.
- New: does `--agents <file>` honour `hooks` and `permissionMode`, which the design says plugin agents ignore?
- New: where is the fixer's cwd when the dead desk's worktree still holds the branch (finding 13)?

## (e) Tests

- Domain unit (vitest): `merge` refuses `unattended` with no identity and with a non-fleetd identity; decides for fleetd's identity. `continue` likewise, allowing the unblocker. `restartWorker` keeps `unattended` for every caller except fleetd. `release` refuses every unattended caller, including fleetd. A token for another action or subject, or an expired or consumed token, refuses.
- Rule unit: a run record with a live pid refuses a second start for the same (role, PR); a record whose pid start time differs is stale.
- Contract (`test/reconcile/`): each `.claude/agents/*.md` hook refuses `plot-host.sh commit-status`, `plot-review.mjs`, unpinned and pinned merges, and a push to `main`, fed as `PreToolUse` JSON on stdin. The test must fail with the hook removed.
- Adapter: `agentRunCommand` with `role: 'fixer'` builds a command whose definitions come from the trusted path, never from `request.worktree`; a fixture tree with a modified `.claude/agents/reviewer.md` is not what runs.

## Amendments

1. Correct the Motivation: only `restart` refuses unattended callers today; `merge` and `continue` refuse none, and `release` proceeds unattended. Add those refusals as the first slice.
2. Scope the identity per caller and per action; no role gets `merge` or `restart`; `release` refuses everyone. Choose a single-use state-file token over an environment variable, and make the HTTP routes read it.
3. Load role definitions from a trusted source (default branch blob or fleetd's copy), never from the tree the role reviews or edits; keep the reviewer's "no settings from the reviewed tree" property.
4. Add `PreToolUse` hooks that deny status writes, review runs, merges, pushes to main and edits to `.claude/**` and gates, for every non-reviewer role.
5. Cover the `sdk` runner or refuse roles on it.
6. Add a per-(role, PR) run record that survives a fleetd crash and refuses a duplicate start.
7. State where the fixer works when the dead desk's worktree holds the branch.
8. Keep `.claude/agent-memory-local/` out of the PR tree, or gate commits that touch it.
9. Reorder: refusals and hooks before the identity that lifts any refusal.
