## What must change

1. **Design › Slice 2 must say how it passes the shell ratchet.** `scripts/check-shell-lines.sh pr` refuses any PR whose non-comment `.sh` line count under `skills/` grows, with no override (its header: "There is no override, no allowance literal and no environment variable"). Slice 2 adds a `Worker loop` key read and an `exec` branch to `plot-worker-loop.sh` and removes nothing, so as written it fails CI. The plan must name the offset (for example the key read lives in the JS entry, or slice 2 deletes loop lines it already replaces) or the order of slices does not hold.
2. **Design › "The process restarts itself on new code" must name which tree's bundle it hashes.** The loop runs from the desk's own tree: `lsof -d cwd` on pid 57720 gives `.worktrees/free-9172bc8c`, now on `bug/a-release-and-a-rejected-push-name-the-agent`, and `plot-worker-loop.sh:72` resolves `script_dir` from `BASH_SOURCE`. `reset_desk` (line 1065) checks out the next slice branch in that tree. CI step "A PR carries no bundle" (`ci.yml:253`) means a slice branch holds the bundle of the main it was cut from. So a hash compare in the desk tree fires on every hop to a branch with a different base, and it restarts the loop into OLDER code, the opposite of the Changelog line "never keeps running yesterday's code". It also lets a slice of this very plan run its own unreviewed loop. The rule needs a fixed source (the main checkout, or a path the launcher pins) and a direction (newer only).
3. **Design › restart: name `process.execve` and its cost.** Node has no `exec` except `process.execve`, added in Node 23.11 and documented as experimental. Measured on v24.4.1: `typeof process.execve` is `function`, and an exec keeps the pid (97062 before and after). That keeps `wait "$agent"` in the dispatch wrapper and the manifest's `pid` valid, which a spawn-and-exit restart would break (the wrapper would record exit 0 and the finding "the worker is finished"). The plan says "`exec`s itself" and should say this is the only restart that preserves the supervisor's pid, and that it depends on an experimental API under `engines: node >=24`.
4. **Design › Approach must state the memory cost per agent.** Measured: a bash loop holds 2,016–5,008 KB RSS (pids 87706, 15968, 57720). An idle `node` holds 44,928 KB. A node that loads a zod-bearing bundle peaks at 57.9–62.1 MB (`plot-claim-answer.mjs`, `plot-slice-spend.mjs`). `plot-registryd.mjs`, the nearest long-running analogue, holds 80,944 KB after 2 d 05 h. `board-server.mjs` holds 562,784 KB after 10 h 40 m. Removing the two monitors saves about 9.7 MB per agent (pids 57715 and 57716: 4,960 + 4,752 KB). Net cost is about +50 to +75 MB per agent. Against the `claude` process each loop runs (718,496 and 1,135,088 KB measured) that is 5–10 %, on a 64 GB machine (`sysctl hw.memsize`). The cost is acceptable; the plan should state it and bound a loop's heap growth, because loops live for days (pid 15968: 3 d 19 h).
5. **Slice 4 must not remove `plot-build-monitor.sh` while the board reads its file.** `packages/board/src/server/findings.ts:42` reads `.plot-worker.monitor.build.jsonl`, and `packages/domain/src/rules/attention.ts:167` has a `BuildMonitor` case. The Board-impact comment says "The board reads the same … findings it reads today", which contradicts removing the writer. Either the JS loop writes that file, or slice 4 lists the board change. This is also 162 of the expected ratchet drop (item 7).

## What holds

- The Motivation's counts are true on main: `grep -vcE '^[[:space:]]*(#|$)'` gives 891 for the loop (3,137 with comments) and `^[a-z_]+\(\) *\{` gives 52 functions; helpers 94, 530, 39, 87, `plot-build-monitor.sh` 162 and `plot-agent-monitor.sh` 181, all non-comment counts.
- The restart CPU cost is negligible: `plot-registryd.mjs`, which imports the same adapter estate, changed in 72 commits in the seven days to 2026-10-04 (`git log --since=2026-09-27`), about ten restarts a day per agent, each a node start of tens of milliseconds.
- Restarting only where the loop holds no work is the right point, and the manifest on disk does carry the state between passes (`.plot/agents/<session>.json` holds `pid`, `slug`, `correctionAttempts`).
- Replacing the shell loop removes a real process-tree cost the plan does not claim: four `plot-agent-monitor.sh` and `plot-build-monitor.sh` pairs (pids 44099/44105, 73345/73366, 79173/79175, 86175/86277) run with ppid 1 for 2 d 15 h, from a desk path that no longer exists, two loops (15968, 87706) run with ppid 1 from test temp trees for 3 d 18 h and more. They come from test runs; one process per agent, with no sidecar monitors, has fewer children to leak.
- Slice 2's `exec` from the launcher keeps the pid the wrapper waits on and the registry records, so the supervisor's view of agents does not change as long as items 2 and 3 hold.
- The key defaulting to `shell` protects adopting repositories during the transition; `Worker command` keeps naming `plot-worker-loop.sh`.
