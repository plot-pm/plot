## What must change

New findings, all in the amended text:

1. **Slice 1 cannot settle the shell wait on a moved tip, so it does not fix #1199's measured case.** The BuildMonitor asks `run-for-sha` for the desk's own `HEAD` (`plot-build-monitor.sh:225-227`: `git -C "$worktree" rev-parse HEAD`, and its comment says it reads "the WORKTREE's HEAD rather than a remote ref"). After somebody pushes on top, the findings file never holds a line for the tip. `checksVerdict` settles only on `last.sha === readings.head` or a null sha. So a containing tip, which is #1199's measured case (an operator's repair pushed on top of `f743e573`), still waits the full 1,800 s. Only the force-push half (a tip that does not contain the commit) is deliverable in shell. Line 204 ("Slice 1 fixes #1246 and #1199 in every repository") and Changelog line 17 claim both halves. Amend: in the shell loop, any tip other than the desk's `HEAD` ends the wait and names the branch that moved, which is #1199's own "Expected"; the settle on a containing tip ships with the JS loop in slice 4, where `BuildPort.runForSha(branch, tipSha)` can ask for it. Move that half of Changelog line 17 to the slice-4 entry.
