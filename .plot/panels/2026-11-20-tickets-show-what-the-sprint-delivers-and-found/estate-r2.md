## Findings

1. **The client has no `TicketPlan` records, so "`ticketPhase` over the ticket's `TicketPlan` records (built per ticket by `ticketPlansOver`)" (line 44) cannot be built as written.** `ticketPlansOver` is a server function in `packages/board/src/server/fleet.ts:1811-1836`; it reads `entry.pulse` / `entry.lastComplete` to count merged slices. Its only callers are server-side (`fleet.ts:1801`, `:1971`, `:2444`, `:2539`, `:2588`, `:2619`), and `waitingTickets` runs on the server too (`waitingOver`, `fleet.ts:2246-2255`). The fleet payload carries only `plans: Record<slug, {file, issues}>` (`packages/board/src/contract/schema.ts:4830-4833`), with no state, total or merged count. `scopeTickets` (line 49) takes the scope's cards and `planTicketRows`, and slice 1 (lines 37, 68) adds neither a `TicketPlan` per ticket nor per row. A key-only delivered ticket has no row at all, so carrying plans on `planTicketRows` rows would not cover it either. A builder must then either compose `TicketPlan` from card fields the plan does not name, or add a third payload field the plan does not list. Ran: opened the callers and the schema. **Change:** in slice 1 (line 37 and the slice line 68), add a payload field `ticketPlans: Record<issueKey, TicketPlan[]>` (schema default `{}`) from the `ticketPlansOver` map the server already builds on the same pass (`fleet.ts:2444`), with a server test that an Approved plan's ticket carries `merged`/`total` and an unread pulse carries `merged: null`; in line 44 say `scopeTickets` reads that field. Alternatively name the card fields `scopeTickets` builds `TicketPlan` from and drop "built per ticket by `ticketPlansOver`".

2. **The server filter "whose title is a review-finding title (`reviewIssueTitle`)" (line 37) has no predicate to call.** `reviewIssueTitle(pr)` builds the title for one known PR, and `findOpenReviewIssue(issues, pr)` matches one known PR; the prefix `TITLE_PREFIX` is module-private (`packages/domain/src/rules/review-issue.ts:7,20,33-34`). The server does not know the reader's scope (the scope selector is client state, `delivery-scope.ts:50-61`), so it must keep every review-finding row, which needs an "any PR" test. Ran: opened the file. **Change:** in line 37, name a new exported predicate in `review-issue.ts` (for example `isReviewIssueTitle(title)`, sharing `TITLE_PREFIX` and the ` on PR #<n>` suffix with `findOpenReviewIssue`) with a unit test, and keep `findOpenReviewIssue` for the per-PR match in slice 2.

3. **`my-sprint` scope is "every active sprint the reader owns" (lines 16, 50) — `deliveryScope` answers the owned sprints the reader selected.** `delivery-scope.ts:61-65`: `mine = owned.filter((s) => selected.includes(s.slug))`, and an empty selection falls back to `release`. Ran: opened the file. **Change:** in line 50, replace "every active sprint the reader owns, as `deliveryScope` already selects" with "the sprints `deliveryScope` returns (`delivery-scope.ts:56-65`)", and the same in the Changelog line 16.
