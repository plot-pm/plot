## Findings

1. **No open delivered ticket can show its title, because the payload drops every ticket a plan names.** The plan says "A ticket the issue index carries (open) shows its title from the index" (plan line 33). The board's `fleet.issues` is built by `inboxOf`, which filters out every referenced key: `rows.filter((row) => !referenced.has(issueKey(row.number)))` (`packages/board/src/server/fleet.ts:2170-2172`), and its schema says "Open tracker issues no plan references" (`packages/board/src/contract/schema.ts:4769-4777`). `waiting.tickets` does carry planned rows, but only those selected for the reader, because an unassigned row is hidden (`packages/domain/src/rules/waiting-tickets.ts:110-118,160-176`). A user therefore sees every delivered ticket of another person, and every unassigned one, as key + plan only, the same form the plan defines for closed tickets. Read and ran (grep, sed). **Change:** in *Approach › Delivered by the sprint*, name the payload array the title comes from. Then choose one option: (a) the server adds the open rows that the scope's plans name, as a new defaulted field from the index it already reads, or (b) the plan states that a title shows only for tickets in `waiting.tickets`, and the rest show key + plan. Add a unit test for "open but not in the payload".

2. **"Not carried" is not "closed", and the row must not claim it.** Both arrays are capped at 50 (`ISSUE_LIMIT`, `fleet.ts:257`, `waiting-tickets.ts:104`) and filtered as in finding 1. A key-only row can therefore be an open ticket. CLAUDE.md's rule *the index never says no* applies here. Read. **Change:** in the Changelog bullet 2 and in Approach, replace "a closed ticket shows its key and its plan" with "a ticket the payload does not carry shows its key and its plan". State that the row prints no "closed" word or styling.

3. **The could-not-read states of the two groups are not defined, and today's code would hide both groups.** `TicketsSectionView` renders only the absence sentence when `state !== 'rows'` (`packages/board/src/app/components/TicketsSection.tsx:77-83`). The Delivered group needs no tracker (keys come from `Card.issues`), and verification findings come from plan files. If the plan says nothing, a failed tracker read drops both groups, which is hidden UI. A failed read must also not show `⚑ 0 found` in grey, because the domain's own rule is "an absent reading is not `0`" (`packages/domain/src/rules/tickets-section.ts:47-49`). Read. **Change:** add a bullet *Unread tracker*. While `issueAnswer` is `failed`, `unsupported` or `unasked`, Delivered shows key + plan rows. Found shows its verification findings plus plan 2's unread or stopped notice for review findings. Each chip shows the unread form instead of a number. Add each state to the domain rule's unit tests.

4. **Review findings from fleetd are usually unassigned, so the plan's choice of array decides whether Found is empty.** `waiting.tickets` hides an unassigned row by default (`waiting-tickets.ts:116-118`), and the client then applies `ticketsForReader` (`AgentList.tsx:864-867`). The section reads `filteredIssues` (`AgentList.tsx:1251`). If the new rule reads the same array, the Found group shows "— none" while open findings exist. Read. **Change:** state that the association reads `fleet.issues` (the unfiltered inbox) for review findings, and that Mine applies through the plan-ownership arm only.

5. **One finding appears in two groups, with two different actions.** A review-finding issue is named by no plan, so it also lands in today's "no plan" group with *Plan it ›* (`inboxOf`, `fleet.ts:2170`; `splitTicketRows`, `packages/board/src/app/lib/agent-rows/waiting-view.ts:122`). The plan's unit-test list covers "both delivered and a finding" but not "a finding that is also unplanned". Read. **Change:** state whether a found ticket stays in the no-plan group, and add that case to the unit tests. The plan leaves out "remove it", so the plan must say so.

6. **Mine on in the all-sprints scope is not resolved for these groups.** The spec's table says Mine on in `release` scope shows "all items assigned to me, also those in no active sprint", with "no sprint" in the row's text (spec lines 84-89). The groups, by definition, hold only the scope's plans. The plan says only that the groups "follow ... the Mine filter like every section" (plan line 38). Read. **Change:** state that Mine narrows the two groups and never widens them to plans in no active sprint, or define how a no-sprint row shows. Also state that a key-only delivered ticket is the reader's only through its plan, because no row carries its assignees.

7. **The default fold of the groups has no stated mechanism, and plan 2 keeps everything open.** Plan 2 keeps `COLLAPSED_BY_DEFAULT` at `['free']` "so every section starts open" (`docs/plans/2026-11-20-every-delivery-section-folds.md:33`; `packages/board/src/app/lib/agent-rows/collapse.ts:17`). `KNOWN_KEYS` derives from `DELIVERY_LAYOUT` and drops unknown keys (`collapse.ts:6`). Read. **Change:** name the two new collapse keys, add them to `KNOWN_KEYS` and `COLLAPSED_BY_DEFAULT`, and state that each group persists its fold per reader like a section.

8. **The ⋯ column on the new rows has no actions named, and the slice does not wait on plan 5.** Approach says the rows use the ⋯ menu "once plan 5's ⋯ column exists" (plan line 42). Plan 5 adds "one ⋯ per row with an action" (`delivery-rows-act-from-one-place.md:44`), and its slices name only the Tickets no-plan row (`:58`). No row action is defined for a delivered or found ticket, so the last column on these rows is either empty or dead, and nobody owns adding it. Read. **Change:** name the actions of each row kind (for example, open the ticket, open the PR or plan). Alternatively, state that the rows carry no ⋯ and that the empty fixed column keeps the x position.

9. **The plan-state text has an existing source, and the plan should cite it.** "Approved · 2 of 3 slices merged" matches `deliverable.ts:366-392` ("M of N slices merged"). The plan names no source, so a builder could write a second formatter in the `.tsx` file. Read. **Change:** cite `deliverable.ts:366` as the state text's source and put the joined string in the domain rule.
