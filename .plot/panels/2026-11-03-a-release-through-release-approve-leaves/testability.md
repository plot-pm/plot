Without a stated rule, an implementer can make a tracker failure fail the release, or swallow it with no line.

## Findings on the test plan

- **The count test is feasible and fails before the change.** `shared-issue-reads-the-post-push-tree.test.ts` already wraps the scripts port so `plot-plan-state.sh` and `plot-issue-status.sh` answer from a stub. `deliver-plan-state.test.ts` copies the script directory and replaces both scripts with recorders. Either pattern counts calls. Today the count is 0 for 3 booked plans, so a test expecting 3 fails before the change and passes after. This test is sound.
- **The count needs a stated unit.** `runRelease` calls `plot-plan-state.sh` for every plan, including a plan that names no issue. The fixture `plan()` in `release-finish-real-repo.test.ts:25` writes no `Issue:` field. The plan must say that the count is one call per booked plan regardless of `Issue:`. The fixture must also give at least one plan an `Issue:` so that the `--skip-issue` logic runs.
- **The already-released repair test is missing.** The slice line says only "test one released write per booked plan". Today a second run makes 0 tracker calls (`release-finish.ts:267`), so a repair test fails before the change. The plan must name this test and its expected count.
- **The push-rejected test is a guard, not a regression test.** Open Question 2 recommends no tracker call on a rejected push. Today the count is already 0, so this test passes before the change. That is acceptable, but the plan must call it a guard.
- **The shared-issue skip has no test.** Use fixture plans A and B, both booked, plus C, which stays Delivered outside the sprint scope. All three name `#999`. The step passes `--skip-issue 999` for A and B, because C still owes the issue. Without C, no skip flag is passed. Today no call is made at all, so this test fails before the change. A second fixture checks the booked tree: the sibling read must see the plans this push booked as Released. Otherwise a release that shares one issue across two of its own plans never closes that issue.
- **The `runRelease` regression guard is not named.** The extraction touches `runRelease`. `test/reconcile/release-tells-the-tracker.test.mjs`, `shared-issue-reads-the-post-push-tree.test.ts` and `deliver-plan-state.test.ts` must stay green unchanged. The plan must list them as the extraction's proof.
