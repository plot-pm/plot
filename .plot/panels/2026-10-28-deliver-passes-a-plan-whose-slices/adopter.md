- **"`owner/repo@branch` … which `plot-impl-status.sh` already resolves" is false.** `plot-impl-status.sh:141` and `:151` read only `→ [owner/repo]#N` and `PR: [owner/repo]#N`. The `@` form already means a **commit** in another repository (`skills/plot/SKILL.md:316`, `templates/plan.md:74`, `commit-evidence.ts:16`), and `SKILL.md:323` says such a slice "stays open". `owner/repo@infra/X` therefore collides with an existing syntax. Fixture `c-at-branch.md` shows that the parser does not read it as a branch reference.

The deliver controller reads the plan through `PlanStore.readPlan` (`deliverability.ts:252`), so a new field must also go into that contract before the domain can see it. This is a bigger board impact than the Changelog states.
- **A cause is missing: one branch name across several repositories.** The ewz plan uses the same branch name, `infra/EWZKUS-3853-monotonie-waechter`, for all six foreign repositories. Every branch reader in Plot keys by branch name alone: `plot-impl-status.sh:118` (`sort -u`), `annotation_for`'s `head -1` (`:142`), `crossRepoReferences` (`cross-repo-reference.ts:51`, first reference wins), and `branchesOf` (`deliverability.ts:74-85`, one `Map` entry per name). ## (b) Approach

1. **The authoring form in step 4 brings the defect back, for exactly this adopter.** I wrote the ewz slices in the proposed backtick form (`e-list-shape.md`: contracts `→ quatico/ewz-kus-contracts#12`, consumptions `→ quatico/ewz-kus-consumptions#7`, ewz-web not yet annotated). The parser reads three branches. The deliver path then sees one:
   - `crossRepoReferences` → `[["infra/EWZKUS-3853-monotonie-waechter", {repo: "quatico/ewz-kus-contracts", number: 12}]]` (executed)
   - the `plot-impl-status.sh` extraction → `infra/EWZKUS-3853-monotonie-waechter -> quatico/ewz-kus-contracts#12` (executed)

   When contracts#12 merges, the plan becomes deliverable while consumptions#7 is open and ewz-web has no PR. That is the reported defect, now written in a form Plot claims to read. A foreign-repository slice needs an identity of **(repository, branch)**, and the readers must stop keying by branch name. Otherwise slice 2 tells adopters to write a shape that passes the same wrong delivery.
2. **The heading form is read differently by the shell and the domain.** `### contracts (Branch: infra/X, PR: quatico/ewz-kus-contracts#12)` (`b-same-name-headings.md`): `plot-impl-status.sh:151` resolves it, but `crossRepoReferences` returns `[]` because its `REFERENCE` regex requires `→` (`cross-repo-reference.ts:23`). `plot-plan-meta.sh` leaves 12 out of `prs` (`prs: [3722]`). The domain path then asks `prMerged(branch)` in **this** repository, which fails in the safe direction but names the wrong repository. The documented form must be one form that every reader reads, or the plan must name which form wins.
3. **A step-4b refusal in skill prose is a rule and does not stop the wrong delivery.** The symptom came from `plot-deliver.sh --dry-run`, which is now a 13-line launcher for `board/plot-deliver.mjs`. The decision runs in `deliverabilityOf` → `deliver` (`deliver.ts:181-188`). `deliverabilityOf` also serves the board (`server/board.ts`, `server/estate.ts`) and `plot-ask.mjs deliverable` (`server/entry/ask.ts`). The refusal must be a `DeliverRefusal` member (for example `branches-unread`), with `unreadBranchItems` on `DeliverReadings`, so that every reader refuses. Under "Every rendered state is a domain property", the board's deliverable signal must come from the same answer. Editing step 4b only changes the prose a model reads.
4. **Detection must not depend on English or German words.** The plan's example shapes, `(dort eigener Branch X)` and `**repo** … Branch X`, are keyed on a word. Fixture `d-other-language.md` (`eigener Zweig infra/…`, `propre branche infra/…`, `siehe infra/… im Repo`) is silent today, and a word-based detector would stay silent. One shape is language-neutral and fits these estates: a list item in a slice section, not in claim form, that contains a **bare** token matching the configured `Branch prefixes` (`^(PREFIXES)/[A-Za-z0-9]`) after code spans are removed. This is the same `PREFIXES` the parser already uses at `plot-plan-meta.sh:424`. Measured with `scan.awk`:
   - ewz-kus-portal, 51 plans: 6 hits, all six true (ewz lines 76-81).
   - Plot, 601 plans: 1 hit (`2026-08-20-a-row-is-a-tuple.md`, a prose cross-reference to `bug/one-column-one-kind-of-fact`), which is a false positive for "a slice", but it still names an unread branch, so a report is fair.
   - Removing code spans first is required: Plot's `docs/` prefix collides with paths such as `docs/plans/…`, which plans write backticked.
   - Line 82 (`**\`vnull\` in ewz-kus-contracts**`) names no branch, and no detector should flag it.
5. **Mixed home has no `Impl:` value.** The ewz plan declares `Impl: own branches` and explains in Notes (line 116) that this covers only the portal slice. `/plot-idea` offers `other repo` only for the whole plan (`plot-idea/SKILL.md:221,230`). Adopters with an umbrella plan have no honest answer. Slice 2 should at least document that a plan can mix homes, slice by slice.

## (d) Open questions

- **Refuse or ask?** Refuse in the domain, in both modes. "Deliver anyway" over work Plot never read is the same guardrail as open PRs (`plot-deliver/SKILL.md:167-171`). The repair is one edit to the plan: annotate the line, or add `<!-- deferred: <reason> -->`. The ewz case shows that a person still wants to deliver by decision. Deferral already records that decision in the plan, so an ask adds nothing.
- **Which shapes count?** Use the configured branch-prefix shape on a bare token in a non-claim slice list item, with code spans removed (measured above: 6/6 true in ewz, 1 borderline in Plot's 601 plans). Do not use words. Add the heading variant (`### repo (dort eigener Branch infra/X)`, which has no `Branch:` colon) to the same rule.
- **Does the board show it?** Yes, as the reason the plan is not deliverable, taken from the domain refusal, not as a separate badge. Today no `unread_*` field reaches the board, so this is new contract work, not a reuse.
- **What should the reconcile scan tell adopters?** One line per finding that names the plan, the line number, the bare branch token, and the repository word on the line if one exists, and that prints the rewrite. For example: `ewzkus-3853-build-identitaet:76 names branch infra/EWZKUS-3853-monotonie-waechter (ewz-kus-contracts) outside the claim form — write it as "- \`infra/EWZKUS-3853-monotonie-waechter\` — … → <workspace>/ewz-kus-contracts#<PR>", or mark it <!-- deferred: … -->`. It should state that delivery refuses until the line is fixed. Section 24b's wording style (`plot-reconcile/SKILL.md:198`) fits. Unlike 24b, this finding blocks delivery, so the SKILL must not group it with the non-blocking 24/24a/24b findings.
- **New questions the plan should carry:**
  1. How does a foreign slice name its repository **before** its PR exists? `→ owner/repo#N` cannot be written yet, and `@` is taken by commits. Until then the line resolves as `prMerged(branch)` in this repository.
  2. Does the identity of a foreign slice become (repo, branch), and which readers change?
  3. On Bitbucket, is `owner` the workspace (`quatico/ewz-kus-contracts`)? `cross-repo-probe.ts` asks the checkout's own backend first, but the template should show a Bitbucket example, because the issue comes from a Bitbucket estate.
