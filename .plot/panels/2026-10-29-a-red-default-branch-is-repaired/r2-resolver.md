## Measurements (executed)

- **Red episodes on main, 30 days:** 306 episodes. An episode runs from a settled red run to the next settled green run, ordered by `createdAt`. Of 3365 settled runs, 573 failed. Median episode 11 min, max 634 min, total 153.5 h. 58 episodes ran longer than 30 min and 38 longer than 60 min.
- **Reds caused outside the change:** 214 of 306 episodes (70 %) turned green across a diff that touched only `docs/`, `.plot/`, `*.md` or `.changeset/`. No code changed, so the red did not come from the code. 16 runs on main were re-runs (attempt 2 or 3) of the same SHA that turned green, and 1 re-run stayed red (`97b3e673a`). The jobs sampled in failed runs: `validate` in 19 of 29 and `corpus` in 3. One failure was the step `Install Playwright browser`, which is a download from outside the repository.
- **The picker against history:** the window from the last green commit to the first red commit holds 1 commit in 297 of 306 episodes. A single PR merge is in the window in 91 episodes, and 48 of those 91 turned green with no code change, so they were flakes. 213 episodes had no PR merge in the window, so the picker answers `unknown`. With `Main repair bound` at 3600 s, 9 episodes reach the bound with a picker answer, and 2 of those 9 were flakes. 28 episodes reach the bound with no picker answer (`exhausted`).
- **The head moves during a red episode:** of the 38 episodes longer than 60 min, 28 (74 %) had more than one red SHA, up to 35 per episode. Main takes 4.7 first-parent commits an hour (3345 since 2026-09-29).

## (d) The seven open questions, answered

1. **Red from outside the repository.** Yes, and earlier than the plan proposes. 70 % of red episodes recovered with no code change. Without a guard, fleetd starts an opus main-repair agent about 300 times a month, and 2 of the 9 revert-eligible episodes were flakes. Answer to record: on a newly settled red, fleetd re-runs the failed jobs of the red SHA once, before `start-repair`. `redMainStep` answers `await-rerun`. A green re-run ends the episode with no agent. Before `revert`, fleetd also re-runs the last green SHA. If that re-run is red, the picker answers `unknown`, which covers a persistent outside cause such as an expired secret or a yanked dependency. Cost: one CI run (median 19.5 min, p90 29.5 min, measured). The re-run of the red SHA comes first because it is the cheaper question and answers most cases. Both need a host `run-rerun` verb, which does not exist today.
2. **Attempts.** One main-repair attempt per episode inside the bound. A merged fix that leaves main red starts no second attempt and goes on to the revert at the bound. The picker window stays fixed at the record's last green SHA and first red SHA, and PRs that the record names as fix PRs are excluded. Otherwise the fix's own merge makes the picker answer `unknown` (see (a)). A person may choose a second attempt, but the bound does not change (anti-goal).
3. **fleetd down longer than the bound.** The code answers this partly. `default-branch-refresh.ts:210` carries `previous.settled` from the file, so a fleetd that was down at the green-to-red change detects the change at restart and records `redSince` then. The bound runs from that observation, so the repair starts first. If the record already existed before the downtime, revert at once (after the Q1 re-runs). The anti-goal counts from the first red, and a revert is undone by re-landing the work. Record `redSince` as the time fleetd first observed the settled red and say so, because a CI completion time would hand a restart an already expired bound.
4. **One writer across machines.** The record is a local file under the common git dir, so it guards one machine only. Use the dispatch claim: an empty `plot: claim <branch>` commit pushed onto a new branch (`agent-loop.ts:723-724`, judged by `rules/claim.ts:40`). The push is non-fast-forward for a second machine, so only one machine wins. Name the branches from host facts that both machines read the same way: `bug/main-repair-<last-green-sha12>` and `bug/revert-<pr>`. Push the claim before the agent starts and before the revert commit. Prefix: `bug/`, from the declared `Branch prefixes`. A red main is a defect, and `infra/` names CI configuration work. Not verified: whether `plot-reconcile-scan.sh` reports these plan-less branches as `unplanned_members` or stale. If it does, that is noise and not harm.
5. **A HIGH or a red repair PR.** This conflicts with D2, which says every HIGH goes to a fixer with two attempts. A repair PR has no desk, and #2903's fixer starts only "on a desk that has a PR". Two fixer attempts also exceed a 60 min bound. Answer to record: a HIGH or red CI on a fix PR ends the repair attempt, and the revert at the bound is the fallback. A HIGH on a revert PR goes to `exhausted`. This carves an exception out of D2, so **a person must decide it**.
6. **Pause the bound for a fix PR in review?** No. The anti-goal ("within the bound plus one review and merge round") rules out a pause. At the bound, fleetd opens the revert, and #2902's one merge in flight merges whichever PR passes first. When main turns green, fleetd closes the other PR: `close-revert` already exists, and it needs a matching `close-repair`.
7. **Return path.** For a Delivered plan, fleetd writes the ticket through #2903's ticket record, keyed by the reverted PR, after the revert merges. #2903 already expects this, so the slice waits on `feature/an-unfixed-high-is-ticketed`. For an Approved plan, no controller writes a new heading (`auto-dispatch.ts:220` covers the Delivered case only), so fleetd notifies and **a person decides** whether a heading-writing controller gets built.

Still a person's choice: Q5 (the D2 exception), Q7 for Approved plans, the bound's default (60 min in the design), and whether a re-run of the last green SHA (about 20 min of CI) is worth its cost before each revert.

## (e) Tests per slice

- **Repair record and rule (domain, table test of `redMainStep`):** stale red never reverts. A pending head blocks the revert. **A moved red SHA within the same episode still answers `revert`.** A green settled reading answers `close-revert`. A pending re-run answers `await-rerun`. A green re-run answers `none`. A test of the parser for `Main repair bound`.
- **Picker (domain, pure):** the window holds 1 PR merge (answers the PR). The window holds 0 PR merges or a direct push (answers `unknown`). A merged fix PR named by the record is excluded. A squash subject `(#N)`. A red re-run of the last green SHA answers `unknown`. The 306-episode history above is a free corpus for this table.
- **Merge exception (domain):** the three existing refusal tests stay unchanged. A mutation test removes the episode pin and the record-name check, and a test must fail for each.
- **fleet unit:** a crash after the record write starts no second agent. A lost claim push starts nothing. The multi-tick fake-clock anti-goal test runs with the head moving every 12 min (the measured 4.7 commits an hour).
- **Adapter, temp git repo and host stub:** revert of a squash landing and of a merge-commit landing, a conflicting revert, `pr-close` and `run-rerun` on both drives.
