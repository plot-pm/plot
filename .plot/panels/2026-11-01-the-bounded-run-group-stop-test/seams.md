# Seams juror — the-bounded-run-group-stop-test

Position: amend

The slice collides with no in-flight work, and its test-side change follows a pattern that the same file already uses in four of its tests. The plan stops short in one place that matters: a reproduction in this review shows that cause 3 exists. `boundedRunProcess` drops a SIGTERM that arrives in the same event-loop drain as its child's end, and the caller then survives the stop. A test-only slice changes the failure message but leaves `main` red at the same rate. The fix in `boundedRunProcess` is a few lines in one file, and it belongs in this plan as a second slice, not in a later plan. The proposed test change shares no code with the teardown fixes of #3008, and it does not need a shared helper: 23 test files probe a pid with `process.kill(pid, 0)`, each with a local helper, and the domain package cannot import the board's or the fleet's test helpers.

## Findings

1. **high — cause 3 is real and reproducible: `finish()` drops a SIGTERM that the run's end overtakes.** `packages/domain/src/adapters/bounded-run/bounded-run-process.ts:137` adds the `ENDING_SIGNALS` listeners. `:139-144` (`finish`) removes them as soon as the child's `close` fires (`:156`). With `stdio: ['ignore', out, out]` (`:114`) the child has no pipes, so Node emits `close` synchronously inside the SIGCHLD dispatch. If the loop drains the SIGCHLD before the SIGTERM, `finish` stops the signal handle, and libuv skips the SIGTERM message that is already queued. The caller then keeps running, because the stand-in holds a `setInterval` (`test/fixtures/bounded-run-group-standin.mjs:64`). Checked with a scratch script against the real adapter at `origin/main`. The script blocks the loop for 1 s, its bounded child (`sleep 0.2`) ends, and an external `kill -TERM` arrives at 0.5 s. The caller survived 10 of 11 runs (it printed `SURVIVED` and exited 99). In the control, the SIGTERM arrives while the child still runs, and the caller exited 143 in 5 of 5 runs. In the group stop, the same SIGTERM kills the prompt (`test/fixtures/bounded-run-prompt.mjs` has no handler), so the wrapper receives SIGCHLD next to the SIGTERM, which is the race that this experiment forces. The experiment ran on macOS. Linux was not run, but on Linux libuv also delivers SIGCHLD through the same signal pipe.
2. **high — the CI evidence rules out an early read and makes a zombie improbable.** The failing case ran for 5282 ms (job 124912486260: `× ends the wrapper, … 5282ms`). That is about 280 ms to READY plus the full 5000 ms `waitForExit` bound at `bounded-run-group-stop.test.ts:49`. In the same file and the same run, the signal-to-pid cases took 282, 351 and 308 ms, and the bound case took 4267 ms for a 4 s bound, so the runner was not slow. The repo's zombie measurements (`test/e2e/monitors-end.test.mjs:131-139`, `packages/board/test/helpers.mjs:101`) are about SYNCHRONOUS waits, which give the loop no turn to reap. This wait is async (`setTimeout`, `:53`) in a vitest `forks` worker (no `pool` in `packages/domain/vitest.config.ts`), so the loop reaps the wrapper. A wrapper that is still alive for 5 s fits finding 1 and does not fit cause 1 or cause 2. Occurrence: 1 of the 94 completed `ci.yml` runs on `main` from 2026-10-31T17:44Z to 2026-11-01T20:02Z (run 41328179417, `926339afd`). The other 10 failures do not contain `survived the group stop`.
3. **medium — Open Question 2 has a false premise, and the file already holds the pattern the slice needs.** The sibling tests do not poll a wrapper pid. *exits normally* reads the wrapper's end from `wrapper.on('exit')` (`:166-168`). The three signal-to-pid cases create `exited` before they send the signal (`:215`) and await it (`:221`). Only the group-stop test (`:134-138`) calls `waitForExit(wrapperPid)`. The slice reuses the `:215` shape: it creates the `exit` promise before `process.kill(-wrapperPid, 'SIGTERM')` and races it against the named bound. The other tests need no change.
4. **medium — the slice duplicates the ready-wait unless it reuses `readyOf`.** `readyOf` (`:69-81`) exists, but three tests inline copies of it (`:109-124`, `:150-161`, `:190-201`). Only the group-stop copy rejects when the stand-in exits early (`:120-123`). If the slice adds a fifth form, it widens the drift. Fold the early-exit reject into `readyOf` and call it from the group-stop test.
5. **low — the plan shares no mechanism with #3008, and it should say so.** #3008 (`docs/plans/2026-11-01-two-test-teardowns-turn-main-red.md`) fixes two `owned-run.sh` TMPDIR leaks: a production stage-directory registry, and a continuation `afterEach` that waits for the reporter's last line. Both are teardown leaks in which every assertion passes. This failure is an assertion on liveness. The common idea, *wait on the actor that acts last and not on a proxy*, matches the plan's change from `kill -0` to the `exit` event, but no code is shared. The slices are disjoint: #3008's slices touch `continuation.test.ts` and `stage-dirs`/`plan-store-ref`, and this slice touches `packages/domain/test/bounded-run-group-stop.test.ts` (and `bounded-run-process.ts` per A1).
6. **low — 23 test files probe a pid the same way, with no shared helper.** `git grep "process.kill(<x>, 0)"` over `packages/` and `test/` at `origin/main` finds 23 test files. 15 of them also carry a `Date.now()` deadline next to the probe, for example `packages/board/test/lifetime.test.mjs:95` (`waitForExit`, 8000 ms), `packages/board/test/rm-tree.mjs:101` and its copy `packages/fleet/test/rm-tree.mjs:101`, `packages/domain/test/desk-monitors-shell.test.ts:89`, `packages/domain/test/run-script.test.ts:239` and `packages/fleet/test/worker-loop-bundle.test.mjs:53`. Two helpers count a zombie as gone: `packages/board/test/helpers.mjs:104` (`untilGoneSync`, `ps stat`) and `test/e2e/monitors-end.test.mjs:165`. A cross-package helper is out of scope: the domain tests cannot import board or fleet test files, and 1 failure in 94 runs does not justify a shared module. Keep the change local.
7. **low — no collision with in-flight work.** 5 PRs are open (#3019 itself, #3016 dependabot, #3013, #3012, #2934 release). None touches `bounded-run*` or `ts-strip-loader`. No active plan on `origin/main` names `boundedRunProcess` or this test, and no remote branch other than `idea/the-bounded-run-group-stop-test` matches. The last changes to the file and the adapter are #2629 and #2390. Five production callers construct `boundedRunProcess` (`packages/fleet/src/server/entry/worker-loop.ts:232`, `agent-run-for.ts:83`, `auto-fixer.ts:617`, `repair-start-world.ts:47`, `packages/board/src/server/entry/review.ts:573`). None registers its own SIGTERM handler, so a dropped signal at the end of a run leaves a worker loop running after `plot-dispatch.sh --stop` sent its group TERM.

## Amendments I require

- A1. Replace "Candidate causes, none yet measured" with finding 1: name `finish()` at `bounded-run-process.ts:139-144` as the mechanism, and give the reproduction (a blocked loop, the child ends, then a SIGTERM arrives; the caller survives). State that the 2026-11-01 failure fits this cause and not causes 1 or 2 (finding 2).
- A2. Add a slice that fixes `boundedRunProcess` in this plan. Do not defer it to a later plan. A minimal form: `finish()` keeps the `ENDING_SIGNALS` listeners until the current loop drain has ended (remove them in a `setImmediate`), or the module keeps one process-wide registration while any run is live. Prove it with a deterministic adapter test that blocks the loop, lets the child end, sends SIGTERM, and expects exit 143. Run the test against the unfixed adapter first: it must fail there (mutation check). The fix needs a changeset, because it changes production behaviour that the worker loop runs. `check-changeset-packages.sh` accepts only `plot` or `@plot-pm/board` as the package name, so the changeset uses one of those two.
- A3. Keep the test slice as planned, and specify its shape: create the `exit` promise before the group signal, as at `:215`, race it against one named bound, and keep `waitForExit` for the prompt and the grandchild. When the bound expires and the `exit` event has not fired, the message names `boundedRun` (required behaviour 2).

## Open questions

- *Which of the three causes produced the failure on 2026-11-01?* Cause 3, by the evidence: the full 5000 ms bound expired while the sibling cases in the same run took about 300 ms, and the dropped-SIGTERM path reproduces with the real adapter (10 of 11 runs). A Linux-container loop of the group-stop test beside a CPU hog is useful as confirmation, but it is a probabilistic test. The deterministic adapter test in A2 settles the mechanism, and the plan does not need the loop before the change.
- *Do the two sibling tests need the same change?* No. *exits normally* (`:166-168`) and the signal-to-pid cases (`:215`, `:221`) already read the wrapper's end from its `exit` event. Only the group-stop test polls the wrapper pid.
