## Findings

1. **The owner reading is a fleet-side decision with no domain rule and no `unread` cell, and a failed worktree listing would read as "no owner".** The plan makes `owner` an input to `fixerScope` and derives it in the tick from `Trees.forBranch` and the claim commits ("The tick reads the claim commits only for a row that passes the checks before `owner-unread`"). That derivation (worktree, or claim marker in `origin/<base>..origin/<head>`, or neither, or a failed read) is the decision that turns a branch into `desk: { dead: true }`, and it lives outside the domain. Today `fixerTick` reads a failed `forBranch` as no worktree: `const deskTree = found.ok ? found.value : null` (`packages/fleet/src/shared/auto-fixer.ts:372-373`). Under the new rule that path gives `owner: 'none'`, and after the quiet hour it gives a dead desk, so a listing failure starts a fixer on a branch that a live desk holds. The plan's table has `owner-unread`, but no test proves that a failed `forBranch` or a failed `commitSubjects` reaches it. Read and opened.
   **Change:** add to slice 1 a pure rule `fixerOwner({ tree: PortResult<Tree|null>, commits: PortResult<CommitSubject[]> | 'not-read' })` in `rules/fixer-scope.ts`, answering `desk | none | unread`, with cells for: a worktree gives `desk`; no worktree and a claim marker (`isEmptyClaim`, `rules/empty-claim.ts:35`) gives `desk`; a claim marker under later work commits gives `desk`; no worktree and no marker gives `none`; a failed `forBranch` gives `unread`; a failed `commitSubjects` gives `unread`. Also name one `fixerTick` test: a `forBranch` that fails holds `owner-unread` and starts nothing.

2. **No slice names a fleet test it adds or changes, but slices 1 and 2 change `fixerTick`'s inputs and outcomes.** `packages/fleet/test/unit/auto-fixer.test.ts` (1049 lines) passes `scope` in `baseReadings` (`:59`), which slice 1 removes from the pass. The `FixerTickWorld.refs` fake is `Pick<Refs, 'defaultBranch' | 'showFile'>` (`auto-fixer.ts:63`), so the claim read needs `commitSubjects` added to the port pick and to every world fake. The two "desk reads elsewhere" tests (`auto-fixer.test.ts:650`, `:665`) keep their outcomes for a new reason: `:665` holds as `head-age-unread`, because `baseRow` carries no `headSince`, not as `desk-alive`. The comment at `:313-318` names `slicePrNext` as the step source. Slice 2 adds a tick-level base-tip read ("the tick reads through `Refs` after it fetches the base"). It also meets the tick's failed-start hold `attempt.start === 'failed' && attempt.headSha === step.head` (`auto-fixer.ts:383`), which ignores the base tip, so a conflict start that failed once holds on that head through every later base tip. Read and opened.
   **Change:** in each slice's Tests bullet, name `auto-fixer.test.ts` and these cells. Slice 1: a deskless row with no claim and a 61-minute-old `headSince` starts a fixer; the same row at 59 minutes starts nothing (`person-pushed-recently`); a claimed branch with no worktree holds `desk-alive`; the two `elsewhere` tests assert their new reasons. Slice 2: an unread base tip holds `unread`; a failed conflict start on one base tip does not hold the next base tip, or the plan states that it does and why.

3. **The record-compatibility test as worded cannot run in the new tree, and `conflictTried` has no named home or cells.** "An old-format reader reads it as unreadable" asks for an older build's decoder, which the new tree does not contain. The behaviour that makes the claim true is already pinned: `fixer-attempts.test.ts:57` decodes a record with an unknown finding kind (`'other'`) as `unreadable`, against the strict union at `entities/fixer-attempts.ts:21-24`. The plan adds `conflictExhausted` and `conflictTried` to `FixerReading` (`slice-pr-next.ts:28-30`). It does not say that `fixerReadingOf` (`rules/fixer-attempts.ts:92`) must take the base tip to compute `conflictTried`, and it does not say how two SHAs compare (full against short, see `sameCommit` at `auto-fixer.ts:500`). Read and opened.
   **Change:** replace the old-reader test with: "`fixer-attempts.test.ts:57` stays and pins the mechanism; add a case that a record holding a `conflict` attempt with `v: 1` decodes under the new schema". Add `fixerReadingOf(record, head, baseTip)` cells to `fixer-attempts.test.ts`: tried on the same head and base tip; not tried on a new base tip; not tried on a new head; a `start: 'failed'` conflict attempt neither spends nor counts as tried (or counts, as the plan decides); `conflictExhausted` is independent of `ciExhausted` and `highExhausted`.

4. **Review widening (operator decision, 2026-11-20) needs its own slice, because review shares `slicePrNext` with merge.** `runReviewPass` calls `slicePrNext` (`auto-review.ts:115`), and `readReviewPass` reads `sprintScopeRef` (`auto-review.ts:218`). The merge pass calls the same `slicePrNext` (`auto-merge.ts:261`) and reads the same scope (`auto-merge.ts:378`). If review widens and merge does not, the plan's own test ("`slicePrNext` still answers `out-of-scope` for a PR that `fixerPrNext` takes", plan line 54) is false for the review step. It holds only for merge. `guardArm` admits a repair or revert PR through `repairNamesPr` before the scope check (`slice-pr-next.ts:183-184`), and those PRs are reviewed today. `fixerScope` answers `repair-owned` for them, so a review that reuses `fixerScope` without that admission stops reviewing repair PRs. The repair merge reads `plotReview`, so this would regress the repair role. The review re-ask is already unscoped (`pr-refresh.ts:1603` passes every stored head to `reviewReaskPrNumbers`), so it needs no change. Read and opened.
   **Change:** add a fourth slice, `feature/the-review-reads-the-fixer-scope` (`waits: feature/the-fixer-scope-reads-every-open-pr`, independent of the conflict and board slices). It adds `reviewPrNext(readings)` in `slice-pr-next.ts` with a scope guard that runs `repairNamesPr` first, then `fixerScope`. `readReviewPass` stops reading `sprintScopeRef`. Tests in `slice-pr-next.test.ts`: a deskless green PR into `main` outside the sprint answers `review`; the same PR with a 59-minute-old person head holds `person-pushed-recently` and with a 61-minute-old head answers `review`; a release PR is out; a repair PR named by the repair record answers `review`; a repair-branch PR that the record does not name is out; `slicePrNext` (merge) still answers `out-of-scope` for the widened PR. Tests in `auto-review` (the fleet test of `runReviewPass`): the pass reads no sprint scope; the budget `REVIEW_START_BUDGET` still bounds the starts over the wider set.

5. **`base-unread` cannot fire from the pass as written.** `readFixerPass` defaults the default branch to `'main'`: `const branch = defaultBranch?.branch ?? 'main'` (`auto-fixer.ts:675`). The plan's `base-unread` cell ("the default branch's name is unread") is reachable in a `fixerScope` unit test, but no pass hands it an unread name. Read and opened.
   **Change:** slice 1 names the source of the default branch's name (`Refs.defaultBranch`, as `holdsApply` callers read it) and adds a `readFixerPass` or `fixerTick` test: an unread default-branch name holds every row as `base-unread`.
