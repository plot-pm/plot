# user — the-fleet-fixes-every-red-or-conflicting-pr

Position: amend

The operator decided on 2026-11-20 that auto-review widens to the fixer's scope, with the same scope rule and the same person-push hold. This verdict judges the plan with that decision in place.

## Findings

1. **A person's own worktree on this machine bypasses the quiet hour, and the fixer starts on it at once.** The plan sets `owner: 'desk'` wherever `Trees.forBranch` finds a worktree for the branch (plan, Slice 1, "How the rule reads a person pushed"). For `owner: 'desk'` it passes on today's desk reading and applies `person-pushed-recently` only to `owner: 'none'`. Today's reading turns every worker state except `elsewhere`, `waiting` and `running` into `{ dead: true }` (`packages/fleet/src/shared/auto-fixer.ts:165-176`, opened). A worktree that a person or the master agent made by hand has no `.plot-worker.*` records, so it reads `none`, which counts as dead. `ciRedArm` then starts a fixer on the first red CI (`packages/domain/src/rules/slice-pr-next.ts:310-316`, opened). This checkout holds such worktrees right now: `.worktrees/idea-bb-budget` and `.worktrees/idea-fixer-scope` (ran `git worktree list`). Today the sprint scope keeps these branches out. The widened scope lets them in, with no hour of quiet. The master agent's fix PRs that the Motivation names (#3591, #3595) are in exactly this case. Change for the plan: `owner: 'desk'` holds only where the worktree carries a fleet desk manifest or claim, i.e. a desk the fleet made. Any other local worktree counts as `owner: 'none'`, so the `headSince` hour applies to it. Add a unit cell: a hand-made worktree with no worker and a 5-minute-old head holds `person-pushed-recently`.

2. **No person can stop the fixer, or now the reviewer, on one PR, except by converting it to draft, and the plan does not say even that.** `fixerScope` reads only row facts and ownership (plan, Slice 1 table). No label, comment or marker opts a PR out. A colleague, for example Max on `experiment/*`, gets merge commits pushed to the branch 61 minutes after the last push, even if work continues locally without a push. The quiet hour measures pushes, not activity. With review widened, the same colleague also gets a `plot/review` commit status and a findings comment on the PR (`packages/board/src/server/entry/review.ts:57-66`, opened). On a HIGH finding, a fixer then pushes code changes that answer the review, which changes a colleague's design without asking. Draft is the only stop (`slice-pr-next.ts:182`, `guardArm`). Draft also stops the merge arm, and the fixer starts again as soon as the person marks the PR ready. Changes for the plan: (a) Name the per-PR stop in the Changelog and the Design. (b) Add one reason before `owner-unread`, `person-opted-out`, read from a host fact the index already carries or can carry, such as a label. If the plan keeps draft as the only stop, it must say so explicitly. (c) For a PR whose `author` is not one of the fleet's app logins, decide whether the HIGH arm fixes it or only the review comments. The plan must state that choice.

3. **The operator does not see why the fixer held back.** Slice 3 names only the kind of a running fixer ("fixing conflict ✗"). The new holds are `person-pushed-recently`, `head-age-unread`, `owner-unread`, `base-out-of-scope`, `repair-owned`, `conflict-attempted` and `conflict-attempts-spent`. They become `none` or `hold` steps that `fixerTick` only pushes into `results` (`auto-fixer.ts:378-381`, opened). `logStart` logs only the outcome of a start attempt, so none of these holds reaches the run log or the board. A person who sees a red PR with no fixer cannot tell "waits 37 more minutes" from "never in scope". Change for the plan: the Delivery row's By cell shows the fixer's hold reason, with the time left for `person-pushed-recently`, as an `agent-rows` view property with a unit cell per reason. The same applies to the widened review hold.

4. **Plan PRs (`idea/*`) come into scope, and the plan does not decide on them.** A non-draft plan PR into `main` passes every reason in the table. A plan PR is a review channel: `Review: pr`, and `Plan PRs: required` (CLAUDE.md Plot Config). With review widened, a reviewer posts findings on plan text, and a HIGH finding sends a fixer to rewrite the plan under a person's review. A conflict on a `State:` line also meets `plot-state-gate.sh`, which refuses a commit that changes `State:` without a receipt (CLAUDE.md "And since 2026-09-09 a gate"). The fixer then spends an attempt it cannot complete. Change for the plan: add `plan-pr` (head starts with `idea/`, or the configured idea prefix) to the out reasons, or state why a plan PR is in scope.

5. **Repair by merge is safe for a person's commits, and the plan should cite the gate rather than the prompt.** The prompt rule "never rebase and never force-push" (Slice 2, The brief) is backed by a gate: `rolePushViolation` refuses `--force`, `-f`, `--force-with-lease`, `+` refspecs, deletes, broad pushes, and any destination other than `PLOT_ROLE_BRANCH` (`packages/domain/src/rules/role-gate.ts:192-236`, opened). A push races a person's later push only as a non-fast-forward rejection, which loses nothing of the person's work. The plan also does not say what the fixer does after a rejected push. Change for the plan: cite `rolePushViolation` as the force-push gate. In the brief, instruct the fixer to stop and report on a rejected push, and never to pull and retry. A person pushed in that window, and the person's push restarts the quiet hour. The generated-bundle restore and the protected-path stop in the brief are correct and match `docs/definition-of-done.md`.

6. **A PR from a fork has no guard.** `PrIndexRow` carries no head-repository field (`packages/domain/src/entities/pr-index.ts:29-75`, opened, and `git grep isCrossRepository` found nothing). For a fork PR, `git push origin HEAD:<branch>` would create a stray branch on `origin`, and the PR would not receive the fix. This repository takes no fork PRs today, but an adopting project can. Change for the plan: add `fork` as an out reason, or state that the fixer refuses a head absent from `origin` (`worktree-failed`) and that the refusal spends no attempt.

7. **A single fixer queue is acceptable for a person.** `fixerAdmission` admits one fixer at a time (plan, Notes). With the scope widened, a person's PR can wait behind other PRs for up to the 3600 s bound per fixer ahead of it. The tick walks rows "in index order", which is PR number order, so the newest PR waits longest. That is acceptable if finding 3 shows the wait. Optional: order the queue by oldest red first.
