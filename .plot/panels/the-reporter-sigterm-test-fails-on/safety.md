# Safety juror — the-reporter-sigterm-test-fails-on

Position: amend

The miss is a real race in the shell under test, not in the test's wait and not a slow CI runner. The reporter subshell is forked with the default `SIGTERM` action and installs `trap '' TERM` only as its first command. The test's `ready` file proves that the agent's command runs. It does not prove that the reporter has run its first command. A group `SIGTERM` in that window kills the reporter. The agent's trap still writes `143`, but no `WorkerMonitor` finding is written and the FIFO stays in the worktree. I reproduced this outside vitest: 13 misses in 150 runs under CPU load with origin/main's `reporterShell`, and 0 in 150 with one change in production code: `trap '' TERM;` in the outer shell immediately before the reporter's `(`. The production path has the same window, because `plot-dispatch.sh --stop` sends `kill -TERM -<pgid>` to a continued desk's group. A test-only fix, a longer bound or fewer iterations would hide a real lost finding. The plan's candidate list contains the right cause (2, in part), but its first candidate is refuted by the logs, two of its factual claims are false, and it does not say where an ignore disposition may go without making the agent's command ignore a stop. With the amendments below the plan is small and sound.

## Findings

1. **high** — The cause is the reporter's trap race, and the evidence settles it. `continuation.ts:871-880` (origin/main `8a767598b`): the reporter is `( trap '' TERM; … ) &`, so the ignore is set only after the child runs. The test (`continuation.test.ts:729-743`) waits for `ready`, which the agent's command writes (`:733-734`), and then signals the group (`:735`). I checked this with a scratch script (`juror-safety/repro.mjs`) that takes `reporterShell` verbatim from origin/main and runs the test's sequence under `/bin/dash` (the `ubuntu-latest` `sh`) with 24 busy processes on 16 cores. Unchanged script: 13/150 misses. Each miss had exit file `143`, a finding file that did not exist, the FIFO still present and no process left in the group. Together these show that the agent trapped and the reporter died. With `trap '' TERM;` inserted in the outer shell before the reporter fork: 0/150 misses, 0 wrong exit codes, 0 groups alive 500 ms after the finding.
2. **high** — The race is in production, not only in the test. `plot-dispatch.sh:1786-1804` (origin/main) stops a running desk with `kill -TERM -- -<pgid>`. A continued or restarted desk's group is the outer `sh -c` started at `continuation.ts:1349-1370` (`detached: true`), and it contains the reporter. A stop that arrives before the reporter runs its first command ends the reporter with no finding. The exit code is not lost, because the agent's trap writes `143`. The finding is lost, and `.plot-worker.reporter.fifo` is left behind. The FIFO does not leak permanently, because `continuation.ts:1312-1318` removes a stale FIFO before the next spawn. So a fix in the rig only (for example, waiting for a reporter-armed marker) makes CI green and keeps the defect. The plan's statement "A change to `reporterShell` is production code and needs its own review" is right, but the plan treats this change as one option of three. The evidence makes it the fix.
3. **high** — The place of the ignore decides whether the fix creates a real survivor. A disposition set to ignore is inherited across `fork` and `exec`. If `trap '' TERM` goes into the outer shell before the agent subshell is forked, then `( ${cmd} )`, and with it `plot-worker-loop.sh` and `claude`, starts with `SIGTERM` ignored. A group stop then ends nothing, and the agent survives `--stop`. The ignore must come after `agent=$!` and before the reporter's `(`. The plan does not name this constraint, and the review of the production change must check it. The reporter's own children (`cat`, `date`, `rm`, `sleep`, `plot_watched_desk`) already inherit the ignore today, so this placement adds no new survivor. Those children are short-lived, and the test's `dispose` still sends `SIGKILL` to the group.
4. **medium** — Plan Approach, first sentence: "The failure message names no line." This is false. Both failing logs name `test/unit/continuation.test.ts:736:75`: run 41361916665 (`main`, `4d33c00dd`) and run 41376720118, attempt 1 (PR #3036). Line 736 is the finding wait after the group `SIGTERM`. The "two `expect` calls can produce it" analysis is therefore unnecessary.
5. **medium** — Candidate cause 1 (the 5 s bound is too short) is refuted by the durations. The failing test took 5709 ms and 5854 ms, which is one 5 s wait plus the iterations before it. A reporter that is alive writes its finding in milliseconds, and a dead reporter writes nothing at any bound. A larger bound only makes the failure slower. The plan must remove candidate 1, or record it as refuted, so that the slice does not ship a bound increase as the fix.
6. **medium** — A second window exists on the agent side, and the plan's fix does not close it. In the scratch script, I sent the group `SIGTERM` immediately after the outer shell exited (with no `ready` wait). Under `dash` this left the agent subshell alive alone in 2 of 60 runs, with no child, no exit file, fd 3 still open on the FIFO and the reporter blocked reading it. `ps` showed the surviving pid as the `.plot-worker.pid` value. In production, `worker_state` would then read the desk as `running` and the desk would never be reported. This happens only when a stop arrives within milliseconds of the start, and the test's `ready` wait excludes it. The fix in finding 1 must not claim to close it. It belongs in a follow-up issue, not in this slice.
7. **low** — The plan does not mention the second failure (PR #3036 at `609cc0c34`, run 41376720118), which the brief names. Both failures add evidence that the miss is not a single event.
8. **low** — `Type: feature` and the branch `feature/…` describe a defect fix. A `bug/` branch matches the repo's convention for #3027's own fix (`bug/the-agent-reporter-waits-without-a-poll`).

## Amendments I require

- A1. Name the cause in Design: the reporter subshell is born with the default `SIGTERM` action, and a group `SIGTERM` before its first command kills it. Cite the scratch reproduction (13/150 before, 0/150 after, under load) or have the slice repeat it. Remove candidate 1, or record it as refuted by the 5.7 s durations.
- A2. Make the fix a change to `reporterShell`: set `trap '' TERM` in the outer shell after `agent=$!` (and after the pid-file write) and before the reporter's `(`. State the constraint in the TSDoc: the ignore must never come before the agent fork, because `cmd` would inherit it and survive a group stop. Keep the reporter's own `trap '' TERM` as it is.
- A3. Add a structural test beside "holds no sleep and no absolute path…" (`continuation.test.ts:653-662`). It asserts that the outer `trap '' TERM;` comes after `agent=$!` and before the reporter's `( trap '' TERM;`. It also asserts that no `trap '' TERM` comes before the agent subshell's `(`. This is the deterministic half of the proof: by `fork` semantics, a child forked after the parent ignores the signal is born ignoring it, and a string-order test fails on every run if a later edit moves the line.
- A4. Add a behavioural row that proves the agent's command still stops: after a group `SIGTERM`, the `cmd` process (pid written by `cmd`, as in the SIGKILL test at `:691-707`) is dead, and the exit file is `143`. This keeps the fix from passing while it makes the agent ignore a stop.
- A5. Keep the 20-run test, its `5_000` bound and its assertions unchanged. Record in the PR the before/after miss counts of a loaded loop run outside CI (for example `repro.mjs`, or the test file run once with a mutation that removes the outer trap). "CI ran green once" is not the proof.
- A6. Correct the false claim "The failure message names no line" (both logs: `736:75`), and add the PR #3036 failure to Motivation.

## Optional

- O1. File a follow-up issue for finding 6: a group `SIGTERM` in the agent subshell's first milliseconds can leave the agent subshell alive with no exit file, under `dash`. Do not widen this slice to cover it.
- O2. Change `Type` to bug and the branch prefix to `bug/`.
- O3. After the fix, the `ready` wait in the 20-run test proves the agent's trap only. A comment in the test can say that the reporter's ignore is proven by A3, not by `ready`.

## Open questions

- *Does the failure reproduce locally under load, or only on the CI runner?* It reproduces locally. On macOS with `/bin/dash`, 24 busy processes on 16 cores, and the test's own sequence (start, wait for the pid file and `ready`, group `SIGTERM`, 5 s wait for the finding), I measured 13 misses in 150 runs. With the outer ignore, I measured 0 in 150. With no load and an immediate signal, `/bin/dash` missed 4/40 and `/bin/sh` (bash) missed 2/40, so the window exists on both shells. Recommendation: the slice repeats the loaded loop before and after the change, and records both counts in the PR.
- *Is 20 iterations still the right count once the miss is fixed?* Keep 20. The loop is what made a race of a few per cent visible in CI. After the fix, with the ignore set before the fork, the window is closed by construction, so 20 iterations cost about one second and do not add flakiness. Fewer iterations would only lower the chance of seeing a regression that A3 does not catch.
