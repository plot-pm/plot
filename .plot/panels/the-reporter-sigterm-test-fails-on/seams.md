# Seams juror — the-reporter-sigterm-test-fails-on

Position: amend

The miss is a real race in production code, not in the test's wait and not in CI timing. The outer `sh -c` forks the agent subshell first and the reporter subshell second, and the reporter installs its own `trap '' TERM` only when the kernel first schedules it. The test's `ready` file comes from the agent branch, so it proves that the agent's trap is armed and proves nothing about the reporter. A group `SIGTERM` that arrives before the reporter's first instruction ends the reporter with the default action: the agent writes `143`, the FIFO stays on disk, and no finding is ever written. I reproduced this outside vitest at 5 of 200 and 7 of 200 iterations, and a one-line change (the parent sets `trap '' TERM` before it forks the reporter, so the child inherits the ignore through `fork`) gave 0 of 200 under the same load. The plan names this cause as candidate 2 but ranks a longer bound first, which the CI durations refute, and it does not see that the fix crosses the production seam that #3027 created. I ask for amendments that fix the cause in `reporterShell`, keep every assertion of the test, and add a check that fails deterministically before the fix.

## Findings

1. **high — the cause is the reporter's trap window, and the `ready` file sits on the wrong side of the fork.** Evidence: `packages/fleet/src/shared/continuation.ts:871-881` on `origin/main` (`8a767598b`): `( trap '...143...' TERM; ( cmd ) 3>&-; ... ) & agent=$!; printf ... > "$PLOT_PID_FILE"; ( trap '' TERM; ... ) & exec 3>&-`. The test (`packages/fleet/test/unit/continuation.test.ts:731-736`) waits for the outer `sh` to exit and for `ready`, which `cmd` writes inside the agent subshell. The outer `sh` exits after `fork` returns in the parent, and the child may not have run `trap '' TERM` at that time. What I checked: I extracted `reporterShell` from `origin/main` byte for byte into a scratch script and ran the test's sequence (spawn detached, wait for exit, wait for `ready` with 20 ms polls, `process.kill(-pgid, 'SIGTERM')`, wait 3 s for the finding) 200 times on macOS `/bin/sh` at load 5.0. Result: 5 misses. Every miss showed exit file `143`, the FIFO still on disk, `ready` present, and no process left in the group. This is the state of a reporter that died before its trap: the agent trapped, the reporter never reached its tail or its `rm -f "$FIFO"`. With no `ready` wait: 7 of 200.
2. **high — the fix belongs in `reporterShell`, and it is one token.** Adding `trap '' TERM;` in the outer shell directly before `( trap '' TERM; ...` makes the reporter ignore `TERM` from the moment `fork` creates it, because an ignored disposition survives `fork` and POSIX keeps an ignored trap ignored in a subshell. The agent subshell is forked before that line, so its `143` trap is unchanged. Result with the same harness and load: 0 of 200 misses with the `ready` wait. A test-side fix (a longer bound, a wait on the reporter's pid, a sleep before the signal) would make the test green and leave the production defect in place: a group stop that lands within milliseconds of a continue or restart loses the `WorkerMonitor` finding, which is the defect #3027 exists to remove. This matches the sibling precedent `2026-11-01-the-bounded-run-group-stop-test.md`, where a lost `SIGTERM` was fixed in the adapter and the test was made to name the failure.
3. **high — the plan's first candidate cause is refuted by the CI logs it cites.** Run 41361916665 attempt 1 (`gh run view 41361916665 --attempt 1 --log-failed`) shows the test at 5709 ms, and run 41376720118 attempt 1 shows 5854 ms; a passing run of the same test shows 912 ms for 20 iterations, about 45 ms each. So the failing iteration did not get slow: it produced nothing for the full 5 s while its neighbours took 45 ms. A larger bound only delays the same failure. The plan should state this and drop candidate 1.
4. **medium — two factual claims in the plan are false on main.** "The failure message names no line": both failed attempts name `test/unit/continuation.test.ts:736:75`, which is the `findings().length === 1` wait. "Two `expect(...).toBe(true)` calls in the test can produce it": the test holds one `toBe(true)` (line 736); the `start` and `ready` waits are not asserted, which the plan's own next bullet says. The plan also omits the second CI failure (PR #3036, run 41376720118, `609cc0c34`), which the brief lists and which shows the miss is not tied to one commit.
5. **medium — the plan is typed as a feature and its branch has a `feature/` prefix.** Every sibling fix plan in the `delivery-loop` sprint carries `Type: bug` (`2026-11-01-the-agent-reporter-starts-a-sleep.md:8`, `the-bounded-run-group-stop-test.md:8`, `two-test-teardowns-turn-main-red.md:8`, `fleetd-s-fixer-and-main-repair.md:8`). This plan changes production behaviour of a shipped script, so it is a bug; the branch should be `bug/...`.
6. **medium — the Linux shell is a separate seam the plan does not name.** CI's `checks` job runs on `ubuntu-latest`, where `/bin/sh` is `dash`; my measurement ran on macOS `/bin/sh`. The inheritance of an ignored signal into a `( ... ) &` subshell is POSIX behaviour and `dash` keeps ignored traps in `forkchild`, but the slice must show it, the way `2026-11-01-the-agent-reporter-starts-a-sleep.md:55` probed `dash` in `debian:stable-slim`.
7. **low — the agent subshell has the same shape of window, and the test closes it only by its `ready` file.** In a no-`ready` run with the fix applied, 2 of 200 iterations left the agent and its inner command alive with no exit file, and 1 of 200 wrote `137` instead of `143`: a `TERM` that reaches the agent before its trap or before it forks `( cmd )` is either fatal or held until `cmd` ends. In production a stop in that window is lost. This is out of this plan's scope, but the plan should name it so that a later reader does not take the fixed reporter for a fixed start.
8. **low — the motivation is stale.** "fleetd's main-repair cannot start until #3028 lands": `origin/main` head `8a767598b` is `plot: deliver fleetd-s-fixer-and-main-repair`, and the sprint file marks that item done (`docs/sprints/2026-W44-delivery-loop.md:42`); issue #3028 is still open.
9. **low — teardown seam with `two-test-teardowns-turn-main-red` holds.** `dispose` sends `SIGKILL` to the group before it removes the tree (`continuation.test.ts`, `reporterRig.dispose`), so a reporter that ignores `TERM` cannot write into a removed desk. The fix does not change this. No experiment process outlived my runs (`pgrep` count 0).
