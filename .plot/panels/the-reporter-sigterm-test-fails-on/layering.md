# Layering juror — the-reporter-sigterm-test-fails-on

Position: amend

The miss is a race in the production shell string `reporterShell` (`packages/fleet/src/shared/continuation.ts:855-883`), not in the test's wait and not in CI timing alone. The reporter subshell installs `trap '' TERM` as its own first command, after the fork, so a group `SIGTERM` that arrives between the fork and that command kills the reporter before it can report. The test's `ready` file proves only that the agent's command started. I reproduced the miss with the exact script string from `origin/main` and the test's exact sequence: 34 misses in 600 iterations before a one-token change, 0 in 600 after it. The plan names this as candidate cause 2, but its fix menu sends cause 2 to the test rig ("a readiness signal in the rig"). That is the wrong layer: the defect also exists in production, the rig has no reporter readiness to wait on, and the owning layer already has a precedent for the correct fix (`skills/plot/scripts/plot-dispatch.sh:1450-1455`, `:1507`). The plan is sound in intent and small enough; it needs its cause stated and its fix moved to `reporterShell`.

## Findings

1. **high — The cause is the reporter's trap window in `reporterShell`, and the evidence settles it.** `continuation.ts:877-880` forks `( trap '' TERM; ... ) &`; the outer `sh` then runs `exec 3>&-` and exits. The rig waits for the outer exit (`continuation.test.ts:585`), the pid file (`:589`) and `ready` (`:734`), none of which proves the reporter executed its first command. What I checked: (a) both CI logs fail at `continuation.test.ts:736:75` (run 41361916665 attempt 1, run 41376720118 attempt 1); (b) the failing test took 5709 ms and 5854 ms while the sibling SIGKILL loop took 1787 ms and 1769 ms for 20 iterations, so the failing iteration spent the full 5 s wait after about ten healthy iterations of tens of milliseconds — a reporter that was dead, not slow; (c) a scratch harness (`scratchpad/layering/h.mts`) that imports the `origin/main` `reporterShell` text and repeats the test's start, pid-file wait, `ready` wait and `process.kill(-pgid, 'SIGTERM')`: 34 misses in 600 on this Mac (load about 5 on 16 cores). Every miss showed exit file `143` (the agent's trap ran), the FIFO still present (the reporter's `rm -f "$FIFO"` never ran) and no process left in the group. So the reporter died before it armed its trap. Candidate cause 1 (the 5 s bound) cannot explain a reporter that no longer exists, and candidate cause 3 collapses into cause 2: an ignored disposition cannot be skipped by delivery order, so only the pre-trap window remains.
2. **high — The plan routes cause 2 to the wrong layer.** Design › Approach says "a readiness signal in the rig for cause 2". The reporter writes no observable readiness, so a rig-side wait has nothing to wait on unless production code gains a test-only marker, which puts test instrumentation into the fleet's start path. The defect is also a production defect: `plot-dispatch --stop` sends a group `SIGTERM`, and a stop that lands in the window loses the `WorkerMonitor` finding the reporter exists to write (`continuation.ts:848-849` states the reporter ignores `SIGTERM` "so a group stop does not end it before it reports"; today that holds only after the reporter runs its first command). The fix belongs where the behaviour lives: in `reporterShell`, put `trap '' TERM;` in the outer `sh` after `agent=$!` and before the reporter fork. The ignored disposition is then inherited at `fork`, so the window is zero by construction, and the agent (forked earlier) keeps its default disposition and its own `143` trap. `plot-dispatch.sh:1450-1455` documents this exact rule ("THE WRAPPER IGNORES SIGTERM, AND ONLY AFTER ITS CHILDREN EXIST ... an ignored signal is inherited by every child started after it") and `:1507` applies it (`( cmd ) & agent=$!; trap "" TERM;`). With that change applied by string replacement in the harness: 0 misses in 600.
3. **medium — The plan treats a `reporterShell` change as a separate, heavier path.** "A change to `reporterShell` is production code and needs its own review" reads as a second review lane or slice. The change is one token moved inside one TypeScript string, in the same package as the test, and it is the fix; one slice with one PR review is enough. The plan's Board-impact comment already allows "possibly the reporter shell string", so the Changelog line should also say what production gains: a group stop right after a continuation start no longer loses the finding.
4. **medium — The proof plan is not deterministic as written.** "A loop with CPU load, or `stress`" reproduces the miss statistically and proves nothing on a green run. The fix removes the window by construction, so the slice can prove it with two things: (a) a deterministic structural assertion in the style of the existing "holds no sleep and no absolute path between the open and the tail" test (`continuation.test.ts:653-662`): in `reporterShell(cmd)`, an outer `trap '' TERM` appears after `agent=$!` and before the reporter subshell's `(`, and no `trap '' TERM` appears before `agent=$!` (the agent must stay killable); (b) a recorded A/B count in the PR body from a harness like mine over the unchanged test sequence, before and after, at a stated N. The existing 20-run test stays unchanged and keeps proving survival and `143`.
5. **low — The fix keeps everything the test proves.** No `waitFor` bound changes, no assertion is removed, and the 20-run loop stays. Raising the bound (cause 1's fix) would have cost 5 s or more per miss and fixed nothing, because the reporter is dead; the plan should drop it from the menu.
6. **low — Small factual drift.** `#3028` is an issue ("fleetd's fixer and main-repair agents never start", OPEN), not a PR, so "until #3028 lands" should name its fix PR or say "until #3028 is fixed". The Motivation cites only the `main` run; the brief's second failure (PR #3036, run 41376720118, same `736:75`) strengthens it and should be cited. The slice prefix `feature/` and `Type: feature` fit a fix poorly; `bug/` matches the convention used by #3027 (`bug/the-agent-reporter-waits-without-a-poll`). The other claims I checked hold: `4c182b6d0` is the first-parent predecessor of `4d33c00dd`, it already carried the test, and `4d33c00dd` only rebuilt bundles (35 generated files).
7. **low — One residual miss outside the test's shape.** In a variant that sends the `SIGTERM` without waiting for `ready`, the fixed script missed once in 200. I did not diagnose it. The CI test waits for `ready`, so it does not reach this path; the agent subshell has its own trap window before `trap ... TERM` (`continuation.ts:876`), which can only change `143` into `137`, not lose the finding. I name it so the implementer does not drop the `ready` wait.
