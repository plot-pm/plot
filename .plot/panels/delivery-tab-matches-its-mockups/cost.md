## Findings

1. **Contrast table: verified, passes, two figures differ.** I converted every oklch/rgb token in `index.css:77-168` (OKLab to sRGB, WCAG ratio). Light values match the plan to two decimals (title 17.84, body 10.34, meta 4.77, blue 6.82, green 4.94, amber 5.05, red 6.42; on-soft slate 6.90, amber 4.87, blue 6.26, red 5.88, violet 6.64, teal 5.17). Dark `-soft` pairs differ by 0.5 to 1.2 (plan blue 8.20, mine 7.64 linear-light composite; the plan likely composited in gamma space, as a browser does). All pass 4.5. Open (small): the `--card-primary` dark figure "4.74 (its text)" does not reproduce: `--card-primary-text` on dark primary is 5.36, and white on it is 3.76. Fix the number or name the pair.
2. **Thin margins, open.** Light `--hue-green` on its soft is 4.72, orange 4.93, meta 4.77, amber 4.87. These pass today and fail on a 0.02 lightness nudge. The planned `theme-contrast.test.ts` is the right gate. It covers text on `--card-surface` and hue on soft only. `--card-meta` on `--card-band`/`--card-panel` (header rows, Fleet card) is about 4.57 light and is not in the asserted set. Open.
3. **Light theme has no reference.** Mockups are dark only (plan line 49). The artifact shows the light theme beside a dark mockup, so light is reviewed by eye with no target. Open; accept explicitly or say so.
4. **ci.yml cite is right** (`ci.yml:1541-1543`: step name, `timeout-minutes: 30`, `run: owned-run.sh ... vitest run`). Upload steps already exist at `:277,:910,:919,:1064`, so the pattern is known. Cost: the screenshot test writes PNGs whenever `PLOT_SCREENSHOT_DIR` is set, and the plan sets it for the whole step, so EVERY PR that selects board-integration (not only the nine delivery PRs) uploads about 8 sections x 4 PNGs. Estimated 5-10 MB per run; the plan gives no figure and no `retention-days`. Add a measured size, `retention-days`, and ideally scope it. Open.
5. **"Link counts as done" is circular.** The PR body links the artifact of the latest CI run, but CI must finish before the link exists, and a fleet agent cannot run browser suites at its desk (CLAUDE.md Testing). Auto-merge on green can land before the body is edited, and artifacts expire (default 90 days). Evidence decays and is not a gate. Open.
6. **Blind styling loop, open.** Agents cannot see a render at the desk. Nine slices of CSS/class work get their first visual feedback after a CI round trip, then a person downloads a zip with `gh run download`. This is the largest attention cost and the plan names only the artifact, not the loop.
7. **Existing tests reading classes: plan understates.** It names five integration files. True, and confirmed (`tuple-row:451` `text-emerald-700` on `[data-tuple-status]`, `agents-tab:1292,1351,1355` `ring-amber-400`, `supervisor-badge:196-291`, `folded-plan-pr-fold:251` `text-slate-400`, `button-claims:227`). Also `dead-fetch.browser.test.ts:91,153` (`p.text-red-600`) is a sixth, and unit tests read class strings: `test/unit/agent-list.test.ts:1021` (source `bg-amber-300/25`) and `:1338-1550` (`classesOf('activity-dot')`), `tuple-row.test.ts`, `unplanned-issues.test.ts`. Primitives edits `TupleRow.tsx` row `li`, `YOU_MARKER_CLASS` and `MACHINE_DOT_CLASS` in `AgentList.tsx`, and visual-fleet/work-items edit `FleetCard`/`RowCell`; the "none of those elements is in scope" claim needs a grep per slice, not an assertion. Open.
8. **Header-row visibility.** 26 integration files use `innerText`; 117 call sites. The plan only audits files naming `columnheader` or grid `innerText`. A visible row changes any `innerText` equality on a grid. Open, cheap to fix by widening the Primitives audit.
9. **Schedule is plausible but front-loaded with idle.** Domain fields and Primitives wait on six slices, three of which have no PR; the sibling plan states the longest chain is nine merges (`delivery-tab-header-and-my-sprint.md:160`). So nothing here starts until nine serial merges land. After that: domain, primitives, then 6 parallel. Six parallel PRs each trigger a 4-8 min integration job (`ci.yml:1536`); CI starvation from rapid pushes is a known cost, bounded by the fleet's parallel limit. Plausible; state the critical path and the chain length in the plan. Open.
10. **Primitives slice is the large one.** It touches `index.css`, `AgentList.tsx` (about 8 regions), `rows.tsx`, `TupleRow`, `RoleChip`, `FleetAgentRow`, `TicketsSection`, catalogue, a scenario, two new tests and `ci.yml`, all in one PR reviewed once. Highest review cost and the sole conflict hub for the six that follow. Consider splitting tokens+contrast gate from the markup pass, or the harness+CI step from both. Open.
11. **Conflict design: good.** One stylesheet per branch, `index.css` touched once, only `delivery-visual-release` edits `AgentList.tsx`. Residual: `RowCell`/`FleetControls` ownership vs the tab-header fleet card's switches is stated; the You group tags depend on `AgentList.tsx` markup Primitives owns. Resolved by the plan, residual risk low.
12. **Bundle churn: honest.** Generated bundle is not committed (`check-no-bundle-diff.sh`); main rebuilds after merge. About nine rebuilds; no cost to the PRs. Resolved.
13. **Tailwind v4 import order**: `index.css:1` is `@import "tailwindcss"`; `styles/` does not exist yet. New `@import`s must follow it and be picked up by the board build; the plan does not mention verifying the built CSS contains the new rules. Open, minor.

## Commitment

The plan is honest about structure (conflict partition, tokens, gate) but understates the class-reading tests, the per-PR artifact weight and the circular done-when, and leaves the thin-margin and light-theme risks unstated. All are fixable by editing the plan.
