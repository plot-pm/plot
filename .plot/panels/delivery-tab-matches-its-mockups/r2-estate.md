# Estate juror, round 2: delivery-tab-matches-its-mockups

Lens: does what the plan adds already exist in the codebase or in a sibling or delivered plan. Checked at `8dcb2ed85` (plan head) against `origin/main` `341df638d` and the open branches `origin/feature/delivery-{tab-todo-list,release-person-cards,tab-footer}`. Round-1 items are not re-raised.

## Findings

1. **misleads — the board already colours phases, in other colours.** Plan `:162` says the Phase chip "maps Development blue and Testing teal", and `:44` says "the two tabs share one palette". `packages/board/src/app/components/PlanCard.tsx:17-24` (`PHASE_ACCENT`) already colours the same phases on the Plans tab: Development green, Testing violet, Discovery sky, Released orange. The domain also has a phase colour key: `PhaseColumn.accent` (`packages/domain/src/rules/workflow-phases.ts:207-238`, `phaseColumns`) gives a default phase its name as the accent and `'neutral'` to a phase outside the five defaults. Phase names come from the `Workflow phases` config key, so a chip map keyed on the literal word `Development` tests a string in the view, and a project with other phase names gets no colour. How checked: grep for `'Development'` under `packages/board/src/app` and `packages/domain/src`. Suggested change: item 2 adds the phase name plus an accent that reuses `phaseColumns`' rule (default name or `neutral`), and the plan states which colour each phase takes on both tabs: the mockups' blue and teal (then `PHASE_ACCENT` moves too, outside the Delivery-tab scope at `:80`) or the Plans tab's green and violet.

2. **misleads — a relative-time formatter exists, three times.** Item 3 (`:163`) adds "a relative merge time (\"merged 2 days ago\") from `mergedAt` and a passed-in `now`" and names no helper. The estate has `storyDateText` (`packages/domain/src/rules/story-date.ts:12`, exported from `domain/src/index.ts:54`, returns `N days ago`), `relativeAge` (`packages/board/src/app/lib/card-presentation.ts:559`, the Plans tab's `N days ago`) and the short form at `packages/domain/src/rules/default-branch.ts:372-387` (`3 d ago`). How checked: grep for `days ago` and `ago` under both packages. Suggested change: item 3 names the formatter it reuses (`storyDateText` is in the domain; its 30-day branch returns `toLocaleDateString()`, which is locale-dependent, so say whether that is accepted or which one is used instead) so the slice does not write a fourth.

3. **misleads — `now` has no source in the files *Domain fields* owns.** `:209` says `delivery-view.ts` "gets the phase and `now`", and "No component". `delivery-view.ts` takes no clock (`grep now` finds none). Its only caller is `placeMapping(mapping, fleet.slices, activeSprints)` at `AgentList.tsx:1147`, a component, and `DeliveryMapInput` (`delivery-readings.ts:50-75`) carries no clock either. So the slice must edit `AgentList.tsx` or call `Date.now()` inside the view builder. The second also makes the screenshot harness's `merged N days ago` text drift between runs. Suggested change: name the one-argument change at `AgentList.tsx:1147` in the slice's Owns (or take the payload's `generatedAt`, which the catalogue already pins through `build.ts`), and drop "No component" or narrow it.

4. **misleads — item 1 names the wrong builder.** `:161` says the outcome is "set where `gateValue` (`:223`) builds the mark". `gateValue` (`delivery-row-form.ts:223-230`) returns a `string` for the Status cell and builds no `CellPart`. The gate-mark `CellPart`s are built in `gatesCell` (`:264-279`) from `gateMarks` (`:244`). Both already read the enumerations the outcome would encode: `PrReading.ci` (`running | failed | passed | unread`) and `review` (`pending | high | passed | none | unread`), at `delivery-placement.ts:40-43`, and `GATE_MARK` (`:175`). How checked: read `delivery-row-form.ts:170-280` and `:430-440`. Suggested change: name `gatesCell` and `gateMarks`, say whether the Status cell's `gateValue` string (where the mockup also colours `CI ⟳`) gets an outcome too, and derive the outcome from `PrReading`, never from the glyph.

5. **misleads — the Plans tab already has the chip, tone and dot vocabulary.** *Primitives* (`:91-95`) defines new chip tones (neutral, warn, input, block), text colours (muted, link, ok, amber, red) and a dot. Item 5 (`:165`) adds a `warn | neutral` tone. The released plan `docs/plans/2026-11-06-one-card-grammar.md` (State: Released) already built this in the board: `Tone = 'neutral' | 'muted' | 'unknown' | 'warn' | 'alert' | 'type'` and `Hue` (`card-presentation.ts:42-45`), the `TONE` class map on the same tokens (`Card.tsx:49-56`: muted `--card-meta`, warn `--hue-amber`, alert `--hue-red`), `DotView` and the `hue()` token helper (`Card.tsx:47`, `:89-91`), and `StatePill` (`:382`). It also fixed a type scale (title 15, body 13, meta 12 px, `one-card-grammar.md:598-601`), and the plan's 11 px small text (`:96`) differs from that. Suggested change: the plan names `Tone`/`Hue` and says whether the Delivery primitives reuse those words and classes or why they stay separate, and it names item 5's tone values from `Tone` (`warn`, `neutral` already match). It also says that the 11 px step differs from the Plans tab's 12 px meta on purpose, because `:44` claims one shared palette.

6. **misleads — CI reuse can leave the PR head with no screenshot artifact.** `:113` and every done-when link "the `delivery-screenshots` artifact of the CI run on the PR's head commit". `board-integration` runs only when `needs.select.outputs.reuse_board == ''` (`ci.yml:1308`). The reuse read (`ci.yml:284-292`, plan `docs/plans/2026-11-09-ci-reuses-green-runs.md`) skips the job when an earlier green run of the same PR on the same base covers the diff. So a push that changes only the PR's changeset or plan note after a green board run produces a head run with no artifact. Suggested change: the PR body links the artifact of the run whose `board-integration` ran (the step summary names the reused run as `reused:<sha>`), or the plan states that a reused head links the earlier run.

7. **cosmetic — the path map has a home already.** `:112` adds a `select` step that greps the diff. Path-to-job mapping already lives in `scripts/ci-job-map.jq` (`:14-27` map `board`, `e2e`, `census`), and the changed list is already written to `$RUNNER_TEMP/ci-inputs/changed.txt` (`ci.yml:260`). The cited command is `git diff --name-only --no-renames HEAD^1 HEAD`, and the plan drops `--no-renames`. Suggested change: add the `delivery` key in `ci-job-map.jq` beside `board`, or say why a separate grep is preferred, and quote the command exactly.
