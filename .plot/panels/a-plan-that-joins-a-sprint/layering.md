# Layering juror: a plan that joins a sprint names the sprint

Position: amend

The problem is real and the measurement holds: on origin/main (68fde7aa8) the W44 sprint's three Scope Changes lines are the three plans fixed by hand in `a9d743627` and `b3e145659`. Through the layering lens the plan is not yet a design. `## Approach` is empty, and the three open questions are exactly the layering decisions. The estate already answers most of them. A pure domain transition for the sprint file exists (`setSprintState`, behind `plot-sprint-transition.mjs`). A pure parser exists (`itemsFrom`, `entities/sprint.ts:129`). A sprint-slug cutter exists (`slugOf('sprint', …)`, `rules/state-transition.ts:96`). A gate table exists (`GATES` in `packages/board/src/server/entry/gate.ts`, reached through `plot-gate.mjs`). The plan must build on these and add no new membership reader. The plan also misses the most important layering fact: the two consumers of the `Sprint:` field, approve and deliver, do not use its value to choose a sprint. They use it only as an "is it empty" guard, and a controller then chooses the sprint file by substring search. If the plan writes the field and leaves that decision in the controllers, the field stays a second source of truth that only a gate holds in line. Today 77 of 412 planned memberships disagree with it, and 58 plans name a sprint that does not list them.

## Findings

1. **high — the field's value selects nothing; a controller makes the membership decision.** `packages/board/src/server/entry/approve.ts:755-760` and `packages/board/src/server/entry/deliver.ts:583-590` return `none` when `plan.sprint === ''`. Otherwise they walk the sprint directory in name order and act on the FIRST file whose text contains the substring `[slug]`. The name the field holds is never compared with the file they act on. Effects: (a) the defect the plan fixes is real only through this guard: an empty field makes approve skip the annotation and makes deliver skip the tick; (b) a plan that sits in two sprint files is annotated and ticked in the alphabetically first one, which is the oldest week; (c) the substring also matches a `### Scope Changes` log line and a `### Deferred` line. This is a decision ("which sprint holds this plan") in a controller, not in the domain. It contradicts the Layering Rule and "Every rendered state is a domain property". Checked by reading both functions on origin/main.

2. **high — a whole-file gate refuses existing estate and refuses approve and deliver commits.** I ran a scan (scratch `layering-juror/scan.mjs`) with `itemsFrom`'s tier headings and `MEMBER_LINE` over all 25 sprint files on origin/main. Result: 428 slug members, 16 name no plan, 335 agree, 17 have an empty field, 23 have no `Sprint:` line, and 37 name another sprint. 7 sprint files carry at least one disagreement (W34 the-board-tells-the-truth 10/10, W39 plot-works-in-the-repos-that-adopt-it 21/33, W42 bitbucket-jira-and-jenkins 9/47, among others). Approve (annotation) and deliver (tick) both commit a sprint file. A gate that checks every member of a staged sprint file therefore refuses an approve or deliver of an unrelated plan whose sprint file is one of those 7. Required behaviour 2 is worded per file ("refuses a sprint file whose member plan…"), so as written it has this false-refusal shape. The brief's "40-plus sprints" is also high: the count is 25 dated sprint files plus one `active/` link.

3. **high — the plan entity says one sprint and the estate says many.** `entities/plan.ts:212` says "a plan has at most one" sprint. 27 plans are listed in two sprint files on origin/main (for example `the-board-answers-agents` in W34 the-board-tells-the-truth and W34 working-shows-the-agent). Required behaviour 2 ("names another sprint" is refused) cannot hold for both files of such a plan. The plan must state the rule that picks the one sprint the field names. That rule is a domain function, and the writer, the gate, approve and deliver must all call it.

4. **medium — the plan adds no reader yet, but there are already five, and the gate must not become a sixth.** Membership is read today by: `itemsFrom` (domain), `parseSprintMembers` (`board.ts:1510`, a declared port of the same regex), `plot-sprint-release.sh` (awk), `plot-reconcile-scan.sh:1740-1750` (bash regex `\[([^\]]+)\]`; it ignores tier headings, so it reads a checkbox in any section, and it does not match a struck `~~[slug]` line), and the `[slug]` substring in approve and deliver. The sprint slug is cut three ways: `slugOf` (domain), `board.ts:1601` (`^\d{4}-W\d{2}-`), and `sed 's/^[0-9]{4}-W?[0-9]{2}(-[0-9]{2})?-//'` in three shell sites. The plan cites reconcile sections 9-11 as the existing reporter. If the gate copies their reading, it inherits a reader that already disagrees with the domain on struck and untiered lines.

5. **medium — the reverse direction is missing.** I ran a second scan (scratch `layering-juror/inverse.mjs`). 417 of 623 plans name a sprint. 58 of those are not listed as a member line by the sprint they name, and 1 names a sprint with no file. This plan's own file shows the reverse direction: it carries `- **Sprint:** delivery-loop` (commit `e6a0e74bf`), and `docs/sprints/2026-W44-delivery-loop.md` in its worktree does not list it. Required behaviour 2 and reconcile sections 9-11 walk sprint files only, so neither one sees a plan that claims a sprint the file does not grant. Under the board's join (finding 7) that plan is not in the sprint.

6. **medium — two factual claims need correction.** (a) "Only `/plot-sprint`'s creation flow writes the field": `skills/plot-sprint/SKILL.md:781` (Scope Change) also says "If plan-backed (`[slug]`), update the plan's Sprint field". The accurate claim is "two prose steps (`:337-342` and `:781`) ask for it, and no command writes it". (b) `plot-reconcile-scan.sh:1690-1692` says "a script writing one would be inventing it". The writer this plan adds is a script. The plan must change that comment: the writer records an add that a person or the master agent asked for, so it invents nothing.

7. **low — the board already chose the sprint file as the truth.** `App.tsx:1137`, `Board.tsx:203` and `Swimlanes.tsx:134` join on sprint-file membership and not on `card.sprint` ("card.sprint showed 5 of 19"). `plot-reconcile-scan.sh:1684` says "THE SPRINT FILE IS THE TRUTH". The field still drives the `PlanCard.tsx:386` badge, the story card's `sprintCounts` (`board.ts:2083-2093`), the fallback in `filters.ts:89-96`, and the guard in finding 1. Board impact is therefore small: a correct field corrects the badge and the story counts. No board view needs a change. The plan's `Board impact` comment can say that instead of "not yet assessed".

8. **low — shell ratchet.** `scripts/check-shell-lines.sh` counts `.sh` under `skills/` only. A new action on `plot-sprint-state.sh` (182 lines) or a new launcher under `skills/plot/scripts/` adds counted lines that another change must remove. A row in `GATES` reached through the existing `plot-gate.mjs` and `plot-state-gate.sh`-style launcher adds zero. A bundle that a skill calls directly with `node` also adds zero. Checked the header of `check-shell-lines.sh` on origin/main.

## Amendments I require

A1. Put the decision in the domain as one pure function with no I/O, in `packages/domain/src/rules/` or `transitions/`, for example `sprintOfPlan(slug, sprints: {slug, content, state}[])`. It answers `{ sprint } | none | ambiguous`, built only on `itemsFrom` and `slugOf('sprint', …)`. State its many-sprints rule (my recommendation: the plan's sprint is the one non-Closed sprint that lists it in a non-deferred tier and does not strike it; else the most recent sprint by week prefix; two non-Closed sprints answer `ambiguous`). Update the `plan.ts:212` comment to match.

A2. Make the writer a domain transition, text in and text out, beside `setSprintState`: `joinSprint(sprintText, planText, {slug, tier, on, reason})` returns the two new texts (member line, Scope Changes line, `- **Sprint:**` line) or a named refusal. Reach it through one bundle entry (a controller, the shape `plot-approve.mjs` has) that reads and writes through `PlanStore` and stages both files in one commit. Do not add an action to `plot-sprint-state.sh`: that script owns the `State:` receipt, and membership is not a state transition. Change `SKILL.md:337-342` and `:781` to call the bundle and to stop describing a hand edit. A `remove`/`defer` verb uses the same transition.

A3. Make approve and deliver use A1. Replace the empty-field guard and the `[slug]` substring walk in `approve.ts:748-772` and `deliver.ts:575-595` with A1's answer, and annotate or tick that one sprint file. Either do this in this plan as its own slice, or name it in the plan as a known follow-up with its own issue. Without it the field this plan writes still does not choose the file.

A4. Scope the gate to what the commit changes. It refuses only a member line the staged sprint file ADDS relative to `HEAD` (and a `Sprint:` value the commit changes) where A1 disagrees with the staged plan. It never refuses a member that `HEAD` already held. Register it as a row in `GATES` (`gate.ts`) that calls a domain refusal function, so the commit hook adds no shell. Run the same function in CI over the PR range. Prove it with a test that approves and delivers a plan whose sprint file is W34 the-board-tells-the-truth at its origin/main content (10 of 10 members drifted), and the gate does not fire.

A5. Cover the reverse direction in the gate: a staged plan whose `Sprint:` value is new or changed must name a sprint that lists it (A1). This would have refused this plan's own commit `e6a0e74bf`.

A6. Correct the two claims in finding 6, and change the reconcile comment at `plot-reconcile-scan.sh:1690-1692` in the slice that ships the writer.

A7. Fill `## Approach`, `## Slices` and a test table. My split, one branch each: (1) `feature/sprint-membership-is-one-rule` — A1 plus a corpus test that A1 and `parseSprintMembers` agree over all 25 sprint files; (2) `feature/a-plan-joins-a-sprint-through-one-command` — A2 and the skill changes, waits on (1); (3) `feature/approve-and-deliver-find-the-sprint-by-rule` — A3, waits on (1); (4) `feature/a-sprint-member-names-its-sprint` — A4 and A5, waits on (1). The test table needs at least: join writes three lines in one commit; join refuses a slug with no plan; a defer keeps the field; a plan in two sprints resolves to the open one; a gate test on an added member with an empty field; a gate test on an unchanged drifted member that passes; a gate test on a plan that names a sprint that does not list it.

## Open questions

- **Writer: a `plot-sprint-state.sh` action, a domain rule behind a bundle, or a board endpoint?** A domain rule behind a bundle (A2). The bundle is the controller, and a board endpoint can call the same entry later. Not `plot-sprint-state.sh`: it adds counted shell lines, and it mixes membership with the `State:` receipt that script owns.
- **Gate at commit time, in CI, or both?** Both, from one domain refusal function. Commit time is a row in `GATES`, which catches the master agent's hand edit that caused this issue. CI runs the same function over the PR range for commits that no hook saw. Both are scoped to added lines (A4), because 7 of 25 sprint files would otherwise refuse every commit that touches them.
- **Does a plan in Deferred keep the sprint's name?** Yes, while no later sprint lists it. A deferred line is still in the file, and `parseSprintMembers` still emits it with `tier: 'deferred'`. When the plan joins another sprint, the field moves to the new sprint, and A1 must read the old Deferred line as history, not as a conflict. A line that is removed outright clears the field only when no other sprint lists the plan.
