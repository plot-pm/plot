# Safety juror — a-plan-that-joins-a-sprint

Position: amend

The problem is real and the measurement of 3 of 15 is true. As written, though, the gate "refuses a sprint file whose member plan names no sprint or a different one" refuses 93 of the 446 member lines on `origin/main` today, in 13 of the 25 sprint files. It refuses the real delivery commit `f57425ec0` if the check reads only the changed line, and it can never be satisfied for the 27 plans that sit in two sprints, because `Sprint:` holds one value. The plan has no Approach, so the trigger, the scope and the writer's failure behaviour are open. These are the three places where the gate and the writer break things. Each one has a clear and cheap fix: scope the gate to non-Deferred member lines of a sprint whose State is not Closed, use a domain rule, and make the writer refuse anything outside the checked-out tree. With those amendments the design is safe. Without them, a CI form of the gate turns main red and holds the fleet's merge queue.

## Findings

1. **high — The gate as worded refuses 93 member lines on main today, all of them in closed sprints.** I copied `docs/` from `origin/main` into a scratch tree with `git archive`. I parsed every `docs/sprints/[0-9]*.md` with the reconcile regex `^- \[( |x)\] \[slug\]`, deduplicated by slug within each file, and compared each member with its plan's `- **Sprint:**` value. The slug cut is `plot-reconcile-scan.sh:1735` (`^[0-9]{4}-W?[0-9]{2}(-[0-9]{2})?-`). The script is `scratchpad/safety-3000/measure.py`. Result: 446 members. 353 agree. 39 have the field unset in a tier, 35 name a different sprint in a tier, 16 name no plan, and 3 sit in Deferred (1 unset, 2 mismatch). All 93 are in sprints with `State: Closed`, and the only Active sprint (`2026-W44-delivery-loop`) has 0. A whole-tree CI check, or a commit-time check that reads the whole touched sprint file, therefore refuses at once. `scripts/check-plan-headings.sh` (header "HISTORY IS NOT DRIFT") is the estate's precedent for this: it reads only plans that are still in work.
2. **high — Approve and deliver write sprint files, so the gate sits in front of the lifecycle commits.** `packages/board/src/server/entry/approve.ts:748-772` (`annotateSprint`) and `entry/deliver.ts:574-599` (`tickSprint`) both rewrite a member line. In the month since 2026-10-01, about 32 of the 40 commits that touched `docs/sprints/` on main were `plot: approve` or `plot: deliver` commits (`git log --since=2026-10-01 -- docs/sprints/`). A gate that the plan describes as acting on "a sprint file" runs on each of these.
3. **high — A real delivery would have been refused.** `tickSprint` ignores the plan's `Sprint:` value apart from checking that it is non-empty. It ticks the first sprint file in the directory listing that contains `[slug]`. `f57425ec0` ("plot: deliver board-hides-a-green-draft-slice") ticked the **Deferred** line of the closed sprint `2026-W42-bitbucket-jira-and-jenkins-work-with-the-board.md`, but the plan says `Sprint: bugfix-2-28-1`. A gate that checks only the member lines a commit changes refuses that delivery. In CI on a push to main (`ci.yml:6-7` runs the `check-*.sh` gates on push), the refusal turns main red. Through `default-branch-red` (CLAUDE.md, "A Decision Reads The Index"), a red main then holds every fleet merge and calls the repair or revert loop. This is a defect next to the plan (`tickSprint` and `annotateSprint` pick the wrong sprint for a carried plan), and the gate brings it into the open.
4. **high — 27 plans are members of two sprints, and one field cannot agree with both.** The script is `scratchpad/safety-3000/multi.py`. 25 of the 27 are pairs of overlapping sprints from the same week or from consecutive weeks (for example the W39/W40 pairs). 2 were carried out of `W42` Deferred into `W43-bugfix-2-28-1` Must, which is the flow `skills/plot-sprint/SKILL.md:655` and `:745` prescribe ("Move incomplete must-haves to Deferred", "Carry deferred items to the next sprint"). Unless the gate excludes Deferred lines and Closed sprints, every carry-over creates a refusal that no write can repair. 4 more plans appear twice in one sprint file (for example `a-released-plan-tells-its-tracker` under Must and Could in W39). The gate must deduplicate by slug as `plot-reconcile-scan.sh:1749-1753` does.
5. **medium — The motivation's claim "Only the creation flow writes the field" is incomplete.** `skills/plot-sprint/SKILL.md:781`, in the Scope Change flow, already says "If plan-backed (`[slug]`), update the plan's Sprint field". So two prose rules exist, and both were skipped. This strengthens the case for one command, but the motivation must state it. Step 6 is at lines 337-344, not 336-342. It also tells the writer to resolve the plan via `docs/plans/active/<slug>.md` and to place the line "after the Phase line", a field that has been named `State:` since 2026-09-07.
6. **medium — The writer can corrupt the Status block unless it handles five existing forms of the line.** Over the 623 regular plan files on main: 416 have `- **Sprint:** <slug>`, 60 have an empty value, 15 hold a placeholder comment, 4 hold a deliberate record such as `<!-- not a member; the sprint closed 2026-08-26 -->`, and 127 have no Sprint line at all. Plans also quote a Status block in prose (`statusStateOf` in `packages/domain/src/rules/state-transition.ts` is scoped to `## Status` for this reason), and one plan has an indented `    - **Sprint:**` in a quoted example. A writer that is not scoped to the first `## Status` section, or that replaces a "not a member" comment without saying so, damages the plan.
7. **medium — Partial failure and branch safety are not stated.** The writer touches two files (three lines). `plot-sprint-state.sh` makes its one-file write atomic with a scratch copy and `mv`, but nothing makes two files atomic. The plan must state the failure behaviour: compute both new contents first, refuse before any write, write the plan before the sprint, make a re-run idempotent, and stage and commit only the two paths. Note: `git add <path>` still commits other staged paths, so the commit must take a pathspec or refuse on a dirty index. A Draft plan with `Review: pr` exists only on its `idea/` branch (this plan is an example). The writer must refuse a slug whose plan file is not in the checked-out tree. It must never check out or write another branch. The Scope Change rule (`SKILL.md:758-760`, dispatched plans only) means a plan that is legitimately added mid-sprint is always on the default branch.
8. **low — The writer does not conflict with `plot-state-gate.sh`.** `stateTransitionOf` compares only the `State:`/`Phase:` value in `## Status` and the `Spike approved` record. A `Sprint:` write leaves both unchanged, and 0 plans on main lack `## Status`, so the writer never needs to add the heading. A new gate inside `plot-gate.mjs --all` runs next to the state gate on the same commit. Both refusals can print, and neither one depends on the other. The gate must not ask for a receipt for `Sprint:`, because a second receipt-keyed field doubles the receipt surface for a field that only the advisory reconcile reads.
9. **low — This plan drifts in the reverse direction itself.** Its Status says `Sprint: delivery-loop`, but `docs/sprints/2026-W44-delivery-loop.md` on main and on `idea/an-issue-shows-its-plan-s` (`e6a0e74bf`) does not list it, and the Scope Change rule forbids adding an undispatched plan. The proposed gate checks only sprint → plan, so it does not see this. The plan must state whether that direction is out of scope.
10. **low — A commit-time hook does not see bundle commits.** `hooks/hooks.json` installs `plot-gates.sh` as a PreToolUse hook on `Bash`. Approve and deliver commit inside a node process, so a commit-time form protects only an agent's hand-made `git commit`. That is the failure measured in the plan (`b1df72cf1` and `fc06f0678` changed only the sprint file). In CI, the same check also sees the bundles' commits on push, and findings 2 and 3 show this matters.

## Amendments I require

- A1. State the gate's scope: member lines (deduplicated by slug) outside `### Deferred`, in a sprint file whose `State:` is not `Closed`, and only the member lines that the commit or PR adds or moves into a tier. A tick (`[ ]`→`[x]`) or an annotation on an existing line is not an addition. Add a test that replays `f57425ec0` and passes, and a test that replays `b1df72cf1` and refuses.
- A2. Record the measurement in the plan: 93 of 446 members disagree on main, 0 of them in an open sprint, and 27 plans sit in two sprints. Add an acceptance criterion that the gate refuses 0 commits over the current tree and over the last 30 days of commits that touch `docs/sprints/`.
- A3. Put the decision in a domain rule, `packages/domain/src/rules/`, as arrow functions. Read it from one bundle through `plot-gate.mjs` for the commit-time form, and through a thin `scripts/check-sprint-membership.sh` launcher for the CI form. The shell holds no parsing, which follows "A Shell Script Asks The Domain" and leaves `check-shell-lines.sh` unchanged or lower.
- A4. Specify the writer's failure contract: it computes both contents and refuses before it writes anything; it scopes the write to the first `## Status` section; it inserts after `Type:` when the line is absent; it refuses to overwrite a non-empty value that names another open sprint and names both sprints in the refusal; it is idempotent; it commits only the plan file and the sprint file; and it refuses when the plan file is not in the checked-out tree. Test each of the five existing line forms in finding 6.
- A5. Answer OQ3 in the Design, and make the gate and the writer agree with the answer (see Open questions).
- A6. Correct the motivation: cite `SKILL.md:781` as the second prose rule that was skipped, and fix the line range and the "Phase line" wording. Replace both prose steps with a call to the writer.
- A7. Name the fix to `tickSprint` and `annotateSprint` (select the sprint file by the plan's `Sprint:` value, not by the first file that contains the slug) as a slice, or file it as a follow-up issue. Without that fix a correct `Sprint:` field still sends a carried plan's tick to the closed sprint.

## Optional

- O1. Leave closed sprints as history, as `check-plan-headings.sh` does. Do not backfill the 93. `plot-reconcile-scan.sh` sections 9 to 11 already report them for a person.
- O2. Ship the commit-time form first, with a stated window during which the CI form only reports, and measure that window before the CI check fails a push to main.
- O3. Drop the `Sprint:` line from this plan until it joins the sprint, or add it to the sprint through the new writer once it is dispatched.

## Open questions

- OQ1 (where the writer lives): use a domain rule behind a bundle, for example `plot-sprint-scope.mjs add|defer <sprint> <slug> <tier>`, with `plot-sprint-state.sh` unchanged. Add a board controller endpoint later only if the board gets a scope-change button. A new action in `plot-sprint-state.sh` grows the shell under the ratchet and duplicates parsing that `sprint-scope.ts` already owns.
- OQ2 (commit time or CI): use both, with one rule. The commit-time hook catches the measured failure, an agent's hand commit of the sprint file. The CI check catches commits from other machines and bundles. Both forms must be diff-scoped as A1 states, or the CI form turns main red on the next carried delivery.
- OQ3 (Deferred keeps the name): yes. A deferred plan keeps the sprint's name until a writer adds it to another sprint, which then overwrites the field. The gate ignores `### Deferred` lines, so the old sprint's Deferred line never refuses. The skill has no removal flow (`SKILL.md:788-790`: removing means moving to Deferred), so required behaviour 3 reduces to this rule. If an explicit removal is added later, it clears the field only when the field still names the sprint the plan leaves.
