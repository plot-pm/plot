# Seams: a-plan-that-joins-a-sprint

Position: amend

The problem is real and the three-of-fifteen measurement holds, but the plan does not yet name the code it meets. Three existing writers already act on a plan's `Sprint:` field: `/plot-approve` (`approve.ts:755`) and `/plot-deliver` (`deliver.ts:584`) skip the sprint file when the field is empty, and the board reads membership from the sprint file on purpose and calls the field "allowed to be stale" (`schema.ts:2620-2625`, `filters.ts:128`). The plan states neither the cost that the empty field already caused on the active sprint (an unticked Delivered item, unannotated items), nor the contract it changes. A gate over every sprint file would refuse 11 of 26 sprint files on origin/main, because 36 plans sit in two sprints and the entity allows one field value (`plan.ts:212`). The gate is safe only if it reads the sprint lines a commit adds. The plan itself names `Sprint: delivery-loop` while that sprint does not list it, so it shows the reverse drift that the plan does not cover. No desk that works now touches the same files, so the order is free today; the plan must still say what waits for what.

## Findings

1. **high — the empty field already has a cost that the plan does not name.** `deliver.ts:582-584` returns `none` before it searches the sprint directory when the field is empty ("a plan that names no sprint owes no tick"), and `approve.ts:755` does the same for the item annotation. `the-commit-gates-match-only-the` was delivered at `251b2abfc` (2026-11-01 02:37) with no `Sprint:` line and got its field at `b3e145659` (14:15). On origin/main its item in `docs/sprints/2026-W44-delivery-loop.md` is still `- [ ]` under Should Have, and none of the three Should Have items carries the `<!-- pr:, branch: -->` annotation that the twelve Must Have items carry. Checked: `git log` on the plan file, `git show origin/main:` on the sprint file and on both entries. The Motivation must name this cost, and the plan must decide if approve and deliver keep the guard (see A3).

2. **high — a gate over all sprint files refuses most of the closed estate.** I parsed every `docs/sprints/[0-9]*.md` and every plan on origin/main (script `scratchpad/seams/count.py`, comment-stripped `Sprint:` value, reconcile's member regex). Of 446 member lines (deduplicated per file), 353 agree, 40 have an unset field, 37 have a mismatch, and 16 name no plan. 11 of 26 sprint files have at least one disagreement. All 11 are Closed, and the active `delivery-loop` has 0 since `a9d743627`/`b3e145659`. 36 plans are listed by two sprints (for example `the-domain-speaks-slices` in `the-board-shows-the-strategic-layer` and `the-domain-is-one-implementation`). One field value cannot agree with both, so a whole-tree CI check can never pass without a rewrite of closed history. The gate must read only the member lines that the commit adds, or only sprints in Planning, Committed or Active.

3. **high — the plan contradicts a declared board contract and does not say so.** `packages/board/src/contract/schema.ts:2620-2625` says "MEMBERSHIP IS THE SPRINT FILE'S ... The plan's own `Sprint:` field is a back-reference, allowed to be stale", and `packages/board/src/app/lib/filters.ts:126-130` says "a plan's `Sprint:` field is HISTORY and does not clear when its sprint ends". Required behaviour 3 ("clears or keeps the field") and the gate both change that contract. The plan must state the new rule and amend these two comments in the same slice. Otherwise the codebase holds two answers.

4. **medium — the claim "only `/plot-sprint`'s creation flow writes the field" is not exact.** `skills/plot-sprint/SKILL.md:781` (Scope Change) also says "If plan-backed (`[slug]`), update the plan's Sprint field". Both places are prose, and no code writes the field: `git grep` over `*.sh`, `*.ts`, `*.mjs` (bundles and tests excluded) finds no writer of `**Sprint:**`, only readers (`plot-reconcile-scan.sh:1765-1775`, `approve.ts`, `deliver.ts`, the plan entity). Step 6 also says "after the Phase line" (`SKILL.md:342`), and plans have no Phase line now (`.plot/templates/plan.md:14` puts `Sprint:` after `Type:`). The writer must insert the line where the template puts it and must handle three shapes: no line (2 of the 3 cases), an empty line (1 case), and a template comment.

5. **medium — the Scope Changes log is also incomplete, so behaviour 1 has a second measured miss.** Five commits added plans to `delivery-loop` after creation (`789fed2e3`, `ab0ab107b`, `b1df72cf1` for two plans, `fc06f0678`), and each changed only the sprint file. The `### Scope Changes` section logs 3 of the 5: `ci-runs-what-the-change-touches` and `the-bundle-gate-refuses-the-repair` have no line. Those two named the sprint already (written at plan creation), so the field count missed them. The Motivation must report 3 of 5 for the field and 2 of 5 for the log, and the writer must accept a plan that already names the sprint.

6. **medium — the reverse direction is not covered, and this plan is an example of it.** This plan and the draft `an-issue-shows-its-plan-s` (#2998, commit `78ec54335`) both carry `- **Sprint:** delivery-loop`, and `delivery-loop` lists neither. `SKILL.md:758-772` allows only a dispatched plan to join a running sprint. 64 plans on origin/main name a sprint that does not list them (most are history). Required behaviour 2 reads sprint to plan only, and `plot-reconcile-scan.sh` sections 9-11 read the same direction. The plan must say if a plan may name a sprint before it joins. My recommendation is no: the writer is the only route to the field, and a Draft carries none.

7. **medium — "a plan in two sprints" is the common case, not an edge case.** It happens through carry-over: close moves unchecked Must Haves to Deferred (`SKILL.md:655`), and the next sprint lists them again (`SKILL.md:745`). The plan's lifecycle list (creation, scope change, deferral, removal, close, two sprints) needs one rule per event. The plan names creation, later addition, removal and deferral, but not close, carry-over, or the first-match search in `approve.ts:758-760` (sorted) and `deliver.ts:587-590` (unsorted). Those searches can tick or annotate the older closed sprint for a plan listed by two. Measured: 36 such plans.

8. **medium — Approach is empty, so the seams are unassigned.** The likely files are the following. A domain rule beside `packages/domain/src/rules/sprint-*.ts` that reuses `sprintMembers` (`entities/sprint.ts`) instead of a third member regex (reconcile has one at `plot-reconcile-scan.sh:1743`, the board another). A row in `GATES` in `packages/board/src/server/entry/gate.ts` for a commit-time gate, plus the bundle wiring in `packages/board/build.mjs` and `contract/bundles.generated.ts` if a new entry is added. `skills/plot-sprint/SKILL.md` steps 6 and Scope Change. `skills/plot/scripts/README.md` for any new script (`check-helper-table.sh`). `approve.ts` and `deliver.ts` if the guard changes. Each of these is a shared file, and the plan must list them so the slice order can be checked.

9. **low — no desk that works now touches those files.** The live desks are the following. `feature/the-scan-modes-run-the-walk` (`desk-13c1ed9a`): its diff against origin/main touches `refs-git.ts`, `plot-fleet-scan.sh`, `plot-fleetctl.sh`, `sprint-scope-ref.test.ts` and two reconcile tests, so no overlap. `feature/a-plan-reference-is-decided-once` (#2996): a new domain rule file, so no overlap. The later slices of `every-plan-reference-shows-its-issue` touch `SprintModal.tsx`, `server/fleet.ts`, `.github/workflows/ci.yml` (a new `check-plan-routes.sh` step), and `contract/schema.ts`. A CI check from this plan would meet that slice in `ci.yml`. A schema comment edit (finding 3) would meet `the-fleet-payload-indexes-its-plans` in `schema.ts`. Both are adjacent edits, not shared lines. The desks `desk-4c0521c9` (`the-commit-gates-match-only-the`, Delivered) and `desk-ce06eb40` (`the-scope-is-read-from-git`, PR #2948 merged) are stale, so `gate.ts` is free.

10. **low — the writer needs no state receipt, and it must not join `plot-sprint-state.sh`.** `plot-state-gate.sh` refuses a changed `State:` line, and membership changes no `State:` line, so the writer needs no receipt. `plot-sprint-state.sh` (182 lines) performs `setSprintState` and nothing else. If the writer joins it, one script holds two decisions, and the shell line ratchet (`check-shell-lines.sh`) charges the lines. A bundle entry (`plot-sprint-member.mjs <sprint> <plan> <tier> [--reason]`) that calls a domain rule and writes both files fits "A Shell Script Asks The Domain" and adds no shell lines.

## Amendments I require

- A1. Name the measured cost in Motivation: the unticked Delivered item and the three unannotated Should Have items on `delivery-loop` (finding 1). Repair them in the first slice through the writer, not by hand.
- A2. Correct the counts and claims: two prose places name the field (`SKILL.md:342` and `:781`), and no code writes it. 3 of 5 later additions missed the field and 2 of 5 missed the log line (findings 4 and 5).
- A3. State the membership contract in one sentence: the sprint file is the source of membership, and the plan field names the latest sprint that lists the plan in a non-Deferred tier. Amend `schema.ts:2620-2625` and `filters.ts:126-130` to say the same. Decide if `approve.ts:755` and `deliver.ts:584` keep the empty-field guard. My recommendation is to remove it, so that both search for `[slug]` and pick the sprint that the field names, else the active sprint. That fixes finding 1 even where the field drifts, and it fixes the first-match search of finding 7.
- A4. Scope the gate to the member lines that the commit adds or moves, in sprint files whose state is Planning, Committed or Active. It reads the plan's field from the index (staged) or `HEAD`. Show by experiment, with the script from finding 2, that it refuses 0 of the 26 sprint files on origin/main and the 3 historic commits `b1df72cf1` and `fc06f0678`.
- A5. Add one rule per lifecycle event to Design: creation, later addition, tier change, deferral, removal, close, carry-over to the next sprint, and a Draft that names a sprint (finding 6, finding 7).
- A6. Fill Approach with the file list of finding 8, and split Slices. (a) A domain rule and a bundle writer, plus the `SKILL.md` steps that call it, plus the repair of `delivery-loop`. (b) The commit gate as a `GATES` row, which waits for (a), so that a person who meets the refusal has a command to run. (c) Optional: the approve and deliver guard change of A3, which waits for (a). Each slice is one branch.
- A7. Remove `- **Sprint:** delivery-loop` from this plan until a scope change adds it through the writer, or record it as the writer's first use. The same applies to #2998's draft.

## Open questions

- Writer: a domain rule behind a new bundle entry (`plot-sprint-member.mjs`). It is not an action on `plot-sprint-state.sh`, which performs one transition and owns a state receipt. A board endpoint can follow later, but the master agent adds plans from a session with no board, so the bundle is the first route.
- Gate: commit time, as a row in `gate.ts`'s `GATES`, scoped by A4. Not CI over the whole tree: 11 of 26 sprint files would fail it on origin/main.
- Deferred: the plan keeps the sprint's name while the plan is listed only in that sprint's Deferred tier. When another sprint lists it in a commitment tier, the writer moves the field to the new sprint, and the old sprint's Deferred line is history that the gate does not read.
