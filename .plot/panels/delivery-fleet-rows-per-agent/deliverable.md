# Juror: Deliverable

Position: amend

Lens: does every slice name something that ships, does the Changelog describe what the two slices build, does each Done When item map to a slice, and can the two slices be built independently. All citations are at HEAD of this worktree.

## Findings

1. **The role chips have no reading for any agent except a loop agent, and no slice names the reading.** The Fleet list comes from `fleet.agents` (`AgentList.tsx:534`, `:1077`), which are `AgentEntry` registry entries. `AgentEntrySchema` (`packages/board/src/contract/schema.ts:3954-4070`) has no role field. `RegistryAgent = AgentEntry & { role?: AgentRole }` (`delivery-readings.ts:29`), and the mapper sets `role: agent.role ?? 'loop'` (`delivery-readings.ts:302`). So today every Fleet row reads `loop`. Reviewer runs live under `.plot/state/reviewer` (`board/src/server/entry/review.ts:407`), and fixer runs live in `.plot/state/fixer-attempts/<pr>.json`, which the payload reads only as `fixerInFlight` on a planless open PR row (`schema.ts:3324-3329`). Neither reaches the agent list. Done When item 2 ("a reviewer, a fixer and a loop agent each show their role chip") therefore needs a new local reading that turns reviewer and fixer runs into Fleet agents. Slice `feature/delivery-fleet-agent-rows` names the chip and does not name that reading. It is a local file read, so the Non-goal (no host reads) permits it, but the slice must say that it builds it.

2. **`AgentRole` lacks two of the eight roles.** `delivery-placement.ts:92` reads `'loop' | 'fixer' | 'reviewer' | 'approver' | 'idea' | 'brief'`. `design` and `verify` are missing. Design and verify runs render today outside the placement rule, in the "Tickets and plan runs" block (`AgentList.tsx:552-553`, `:1491-1497`, `:1548`). The design says "no separate list of special agents exists". No slice in this plan, and no sibling plan, names moving those plan-run rows into Fleet. A grep for "plan run", "Tickets and plan runs" and "outside-rule" over `docs/plans/active/*.md` and the design returns nothing. Slice 1 has to own that move, or the plan has to state that it does not.

3. **The first Changelog bullet's "output tokens spent today" and slice 2's "output tokens today" depend on a reading that slice 1 builds. Both slices wait only on `feature/delivery-section-header`.** Open Question 1 says the header falls back to "the per-agent figure only". A header that shows a per-agent figure is an aggregate of slice 1's per-agent token fact, so slice 2 cannot ship its token count unless slice 1 ships first, or unless slice 2 builds a second token reading. The plan must either add `<!-- waits: feature/delivery-fleet-agent-rows -->` to slice 2 or move the header token figure into slice 1.

4. **Open Question 1 has a partial answer in the estate.** No per-day token reading exists: a grep over `packages/*/src` for token readings with today, per-day or daily returns nothing. But the slice-spend record holds run lines with `at`, `role` and per-model `outputTokens` (`packages/domain/src/entities/slice-spend.ts:94-112`), and seal lines with `at` and `tokens` (`:45-62`). The board already reads this record for the plan-cost badge (`schema.ts:540-555`, `card-presentation.ts:492`). So "output tokens today" can be derived from an existing machine-local record with no new host read. The record has gaps that the plan should state: it is written only when a run ends or a slice seals, the bound path writes nothing (`board/src/server/entry/slice-spend.ts:31-41`), and it is machine-local. The per-agent "current run" figure has the same gap. `AgentEntry.contextTokens` and `contextSpend` (`schema.ts:4062-4063`) count the context ceiling, which excludes output by design (`slice-tokens.ts:22-27`), so they cannot stand in for it. The plan also omits the design's definition of the Tokens column, "what the agent spent on its current run" (design, Fleet section). With that definition left out, slice 1's token cell has no stated subject.

5. **Open Question 2 is answered in code.** Design and verify use `Worker bound`: `DEFAULT_DESIGN_BOUND_SECONDS = 28800` (`packages/fleet/src/shared/auto-design.ts:44`, `:465`) and `DEFAULT_VERIFY_BOUND_SECONDS = 28800` (`auto-verify.ts:43`, `:366`). A brief run has no time bound: "The run has no time bound, because a bound turns a usage-limit wait into an end" (`brief-ask.ts:105-107`). The reviewer has `REVIEW_BOUND_SECONDS = 3600` (`board/src/server/entry/review.ts:94`), and the plan's Time left text does not name it. The fixer has `FIXER_BOUND_SECONDS = 3600` (`domain/src/rules/fixer-attempts.ts:8`). I found no bound for idea or approver. Slice 1 therefore needs a rule for a role with no bound, at least brief. Today nothing says what the bar shows for that role.

6. **Done When item 1 conflicts with the estate's placement rule.** "Every agent shows once, in exactly one of Working, Blocked or Free" is already true for a placed agent: `agentGroup` gives one group (`delivery-placement.ts:262-267`). An agent whose process is unread gets no group and goes to `unplaced` with reason `unread` (`:263`, `:299-302`), and the "not placed" block renders it (`AgentList.tsx:1467-1490`). Item 1 either has to say "every placed agent", or slice 1 has to change the rule, which the Non-goals ("no change to the placement rule's decisions") exclude.

7. **Changelog bullet 4 ("Internals such as 'no manifest names this desk' leave the rows") has no slice and no Done When item.** The text comes from `domain/src/rules/desk-manifest.ts:238-261`. Neither slice description mentions removing it, and no Done When item checks for it. Either add it to slice 1's description and to Done When, or drop it from the Changelog.

8. **Most of slice 2's `builds:` marker already ships.** `AgentList.tsx:1403-1418` already renders `WorkingCounts` and the four switches (`AutoDispatchSwitch`, three `AutoSwitch`) with `ParallelAgentsStepper` on one line, right-aligned (`ml-auto`), directly below the Fleet `<h2>`. The switches already write through `/api/fleet-controls` (`FleetControls.tsx:35`, `:50`), so Done When item 4's "write their config keys through their controllers" is met today. Plan 1's `feature/delivery-section-header` slice builds "counts with their group targets … applied to every Delivery section as it stands" (`delivery-tab-header-and-my-sprint.md`, Slices), which covers Fleet's working, blocked and free counts. What slice 2 adds is the move of the existing switch strip into plan 1's header component and the token figure from finding 3. The slice is real but small, and its description should name only that.

9. **Plan 3 builds the same role chip in parallel.** `delivery-work-items-show-gates`, slice `feature/delivery-work-items-by-chips`, builds "the By column with the agent's role chip". It waits only on `feature/delivery-section-header`, as this plan's slice 1 does. Nothing names which slice builds the chip and which one reuses it, so two chip implementations can land. One of the two slices should own the chip, and the other should wait on it.

10. **Slice 1 names Waits-on gates that have no agent reading.** Agent `blockedOn` is set only to `'person'`, from state `waiting` (`delivery-readings.ts:303`). The slice lists `CI ⟳` with its run, review and a rate limit as Waits on targets, but no current reading sets those gates for an agent. Done When does not require them, so the gap does not block delivery. The slice still has to build those readings or narrow its text.

11. **The time-left bar needs a reading the payload does not carry.** `Worker bound` reaches the payload only when an ended free wait is present (`board/src/server/fleet.ts:8612-8619`). `AgentEntry.startedAt` exists (`schema.ts` AgentEntry, `startedAt`). The bar needs the bound for each role on every render. This is a local config read, so no Non-goal blocks it, but slice 1 has to name it.

## Verdict

Both `builds:` markers name things that can ship. The rows-versus-header split is not independent as written (finding 3). Slice 1 leaves out three readings it needs: role (findings 1 and 2), bound (findings 5 and 11) and tokens (finding 4). One Changelog bullet has no slice (finding 7). Done When item 1 conflicts with the placement rule (finding 6). Most of slice 2 already exists (finding 8). The code answers both Open Questions (findings 4 and 5). None of these problems is fatal. Each one has a named change.
