# Juror: Cost

Position: amend

The header-switches slice costs nothing new. The agent-rows slice adds per-refresh reads and payload fields that the plan does not name, and the plan's "readings the board and fleetd already take" claim is false for four of its six columns. Both Open Questions have answers in the code. The fixes are named changes, not a redesign, so the position is amend.

## Findings

1. **The switches already sit at the Fleet header, so moving them adds no read.** `AgentList.tsx:1403-1419` renders `AutoDispatchSwitch`, three `AutoSwitch`es and `ParallelAgentsStepper` in the first line under the Fleet `<h2>`, read from `fleetControlsOf(fleet)` and `switchesOf(fleet)` (`:1092`), which the payload already carries. Slice 2 is a layout change at zero read cost. One constraint the plan does not name: the group headers' "held" links scroll to the anchor `fleet-controls` (`AgentList.tsx:1410`, `:1439`). A move that drops that id breaks every "auto-review off · review ›" link without a test failing.

2. **Time left for a loop agent needs a config read on every refresh, and the board refuses that read today.** `packages/board/src/server/fleet.ts:8612-8619` reads `Worker bound` ONLY when an ended free desk exists: "the config read is an uncached subprocess (0.12-0.94 s measured) and `/api/fleet` is polled every 4 s per viewer, so paying for it on every refresh … would be a cost with no reader." A Time-left bar on every working loop agent makes that read unconditional whenever one loop agent runs. That costs up to about 0.94 s per 4 s poll per viewer, or the plan has to cache it. The plan claims no new reads (line 45) and names neither choice. `startedAt` is already in the payload (`schema.ts:4000`), so only the bound is missing.

3. **No live per-agent token reading exists, and the record that does exist misses running agents.** The per-slice record is written once, at `seal_declaration` (`workflows/slice-spend.ts:49-56`), or once per finished SDK run (`worker-loop.ts:259`, `:2448`, role `'worker'` only). "THE BOUND PATH RECORDS NOTHING" (`slice-spend.ts:62-70`), so the runs the bar turns red for are the ones the record never holds. The live reading on an agent entry is the transcript tail (`fleet/src/shared/transcript.ts:137`, 256 KiB, last turn only). It carries `contextTokens` (cache read) and `contextSpend` (`schema.ts:4054-4062`), not output tokens. A cumulative output figure per running agent needs a full transcript scan each refresh. `slice-spend.ts:57-60` measured that scan: up to 7.7 MiB per file, 90-250 ms on the largest, per agent, every 4 s. The plan's "tokens … come from readings the board and fleetd already take" (line 45) does not hold for the Tokens column.

4. **Open Question 1, per-day output tokens: no such reading exists.** No source matches `tokens today`, `perDay` or `startOfDay` (`git grep` over `packages/*/src`). A derivable proxy exists: seal and run lines carry `at` (`entities/slice-spend.ts:49`) and four counters, so "output tokens of runs finished today" can be summed from `.plot/state/slice-spend.jsonl`, which the board already opens (`board.ts:459-460`). That figure is machine-local, covers finished loop runs only, and is biased low by finding 3. It is not "spent today". The plan can name the figure honestly or show none. It has no live per-day reading to read.

5. **Open Question 2, bounds for other roles: the code answers it, and the plan's two-bound model is incomplete.** Design and verify run under `Worker bound` (`auto-design.ts:465,768`, `auto-verify.ts:366,515`, default 28800). The reviewer has `REVIEW_BOUND_SECONDS = 3600` (`board/src/server/entry/review.ts:94`), which the plan omits. The fixer has `FIXER_BOUND_SECONDS = 3600` (`rules/fixer-attempts.ts:8`). The unblocker has 1800 (`rules/unblocker-due.ts:39`). Implement has 300 s (`implement-run.ts:134`). Idea, brief, story and interrogate pass no `boundSeconds` (`board-run.ts:53,255`: "`0` or absent for no bound"). `implement-run.ts:204` states "A brief run has no time bound". So the answer for idea and brief is "no bound: no bar". These are constants, so only `Worker bound` costs a read (finding 2).

6. **The payload does not carry the role, so every chip reads "loop".** `AgentEntrySchema` (`schema.ts:3906-4070`) has no `role` field. `delivery-readings.ts:29` types `role?` as an addition and `:302` defaults it to `'loop'`. `AgentRole` holds six values (`delivery-placement.ts:92`) and the plan names eight, adding design and verify. Reviewer, fixer, design and verify runs are not registry entries. Showing them as rows needs new readings or new payload fields. The board reads design and verify status per plan (`fleet.ts:8810-8812`) and fixer `inFlight` per PR row (`fleet.ts:6614`), and nothing reads reviewer runs. The plan states no new reads and names none of these sources.

7. **Doing now needs git reads the board does not take.** "writing code · 4 commits" and "the last commit message for a loop agent" have no payload field. `git grep` finds no `lastCommit`, `commitCount` or subject field in `contract/schema.ts`, and the row carries only `localAhead`, `changedPaths` and `runHistory` (`schema.ts:2489-2537`). That is one `git log` per agent branch per board build. The reads are local, not host reads, so the design's non-goal (no host or tracker reads) holds. The plan's stronger claim does not.

8. **Payload growth is unbounded per agent and the plan does not state it.** Each agent row gains a role, a token figure plus three tooltip counters, a bound, a commit count and a subject. With `Parallel agents` rows polled every 4 s per viewer, a commit subject is the only free-text field, and it should be capped. The plan does not say whether the figures are computed server-side or shipped raw.

9. **Rebuilding the board artifact per slice cannot ship.** Line 22 says "Rebuild the board artifact (`pnpm build:board`) with each slice". `scripts/check-no-bundle-diff.sh` refuses a generated bundle in a PR's diff, and `main` builds its own bundles. Every slice that follows line 22 fails CI once. Sibling `delivery-you-blocks-or-feeds.md:96` already records the same defect for its plan.

10. **The role chip has two builders.** `delivery-work-items-show-gates.md:41,75` adds role chips to `delivery-row-form.ts` in its By slice, and this plan's slice 1 builds them too. Both wait only on `feature/delivery-section-header`. That gives two concurrent PRs on one file and one domain fact, which costs a rebase and a review round. `agentRowCells` already emits the role as its `kind` cell (`delivery-row-form.ts:324`) and a gate-named Waits-on cell (`:313-321`), so part of slice 1 exists already.

## Named changes

- Replace "readings the board and fleetd already take" with a list of what each column reads, at what cost per refresh. Cover the `Worker bound` config read (cached or conditional), the transcript scan or a reduced figure for Tokens, git log per branch, and role sources for the non-registry agents.
- Answer OQ1 with "no live reading". Either name the finished-runs-today proxy from `slice-spend.jsonl` and its low bias, or drop the header figure.
- Answer OQ2 from the constants in finding 5, and add the reviewer's 3600 s bound. Idea and brief show no bar.
- Keep the `fleet-controls` anchor in slice 2.
- Drop "rebuild the board artifact with each slice".
- Give the role chip one owner, with a `waits:` on the other plan's slice.
