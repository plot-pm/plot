# Round 1 — domain juror

Position: amend

The direction is right: a built bundle is `main`'s output, and the repair script goes. The plan places its two new decisions in the right layer (a CI gate under `scripts/`, a desk reading in shell, no new `plot-*.sh`). But it amends one of four readers of "what counts as uncommitted work". It also derives the generated set a fifth time while deleting the test that holds the derivations together. Its repair line and the slice-2 gate both fail on their own cases. All evidence below is read from `origin/main` on 2026-10-02.

## 1. Does the design remove the stated failure?

For a PR that carries no bundle, yes. A three-dot diff that touches no `-merge` path cannot conflict on one. These paths still conflict or still stick:

- **The bundle PR itself is refused by slice 2.** Slice 2 refuses "the PR when the diff against its merge base changes a generated path". `bot/board-artifact` is a PR whose whole diff is generated paths. The plan says "on `main` the step stays a freshness check", but the bundle PR runs as `pull_request`, not as a push to `main`. Without an exemption keyed to the head branch `bot/board-artifact`, slice 2 makes `main` permanently stale. This is a defect in the design text, not an open question.
- **The printed repair does not clear the refusal.** `git checkout origin/main -- skills/plot/scripts/board/ && git commit` writes `origin/main`'s bundles. The gate compares against the merge base. When `main` has moved since the branch was cut (the normal case, and the case the plan exists for), HEAD now holds `main`'s newer bundle and the merge base the older one. The diff is non-empty, so the gate refuses again. The repair must restore from the merge base: `git checkout "$(git merge-base HEAD origin/main)" -- <paths>`.
- **The repair is a directory and the generated set is not.** `git ls-tree origin/main skills/plot/scripts/board/` holds 36 entries. Two of them are not generated: `README.md` and `plot-monitor.mjs`. `.gitattributes` excludes `plot-monitor.mjs` deliberately ("nothing rebuilds it"), and `scripts/check-bundle-attributes.sh` says the same. A directory-wide checkout reverts a PR's legitimate edit to either file. The repair must name the derived paths, never the directory.
- **Residual real conflicts stay real, and that is correct.** `.gitattributes` (two PRs that each add a bundle append adjacent `-merge` lines) and `packages/board/src/contract/bundles.generated.ts` (one sorted array, written by the build, committed source per `build.mjs:62-64`) still conflict when two PRs add bundles. That is rare, and reading such a conflict is the correct repair, so it needs no change. The plan should say so, so that the gate never adds `bundles.generated.ts` to its set.

## 2. What breaks for consumers

- **A desk that follows the new prompt reads `stalled` and spends the supervisor's correction budget.** This is the main domain finding. The plan excuses generated paths in `plot-desk-dirt.sh`, but that file serves only the reaper and reconcile §21 (`plot-reap.sh:276`, `plot-reconcile-scan.sh:323`). The supervisor reads a different filter. `packages/domain/src/adapters/trees/trees-git.ts:134-143` answers `Trees.dirtyPaths` by sourcing `plot_worker_dirty` from `plot-worker-state.sh:389-438`. That value feeds `rules/gates.ts:163-172` ("still holds uncommitted work … This is the only copy of it") and `rules/movable.ts:115`. The same filter decides `stalled` in `plot_worker_state`. The board's drop rule has a third copy, the inline `bashCleanliness` in `packages/board/src/server/registry.ts:1153-1190`. `plot-dispatch.sh`'s `uncommitted_files` (`:3541`) and its `--restart` check (`:1925`) read raw porcelain, and so does `plot-fleetctl.sh:1155`. An agent told to "build and not stage" therefore leaves 34 modified bundles. That agent reads `stalled`, the registry hands it a correction naming a bundle as "the only copy" of its work, and after `Correction budget: 2` it is marked `PLOT-BLOCKED`. The correction text then tells it to commit the bundle, which CI refuses. Excusing one reader of four makes the four disagree about one tree, the failure `plot-desk-dirt.sh:8-12` was written to prevent.
- **The excuse is destructive-side, so it must be exact.** `desk_dirt` feeds the reaper, which removes worktrees. `plot-desk-dirt.sh:20-21` states "EACH EXCLUSION IS NAMED … there is no glob". The generated set must be matched path by path, never as `skills/plot/scripts/board/`. A directory excuse would let the reaper delete a desk whose only work is an uncommitted edit to `plot-monitor.mjs` or `README.md`.
- **`main` is red after every source merge, by design.** In slice 2 the push-to-`main` step stays "a freshness check". Every merge of board source therefore produces a red `main` run until the bundle PR lands. A `main` that is routinely red hides a real failure. The memory file already records the cost of a red `main` ("CI is red on main, three browser tests"). On push to `main` the step must report staleness and not fail. The bundle PR's own run is where freshness is proven, and that run must show an empty `git diff` after `build:board`.
- **The release tag can hold a stale build.** "A release tag holds a fresh build, because the release PR is cut from `main`" is not guaranteed. `release.yml` tags on the changeset-free push that merges the Version Packages PR. If that merge lands while a bundle PR is pending, the tag and the plugin cache for that version hold trailing bundles. The plugin cache is keyed by version: `~/.claude/plugins/cache/plot-marketplace/plot/<version>`, and `marketplace.json` uses `source: ./`. The release job must run `pnpm build:board`, and it must either refuse to tag or wait while the tree differs.
- **"Could not ask" means different things to different callers.** The plan says every bundle caller "already treats a missing answer as 'could not ask'". That is true, but the callers degrade differently. `plot-desk-root.sh` exits 3 and stops its caller ("No caller keeps a fallback default"). `plot-start-command.mjs`'s caller starts nothing. `plot-sprint-release.sh` stops on an unaskable rule. During the window, a PR that pairs a shell caller with a new bundle option stops those scripts. The window is real, and the plan should say so rather than call it harmless. A `main` checkout running under `node --watch` stays on the old board until the bundle PR is pulled, which is acceptable. An operator who runs `pnpm build:board` in the `main` checkout to close the gap then holds dirt that blocks the next `git pull`. The plan should state that too.
- **Tests that load the built artifact.** CI builds before it tests, and the plan keeps that. Locally nothing changes, and a desk must build first, as today.

## 3. Slice order and what is missing

The order (workflow, then gate, then retire) is right, and each slice can land alone once these items are added:

- **Slice 2: exempt the bundle PR** by head ref `bot/board-artifact`, and test the exemption.
- **Slice 2: write the gate as `scripts/check-no-bundle-diff.sh` with a fixture test**, not as inline YAML in `ci.yml`. This follows the `check-bundle-attributes.sh` and `test/reconcile/bundle-attribute-gate.test.mjs` precedent: "a gate nothing tests is a gate that passes because nobody looked". The `<!-- builds: the no-bundle gate in ci.yml -->` annotation should name the script.
- **Slice 2: excuse the generated set in every dirt reader, or route them through one.** At minimum: `plot_worker_dirty_filter` in `plot-worker-state.sh` (supervisor, `stalled`, `--release`), `plot-desk-dirt.sh` (reaper, §21), and `bashCleanliness` in `registry.ts`. Add a test that one desk holding only rebuilt bundles reads clean in all three, and reads dirty when a source file sits beside them. Both shell filters are already sourced, so one filter can serve both. The rule ("uncommitted work blocks") stays in `rules/gates.ts` and `rules/reapable.ts` unchanged. Only the reading changes, which is what `plot-desk-dirt.sh:14-17` prescribes.
- **Slice 2: change the actual prompt text.** `.plot/worker-prompt.sh:186` says "run pnpm build:board in THIS worktree and commit the artifact". The prompt is this repository's own file, not the shipped template, and the change belongs there to keep Plot project-agnostic. Also update the CLAUDE.md "The board is first-class" and "On a conflict in `board-server.mjs`" paragraphs (`CLAUDE.md:663`), and `docs/definition-of-done.md:27` ("produces no git diff"), whose `:30` section "Resolving a board artifact conflict" also needs revision.
- **Slice 2: `main`'s step reports and does not fail.** See section 2.
- **Slice 3: do not delete the set-equality and freshness assertions with the script's tests.** `test/reconcile/resolveartifact.test.mjs` (~lines 560-600) holds the only test that `bundles.generated.ts` is fresh ("bundles.generated.ts is stale — run `pnpm build:board`") and that the shell derivation equals `BOARD_ARTIFACT_PATHS`. Move those assertions, retargeted at the new gate's derivation and the dirt filters, into a surviving test file before deleting the rest.
- **Slice 3: the full removal list.** The plan says "the board's automatic call to it". The call sites on `main` are `packages/board/src/server/resolver.ts` (whole module: `mayResolve`, `REPAIR_SCRIPT`, `spawnRepair`), `packages/board/test/unit/resolver.test.ts`, `packages/board/build.mjs:1158,1191,1198` (the shipped-scripts list), `packages/board/package.json:42` (`files`), `packages/board/.gitignore:21`, `scripts/check-script-names.sh:110` (exception row), `packages/domain/test/scripts-shell.test.ts:350`, the CLAUDE.md helper-table row, the comments at `schema.ts:2062,2102-2106`, `stuck.ts:138` and `plot-reap.sh:48`, and `release-smoke.sh`.
- **Slice 3: decide the fate of `artifact-conflict`.** `stuck.ts:152` (`isArtifactOnly`), `StuckState 'artifact-conflict'`, `StuckSummary.artifact` (`stuck.ts:332-373`), `stuck-display.test.ts` and `stuck-rows.browser.test.ts` classify and render a conflict whose only automatic answer is being removed. After slice 2, an artifact-only conflict means "this branch committed a bundle". The rendered state should name that repair, the gate's merge-base checkout, rather than a pending automatic repair. Per "Every rendered state is a domain property", that wording is a property and gets a unit test. Keeping the classification and changing its meaning is acceptable. Leaving it to promise a repair nobody runs is not.
- **Slice 1: give the workflow a `concurrency` group with `cancel-in-progress: true`.** Two pushes to `main` must not race two force-pushes to `bot/board-artifact`.

## 4. Open questions

- **The token: a blocker for dispatching slice 1, and it belongs in the plan before approval** because one answer changes the design. A PAT or App token is one route. The token-free route is a `workflow_dispatch` of `ci.yml` on `bot/board-artifact`. GitHub documents `workflow_dispatch` and `repository_dispatch` as the two events a `GITHUB_TOKEN` may start. The plan must verify that the resulting `validate` check run on that SHA satisfies the required check. A fleet worker cannot create a repository secret, so a person must settle this before slice 1 is dispatched.
- **Two merges inside one CI run: the right question, not a blocker.** With `strict: false`, auto-merge merges the head whose checks passed. The worst case is one build that trails by one merge, and the next push fixes it. Add the concurrency group above.
- **PRs open at the switch: the right question, but the plan's answer is wrong as written.** The repair line it would rely on fails (see section 1). Fix the line. Then the one-time sweep becomes optional.
- **The changeset-release PR is not just "confirm".** It is a stale-tag risk (see section 2), and slice 1 or slice 2 should own the release job's freshness check.
- **Missing questions:** (a) `main` red after every merge (section 2); (b) four dirt readers against one excuse (section 2); (c) where the shell reads the generated set. Today three readers grep `build.mjs` with one regex (`build.mjs:77`, `check-bundle-attributes.sh`, `bundle_set()`), and the plan adds a gate and one or two filters. Name one sourced derivation, or have the filters read the exact `-merge` entries under `skills/plot/scripts/board/` (already gated against the build). Then hold them equal to `BOARD_ARTIFACT_PATHS` with the test moved out of `resolveartifact.test.mjs`.

## Vocabulary

The plan matches the specs: one branch per slice, "desk" for the worktree, and "agent" for the actor. "Bundle" and "artifact" are both estate words. The plan should keep "generated path" defined once as "an entry of `BOARD_ARTIFACT_PATHS`", so that `plot-monitor.mjs` and `README.md` are visibly outside it.
