# Safety juror: the-commit-gates-match-only-the

Position: amend

The plan is right that the four gates miss `git -C <dir> commit`, `git -c k=v commit`, `git  commit` and the `--continue` forms, and a parsed reading is the right fix. Through the safety lens it fails in both directions as written. In the escape direction, three things remain: the initiating forms (`git merge X`, `pull`, `cherry-pick X`, `revert X`, `am`) are read before git writes the commit, so the gates read an index that holds none of it; `bash -c "git commit"`, `eval`, `timeout`, `nice` and `command git commit` parse to a non-null reading with no `git` program word, so the rule matches less than the substring test does today; and the chained-add readers do not know `git -C <dir> add`, so `git -C wt add -A && git -C wt commit` still escapes the state gate. In the refusal direction, the state gate spends a single-use receipt on every call it runs on, so widening it to `pull` and `merge` can spend a receipt before the real commit; `merge --abort` and the other `--abort/--skip/--quit` forms match the plan's wording and the phase gate can refuse them; and `rebase --continue` reads no picked-commit parent, so a replayed receipted `State:` change is refused. The legitimate repairs in the brief (`merge -X theirs origin/main`, `merge --continue` after taking main's bundle, a fix agent's `git -C <scratch> commit`) pass, and I checked each. The design also has an existing placement reader, `writeDirsWhere` in `main-checkout-write.ts`, that the plan says does not exist.

## Findings

1. **High: the initiating forms give no protection.** The gates run as a PreToolUse hook and read the index before the command runs (`gate.ts:104` `stagedEntries`, `:253`, `:408`). For `git merge X`, `git pull`, `git cherry-pick X`, `git revert X` and `git am`, the commit content comes from another commit, not from the index, so every gate reads an empty or unrelated index and allows. Checked by experiment in a scratch repository: `git merge -X theirs main` from a clean index made the merge commit in one step (`Merge made by the 'ort' strategy`, exit 0), with nothing staged before the call. A `git cherry-pick <sha>` that carries a hand-written `State:` line still escapes after this plan. The Changelog line "run on every Bash call that makes a commit" is true as a matching statement but implies a protection that only the `--continue` forms and `commit` get.
2. **High: the state gate spends a receipt on a call that commits nothing.** `stateReceiptsFile.spend` renames the receipt away on the first match (`packages/domain/src/adapters/state-receipts/state-receipts-file.ts`, the `rename(file, spent)` step), and `gate.ts:320-326` spends for each transition it sees. The owning scripts do not stage or commit (grep over `skills/plot/scripts/*.sh` for `git add`/`git commit` in the approve, deliver and sprint-state scripts finds none), so the agent stages and commits later. A `git add <plan>` followed by `git pull` (fast-forward with a staged change succeeds), or a `git pull --all` (`takesModifiedOf`, `state-transition.ts:399-400`, reads ` --all` as `-a`), now spends the receipt, and the later `git commit` is refused with no receipt left. The plan's sentence "A gate that runs on a command that commits nothing reads the index and allows" is false for the state gate.
3. **High: the rule matches less than the substring test for wrapper forms.** `readShell` returns a non-null reading for `bash -c "git commit -m x"` (`[["bash","-c","git commit -m x"]]`), `sh -c '...'`, `eval "git commit -m x"`, `timeout 60 git commit`, `nice git commit`, `command git commit` and `xargs git commit` (node experiment against `shell-reading.ts`). `programWords` (`ci-suite.ts`) strips only `env` and `NAME=value` (experiment: `["command","git","commit"]` and `["timeout","60","git","commit"]` are returned unchanged). The plan's floor ("a line `readShell` returns `null` for falls back to the substring test, so the rule never matches less") covers only the null case. Today `command.includes('git commit')` matches all of these.
4. **Medium: `--abort`, `--skip` and `--quit` match, and the phase gate can refuse them.** The plan matches `cherry-pick`, `revert`, `am` with no action filter and `merge` unless `--no-commit`, so `git merge --abort` matches. During a conflicted merge of `origin/main`, the non-conflicted paths from main are staged (`stagedEntriesOf`, `refs-git.ts:334-355`; unmerged `U` entries are dropped, checked by experiment: `git diff --cached --raw` printed `U` for both conflicted paths). The phase gate has no other-parent carve-out: `holdRefusal` (`phase-gate.ts:149-161`) and the Draft check (`gate.ts:430-434`) refuse any path outside the plan directory. On a branch in `.plot/hold`, or on a Draft plan's work branch (a plan placed "on the work branch" by `/plot-idea`), `git merge --abort` is refused, which blocks the agent's way out of the conflict. `git merge --squash` also matches and commits nothing.
5. **Medium: `rebase --continue` and `cherry-pick --continue` refuse a replayed, receipted `State:` change.** The state gate reads only `MERGE_HEAD` as another parent (`refs-git.ts:479-485`; `gate.ts:279-282`). During a rebase or cherry-pick, git writes `REBASE_HEAD` or `CHERRY_PICK_HEAD`, not `MERGE_HEAD`. A commit on a plan branch that made `Draft -> Design` through `plot-needs-design.mjs` spent its receipt when it was first made. If a rebase of that branch stops on it, `git rebase --continue` sees the transition against the new `HEAD`, finds no other parent and no receipt, and refuses. The same holds for `cherry-pick --continue` of such a commit into a fix worktree.
6. **Medium: the directory rule reads the wrong tree for common forms, and an existing reader already does it right.** The plan takes "the last `-C` of the matching simple command, resolved against the session directory". `readShell` returns `cd /w` and `git -C sub commit` as separate simple commands (experiment), so `cd /w && git -C sub commit` resolves `sub` against the wrong base, and `cd /wt && git commit` reads `process.cwd()`. git joins successive `-C` paths, so "the last `-C`" is wrong for `git -C a -C b commit`. `git -C a commit && git -C b commit` has two matching commands and the plan returns one directory. `writeDirsWhere` and `gitWriteDirs` (`main-checkout-write.ts:255-310`) already place every git call by literal `cd`, `pushd` and joined `-C`, one entry per call, and take an `accepts(sub, args)` predicate. `commitIndex` (`controller-gate.ts:87-100`) with `GIT_VALUE_OPTIONS` (`:43`) already skips git global options before `commit`. The plan's "The deliverable search found no existing commit test" is false.
7. **Medium: an unplaceable directory is not specified, and the existing readers fail open.** `git -C "$WT" commit` reads as a word with `value: null` (experiment: `<"$WT">`). `commitIndex` returns `null` on an unknown value (`controller-gate.ts:92`), so a rule copied from it does not match at all. `gitWriteDirs` leaves the call out "so the gate allows them" (`main-checkout-write.ts:266-270`). Either way the commit gates either skip the call or read `process.cwd()`, which is a different tree, and allow silently.
8. **Medium: the chained-add readers do not know `-C`, so the motivating form still escapes the state gate.** `chainedAddsOf` (`chained-add.ts`) and `chainedStagesOf` (`brief-name.ts`) search for the substring `git add`. Experiment: `effectivePaths({staged: [], workingChanges: ['docs/plans/x.md'], showPrefix: ''}, 'git -C /wt add -A && git -C /wt commit -m x')` returns `[]`, against one `working` path for `git add -A && git commit -m x`. The state gate then reads the pre-add index and a hand-written `State:` line in the working tree reaches the commit. The PR #2965 repair used exactly `git -C <worktree>` forms.
9. **Low: `--git-dir`, `--work-tree`, `GIT_DIR=` and `GIT_INDEX_FILE=` read the wrong repository or index.** `readShell` keeps `GIT_DIR=/x/.git` as a word and `programWords` drops it (experiment). The plan skips `--git-dir`/`--work-tree` and threads only `-C`, so the gate reads the hook's tree. These forms are rare; the plan should name them as UNVERIFIED rather than imply coverage.
10. **Low: the legitimate repairs in the brief pass.** `git merge -X theirs origin/main` is read before the merge, against a clean index, so all four gates allow (experiment above; `-X theirs` resolves a `-merge` path to theirs with no conflict). `git merge --continue` after taking main's bundle: the bundle gate's base is `git merge-base origin/main HEAD MERGE_HEAD` (`gate.ts:112-120`), which is the `origin/main` tip, and the staged bundle equals it, so `bundleCommitTouches` skips it (`bundle-commit.ts:140`). A rebase conflict on a `-merge` bundle keeps `HEAD`'s copy, which is the upstream copy, so nothing is staged for it. A fix agent's `git -C <scratch> commit` on a detached `HEAD` gets no slug from `slugOfBranch`, so the phase gate allows. The state gate clears a merge's staged text that equals `MERGE_HEAD`'s. With amendments A1-A4, I find no false refusal in these four forms.
11. **Low: cost is not a concern.** `readShell` takes 6.6 µs per call on a 4.3 KB command with a 200-line heredoc (1000 iterations, node 26.13.0). The added cost is the git reads that each matched `merge`/`pull` call starts in four gates, which A1 removes. Over-matching is not free in this estate: during this review the controller gate refused two read-only `grep` calls because a word ended in `.sh` and named an approve script.
12. **Low: the facts I checked are true, except one.** `command.includes('git commit')` sits at `gate.ts:87`, `:153`, `:232` and `:371` on `origin/main` (`git show origin/main:...`). `readShell` splits on `&&`, `;`, `|` and subshells and removes quotes (`shell-reading.ts:1-9`, experiment). `mergesBy` is at `packages/domain/src/rules/controller-gate.ts:266`. The hook is `hooks/hooks.json` → `plot-gates.sh --all`; `plot-state-gate.sh` and `plot-bundle-commit-gate.sh` exec the same bundle with no shell prefilter, so a change to `wants` reaches them. The brief's `.claude/settings.json` does not exist on `origin/main`. The false claim is the one in finding 6.

## Amendments I require

- A1. Match only forms whose commit is the index: `commit` (including `--amend`) and `merge --continue`, `cherry-pick --continue`, `revert --continue`, `am --continue`, `rebase --continue`. Do not match the initiating `merge`, `pull`, `cherry-pick`, `revert` or `am`. Rewrite the Changelog to say so, and add a `## Notes` line that names the initiating forms as a known escape that a PreToolUse reading cannot close, because the commit content is not in the index when the hook runs.
- A2. Never match `--abort`, `--skip`, `--quit` or `merge --squash`. Add a test row for `git merge --abort` on a held branch with main's paths staged, which must allow.
- A3. Keep today's substring test as the floor: `makesCommit` is the parsed answer OR `command.includes('git commit')`, for every reading, not only a null one. Alternatively recurse into the string of `bash -c`, `sh -c` and `eval`, and skip `command`, `builtin`, `exec`, `timeout <n>`, `nice` and `xargs` before the program word. Drop the `git commit-tree` line from the Changelog, because running on it reads an index and costs nothing. Add test rows for `bash -c "git commit -m x"`, `eval "git commit"`, `timeout 60 git commit` and `command git commit`, each of which must match.
- A4. For `rebase --continue`, `cherry-pick --continue` and `revert --continue`, give the state gate the picked commit as a reading: a transition clears when the picked commit (`REBASE_HEAD`, `CHERRY_PICK_HEAD` or `REVERT_HEAD`) made the same `before -> after` change against its own parent. Add a test row for a rebase that stops on a receipted `Draft -> Design` commit, which must allow.
- A5. Build the rule on `writeDirsWhere` with an `accepts` predicate (export it, or export a `commitDirs(command)` beside `gitWriteDirs`), so placement follows literal `cd`, `pushd` and joined `-C` paths. Each gate asks once per placed directory and refuses if any directory refuses. Correct the reuse sentence in `## Design`.
- A6. A matching commit whose directory cannot be placed (`-C "$WT"`, a `cd` after `popd`) prints `UNVERIFIED` naming the gate and the reason, the way `onError: 'allow'` does, and never reads `process.cwd()` in its place.
- A7. Make `chainedAddsOf` and `chainedStagesOf` read `git [global options] add` and `git [global options] mv` through the same parsed reading, and count an add only when it is placed in the same directory as the commit. Add a test row: `git -C /wt add -A && git -C /wt commit` with a hand-written `State:` line in `/wt`'s working tree must refuse.

## Optional

- O1. Name `--git-dir`, `--work-tree`, `GIT_DIR=` and `GIT_INDEX_FILE=` as UNVERIFIED in the same way as A6.
- O2. Treat a `git` alias (`git ci`) as a known escape in `## Notes`; neither today's test nor the plan's rule matches it.
- O3. Give the phase gate the state gate's other-parent carve-out for `merge --continue`, so a path whose staged text equals `MERGE_HEAD`'s does not count as an implementation path. Today a conflicted merge of main into a Draft work branch is refused at `git commit` and allowed when it merges clean; this plan extends that refusal to `merge --continue`.

## Open questions

- Q1 (`git pull` and `git merge` match when they fast-forward): do not accept it. The cost is not only a read: the state gate spends receipts and the phase gate refuses on staged content, and the gates read nothing that becomes the commit for these forms (findings 1 and 2). Match `commit` and the `--continue` forms only (A1).
- Q2 (`main-checkout`, `controller`, `role-deny` read `process.cwd()`): leave the controller and role-deny gates to a follow-up plan. The main-checkout gate already places calls by `cd` and `-C` through `gitWriteDirs`, so it needs no change. If this plan builds `makesCommit` on `writeDirsWhere` (A5), the follow-up reuses the same placement and adds no second reader.
