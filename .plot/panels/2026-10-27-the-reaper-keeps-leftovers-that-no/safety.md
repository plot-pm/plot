## 1. The problem

The three tickets hold up against the code (read).

- **#2714.** `reapProblems` (`packages/domain/src/rules/reapable.ts:111-142`) refuses `no-merged-pr` whenever `merge !== 'merged'`, and it refuses `blocked-marker` unless `markerRecordsWork === false`. `reap.ts:653-664` sets `markerRecordsWork = true` whenever `origin/<default>..HEAD` holds a file-changing commit, *including pushed ones*. So a deferred desk with a pushed head and a marker is held by two refusals, not one. The issue output matches this: it lists both.
- **#2705.** `runClaimKind` (`reap.ts:964-1022`) walks `listBranches(false)` and never asks whether `origin/<br>` exists. `--release` returns "holds no claim" at `plot-dispatch.sh:2186-2190` when `ref_present = 0` and no manifest names the branch. The two controllers disagree, as the issue says.
- **#2697.** The plan does not name the cause, and the cause matters for safety. The reaper's liveness comes from two places (`reap.ts:305-319`). (a) `processWorkerPid` calls `plot_worker_state`, which compares the pid's start time against the manifest's `startedAt` (`plot-worker-state.sh:1203-1245`, `:301-337`). (b) `deskLoopAlive` checks the manifest's `pid` and `wrapperPid` with `pidAliveEverywhere`, which is plain `kill -0` (`packages/fleet/src/shared/desk-loop.ts:39-46`). `desk-loop-alive.ts` documents that it **accepts** a reused pid as alive on purpose, because a wrong *not-alive* starts a second loop.

**The existing start-time check cannot catch the reuse in #2697.** `plot_pid_is_current` returns *current* when the process started **at or after** `startedAt` minus 3 s (`plot-worker-state.sh:332-337`). A reused pid always belongs to a process that started *after* the original worker, because the kernel reuses a pid only after the original exits. The Siri process in #2697 started about 20 minutes before the dry run, long after the worker's launch, so it passes this check. The plan's Approach 1 says "compare the process start time … against the worker's launch record". The obvious way to build that copies this one-sided comparison, and that fixes nothing. I read this from the code and did not reproduce it.

## 2. The approach against the code

- **Slice 1 sits on a rule with three callers.** `deskLoopAlive` and `pidAliveEverywhere` also serve `readDeskLoop` (`desk-loop.ts:79-88`) and `continueOnDesk` (#1294). Those callers chose the opposite error direction on purpose. `plot_worker_state` is read by fleet-scan, dispatch `--release` (`plot-dispatch.sh:2258`) and the board. The plan says "states it as a reading in the domain" but does not name which pid source it changes or which callers may see the new answer.
- **Slice 2 has an existing definition to reuse.** `--release` already defines a claim as "origin ref present, or a manifest names it". The reaper can ask the same two readings. The plan should pick one removal owner. Today the Open Question leaves it unanswered, and the safety contract depends on the answer (see 3b).
- **Slice 3 needs a reading that does not exist.** `MergeReading` (`reapable.ts:13`) is `merged | not-merged | unreachable`. *not-merged* covers "no PR", "open PR" and "closed unmerged" together. "Closed unmerged" needs a new host reading, and it must exclude an open PR on the same branch. `RefReadings.openPr` (`reapable.ts:204`) already exists for this purpose. `givenUp` in `RefReadings` covers `deferred:` **and** `moved:`. The plan names only `deferred:`.
- **The corpus sentence is stale.** `plot-reap.sh` is now a 13-line launcher (`skills/plot/scripts/plot-reap.sh`) and duplicates no rule. The Design should not promise a corpus pair for it.

## 3. Safety — the destructive paths

**3a. Slice 1 (#2697): a stricter liveness check can reap a desk under a live loop.**
- Path: the slice applies a start-time comparison to `wrapperPid`. The manifest records one `startedAt`, for the agent `pid` only, and rewrites it on every relaunch (`manifest-stamp.ts:50,87-92`). The wrapper or loop started earlier than that stamp. A two-sided check ("start time ≈ `startedAt`") therefore reads a live `wrapperPid` as dead. The desk then has a merged branch, a clean tree, and a loop sleeping between agents, which is exactly the case `deskWorkerPid`'s fallback exists for (`reap.ts:305-311`). The reaper runs `git worktree remove --force` (`trees-git.ts:484`) under the live loop.
- Path: if the slice changes `deskLoopAlive`, `pidAliveEverywhere` or `plot_worker_state`, then `continueOnDesk` and the fleet read a live loop as gone and start a second loop on the desk. That is the failure #1294 fixed.
- Path: a two-sided check with too little slack reads a live worker as dead on a loaded machine. `startedAt` is stamped after launch by awk or JS, and Linux procps already skews the start time by up to 1.2 s (`plot-worker-state.sh:333-336`). Dispatch and fleet would then treat a running slice as free.
- What must hold: a pid reads dead **only** when its own recorded start time is known and differs from the live process's start time. A pid with no start time recorded for it (`wrapperPid`, `.plot-worker.pid`, an old manifest, a manifest from another machine) keeps today's `kill -0` answer. The change is scoped to the reaper's question, or each other caller states that it accepts the new direction.

**3b. Slice 2 (#2705): deleting a local claim branch is low-risk only with three guards stated.**
- `isWhollyEmptyClaim` (`reap.ts:333-338`) admits a branch only when every commit in `origin/<default>..br` is an empty claim. Deleting it therefore loses no file content. That part is safe.
- The guards the plan does not state are these. (i) No worktree has the branch checked out. Today `git branch -D` refuses a checked-out branch (`trees-git.ts:486-487`), but that is git's backstop, not the rule's. An implementation that uses `update-ref -d` or `--release`'s shell would lose it. The agent-loop take-up (`agent-loop.ts:723`) and `auto-design.ts:734-741` both commit the claim in a checked-out desk *before* the push. Between those two steps the branch is local-only, empty, and owned by a live run. (ii) No manifest names the branch. (iii) The origin reading is the host's. A missing `refs/remotes/origin/<br>` on a checkout that has not fetched does not prove that no remote claim exists. The issue's own words, "no remote claim exists to protect", need a fresh `ls-remote` or fetch, or the slice must state that a stale tracking ref is acceptable *because* only an empty local ref is deleted.
- If the removal goes to `--release`, it lands in `plot-dispatch.sh`. That file is a controller, and the shell-line ratchet (`check-shell-lines.sh`) charges for it. Putting the removal in `reap.ts`, beside the existing `deleteBranch` call, costs no shell lines.

**3c. Slice 3 (#2714): "removes the desk and its refs" destroys the only copy of deferred work.**
- The plan's Approach 3 ends with "The reap entry removes the desk and its refs." The issue says the opposite: "The work stays on the remote branch." The branch never merged, so the remote ref is the only place its commits live outside this machine. `refDeletionProblems` refuses this case twice, with `given-up` first and `no-merged-pr` second (`reapable.ts:247-254`), and the comment explains why: `/plot-reconcile` reads the deferral against the ref. *One Answer To "Did This Land"* forbids any destructive decision that does not read `mergedAt`. Deleting the remote ref of a closed-unmerged PR is irreversible and has no `mergedAt` to read. Open Question 3 must be answered "the desk only, never the remote ref, never the local branch". The slice's test must assert that the remote ref and the local branch survive.
- Removing only the worktree is recoverable. `removeOnly` keeps the local branch ref, and kind 2 (`reap.ts:864-930`) deletes local branches only when they merged. So the commits survive in `refs/heads/<br>` even when the remote-tracking ref is stale. This is the safety net. The slice must not add a local-branch deletion that removes it.
- Inputs that must keep the desk, each needing a test:
  - **An open PR on the branch.** An operator resumed the deferred slice and opened a new PR. Today this reads `not-merged` and is kept. The new case would reap it unless it reads `openPr`.
  - **A host that cannot be asked** (`unreachable`). It must keep, as it does today.
  - **A `moved:` annotation.** The slice may continue under another plan on the same branch, so only `deferred:` qualifies. Reusing `givenUp` would admit `moved:`.
  - **Uncommitted changes or unpushed commits.** The slice must lift only `no-merged-pr` and `blocked-marker` for this case, never `uncommitted-changes` or `unpushed-commits`. For a not-merged branch, `unpushed` is `trees.unpushedCommits` against every remote (`reap.ts:356-359`), so a head behind a stale tracking ref reads as pushed. That is acceptable only because 3c's safety net holds.
  - **A live worker.** `plot-continue-command.mjs` can relaunch an agent on the deferred slice (the issue names it). `live-worker` must stay first, and it depends on slice 1 not weakening liveness.
  - **A marker written after the deferral.** That marker asks a new question, and the deferral did not end it. The deferral annotation carries a date (`<!-- deferred: 2026-10-25 … -->`), and the marker has an mtime. The slice should compare them, or say why not.
- Deferral lookup: `claimDisposition` (`reap.ts:942-960`) matches the first line in any active plan that names the branch in backticks. A branch named in two active plans, deferred in one and scheduled in another, reads as abandoned. Slice 3 must reuse the lookup with that limit stated, or scope the lookup to the plan that owns the slice.

**3d. What stops working that works today.** If slices 1 and 3 keep the guards above, nothing does. Without them: continuation can double-start (3a), the deferred-but-resumed PR loses its desk (3c), and remote unmerged work is deleted (3c).

## 4. Slices against Changelog and acceptance

- Each slice ships a reaper output a person can see change: a `would`/`reaped` row where a `keep` row appeared before. The three slices are independent. The order is right, with one exception: slice 3's `live-worker` guard depends on slice 1 not weakening liveness, so slice 1 must land first or stay strictly reaper-scoped.
- The Changelog line "a controller removes each leftover desk or claim ref" over-claims for #2714. It must say the *desk* is removed and the refs are kept.
- Acceptance is "one test per case". That proves that a leftover is reaped. It does not prove that the neighbouring live case is kept. Each slice needs a negative test that fails on a careless implementation: the live wrapper (3a); the checked-out, manifest-named or remote-present claim (3b); open PR, `moved:`, unreachable host, dirty desk, remote ref survives (3c). The #2697 positive test needs a pid whose process started **after** `startedAt`. A test with an earlier start passes today's code and proves nothing.

## 5. New defects

- Slice 1, if it lands in `plot-worker-state.sh`, changes a declared shell duplicate and costs shell lines. In the domain it needs a `Processes.startedAt` reading (`processes-shell.ts:192` already exists), so it should be built there.
- Bash 3.2 and Bitbucket: slice 3's "closed unmerged" reading needs a `plot-host.sh` verb that works on both hosts. Bitbucket calls the state `DECLINED`, not `CLOSED`. The plan names neither.
- `ps -o lstart` has 1 s resolution and a different format on Linux. Equality needs slack. The slice should quote and test the existing 3 s (`plot-worker-state.sh:336`).
- For adopting repos with no `origin`: `origin/<default>..br` fails, `isWhollyEmptyClaim` answers false, and nothing is deleted. That is safe, and a test should hold it.

State that `refDeletionProblems`' `given-up` and `no-merged-pr` refusals stay unchanged. Fix the Approach sentence "removes the desk and its refs" and the Changelog line to match. Lift only `no-merged-pr` and `blocked-marker`. Add a negative test for each other input. Address a marker that is newer than the deferral date.
3. **#2697: name the cause and the direction.** State that `plot_pid_is_current`'s one-sided "started at or after `startedAt`" comparison cannot detect reuse, and that the reaper's fallback uses plain `kill -0`. Require a two-sided start-time comparison, applied only to a pid whose own start time is recorded. Every other pid source (`wrapperPid`, `.plot-worker.pid`, old manifests) keeps `kill -0`. Scope the change to the reaper's reading, or list `continueOnDesk`, `readDeskLoop`, fleet-scan and dispatch as callers that accept the new direction. The negative test keeps a live loop whose `wrapperPid` predates a relaunched `startedAt`.
4. **#2705: state the guards for deleting a local claim.** The branch is not checked out in any worktree, no manifest names it, and it holds only empty claim commits. Say whether "no origin ref" is read from the host or from the tracking ref, and why that is enough. Prefer `reap.ts` over `plot-dispatch.sh` as the owner, because it costs no shell lines and already holds `deleteBranch`. Add negative tests for a checked-out branch, a manifest-named branch and a remote-present claim.
5. **Drop the corpus promise for `plot-reap.sh`.** It is a launcher with no duplicated rule. Name the actual duplicate pair if one is touched (`plot_worker_state` ↔ domain).
