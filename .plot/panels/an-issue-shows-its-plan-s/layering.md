# Juror verdict: layering — an-issue-shows-its-plan-s

Position: amend

The plan names five real gaps, and gaps 1, 2 and 4 point at the right owners. Through the layering lens, three of its premises do not hold on `origin/main` (1be47ec3c). Gap 1's fix direction "reuse the plan walk's set" cannot work as written: the walk's output (the pulse) drops released plans, and the walk's `PlanRecord` carries no `issues` field, so the board would still need its own plan read. Gap 5's diagnosis is wrong: the board reads its PR records only from the PR index, and the index itself held the old head until 13:09:35; the delay is the index's 8-minute cadence, not a stale record overriding a newer index answer. Gap 3's premise is outdated: `plot-review` opens no ticket since 2026-10-29 (`reviewIssue` answers `none`), so gap 3 is a backlog of 196 open legacy tickets, not a missing lifecycle write. Each gap has a layering-correct fix that adds no host call per beat, and the amendments below name it.

## Findings

1. **high — Gap 1: the plan walk's set does not carry what `referencedIssues` needs.** `packages/domain/src/ports/plan-store.ts:10-64` (`PlanRecord`) has no `issues` or `ticket` field, although `plot-plan-meta.sh:355` emits `issues`. `packages/domain/src/workflows/plan-walk-assembly.ts:195-224` drops every `released`, `rejected` and `superseded` plan and every delivered docs/infra plan from the pulse. `packages/board/src/server/fleet.ts:1539-1546` states why that set is wrong for references: a released plan must keep its issue named. So "read the plan walk's resolved set" (Approach, Open Question 1) is the pulse set, which is the wrong set, or the pre-assembly `Estate` (`packages/domain/src/workflows/plan-walk-estate.ts:21-36`), which exists only inside fleetd's beat and lacks issues. Checked by reading the four files at `origin/main`.
2. **high — Gap 5: the index, not the board, held the old head.** The board fills `entry.prs` only from the PR store (`fleet.ts:2494-2506`, `readPrsFromStore` → `applyPrMaps`). The live store (`.git/.plot/state/index/github.json`, read with `jq`) holds PR #2996 with `headSha`/`checksSha` `75da18f…` and `headSince` `2026-11-01T13:09:35.183Z`; `updatedAt` `13:02:59Z` is the host's update time, not the index's read time. The stored rows' `headSince` values step 13:01:35 → 13:09:35, and `github.reader.json` reads `prNextAt − at` = 477 s. So the index first saw the new head at 13:09:35 and the row moved at about 13:10, which is the index's cadence. The fix direction "a newer index answer replaces an older one" changes nothing, because there is no older non-index answer on this path. The plan copies the issue's misreading of `updatedAt` as an index read time.
3. **high — Gap 3: no writer opens review tickets on main.** `packages/domain/src/rules/review-issue.ts:20` answers `none` for every count since `7f277875e` (2026-10-29, "plot-review: a review opens no follow-up issue"); a HIGH finding holds the PR at `plot/review=failure` (#2903). `gh issue list --search 'in:title "findings on PR"' --state open` returns 196 open tickets, the newest created 2026-10-29T23:03Z. So gap 3 is a one-off backlog plus whatever #2903's fixer escalation opens later; a standing closure mechanism tied to "plot-review opens one ticket per PR" designs for a writer that no longer exists.
4. **medium — Gap 2: the count is 114, not 38.** Over `origin/main`, 342 distinct issues are named by plans in state Released; 228 issues carry `plan:released`; 114 of the named issues are closed issues without it (checked per issue with `gh issue view --json state`). Closed issues with some `plan:*` label and no `plan:released`: 3. Neither query gives 38. The write path already exists: `plot-plan-state.sh --phase released` → `packages/board/src/server/entry/plan-state.ts:143` (`writePlanStates`) → `githubPlanStateWrite` (`packages/domain/src/adapters/tracker/tracker-plan-state.ts:176`, released branch at `:219`). A backfill must call that path and add no new `gh issue edit` caller (`scripts/check-host-cli-callers.sh`).
5. **medium — Required behaviour 1 is a domain rule the plan does not touch.** `packages/domain/src/rules/ticket-lane.ts:52` answers `in-progress` for any open issue a plan names, whatever the plan's phase; `ticket-lanes.ts:157` passes only `namedByPlan: boolean`. Behaviour 1 says "while the plan is started and not delivered". Either the behaviour is reworded to match the rule, or the rule takes the phase (the board already computes per-issue phases in `ticketPlansOf`, `fleet.ts:1636-1660`), and that change belongs in `ticket-lane.ts` with a unit test, not in `fleet.ts`.
6. **medium — Gap 1 has two board readers of the plan set, not one.** `planMetasOf` (`fleet.ts:1583`) feeds both `referencedIssues` (`:1558`, the lane) and `ticketPlansOf` (`:1636`, the phase badge). Both read the working tree plus `git show origin/<idea-branch>` for drafts (`draftPlanFiles`, `:1676-1700`). A fix that moves only `referencedIssues` to `origin/main` lets the lane and the badge disagree. The plan's Board-impact comment names only `referencedIssues`.
7. **medium — Gap 5's decision would land outside the domain.** The row section comes from `classifyGroup` (`fleet.ts:3635`) and `prEvidence` (`:3618`), and `ci-failing` from `stuckState` (`packages/board/src/server/stuck.ts:303`). All three are board code. "Every rendered state is a domain property" requires that a new head-binding rule go into `packages/domain/src/rules/` and that the board only pass readings in. The plan names no domain home for it.
8. **low — The plan claims `ticket-lanes.ts:149` holds the lane decision.** Line 149 is the private `laneOf`; the decision is `ticketLane` in `packages/domain/src/rules/ticket-lane.ts:52`. The other cited lines (`approve.ts:1177`, `deliver.ts:546`, `:969`, `auto-progress.ts:39`, `fleet.ts:1558`) match `origin/main`.
9. **low — Gap 4 is scoped correctly.** The plan tracks #2935 and #2924 as acceptance and re-designs neither. Through this lens that is right: both defects sit in one adapter path (`plot-plan-state.sh`/`plot-host.sh:691`), and a second fix here would create a second writer.

## Amendments I require

- A1. Gap 1: state the fix as "the board reads the plan set through the domain's estate workflow, `readEstate`, over `origin/<main>`", not "consumes the walk's resolved set". Add `issues` to `PlanRecord` and to every `PlanStore` adapter (`plan-store-ref.ts`, `plan-store-shell.ts`, `plan-store-fixture.ts`), with a corpus row proving it equals `plot-plan-meta.sh`'s `issues`. Replace `planMetasOf`'s `readdirSync` and `draftPlanFiles` with one `readEstate` call that feeds both `referencedIssues` and `ticketPlansOf`. The estate already reads branch-only plans, so `draftPlanFiles` and its temp directory retire. Name the cost: one estate read per lane request, against the 132 ms the current read costs (`fleet.ts:1549`); if it is more, cache it by the `origin/main` oid in the board's cache entry, never by ref name.
- A2. Gap 1: decide behaviour 1 against `ticket-lane.ts:52`. Either reword it to "a plan names it" or change the rule to take the plan phase, in the domain, with the Draft, Approved-not-started, Started and Delivered cases in a unit table.
- A3. Gap 5: rewrite the Motivation from the store evidence in Finding 2 and drop "a newer index answer replaces an older one". Replace it with a domain rule, for example `rules/pr-head-checks.ts`, that reads the index row's `checksSha` and the branch's remote tip the board already reads from refs, and answers `stale` when they differ. A stale answer must not place a row in *Waiting on you* as "checks failing"; it reads as "new head, checks not yet read". This costs zero host calls and reaches the tip through the existing `Refs` adapter. If the plan also wants the index to refresh sooner after a push, that is a cadence change in `pr-refresh.ts` (part 3 of "A Decision Reads The Index", a trigger on a ref move) and needs its own measurement of the rate-limit spend.
- A4. Gap 3: restate the gap as the 196-ticket backlog plus #2903's future tickets. The closure decision ("settled") is a pure rule in `packages/domain/src/rules/review-issue.ts` beside `findOpenReviewIssue`; "the PR merged" is read only from a MERGED index row (terminal, per "A Decision Reads The Index"); the close goes through the tracker port, called from a controller entry, never from `plot-reconcile` (which runs nothing) and never by a direct `gh issue close`.
- A5. Gap 2: correct the count to the measured figure with the query that produces it, and route the backfill through `plot-plan-state.sh --phase released` per released plan from an operator command. Plot-reconcile may report the drift (read-only, it prints the command) but must not write.
- A6. Slice the plan by owner, one branch per slice: (1) `PlanRecord.issues` in the port and adapters; (2) the board reads the estate for lanes and badges, waits on 1; (3) the lane rule takes the phase, if A2 chooses that; (4) the head-checks rule and its board call; (5) the `plan:released` backfill command; (6) the review-ticket closure rule and controller. Gap 4 stays a tracked dependency, not a slice.

## Open questions

- Gap 1 (walk set or shared index): neither as asked. Read the plan set through the domain's `readEstate` over `origin/<main>` with `issues` added to `PlanRecord` (A1). The `every-plan-reference-shows-its-issue` index is a client-side rendering concern and must not become a second server-side reader.
- Gap 2 (one-off or standing): a one-off operator command over the existing `plot-plan-state.sh --phase released` write, plus a read-only reconcile line that reports future drift and prints that command. No standing writer, because `/plot-release` and `deliver.ts:969` already write the label for new releases.
- Gap 3 (what counts as settled): the PR's index row reads MERGED and a person marks each finding fixed or won't-fix on the ticket; the rule closes on that and otherwise writes one comment naming the open findings. A re-review that re-runs the reviewer per ticket costs a model run per ticket for 196 tickets and is not needed for a backlog.
- Gap 5 (which read is stale): the index, by its own cadence (Finding 2); the board's records are the index's. The row takes the index row only when its `checksSha` equals the branch tip, and otherwise shows the checks as not yet read (A3).
- Gap 4 (own slices or external): external dependencies. #2935 and #2924 own the design, and a second implementation would add a second writer to `plot-plan-state.sh`.
