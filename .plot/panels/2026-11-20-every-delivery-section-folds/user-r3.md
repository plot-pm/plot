## Findings

1. **The Tickets hidden count reads the wrong number, so "N hidden by Mine" is false.** Line 67 says: "For Tickets, the count is `ticketsSection`'s `hidden` input behind *show all*." That input is `fleet.waiting?.hidden` (`packages/board/src/app/components/AgentList.tsx:1797`). Its TSDoc says "How many open tickets the waiting read holds back" (`packages/domain/src/rules/tickets-section.ts:20-21`). The server's `waitingTickets` default sets it when it hides an unassigned ticket (comment at `AgentList.tsx:855-857`). The Mine chip does not set it, and it is non-zero with Mine `off` too. The Mine filter on tickets is `ticketsForReader` (`packages/board/src/app/lib/agent-rows/mine-filter.ts:279-284`), applied inside `waitingView` at `AgentList.tsx:864-866`. A reader with Mine off and no tickets of their own sees "No ticket waits for a plan · 4 hidden by Mine" and turns Mine off, and nothing changes. Read the plan, opened code. **Change to the plan:** in line 67, replace the Tickets sentence with: "For Tickets, the Mine count is the waiting tickets before `ticketsForReader` minus the tickets after it (the same call `waitingView` makes, `AgentList.tsx:864-866`). The read's own held-back count `waiting.hidden` stays in the host's `hiddenSentence` and is never counted as hidden by Mine." Add a unit cell: Mine `off` with `waiting.hidden = 3` answers hidden count 0.

2. **An empty Work items or Fleet section reads clear while its readings are unread.** The spec's anti-goal is *"Could not read" that looks like "empty"* (spec line 41). Placement puts an item or an agent in `unplaced` with reason `unread` (`packages/domain/src/rules/delivery-placement.ts:417, 455-456`). The spec's header rule says that then the You, Work items and Fleet groups "never [show] their clear form" (spec line 91). The plan's table gives Work items only one kind (line 58: clear at count 0), and Fleet clear for `up` with 0 agents (line 59). Suppose every agent of an up fleet is unplaced as unread. The header (plan 4) then shows "! 2 not read" under Fleet, and the open Fleet section shows green ✓ "No agent runs." on the same screen. Work items behaves the same way. Read the plan and spec, opened code. **Change to the plan:** add to the table: "You, Work items and Fleet: where `view.unplaced` holds an entry of reason `unread` for that section's subject (`item` for You and Work items, `agent` for Fleet), the empty kind is unread with 'N not read', never clear." Add one unit test per section for that case.

3. **"Hidden by the scope" cannot fire, because `wholeReadings` is already scope-filtered.** Line 37 answers `hidden: 'filter'` for an item "that the whole readings hold and the shown placement does not, because the scope or Mine hides it", with the reason "hidden by the scope". `deliveryMapping` gets `rows: filteredRows` (`AgentList.tsx:1172`), and `filteredRows` is the scope filter's output (`AgentList.tsx:830-832`). So `wholeReadings` (`delivery-readings.ts:460-471`) differs from the shown placement by Mine only. A jump to a row that the scope hides gets `null` or a non-hidden answer, and falls back to the section scroll with no reason shown. The fallback is visible, so the user loses only the reason. Read the plan, opened code. **Change to the plan:** either drop "or hidden by the scope" from line 37, or state that `anchorOwner` reads a scope-free placement over `fleet.rows` for the scope case, with its unit test.

4. **Minor, for the builder.** Line 71 cites `delivery-scope.ts:56-65` without a path. The file is `packages/domain/src/rules/delivery-scope.ts`, and `deliveryScope` spans `:50-62`. The You, Work items and Fleet count sources hold: Fleet rows are every agent placed into `working`, `blocked` or `free` (`delivery-placement.ts:374-376`), so `fleet.agents` minus `agentsForReader` equals the rows that Mine hides.
