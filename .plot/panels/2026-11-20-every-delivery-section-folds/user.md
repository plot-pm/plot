# user — every-delivery-section-folds

Position: amend

## Findings

1. **A jump into a folded section lands nowhere, and the plan makes six more sections foldable.** `scrollToAnchor` returns without effect when the target element is not mounted (`packages/board/src/app/components/DeliveryRows.tsx:20-22`). A folded section renders no groups or rows (`AgentList.tsx:1712`, `!folded && …`). Only Release delivery has a jump that opens the section first (`jumpToReleasePlan`, `AgentList.tsx:527-535`; `expandSection`, `:520-524`). After this plan, these controls do nothing when their target section is folded: the You count links (`AgentList.tsx:1575`), the phase-strip links (`:1588`), the summary links (`:1605`), the TodoList jumps (`:1541`), the held-switch "… ›" links (`:1735`), row anchor links into another section (`DeliveryRows.tsx:42-48`), and plan 4's header "open ›". To a user these are dead controls, which the spec's anti-goals forbid. Read and opened code. **Change to the plan:** add to Approach: "A jump to an anchor inside a folded section or group opens that section and group, persists the open state, and then scrolls, as `jumpToReleasePlan` does today. The mapping from anchor to section and group is a view property with a unit test per section." Add the same text to the slice line.

2. **The empty kinds take no input from scope or Mine, so a filtered section reads as clear.** The You and Work items rows come from `filteredRows` and the reader's Mine `mode` (`AgentList.tsx:1170-1176`). The `my-sprint` scope narrows them through `selection` (`packages/domain/src/rules/delivery-scope.ts:24-27`). Tickets hides others behind *show all* (`packages/domain/src/rules/tickets-section.ts:65-73`). The plan's table gives one sentence per section. That sentence states a false fact in three cases: Mine on or `my-sprint` with items outside the view ("Nothing waits on you" while 3 items wait in another sprint), Tickets with the reader's list empty and others behind *show all* ("No ticket waits for a plan"), and Release delivery under `my-sprint` ("No approved plan belongs to a release or sprint yet" while other sprints hold plans). The spec's scope × Mine table and its anti-goal ("could not read" that looks like "empty") apply. Read the plan and spec, opened code. **Change to the plan:** add a row or qualifier to the empty-kind table: "Where the scope or Mine hides rows, the sentence names the scope and the hidden count (e.g. 'Nothing waits on you in my sprint · 3 hidden by Mine'), and the frame shows the control that removes the filter." Add the input "hidden-by-filter count and scope kind" to `sectionEmptyKind`, and require a unit test for each of the four scope × Mine cells.

3. **The whole-row toggle swallows the controls in the header rows.** The You header holds count and phase-strip buttons (`AgentList.tsx:1575, 1588`). Other headers hold summary buttons (`:1605`). The Fleet heading holds the real switches and the stepper (`:1622-1629`), and they stay there until plan 5's `feature/fleet-switches-in-fleet-section`. Today only `ReleaseHeaderCounts` stops propagation (`ReleasePlanParts.tsx:73-77`). With a toggling row, a click on a Fleet switch also folds the section, and a click on a You count folds the section and then scrolls to nothing (finding 1). `releaseFold` wraps interactive children in a `role="button"` div (`AgentList.tsx:1514-1528`), which nests buttons inside a button for assistive technology. Read and opened code. **Change to the plan:** add "Every control in a header row stops click and key propagation. The 28 px button is the one element with `aria-expanded` and the accessible name. The row click is a pointer shortcut and carries no `role="button"`. A unit or browser test proves that a click on a header switch or count does not fold the section."

4. **Retry has no named target.** The board app has no retry control today (`grep -rn -i retry packages/board/src/app` finds nothing outside tests). The only refetch is `load()` (`App.tsx:573`). While a fleet runs, the board reads tickets from `issues.json` that fleetd writes and makes no `issue-list` call (CLAUDE.md, *A Decision Reads The Index*). A Retry that refetches the board then shows the same failure again: to the user it does nothing. Read CLAUDE.md, opened code. **Change to the plan:** name what Retry calls, what it shows while the call runs, and what it shows when the call fails again. If no call can re-ask the tracker in a fleet-run board, show Retry disabled with that reason, per "no hidden UI".

5. **Fleet and Machine have no kind, and the plan departs from the mockup without saying so.** The table gives Fleet "no agents" and Machine "no reading" with no kind. The mockup draws Machine with a fourth glyph `?` (`header-and-sections-v2.html:285-286`) and Release delivery with a faint `○` (`:174-175`), not the green ✓ the plan gives it. The Fleet stopped frame carries a "Start fleet" link (`:261`), and the board has no start-fleet controller (`FleetControls.tsx:37` is `/api/fleet-controls` only). The mockup keeps the switch row in the empty Fleet section (`:262`). The plan does not name which reading decides "stopped" (`fleet.supervisor`, `FleetAlert`, `AgentList.tsx:1706`). Read the mockup, opened code. **Change to the plan:** assign a kind to every table row ("no agents" = clear, "no reading" = stopped, or a named fourth glyph). State that the Start fleet link is dropped because no controller exists. State that the Fleet switches stay visible in the open-but-empty Fleet section. Name the supervisor field that decides "stopped".

6. **Not placed already has a toggle, and the plan adds a second one with the opposite default.** Today the footer "details" button (`AgentList.tsx:1858-1869`, `data-unplaced-toggle`) opens Not placed. Its state is `showUnplaced`, which defaults to `false` and is not persisted (`:684`). The section has no title (`:1768-1774`). The plan adds a `collapse.ts` key with every section starting open. Not placed would then show by default where today it is hidden, and the user would have two controls for one section. Read the plan, opened code. **Change to the plan:** state whether the footer "details" button is removed or becomes a jump to the section, state the section's title, and state its default fold.

7. **Some content renders outside the fold gate.** `WorkingCounts` and `FleetAlert` (`AgentList.tsx:1699-1708`) and `MachineSection` (`:1709-1711`) render without a `folded` check. Machine has no groups, so its count is 0 and it has no toggle today. The plan must say that folding hides these blocks, or which of them stays in the folded line. A user who folds Machine and still sees its meters reads the fold as broken. Opened code. **Change to the plan:** add one sentence that names these three blocks as fold content.

8. **The plan does not state when the frame shows and when the "— none" groups show.** The mockups draw the dashed frame alone when the section holds no row (`header-and-sections-v2.html:199, 222`), and "— none" groups when the section holds some rows (`:215, 247`). Read the mockup. **Change to the plan:** add "A section with zero rows shows the frame and no group. A section with at least one row shows every group, and an empty group shows '— none' and its hint."

9. **Minor, for the builder.** Browser tests take `[data-group-toggle]` `.first()` (`packages/board/test/integration/row-withholds.browser.test.ts:320, 357`) and will select another element once every section has a toggle. Two line references are off by one: the empty-group filter is at `AgentList.tsx:1712` and Not placed at `:1768`. `ticketsSection`'s `state` union is at `tickets-section.ts:32`, and `:57` is the function. The other references hold: `DELIVERY_LAYOUT` at `delivery-placement.ts:12-18`, and `collapse.ts:6,17,56,82,93-109`, and the test at `agent-list.test.ts:1410`. Opened code.
