## Findings

1. **Slice 2 restates a Mine rule that plans 5 and 7 build, and the rule differs from today's.** The plan's paragraph *Mine, per section* (plan:65) defines modes `mine` and `strict` for You, Work items, Fleet and Tickets, and slice 2 tests the empty kind and hidden count in each scope × Mine cell. Plan 5's slice `feature/delivery-you-rows-verb-first` builds `rowSprintMembership` "with the scope and Mine cells", and plan 7 builds `ticketIsMine`. Slice 2 has no `waits:` on either. Today's rule is different. `deliveryMapping` (`packages/board/src/app/lib/agent-rows/delivery-readings.ts:438-472`) keeps an unknown-owner item under You in every mode, strict included ("You lists the same items in every Mine mode, and the mode narrows Work items only", `:445-446`). `mineAllows` (`packages/domain/src/rules/delivery-placement.ts:302-304`) applies to tickets only ("no other item asks it"). Agents are filtered by `agentsForReader` (`AgentList.tsx:644`). So the plan's "Mode `strict` keeps today's narrower rule, `isMineStrict`" does not describe You today. A wait on plan 7 would form a cycle: plan 7 waits on plan 3, and plan 3 waits on this slice. OPENED. Change to the plan: delete the rule definition at plan:65 and point to plans 5 and 7 as its owners. Define the hidden count without reference to the rule, as the number of items in `deliveryMapping`'s `wholeReadings` (`delivery-readings.ts:471`) placed in the section minus the number of items shown there. For agents, use `workersHiddenByFilter` (`AgentList.tsx:879`). For tickets, use `ticketsSection`'s `hidden` input. Test the cells against today's modes. A test cell that depends on plan 5's rule belongs to plan 5.

2. **The jump list misses existing jumps, and an existing open-then-scroll mechanism.** Plan:35 says only `jumpToReleasePlan` opens a fold before it scrolls. `expandSection` (`AgentList.tsx:520-524`) does the same for `BlockedByMark`'s jump (`packages/board/src/app/lib/agent-rows/marks.tsx:325-355`), keyed on the legacy group word `'done'`. The plan's list also omits these jumps. App's reveal effect scrolls to `agent-row-<branch>` (`App.tsx:1273-1283`), and that row can sit in a folded Fleet or Work items section. The agent link lines use their own `scrollTo` (`AgentList.tsx:1253-1256`, used at `:1266`). `FleetCard`'s "Fleet controls ›" calls `onJump('fleet-controls')` (`FleetCard.tsx:64`, wired to `scrollToAnchor` at `AgentList.tsx:1550`) until plan 4 removes `FleetCard`. Row anchor links call the module-level `scrollToAnchor` directly (`DeliveryRows.tsx:47`), so the new jump must enter through `LinkHandlers` (`DeliveryRows.tsx:7-12`). OPENED and grepped. Change to the plan: name `expandSection` and `BlockedByMark` as callers the one jump replaces, and add the App reveal effect, the link-line `scrollTo`, `FleetCard`'s `onJump` and a `LinkHandlers.onJump` field to the list. `anchorOwner` must also cover `agent-row-<branch>` (`working-agents.ts:218`), the slice-row selector `BlockedByMark` uses, and Not placed's existing id `unplaced-details` (`AgentList.tsx:1769`).

3. **Not placed starts open for every reader who has a stored fold.** Plan:43-44 says Not placed "starts folded, so its default matches today's hidden one", through `COLLAPSED_BY_DEFAULT = ['free', 'not-placed']`. `readCollapsed` uses the default only when nothing is stored or no stored key is known (`collapse.ts:63-74`). A reader whose stored set is `["free"]` gets a set without `not-placed`, and the section opens on the first load after the change. Today the same reader sees it hidden. OPENED. Change to the plan: state how a key added to `COLLAPSED_BY_DEFAULT` reaches an existing stored set. For example, store the version of the key list and add the new default keys once, with a unit test for a stored `["free"]`.

4. **More tests pin the toggle the plan moves.** Plan:74 lists `release-delivery-fold.browser.test.ts` only. These also read `[data-group-toggle="release-delivery"]`: `agents-tab.browser.test.ts:1744,1874,1912` (its `aria-expanded`), `deliver-control.browser.test.ts:132` and `slice-status-speaks-verdict.browser.test.ts:57`. `plan-row-shows-plan-status-only.browser.test.ts:286-289` clicks the footer "details" and waits for `section[data-unplaced]` rows, which depends on the new jump opening the fold. `agent-list.test.ts:1384` pins `COLLAPSED_BY_DEFAULT` to `['free']`.
