# estate — every-delivery-section-folds

Position: amend

## Findings

1. **Retry has no mechanism to call.** The plan requires "Retry shows on every unread frame" (plan:49) and Retry on You and Tickets (plan:41,45). No Retry control exists anywhere in `packages/board/src/app` (grep for `retry`/`Retry` outside tests: 0 hits), and no `/api/*` route re-reads the tracker (the server route list has no refresh or issue-read route). The nearest existing mechanism is App's board refetch `load()` (`packages/board/src/app/App.tsx:573`), which `AgentList` does not receive as a prop. A client refetch also does not force a new tracker read where fleetd owns `issues.json`. RAN (grep). Change to plan: name what Retry does. Either pass App's `load` into `AgentList` and state that Retry refetches the payload and does not re-ask the tracker, or drop Retry from this plan and record that in the Open Questions. "No new data sources" (spec:33) rules out a new server read.

2. **Not placed already has a disclosure, and the plan's condition for it is wrong.** The section renders only when `view.notPlaced.length > 0 && showUnplaced` (`AgentList.tsx:1766`). `showUnplaced` is session state that the footer's "details" button toggles, with `aria-controls="unplaced-details"` (`AgentList.tsx:1858-1869`). The plan says "Not placed shows only when it has rows" (plan:32). That holds only after the reader clicks "details". A persisted section fold on top of the session toggle gives one section two controls that disagree after a reload. RAN (read). Change to plan: decide which control owns Not placed. Either the footer "details" becomes a jump that opens the section fold, with `showUnplaced` removed, or Not placed keeps its footer toggle and gets no section fold key. Name the choice in the slice line.

3. **Interactive controls inside the header row would toggle the fold.** The plan makes "the whole row toggle" on every section (plan:31). Today the section `h2` holds buttons: the You count links and phase-strip links (`AgentList.tsx:1575,1589`), the summary links (`:1605`), and in Fleet the real switches and the stepper (`:1624-1628`). None of them stops propagation. Only Release delivery's header counts do (`ReleasePlanParts.tsx:73-77`), because Release delivery is the one row that toggles today (`AgentList.tsx:1510-1531`). A click on Auto-dispatch in a toggling Fleet row would fold Fleet. RAN (grep `stopPropagation`). Change to plan: state that every control inside a toggling header row stops click and key propagation, as `ReleasePlanParts.tsx:73-77` does. Add a unit- or browser-level assertion that a switch click leaves `aria-expanded` unchanged.

4. **Fleet and Machine content renders outside the fold today.** `WorkingCounts` and `FleetAlert` (`AgentList.tsx:1699-1707`) and `MachineSection` (`:1708-1710`) have no `!folded` guard. Machine never folds today because its `count` is 0 (`delivery-view.ts:617`, `isCollapsible` at `collapse.ts:107`), so the gap is hidden. Once Machine folds, the fold hides nothing. `FleetAlert` at prominence `alert` is the sentence a person missed for an hour (`FleetControls.tsx:400-403`). Folding it away re-opens that defect. RAN (read). Change to plan: say that `MachineSection` and `WorkingCounts` render only when open. Say also that a `FleetAlert` with prominence `alert` stays visible when Fleet is folded, or moves into the folded summary slot.

5. **Fleet's empty kinds miss an existing state.** The plan gives Fleet "stopped when the fleet is not running; 'no agents' when it runs with 0" (plan:43). `SupervisorState` is `'up' | 'down' | 'unknown' | 'died'` (`packages/domain/src/rules/supervisor-reading.ts:58`), and `FleetAlert`'s doc requires that `unknown` reads as neither alarm nor all-clear (`FleetControls.tsx:408-410`). The plan does not map `unknown` or `died`. RAN (read). Change to plan: add the mapping to the table. Suggested: `down` → stopped, `died` → stopped with the alert's detail, `unknown` → stopped grey with the supervisor's `note` wording, never clear. Derive it from `supervisorVerdict` (`supervisor-reading.ts:388`) and not from new fields.

6. **Machine's "no reading" already exists under another word.** `machineHealth` returns grey `not measured` for headroom `unmeasured` (`packages/domain/src/rules/machine-health.ts:88-93,216-227`), and `MachineSection` always draws that line (`AgentList.tsx:21-26`). The Machine section is never empty in the row sense. RAN (read). Change to plan: state that Machine's empty kind is `machineHealth`'s `unmeasured` reading, drawn as the stopped kind and reusing its word, and that no second "no reading" vocabulary is added.

7. **Tests the plan does not name will change.** `release-delivery-fold.browser.test.ts:54-66` pins the Release delivery toggle as the row element with `data-group-toggle="release-delivery"` and the glyphs `▾`/`▸`. A 28 px button with a rotating `▸` changes both. The unit test at `agent-list.test.ts:1410-1422` is named correctly in the plan. Group toggles (`[data-group-toggle="queued"]`, `"unblock"`) are pinned in `quiet-kinds-render.browser.test.ts:85,264` and `group-activity.browser.test.ts:134,365`. Sections and groups share the one attribute and one key set (`collapse.ts:6`). RAN (grep). Change to plan: list `release-delivery-fold.browser.test.ts` as updated, and state whether section toggles keep `data-group-toggle` or take a new attribute such as `data-section-toggle`, so that group selectors stay unambiguous.

8. **References that hold, with small offsets.** `DELIVERY_LAYOUT` is at `delivery-placement.ts:12-18` (holds). `KNOWN_KEYS` is at `collapse.ts:6`, `COLLAPSED_BY_DEFAULT` at `:17`, `readCollapsed` at `:56`, `writeCollapsed` at `:82`, and the `isCollapsible` comment and body at `:93-109` (all hold). `ticketsSection` is at `tickets-section.ts:57`, with the `state` union as stated (holds). Its `rows` state with zero rows is the "clear" case. The plan should say so, because no `empty` state exists. The empty-group filter is at `AgentList.tsx:1712`, not `:1711` (the line the spec cites). The Tickets render is at `:1792` and the `unasked` sentence at `TicketsSection.tsx:82` (holds). `TICKETS_ANCHOR` sits on the `<section>` (`TicketsSection.tsx:55`), so `#tickets` survives a fold. RAN (read).

9. **No duplicate of the proposed builder exists.** No `sectionEmptyKind`, `emptyKind` or equivalent exists in `packages/board/src` or `packages/domain/src` (grep: 0 hits). The group hints the "— none" rows need already exist in `GROUP_LABELS` (`delivery-view.ts:66-76`) and reach the view as `GroupView.hint` (`:252`). Today the only decision in `.tsx` about an empty kind is `TicketsSection.tsx:82`, which the new view property should absorb. RAN (grep).

10. **Jump links into folded sections.** Only Release delivery opens its fold before scrolling (`jumpToReleasePlan`, `AgentList.tsx:527-535`). `scrollToAnchor` returns silently on a missing id (`DeliveryRows.tsx:20-22`). Group anchors (`groupAnchor`, rendered only when the section is open, `AgentList.tsx:1747`) and the `fleet-controls` target of held-switch links (`:1740`) fail silently when their section is folded. More sections fold after this plan, so the gap widens. RAN (read). Change to plan: generalise `jumpToReleasePlan` to open the owning section's fold before scrolling, for every jump into a section.
