## (a) Problem statement

- Cited lines check out at this tree: `App.tsx:542` (`if (tab !== 'delivery') return;`), `:772` (visibility guard), `:1524`, `:1537`, `:1597`, `PlanSourceLine.tsx:145`, `schema.ts:4285` (`ageSeconds`), `schema.ts:1473` (`planSource`).
- One citation is wrong: the Approach says the Planning tab fetches `/api/board` on its own poll "(`load`, `App.tsx:772`)". Line 772 is the visibility handler. The poll is `App.tsx:528-532` (`setInterval(load, POLL_MS)`, `POLL_MS = 30_000` at `:48`), and `load` is defined at `:407`.
- **The cause of the age defect is misnamed in one respect.** The plan says `ageSeconds` "dates a different read from the one the sentence describes". The component's own contract says the opposite on purpose: `PlanSourceLine.tsx:53-58` documents that "the scan and this read see the same refs, and the scan is what fetches them, so its age dates this too". That is correct. `/api/board` reads `origin/<default>` as a local ref on every request (`board.ts:2192`, `collectPlanSources` with `origin/${defaultBranch}`), so the board's read is always at most one poll old. What actually dates the plan content is the last `git fetch` of that ref, and the fleet scan runs it (`plot-fleet-scan.sh:385`; `fleet.ts:2708-2710` "Default mode, WITH the fetch"). So the fleet's scan age is the right *event*. The defect is the *transport*: the value reaches the Planning tab only through the Delivery-only `/api/fleet` poll, and nothing ticks it.
- **A second, smaller cause the plan does not name:** the page reads `fleet.ageSeconds`, which `buildFleet` sets to `0` when no scan has landed (`fleet.ts:7506`; probe output `ageSeconds 0`). On a cold server with no bridge seed, a Delivery visit therefore makes the Planning line print `· 0s ago`, the exact claim the plan forbids. The fleet already carries the honest field, `readRefAge` (`fleet.ts:7658`, `schema.ts:4317`, null before the first scan). The page picked the wrong one of two existing fields.
- **The server already warms the value on the Planning path.** `/api/board` calls `ticketLaneData(opts)` unconditionally (`index.ts:493`, also via `discoveryLanes`, `discovery-lanes.ts:49`), and `ticketLaneData` opens with `ensureCache(opts)` (`fleet.ts:1703`). `ensureCache` seeds `entry.at` from the bridge and starts the 5 s scan pulse (`fleet.ts:2982-3040`). So a Planning-only page keeps the scan, its fetch, and `entry.at` current with no `/api/fleet` request. The plan's statement that a server field "needs a new optional field" is right; it costs one property read on an entry the handler already holds.

## (b) Approach, and the two open questions

**Open question 1 (which event "Ns ago" dates): the fetch of the ref, carried as a new optional board field. Not `generatedAt`.**

- `generatedAt` is `new Date()` at the end of `buildBoard` (`board.ts:2659`), and `boardState` shares one in-flight build between concurrent callers (`fleet-state.ts:196-250`). An age from it measures "time since the page last polled", which runs 0-30 s and resets on every poll. It says nothing about how old `origin/main` is: a board whose fleet scan has failed to fetch for an hour would still print "· 12s ago". It answers a question the page already answers elsewhere (the unreachable banner).
- `entry.at` is set when a scan completes (`fleet.ts:2879`), or to fleetd's bridged scan time when fleetd owns the scan. Both scans fetch. That is the event "Plans read from `origin/main`" depends on.
- Carry it as a relative age computed on the server, in the shape the Delivery tab already uses: server age in seconds at response time, plus a client tick that resets on each payload and stops while the poll is failing (`AgentList.tsx:577-601`). Do not compute `Date.now() - Date.parse(generatedAt)` in the browser: the board serves remote viewers (`server.hostUser`, "the board serves a team" sprint), and a client-clock subtraction adds clock skew to every reading. No client code parses `generatedAt` today (grep over `packages/board/src/app` and `packages/domain/src`: 0 hits).
- Proposed field: `planSource.readAgeSeconds: z.number().nullable().optional()` (or a top-level `planSourceAgeSeconds`), filled in the `/api/board` handler from `ensureCache(opts).at`, `null` when `at === null`. Attach it in `index.ts` next to `ticketData`, not inside `buildBoard`: `index.ts:520-523` records that `boardState` has no dependency on the `fleet.ts` cache, and the mock estate goes through `boardState` unmodified. Expose a one-line reader from `fleet.ts` (e.g. `refsReadAt(opts)`) rather than reaching into `CacheEntry` from `index.ts`.
- **Older server:** the client casts and never parses the payload (`PlanSourceLine.tsx:44-50` states this), so an absent field arrives as `undefined`. The domain rule must treat `undefined` and `null` alike, and print no age. An older client ignores the extra field. No `.default(0)` in the schema: a default would never run on the client and would say "just read" on the server side.
- **Stop the tick** when `/api/board` is unreachable (`boardUnreachable`, `App.tsx:382`) or failing (`boardFailures > 0`), the rule `AgentList.tsx:584-594` already states for the fleet.
- **A new question the plan should carry: a failed fetch.** `fleet.ts:2879` moves `entry.at` whether or not the scan's `git fetch` succeeded. The scan reports `fetch_failed`/`fetch_error` in `--json` (`plot-fleet-scan.sh:159, 383-393`), but nothing in `packages/board/src` or `packages/domain/src` reads it (grep: 0 hits). So any age built from `entry.at`, including today's fleet `ageSeconds`, claims a fresh read of a ref that was not refreshed. Either carry the fetch time separately, or state this limit in the plan and file it.

**Open question 2 (plan file for a sprint slug with no card): no new field. The board payload already answers it, and the fleet fallback adds nothing measurable.**

- The board's cards already cover every source the fleet fallback reads. Cards come from the ref, from working-tree-only plans (`localOnly`), and from plans on branches under `Branch prefixes` (`board.ts:2250-2287`). `fleet.draftPlans` is "every plan at Draft in the working tree" (`schema.ts:4560-4569`), which the local-only cards include, and fleet rows name plans on branches, which the branch-plan cards include. `/plan/<file>` resolves the same three sources (`board.ts:3080-3115`).
- The server already marks a slug with no card: `collectSprints` sets `known: false` for any member not in the card slugs (`board.ts:1645-1654`, called with `new Set(cards.map((c) => c.slug))` at `board.ts:2654`; `schema.ts:867`), and `SprintModal.tsx:209` draws a `?` badge for it. The modal still renders that member as a button (`SprintModal.tsx:177`), so the click goes to the fleet fallback.
- Measured: 16 sprint members on `origin/main` name no plan on the ref or on any branch. All are renamed or unwritten plans in W36-W39 sprints. 0 members name a branch-only plan, and the active sprint has none. The fleet cannot name a file for a renamed slug either, so for every measured case the fallback returns `''`.
- The fallback can differ from the board only in edge cases: `collectBranchPlans` failing silently (`board.ts:2288-2292`, catch with no report) while the scan succeeds, or a branch plan that appeared within the last 30 s board poll. Neither justifies a second Planning-tab source.
- So the fix is: drop `planFileFromFleet` from the sprint modal, and let `known: false` decide that the member is not a button (text plus the existing `?` badge, or a disabled control with "Plan not found in board"). That is a domain property already on the payload, which "Every rendered state is a domain property" asks for. This reverts the fleet half of `60528c93c` (#2641). The comment it replaced said the same thing: "there is no `/plan/<file>` path to fall back to". `AgentList.tsx:564` keeps its own `planFileFromFleet` use, which is a Delivery-tab read and correct there.
- If the plan wants a slug whose card is missing for a transient reason to still open, the honest version is the board's own data: `planFileForSlug(allCards, slug)` (`plan-level-row.tsx:92-98`) already exists. It needs no new field.

**Rules.** Both answers comply with "A Decision Reads The Index": neither adds a host call. The age reads an in-memory scan timestamp the handler already holds. The sprint answer reads a payload field. The layering holds if the age is attached in `index.ts` and the age rule (absent → null, tick, stop when stale) is a domain function.

## (d) Open questions

1. **Answered:** date the fetch of the ref (`entry.at`), carried as a server-computed optional age on `/api/board`, ticked on the client from each payload and stopped while the board poll fails. `generatedAt` dates the poll, not the plans.
2. **Answered:** no new field. Cards already cover the fleet's sources, `known: false` already marks the missing slug, and the measured cases (16 of 16) are slugs no source names. Remove the fleet fallback and render a `known: false` member as text, not as a button.
   Sub-question "does a slug with no card exist for any other reason": yes, two transient ones. `collectBranchPlans` fails silently (`board.ts:2288`), or a branch plan is less than one board poll old. The measured cases are all renamed or unwritten plans.
3. **Partly answered from the server side:** `grep -n fleet App.tsx` shows `planAgeSeconds` (`:1524`, `:1537`) and the sprint fallback (`:1597`) as the only Planning-tab reads of `fleet`. The rest are Delivery-gated (`:1385-1393`, `:1215`, `:801`) or comments.

New questions the plan should carry:
- Does the age dim, freeze or vanish while `/api/board` fails? The Delivery footer freezes and labels it "(frozen)" (`AgentList.tsx:2734`). The Planning line needs the same rule.
- What does the line print after a failed fetch? Today nothing tells it apart from a successful one (see (b)).
- Should the Delivery footer move off `ageSeconds` (0 before a scan) to `readRefAge` for the same reason? That is out of scope here, but it is the same defect.

## (e) Tests

- **Domain unit** (`packages/domain`): `planSourceAge(serverAge: number | null | undefined, tick: number, stale: boolean): number | null`. `undefined` → null, `null` → null, `0` with tick 5 → 5, stale → frozen value (or null, whichever the plan decides), and it never takes a fleet argument.
- **Board unit** (`packages/board/test/unit`): the `/api/board` handler, or the exported reader, gives `null` for a fresh entry (`freshCacheEntry().at === null`, which the probe confirmed) and seconds since `at` for a seeded entry. The handler must not start a second `ensureCache` (it reuses the one `ticketLaneData` opened).
- **Board unit**: a `known: false` sprint member gets no plan action. `sprint-members.test.ts` is the existing home for member parsing; the "is it actionable" decision should be a function there or in the domain.
- **Browser** (`plan-source.browser.test.ts`, which has nine cases and none about age): a fresh `?tab=planning` page with a mock board that carries the age shows `· Ns ago`, and the number grows between two ticks with no `/api/fleet` request (assert the route was never hit). A payload without the field shows no age. A stubbed `/api/fleet` with a frozen `ageSeconds: 999` is visited and left, and the Planning line never shows 999.
- **Browser** (`plan-link-click.browser.test.ts`, which already opens a sprint modal at `:311`): a `known: false` member is not clickable on a fresh page or after a Delivery visit.
