## Findings

1. **The Mine rule names the wrong type, so the planned test can pass without proving anything.** Plan line 48 says the groups read "a placement built with the Mine mode `off` (`DeliveryMine`, `delivery-placement.ts:32`)". The Mine filter does not act through `DeliveryMine`. It acts in `deliveryMapping`, which narrows the rows by the board's `MineMode` (`'all' | 'mine-and-unknown' | 'mine'`, `packages/domain/src/rules/mine-mode.ts:12`) *before* the placement runs (`packages/board/src/app/lib/agent-rows/delivery-readings.ts:461-470`). `DeliveryMine` is derived from it afterwards (`MINE` map, `delivery-readings.ts:143`: `all → off`). A placement built with `mine: 'off'` over rows that `deliveryMapping` has already narrowed still follows Mine. A `deliveryHeader` unit test over one fixed placement, with `off`/`mine`/`strict` as the only variable, cannot detect that. The existing precedent is `deliveryMapping({ ...input, mode: 'all' })` in `sprintCardViewOf` and `releaseCardsOf` (`delivery-readings.ts:541,571`). The scope's narrowing comes from `filteredRows` (`AgentList.tsx:830-832`), not from Mine. The plan's heading also says "Mine mode `all`" while its body says `off`. Ran sed. **Change:** In plan line 48, replace "a placement built with the Mine mode `off` (`DeliveryMine` …)" with "a placement over `deliveryMapping({ ...input, rows: <scope-filtered rows>, mode: 'all' })`, as `releaseCardsOf` does (`delivery-readings.ts:571`)". Put the equality test at the agent-rows level, varying `MineMode` over `all`, `mine-and-unknown` and `mine`.

2. **`releaseStatusLine` and "ReleaseApprove reused unchanged" contradict each other.** Plan line 81 has `releaseStatusLine(group, prReading, passkey, now)` decide the text and the button state. Plan line 84 asks for a dashed outline and has the reason shown as the status line. `ReleaseApprove` decides on its own. It reads the passkey in its own `useEffect` (`ReleaseApprove.tsx:19-21`) and computes `releaseCardApprovable` itself (`:24`). It renders its own reason span (`:51`, `data-testid="release-approve-reason"`) and uses the class `delivery-approve` (`:47`). If the component is reused unchanged, two decisions are made and the reason is printed twice. The passkey also stays out of reach of the domain function, so the "passkey unread" test has no input. Ran sed. **Change:** In plan line 82, say that `ReleaseApprove` takes its enabled state and its reason from `releaseStatusLine`, that the passkey read moves to the header, that its reason span is dropped in favour of the status line, and that the dashed outline is a `.delivery-approve:disabled` rule in CSS. Keep "no controller and no refusal changes".

3. **Four test files that pin the removed components are not listed.** `integration/sprint-exempt.browser.test.ts:168,174` asserts `[data-release-card="untargeted"]` and `[data-sprint-card-sprint]`. `unit/delivery-link-icons.test.ts:9-10,86` renders `TodoList` and `ReleaseCard`. `unit/release-plan-parts.test.ts:8` imports `SEGMENT_CLASS` from `SprintCard.js`, so it breaks when the word maps move. `catalogue/states.ts:892,905` describes the header as "the ReleaseCard and the *Approve release* to-do". Ran grep over `packages/board/test`. **Change:** Add `delivery-link-icons.test.ts` to the Slice 1 list. Add `sprint-exempt.browser.test.ts`, `release-plan-parts.test.ts` and `catalogue/states.ts` to the Slice 2 list. For each file, say whether it is rewritten or moved.

4. **`lastRelease` must parse both record forms the estate holds.** Plan line 85 calls the record `Released: <date>, vX.Y.Z` and skips "an unparseable record". Over `docs/plans/`, 483 records read `YYYY-MM-DD, vN.N.N`, 210 read `YYYY-MM-DD, N.N.N` with no `v`, 1 reads `vN.N.N-beta.N` followed by prose, and 1 is the template comment. A parser written to the plan's stated form skips 210 real releases. With today's data it would still pick the right release (2026-11-19, v2.35.0), but only by chance. `normalizeVersion` already exists (`packages/domain/src/entities/version.ts:25`) and `releaseCards` uses it. Ran grep with digit classing. **Change:** In plan line 85, state that `lastRelease` accepts `vX.Y.Z` and `X.Y.Z` through `normalizeVersion` and orders by semver, with a pre-release below its release. Add a unit test for a bare-version record and for trailing prose after the version.
