## Findings

1. **"last vX.Y.Z <date>" has no data source, which contradicts "No new data sources".** The plan's *No release targeted* bullet asks for the last released version and its date. The `none` card of `releaseCards` carries `version: ''`, `bar: null` and `stateText: ''` (`packages/domain/src/rules/release-card.ts:185-198`). A grep of `packages/board/src/contract/schema.ts` finds no last-release, tag or released-at field; the only `version` field is the release row's branch `package.json` version (`schema.ts:2736`). The plan's own *No new data sources* bullet names only the machine readings, so the gap is never stated. Ran grep. **Change:** either name the new reading (git tag plus date, where the board reads it, and which adapter reaches it) as part of the slice, or drop "last vX.Y.Z <date>" from the plan and state that the spec line is deferred.

2. **The segment bar has five states, and the plan names four.** The plan's Release row lists "delivered / at gates / blocked / not started". `SLICE_STATES` is `['delivered', 'blocked', 'at-a-gate', 'being-built', 'not-started']` (`packages/domain/src/rules/slice-states.ts:9`), and every bar `releaseCards` and `sprintCards` build has five segments (`release-card.ts:52`, `sprint-card.ts:73`). The plan copies the spec's table (spec line 74), which has the same omission. Ran grep. **Change:** say the bar and legend keep the five `SLICE_STATES` segments, `being-built` included, or name the decision to merge `being-built` into another segment and the rule that does it.

3. **The Mine filter changes the readings the header would reuse.** The plan says "The Mine filter does not change the header". In `AgentList.tsx:1189-1195` the header's `placement` is `placeDelivery(mapping.readings, mapping.input)`, and `deliveryMapping` applies the Mine `mode` (`AgentList.tsx:1170-1178`). `TodoList` and `FleetCard` read that placement today, so their counts follow Mine. Only `releaseCards` reads "in Mine mode `all`" (`release-card.ts:114`). Read code; not run. **Change:** state that the You, Work items and Fleet groups read a placement built with mode `all` under the scope selection, and that a unit test asserts equal header counts for every Mine mode.

4. **The plan removes components that other code imports, and it does not say what stays.** `SprintCard.tsx` exports `SEGMENT_CLASS` and `SEGMENT_WORD`, which `ReleasePersonCards.tsx:2` and `ReleasePlanParts.tsx:5` import. `ReleaseCard.tsx:4` holds `ReleaseApprove`, which the new release slot needs. `readOnly` on `AutoDispatchSwitch` (`FleetControls.tsx:79-115`) and on `AutoSwitch` and `ParallelAgentsStepper` has `FleetCard` as its only caller, and it emits `data-fleet-card-auto-dispatch`. Ran grep. **Change:** state that the segment class and word maps move or stay, that `ReleaseApprove` is reused unchanged in the slot, and that the `readOnly` branches of `FleetControls.tsx` leave with `FleetCard`.

5. **Browser tests pin the current header, and the plan names only the count test.** `delivery-tab-header.browser.test.ts:37-82` asserts two columns at 1280 px, stacking at 767 px and the to-do grid rows. `fleet-settings.browser.test.ts:333-338` asserts `[data-fleet-card]` and the read-only `data-fleet-card-auto-dispatch` and `data-fleet-card-parallel-agents`. `release-approve.browser.test.ts:55-59` locates the button through `[data-release-card-version="2.7.0"]`. `delivery-tab-screenshots.browser.test.ts` reads `--delivery-section` from `[data-tab-header]` (`delivery-header.css:5`). Unit tests `fleet-card.test.ts` and `todo-list-markup.test.ts` render the removed components. Ran grep. **Change:** list these files in *Board tests*, and say for each one whether it is rewritten, moved into a unit test or removed. `stubbed-tests-start-no-board.test.ts` already records the 2026-11-19 additions to `delivery-tab-header.browser.test.ts` (lines 563 and 949), so its count changes too.

6. **The parallel-agents value leaves the header with no statement.** `FleetCard` shows `ParallelAgentsStepper` read-only today (`FleetCard.tsx:60`). The plan's Fleet marks list four switches only. Spec goal 10 names "(and parallel agents)" among the real switches and lists four marks in the header (spec lines 27 and 77). The plan follows the spec, but the regression is not stated. Read code and spec. **Change:** state that the header drops the parallel-agents value, or add it as a number beside the marks.

7. **Existing helpers the plan does not name.** "oldest wait" already exists as `oldestWaitsClause` and `oldestAgeMinutes` (`packages/domain/src/rules/delivery-work-columns.ts:57-68`). The Work items numbers already exist as the groups `at-a-gate`, `being-built` and `queued` (`delivery-placement.ts:15,25`). `machineHealth` is at `packages/domain/src/rules/machine-health.ts:216` and is wrapped in `packages/board/src/app/lib/agent-rows/machine-health.ts`. Its buckets `graphql` and `core` map to the labels GraphQL and REST (`machine-health.ts:103-104`), so the meters need no new source. The fleet states that the plan calls "circles coloured by state" are `fleetCard`'s `free`, `working` and `blocked` (`fleet-card.ts:24-31`). Ran grep. **Change (minor):** name these as the inputs so that the builder does not rebuild them.

8. **References that hold.** `AgentList.tsx:1537-1552` holds the three widgets. `AgentList.tsx:1624-1628` holds the real switches. `FleetCard.tsx:3` imports from `FleetControls.tsx`. `DeliveryScopeKind` is at `delivery-scope.ts:8`. `NO_RELEASE_TARGETED` is at `release-card.ts:37`, `releaseCards` at `:117` and `releaseCardApprovable` at `:209`. `sprintCards` is at `sprint-card.ts:154`, `todoList` at `todo-list.ts:103` and `fleetCard` at `fleet-card.ts:24`. `delivery-header.css` exists. The disabled reason for the `none` card is `unboundReason: 'no release PR exists'` (`release-card.ts:197`), which `releaseCardApprovable` returns. Plan 1's slice `feature/delivery-tuples-in-every-row` exists (`2026-11-20-delivery-link-tuples-everywhere.md:56`), and plan 5's Fleet slice waits on this one (`2026-11-20-delivery-rows-act-from-one-place.md:80`). `releaseCards` already builds one card per version.
