## HIGH

**H1. The SDK `env` option replaces the child's environment, so the waiting gate's part 1 strips PATH and HOME and the plugin gates fail open.** The plan passes `env: { CLAUDE_CODE_DISABLE_BACKGROUND_TASKS: '1' }` and says this is safe because it is "not a settings `env` key". `sdk.d.ts:1646-1650` reads: "When set, this value REPLACES the subprocess environment entirely — it is not merged with `process.env`. Spread `process.env` yourself if the subprocess still needs inherited variables like `PATH`, `HOME`". `packages/domain/src/rules/agent-settings.ts:112` refuses a settings `env` for exactly this consequence: "a PATH hiding their tools makes them fail open (measured 2026-09-30: plot-state-gate.sh allowed a State: change and exited 0)". The child also loses `PLOT_UNATTENDED`, `PLOT_AGENT`, `PLOT_SCRIPT_DIR` and the `PLOT_*` names that `.plot/worker-prompt.sh` reads today. The slice 1 Done-when ("`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` in `env`") passes on the defective form. Fix: the adapter passes `{ ...process.env, CLAUDE_CODE_DISABLE_BACKGROUND_TASKS: '1' }`, and a test asserts that PATH and the `PLOT_*` variables reach the child. (Command: `grep -n` in the fetched `sdk.d.ts`.)

**H2. Per-run spend lines double-count a resumed session, and the existing record cannot hold them.** The plan resumes the session for `checks` and for every CI correction, appends one line per run with `total_cost_usd` and `modelUsage`, and has slice 2 sum the run lines per branch. `sdk.d.ts:5679` says `total_cost_usd` shares `modelUsage`'s lifecycle and "a resumed or forked session continues from the total its transcript saved … (so the first result already carries the earlier turns …)". So a sum over the lines of one resumed session counts each earlier run again. `sliceSpendRefusal` and `Slice max spend` then trip early, in the direction that stops work. The record shape also refuses the planned line: `packages/domain/src/entities/slice-spend.ts` declares `SliceSpendSchema` `.strict()` with `branch, at, tokens (one summed TokenCounts), turns, models`. It has no role, no session id, no cost and no per-model tokens, so `decodeSliceSpend` returns null for the new line and readers count it `unreadable`. The reader is the domain, not only "the board's spend reader": `rules/slice-spend-record.ts:84` returns `latest: history.at(-1)`, the newest line as "what the branch cost on its last run", and `rules/plan-spend.ts:82` builds on it. Fix: name the schema change and its version, key run lines by session id and keep the newest per session before summing across sessions (or store per-run deltas), and move the change into `readSpend` and `planSpend` with their tests. (Commands: `git show origin/main:` on the three files; SDK text from reading the fetched package.)

**H3. "Every fleet agent run" covers fewer than half of the board's agent starts.** `grep -rEn '(spawn|execFile…)\s*\('` over `packages/board/src` on origin/main, outside `adapters/`, lists `sh -c` agent starts at `idea.ts:711`, `commission.ts:407`, `reslice.ts:464`, `story.ts:504`, `brief-ask.ts:116`, `implement.ts:233`, `interrogate.ts:321`, and also `deliver.ts:550` (an `Idea command` run, the same shape as commission and reslice), `approve.ts:373` (`Approve command`), `auto-deliver.ts:432` (`Deliver command`, `auto-deliver.ts:78`) and `continue.ts:563` (`Worker command`). Slice 3 and its Done-when grep name the first seven only, and the Board-impact comment says "five". The shell path `plot-dispatch.sh:571` (`brief_command`, `Brief command`) also starts an agent and is not covered. `continue.ts` matters most: `a-spent-correction-budget-gets-a-fresh-agent` starts its fresh agent through "the registry tick's continue", which slice 2 reuses for `turns-spent` and `spend-spent`. Fix: list every agent-starting site with its key, and either move each one or name it as out of scope with the reason. The Summary's "Every fleet agent run" must match the list. (Command output above.)

**H4. The plan adds `Agent models` and `Agent context window` beside a charter that already declares both.** `packages/domain/src/entities/charter.ts:104-118` declares `harness`, `model`, `effort`, `capabilities` and `bounds.{contextCeiling, contextWindow, atCeiling}`. `.plot/worker-prompt.sh:136-144` runs the charter's `PLOT_HARNESS`, `PLOT_MODEL` and `PLOT_EFFORT`. The plan's request carries "the charter's capabilities" only. Its model lookup ("its entry, then `PLOT_MODEL`, then the CLI default") never names the charter, and it drops `effort` entirely. That leaves two sources for one fact, and nothing says which one wins. The charter's own doc says a model-to-window table "is refused" because "a declaration is a fact a person wrote". `Agent context window` (an auto-compact size) is a second window number beside `bounds.contextWindow` (a ceiling denominator), with no stated relation. Fix: the request reads model, effort and harness from the charter; `Agent models` applies only to the board roles, which have no charter, or is dropped; and the plan states how `autoCompactWindow` relates to `bounds.contextWindow`. (Reading only, plus `git show` of the files.)

**M3. The budget entry has no field for `utilization`, and the plan does not map the usage-limit ending.** `entities/budget.ts` declares `BudgetEntry { key: {connector, account, bucket}, at, spent, limit, remaining, resetAt, basis }`, with `basis ∈ actual|predicted|unknown` (`entities/limit.ts:26`).
