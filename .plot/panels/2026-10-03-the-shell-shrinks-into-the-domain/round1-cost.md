## What must change

1. **Slice 3 (Approach, "Slice 3 answers #1245") must keep a no-`node` fast path, and the plan must say so.** The controller gate costs 19-21 ms per Bash call today because it exits at `[ -n "$named_script" ] || exit 0` (`plot-controller-gate.sh`, after the token loop) without starting `node`. A slim bundle adds 27-30 ms per start and a plot-ask-sized one adds about 52 ms at the measured load. If the hook asks the rule on every Bash call, the controller gate goes from about 20 ms to 50-75 ms, and the four hooks together from about 68 ms to 100-120 ms on every tool call of every agent, the 14 live worker loops included. The same file already sets the pattern at line 159: "two cheap shell readings stand before any `node` start". The amendment: a `case` substring test for the three basenames (no word splitting, so no glob expansion) gates the `node` call; only a command whose text names a gated script reaches `controllerInvocation`. That keeps today's cost on the common path and still sends every #1245 false positive to the rule. Open Question 3 then becomes a recorded number for the rare path, not a design risk.
2. **Slice 3 must state what a missing bundle or a missing `node` does.** `plot-controller-gate.sh:71` sets `trap 'exit 0' ERR`, so a failed `node` start fails open: the gate turns off with no message. The sibling plan `a-branch-carries-no-built-bundle` (Approved, slices 1-2) removes bundles from PRs and builds them on `main` after the merge, "about 3-5 min" later per its Board impact comment. In that window, and on any desk that has not built, a new hook bundle is absent. The plan must choose fail-open or fail-closed, name it, and test it. The same applies to slice 4's launcher: under the sibling plan, `main` holds the launcher before it holds the bundle, so every caller fails for 3-5 minutes after the merge. Slice 4 must either keep the `.sh` body as the fallback until the bundle exists, or be ordered after the sibling plan's slice 1 with that window named.
3. **Slice 1 (Approach, "Slice 1, the ratchet") must state the refusal rate and the path for an urgent shell fix.** On the last 14 days of `main`, 76 of 85 commits that touched shipped shell code grew it, 22 of them by 10 lines or fewer. Under this ratchet each of those is refused unless it removes lines elsewhere or moves a rule into the domain. Both open shell PRs would be refused if slice 1 merges first: #1234 (+37, a bug fix) and #1244 (+19, the PR the plan names as its first instance). The plan says "no exemption list" for slice 3 and is silent for slice 1. The plan must say one of: (a) a fix pays in the same PR, accepted cost, with the 76-of-85 figure; or (b) a named, counted override, for example a commit trailer naming an issue that CI reports. It must also say what happens to #1234 and #1244, for example that slice 1's baseline is taken after they land.
4. **Slice 1 must not store the baseline as a number in the script.** Every PR that lowers the count edits the same line, so any two concurrent shrinking PRs conflict on it; with a fleet running parallel slices, that is the common case, and the sibling plan measures each conflict repair at about 20 minutes because one `validate` run takes 16-18 minutes. A comparison against the merge base (`count(HEAD) <= count($(git merge-base HEAD origin/main))`) stores nothing, never conflicts, needs no "lower the baseline in the same PR" bookkeeping, and refuses exactly the same growth. CI already checks out with `fetch-depth: 0` (`ci.yml:75`, `ci.yml:117`). The `check-helper-table.sh:108` precedent (`BASELINE=31`) is a missing-row count that rarely moves; a line count moves on most PRs.
5. **"Further slices" (Approach) must name an end, and the plan's cost per slice.** 58 scripts, one per amendment, makes this plan open-ended: each amendment re-enters review, and each slice costs at least one 16-18 minute `validate` run plus a bundle (until the sibling plan ships, a bundle is also a new merge-conflict source for every open PR). The plan must state that it delivers after slice 4 and that each later script is its own plan or its own amendment, and say which, so that the operator's attention per script is a known number.
6. **Slice 2 (Approach, "Slice 2, the inventory") must not add a second per-script table with no gate.** `skills/plot/scripts/README.md` already holds one row per script (62 rows) and `scripts/check-helper-table.sh` gates it. ## What holds

- The ratchet's own CI cost is negligible: the count takes 0.044 s.
- The node dependency the launchers add is not new: 27 of 58 shipped scripts already start a bundle, so adopting repositories already need `node`.
- Hook paths stay stable: "What does not change" keeps the file names registered in `hooks/hooks.json` (four `${CLAUDE_PLUGIN_ROOT}/skills/plot/scripts/*.sh` entries), and adopting repositories install the plugin by version into `~/.claude/plugins/cache/plot-marketplace/plot/<version>`, so a launcher plus its bundle reaches them only through a release, which the sibling plan's release job checks for freshness.
- Running workers are not exposed mid-run by a merge to `main`: they execute `skills/plot/scripts/plot-worker-loop.sh` from their own desk, so a script becomes a launcher for a worker only when its desk resets to `main`.
- The cost rule (39 ms per `node` start, `docs/shell-and-domain.md`) holds on this machine under load: 24-30 ms for `node -e ''` and a small bundle, about 52 ms for a 528 KB bundle. The plan keeps that rule for per-pass call sites and leaves `plot-worker-loop.sh` as an open question, which is honest.
- The slice order holds for cost: the gate lands before the migration, and slice 4 lowers what slice 1 counts.
