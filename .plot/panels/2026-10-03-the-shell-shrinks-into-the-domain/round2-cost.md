## What must change

1. **Slice 1 (Approach, "Every change pays for the shell it adds") must say what a revert does.** The gate has no override, and `git revert` of any change that shrank the shell grows the count by the same amount. The revert of a broken slice 5 is the clearest case: it restores the `.sh` body the launcher replaced, so CI refuses the rollback unless the revert also removes the same number of lines elsewhere. A revert is the urgent fix this ratchet blocks hardest, because a revert cannot offset without becoming a new change. The plan must choose and state one of: (a) a revert pays like any change, accepted, with that cost named; or (b) the gate compares a commit whose subject is `Revert "<subject>"` against the reverted commit's parent count, which is a rule the gate checks and not an environment switch. Either answer is one sentence; silence leaves the decision to whoever is on call.
2. **Slice 4 (Approach, "Slice 4 brings the other three hooks onto the same reading") must state its cost and what it ships, because the stated design adds latency to every commit for no #1245 benefit.** The three hooks prefilter on `*"git commit"*` (`plot-phase-gate.sh:57`, `plot-state-gate.sh:59`, `plot-brief-name-gate.sh:57`). None of the four commands #1245 lists contains `git commit`, so those three hooks exit at line 58-60 on all of them today; "all four agree on the fixture table" holds already for three of the four. "Behind the same `case` prefilter" is ambiguous: the three basenames would never match what these hooks look for, and the `git commit` prefilter matches 4.7 % of Bash calls. If each hook starts `node` on a commit, a commit command goes from about 230 ms of hooks to about 300-410 ms (three starts of 22-61 ms each). The glob defect in these hooks is `for tok in $segment` without `set -f`, a one-line change per hook that costs 0 ms. The amendment: slice 4 adds `set -f` around each token loop (and a fixture test that `git add 'docs/plans/*.md'` reads one token), and moves the word reading to the domain only where a hook needs RUN-versus-READ, which none of the three does. If the plan keeps the `node` reading, it must name the per-commit cost and the failure direction for these three hooks, which still sit on `trap 'exit 0' ERR`.
