## 3. What breaks, and what an agent will actually do

- **The gate arm cannot fire for a worker as described.** `plot-controller-gate.sh` exits 0 at `[ -n "$named_script" ] || exit 0` when no gated script is named. It also exits 0 for every linked worktree (*"A linked worktree — a desk. A dispatched worker's own call"*). Fleet agents run in linked worktrees, so a new arm placed after either exit never runs for them. The arm must run before both exits, as a separate pre-check, and a test must prove a refusal from inside a linked worktree. The plan's `test/reconcile/` test does not specify a worktree, so it can pass from the repository root and prove nothing about agents.
- **Keying on `PLOT_UNATTENDED` contradicts the gate's own header.** The header says *"NOT AN ENVIRONMENT VARIABLE … a working directory is a measurement"*. The hook reads Claude's environment and not the command's, so `env -u` in the command does not evade it. But every master-agent command (`Idea`, `Brief`, `Interrogate`, `Implement` in `## Plot Config`) also sets `PLOT_UNATTENDED=1`. Those are legitimate non-desk callers, for example a master agent verifying a release. The plan wants "a fleet agent in a desk", and the gate already measures that: use the linked-worktree test the gate already has, AND unattended. Otherwise state why a master agent is also refused.
- **Token matching refuses commands that only mention a suite.** In this session I measured it: a read-only `for b in … plot-dispatch.sh …; do git grep …` loop was refused by the installed `plot-controller-gate.sh` because a token named the script. A `CI suites` arm matching `test:contracts` tokens would refuse `grep test:contracts package.json`, a double-quoted `gh pr create --body "…test:contracts…"`, and a PR body that reports which suites CI ran. The gate strips only single-quoted heredocs. Specify the match as the runner position (`pnpm run <suite>`, `pnpm <suite>`, `pnpm --filter … <suite>`). Add tests that a `grep` and a double-quoted body mentioning the suite pass.
- **The gate is trivially routed around by the command the suite expands to.** An agent told *"never skip a failing test"* that is refused `pnpm run test:contracts` has the expansion one `cat package.json` away: `node --test test/reconcile/*.test.mjs`, `./scripts/owned-run.sh ./scripts/bounded.sh 1500 node --test …`, `pnpm --filter @plot-pm/board exec vitest run`, or `pnpm --filter @plot-pm/domain exec vitest run --coverage` (CI's own spelling). The refusal does not cover these, so it is a rule with a speed bump. Either refuse a glob over a whole suite directory (`test/reconcile/*.test.mjs`, a bare `vitest run` with no file arguments), or state plainly that the gate catches only the script names and that the prompt carries the rest.
- **The selection is near-full for the files agents change most.** I measured over `origin/main` with `git grep -l -F <basename>` across the test globs: `plot-dispatch.sh` is named by 69 test files, `plot-fleet-scan.sh` by 56, `plot-config.sh` by 43, `board-server.mjs` by 38 (it changes on every board change, because the worker prompt orders the rebuild and commit), and `plot-worker-state.sh` by 27. A slice that touches `plot-dispatch.sh` therefore runs about 60% of `test:contracts`, and any board slice runs 38 files for the bundle alone. That is the same load the plan removes. Two amendments: exclude generated bundles (`.gitattributes` already marks them, the way `plot-deliverable-search.sh` reads them), and add a cap. Above N selected files, print *"CI runs these"* and run only the files that name the changed file in a line the diff touches, or only the changed test files. The Open Point names the bundle risk; it needs a decision, not only a measurement.
- **Agents also read other instructions that say "run everything".** These come from `CLAUDE.md` Testing (*"Always install dependencies and run tests"*, and the command block listing `test:contracts` and `test:board`), from existing briefs already written with the full list (every brief on disk before slice 2), and from `docs/definition-of-done.md`. Slice 2 edits `CLAUDE.md` and the DoD, but briefs written earlier keep their `### Gates` line until rewritten. Name what happens to briefs already queued: rewrite them, or let the gate carry them.
- **The shipped gate reaches agents through the plugin cache, not the checkout.** The refusal above came from `~/.claude/plugins/cache/plot-marketplace/plot/2.22.1/…`. Slice 3 has no effect on this fleet until a release ships and the plugin updates, and the user's memory forbids a release unless someone asks for one. Say so in the plan, or have slice 3 run `plot-install-hooks.sh` from the repository.
- **The typecheck key is too narrow.** Root `pnpm run typecheck` checks only `@plot-pm/board` (`package.json` `"typecheck": "pnpm --filter @plot-pm/board typecheck"`). A domain `.ts` change needs `pnpm --filter @plot-pm/domain typecheck`. One `Typecheck command` key cannot express both. Make it `glob = command` like `Test runners`, or prove that the board typecheck covers the domain through its imports.
