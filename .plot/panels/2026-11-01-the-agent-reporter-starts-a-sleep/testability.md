# Testability juror: the-agent-reporter-starts-a-sleep

Position: amend

The fix is testable deterministically, and I proved the two main test shapes by probe on this machine under `/bin/sh` (bash 3.2) and `/bin/dash`. The plan as written is not yet buildable as a proof: requirement 4 contradicts one of its own two candidate mechanisms, the plan names no reproduction for any of the three race fixes, and the race fixes have almost no unit-tier tests today. Of the three commits, `d4bc9b8fc` shipped no test at all, and the reporter's `WorkerMonitor` line, the SIGKILL `137` and the group-TERM survival are proven only by `test/e2e/*`, which CLAUDE.md makes CI-only. A slice that rewrites the reporter therefore has no local test that fails when it breaks a race fix. The plan must add that test table before approval.

## Findings

1. **high — Requirement 4 refutes the bounded-poll candidate.** Plan § Approach, requirement 4: "fails when that count grows with the agent's run time". A poll at one second still starts one `sleep` per second, so its count grows linearly with run time (28,800 starts over the `Worker bound`). Issue #3024 has the same contradiction: its Required behaviour 1 offers "a poll with a bounded interval of at least one second", and its Required behaviour 3 fails that poll. No builtin wait exists that removes the `sleep` from a bounded poll on both target shells: `read -t` is absent in dash, and bash 3.2 has no loadable `sleep` builtin. So the bounded poll is either "one process per second", which requirement 4 refuses, or not buildable. Checked: plan text, issue body, `command -v dash` (present at `/bin/dash`), CI runs board tests on `ubuntu-latest` (`.github/workflows/ci.yml:704`), where `/bin/sh` is dash.

2. **high — The race fixes have no local regression test, so the slice cannot prove it keeps them.** `git show --stat d4bc9b8fc` touches only `packages/fleet/src/shared/continuation.ts`; the commit body cites a probe ("18/20 and 20/30 failures") that was never committed. `ad509c157` is also code-only. `6b0ac7188` changed only `test/e2e/monitors-attached.test.mjs`. The unit tier, `packages/board/test/unit/continue-route.test.ts:2699-2830`, checks ppid 1 (`:2730`), the exit code of `exit 3` (`:2752`) and absence from the board's tree (`:2801`). It checks no `WorkerMonitor` line, no SIGKILL `137`, no group TERM, and no "exit file present at the instant the agent is gone". Those live in `test/e2e/monitors-end.test.mjs:303-442` and `test/e2e/monitors-attached.test.mjs`, which CLAUDE.md § Testing says do not run locally. The plan names none of these files.

3. **high — The held-descriptor design has two deterministic failure modes the plan must test, and one of them it does not name.** Probe on 2026-11-01, both shells: with `3>&-` on `( cmd )`, `kill -9` of the agent subshell gave EOF at once and the reporter ran; without `3>&-`, the reporter stayed blocked while the inner `sleep 4` lived (`done=none` after 1.5 s), so the plan's Open Question 1 has a deterministic fail-before test. A natural exit gave the reporter an exit file that already held `0`, so the d4bc ordering holds. The unnamed mode is the open order: `read < fifo` blocks until a writer opens, so an agent that dies before its `exec 3>fifo` leaves the reporter blocked forever, an orphan at ppid 1 that writes no finding. A test must kill the agent before it opens the descriptor and assert that the finding still arrives.

4. **medium — A process-table sample cannot be the count.** Plan Open Question 3 names "a process-table sample of the wrapper's children". A sample sees only the processes alive at sample time; a 50 ms `sleep` under load is seen or missed by chance. Probe of the current loop with a `PATH` shim named `sleep`, agent gated on a fifo with no timer: 12 starts at T=1 s and 37 at T=3 s, against a nominal 20 and 60. The count grows with T, and its absolute value depends on load. So the assertion must be "zero reporter starts while the agent runs", not a rate or a ceiling.

5. **medium — A `PATH` shim catches only `PATH`-resolved starts.** `/bin/sleep 0.05` or `command sleep` through an absolute path passes the shim unseen. The reporter command is a TS string (`continuation.ts:1394-1398`), so a structural assertion on the string that `input.spawn` receives (`continuation.ts:1353`, `const spawnFn = input.spawn ?? spawn`) is a cheap second arm: no `sleep` and no absolute path between `while` and `done`. The shim must also not log the agent's own command, so the agent in the test must block on a test-held fifo, never on `sleep N` (the current unit tests use `sleep 2` as the Worker command, `continue-route.test.ts:2737`).

6. **medium — dash execs a subshell's last command, which changes which process the recorded pid names.** In my first probe the agent subshell ended with `( cmd )`; dash exec'd it, so `3>&-` closed the only writer at once and the reporter saw EOF immediately. The shipped agent subshell ends with `rc=$?; [ -f ... ] || printf ...`, so it does not hit this today. A rewrite that moves the exit write elsewhere can hit it, and only a dash run shows it. The board unit tests run on Linux in CI and on macOS locally, so both shells are covered only if the test is in that tier.

7. **low — Count of short-interval poll loops in shipped code.** `git grep -nE "sleep 0\.[0-9]" origin/main -- skills packages/*/src`: one source site grows with run time, `continuation.ts:1398`, copied into five generated bundles (`board-server.mjs`, `plot-continue-command.mjs`, `plot-fleetd.mjs`, `plot-restart-command.mjs`, `plot-restart-stopped-command.mjs`). The others are bounded waits: `plot-board-verify.sh:42` (0.1 s, at most 100 polls), `plot-boardctl.sh:454` and `:553` (0.5 s, start and stop bounds), `plot-fleetctl.sh:571` (0.5 s, `--wait` bound), `plot-worker-state.sh:1110` (one 0.4 s sample). One more loop grows with run time at one second: `plot_monitor_wait` (`plot-monitor-subject.sh:193-198`) runs `sleep 1` plus `plot_monitor_subject` for every AgentMonitor, on every agent, dispatched or continued. The plan should name it as out of scope with a follow-up, because a test written for this plan does not cover it.

8. **low — The normal dispatch path uses a parent `wait`.** `start_worker` in `skills/plot/scripts/plot-dispatch.sh:1507-1542` ends with `wait "$agent"`, so it starts no poll processes. The plan's claim that only the continue and restart routes carry this reporter is true. The line numbers `continuation.ts:1398` and the comment from about `:1270` (`TWO SUBSHELLS` at `:1275`) are correct on `origin/main`.

## Amendments I require

- A1. Choose the held-descriptor mechanism, or move the reporter's wait out of shell, and drop the bounded poll. Restate requirement 4 as: "while the agent runs, the reporter starts zero processes; after the agent ends, the tail starts each of its commands once". This removes the contradiction in Finding 1.
- A2. Add a test table with one row per behaviour, each run under real `sh` at the unit tier in `packages/board/test/unit/continue-route.test.ts` (or a new file beside it), and each with its fail-before mutation:
  - (a) zero reporter starts while the agent runs: `PATH` shim that logs every start, injected through `input.spawn` (a wrapper over `spawn` that sets `PATH` and the log path in `env`, not a change to `process.env`); agent blocked on a fifo the test holds; release; assert zero `sleep` lines before release and exactly one `date` line after. Fails on `main` deterministically.
  - (b) structural arm: the command string that `input.spawn` receives holds no `sleep` and no absolute path inside the wait.
  - (c) the d4bc ordering: after the test sees `kill -0` fail on the recorded pid, `.plot-worker.exit` already exists and holds the right code. Make it deterministic: a shim that delays the reporter's first command makes the pre-d4bc shape fail every time, not 18 of 20.
  - (d) SIGKILL to the recorded pid while `( cmd )` still lives: `.plot-worker.exit` reads `137`, and `.plot-worker.monitor.worker.jsonl` holds exactly one `gone` line, asserted while the `cmd` pid is still alive. Fails if `cmd` inherits the write end.
  - (e) the agent dies before it opens the descriptor: the finding still arrives, and no reporter process is left at ppid 1.
  - (f) group SIGTERM: the agent writes `143`, the reporter survives and writes exactly one `gone` line.
  - (g) `PLOT_SCRIPT_DIR=/nonexistent`: the exit file and the finding are still written (the `6b0ac7188` guard).
  - (h) the existing ppid-1 test (`:2730`) and tree test (`:2801`) stay unchanged and green.
- A3. Wait in each test for the exit of every process it started, by its own pid, and remove the fifo and the worktree by the exact name `mkdtempSync` returned, so `owned-run.sh` finds no leaked entry. A blocked reporter from a failing row must be killed in `afterEach`, or the failure shows as a hang.
- A4. Name `test/e2e/monitors-end.test.mjs` and `test/e2e/monitors-attached.test.mjs` in the plan as the CI gate that must stay green, and state that A2 is the local proof.
- A5. Name the fifo's path, its owner and its removal: it lives in the worktree beside `.plot-worker.exit`, the controller removes a stale one before the spawn, as it removes `.plot-worker.wrapper.pid` (`continue-route.test.ts:1019`), and a test asserts that removal.

## Open questions

- Q1 (EOF on SIGKILL, child inherits the fd): Yes on both shells, provided `( cmd )` gets `3>&-`. Probed on 2026-11-01 under `/bin/sh` and `/bin/dash`: with `3>&-`, EOF arrived in the same second as `kill -9`; without it, the reporter stayed blocked until the child ended. Recommend the descriptor, with A2 (d) and (e) as its proof.
- Q2 (builtin wait for a bounded poll): None that works on both shells. `read -t` is not in dash, and bash 3.2 has no `sleep` builtin. Recommend dropping the bounded poll (A1).
- Q3 (how the test counts): A `PATH` shim injected through `input.spawn`'s `env`, with the agent gated on a test-held fifo, and the assertion "zero starts while the agent runs" plus "one tail start after it ends". Add the structural string check as a second arm. Reject the process-table sample: it measures load, not starts (Finding 4).
