# Safety juror: the-agent-reporter-starts-a-sleep

Position: amend

The plan is right about the cause and the scope, and the held-descriptor candidate works: probes on macOS `/bin/sh` (bash 3.2) and on Debian `dash` wrote the exit record and exactly one finding for a natural exit, `exit 3`, an instant exit, a `SIGKILL` to the recorded pid, and a group `SIGTERM`, with four process starts per run regardless of run time. But the same probes show three ways a held descriptor loses the finding or leaves a reporter alive forever, and the plan names only one of them. The bounded builtin poll does not exist in `dash`, so it cannot meet requirement 4. The plan needs the descriptor discipline, a non-fatal fallback and a named test table before approval.

## Findings

1. **high — a leaked write end makes the reporter outlive its agent forever, immune to `--stop`.** The plan's Open Question 1 names only the agent's child. Probe (`scratchpad/probe/probe.mjs`, mode `fifo-noreporterclose`): when the reporter keeps the inherited write end, it never sees EOF, never writes the exit record or the `WorkerMonitor` line, and survives the group `SIGTERM` because of its own `trap '' TERM`. The process stayed until I sent `SIGKILL` (pid 22140). The same holds for the outer `sh -c` if it opens the write end and does not exit. Today's `kill -0` loop cannot hang this way. Checked: `continuation.ts:1394-1398` on `origin/main`, and the probe on macOS.
2. **high — a failed FIFO open ends the reporter before it writes anything.** `exec 4<"$FIFO"` on a missing path ends the subshell under both shells: `/bin/sh -c '( exec 4</nonexistent/x; echo after-exec ); echo outer'` prints no `after-exec`, and `dash` in `debian:stable-slim` does the same. A stale FIFO from an earlier run makes `mkfifo` fail, and a full disk or an unwritable directory does too. The result is a lost `WorkerMonitor` line and, after a `SIGKILL`, no `137` in `.plot-worker.exit`. The redirect on a compound command is not fatal: `{ ...; } < "$FIFO" || fallback` fell through to the fallback on both shells.
3. **high — the agent's command must not hold the write end, or a `SIGKILL` report waits for the command's descendants.** Probe mode `fifo-nocmdclose`, `SIGKILL` to the recorded pid: the finding arrived after 4 s (when `/bin/sleep 4` ended) instead of after 1 s. With `cmd = '/bin/sleep 6 & exit 0'`, it waited 6 s. A real Worker command that leaves a daemon would delay the finding with no bound. `( ${cmd} ) 3>&-` fixes both (measured: 1 s and 1 s). This is the plan's Open Question 1, and the answer is "only if the plan requires the close".
4. **medium — open order can deadlock an instant-exit agent.** If the agent opens with `>` and the reporter with `<`, each open blocks until the other end opens, and an agent that exits before the reporter opens leaves the reporter blocked forever. The working shape opens the FIFO read-write (`3<>`) in the outer shell before either fork. The reporter then opens its read end while it still holds the inherited fd 3, and closes fd 3 only after that. Probe: the `instant` and `exit3` cases, and a reporter that slept 0.3 s before it opened, all reported on macOS and on `dash`.
5. **medium — the bounded builtin poll is not available in the shell CI runs.** Linux `sh` is `dash` (`/bin/sh -> dash` in `debian:stable-slim`). `dash` has no builtin `sleep` and no `read -t`. A 1 s poll therefore starts one external `sleep` per second. That is 20 times fewer starts, but the count still grows with run time, so requirement 4 fails by construction. A 1 s poll also widens the window in which `kill -0` succeeds on a reused pid and holds the reporter on an unrelated process (low likelihood).
6. **medium — no test outside `test/e2e` runs the reporter.** `git grep` for `PLOT_EXIT_FILE|reporterTail|WorkerMonitor` in `packages/*/test` finds none. The three earlier race fixes are held by `packages/board/test/unit/continue-route.test.ts:2730` (ppid 1), `test/e2e/monitors-end.test.mjs:378,423` (`SIGKILL` at the bound), and `test/e2e/monitors-attached.test.mjs:309` (`--stop`). The e2e suites run only in CI. The command string is built inline in `continueOnDesk` (`continuation.ts:1394-1398`), so a unit test cannot spawn it alone.
7. **low — the shim count is deterministic and the poll shape fails it.** Probe with a PATH shim that logs `sleep`, `cat`, `date`, `rm`, `mkfifo`, and a command that calls `/bin/sleep` by absolute path: the poll shape started 11 `sleep` for 2 s and 16 for 5 s (a loaded machine, about 150 ms per start). The FIFO shape started 4 processes (`mkfifo`, `rm`, `cat`, `date`) in every scenario. This answers Open Question 3.
8. **low — `SIGKILL` to the recorded pid leaves `( cmd )` running in both shapes.** The probe's process group still held `/bin/sleep 4` after the reporter wrote `137` for both the poll and the FIFO shapes. This is today's behaviour and not a regression. The plan must not claim otherwise.
9. **low — every other short poll in shipped code is bounded and runs once per operator command.** `git grep -nE "sleep 0\.[0-9]"` over `skills` and `packages/*/src`, excluding tests and bundles: `continuation.ts:1398` (unbounded, once per agent for its whole run), `plot-board-verify.sh:42` (at most 100 × 0.1 s), `plot-boardctl.sh:454` (at most 40 × 0.5 s), `plot-boardctl.sh:553` (bounded by `wait_bound`), `plot-fleetctl.sh:571` (bounded by `--wait`). The same string ships in five bundles (`board-server.mjs`, `plot-continue-command.mjs`, `plot-fleetd.mjs`, `plot-restart-command.mjs`, `plot-restart-stopped-command.mjs`), which `main` rebuilds. `start_worker` in `plot-dispatch.sh:1507-1542` uses a parent `wait "$agent"` and has no poll. Only the reporter belongs in this plan.
10. **low — line references.** `continuation.ts:1398` is correct. The ppid-1 argument starts at `:1264`, not `:1280`; the sibling argument is at `:1291`. The comment block at `:1275-1374` describes the poll ("It polls `kill -0`", "the one case where polling is unavoidable") and is wrong once the wait changes.

## Amendments I require

- A1. Choose the held descriptor and state its descriptor discipline as requirements. The outer shell runs `rm -f` on the FIFO path, then `mkfifo`, then opens it read-write on one fd before either fork. The agent runs `( ${cmd} )` with that fd closed. The reporter opens its read end before it closes the inherited fd, as `{ exec 3>&-; while read -r _; do :; done; } < "$FIFO"`. The reporter removes the FIFO by its exact path after the read ends. No other process keeps the write end.
- A2. Require a non-fatal fallback. A failed `mkfifo` or a failed open sends the reporter to the existing `kill -0` loop at an interval of 1 s, never to an `exec` redirection that ends the shell. The reporter still writes `137` and exactly one finding on that path.
- A3. Extract the `sh -c` string into one exported arrow function in `packages/fleet/src/shared/continuation.ts`, and add a unit test that spawns it with `detached: true`, a PATH shim and a command that calls `/bin/sleep` by absolute path. The test cases are: natural exit `0`; `exit 3`; instant exit; `SIGKILL` to the recorded pid (`137`, one `gone` line); group `SIGTERM` (`143`, one `gone` line, the reporter survives the signal); a command that leaves a background grandchild (the finding does not wait for it); a failed `mkfifo` (fallback, one line); a process-start count equal for a 1 s and a 4 s run; and, after each case, no reporter left in the group and no FIFO left on disk. The probes in this juror's scratch directory show each case can be made deterministic, with no timing assertion beyond a bound.
- A4. Name `continue-route.test.ts:2730`, `monitors-end.test.mjs:378,423` and `monitors-attached.test.mjs:309` as the existing guards that must stay green, and say that CI runs the e2e ones.
- A5. State where the FIFO lives. Inside the worktree it needs a `.gitignore` line beside `.plot-worker.exit` (`.gitignore:63-74`); in `TMPDIR` the test removes it by the exact name it created, as `CLAUDE.md`'s owned-run rule requires.
- A6. Rewrite the comment block at `continuation.ts:1275-1374` to describe the wait it now does, and fix `:1280` to `:1264` in the plan.
- A7. Drop the bounded builtin poll as a candidate, or keep it only as the A2 fallback, and say that it starts one process per interval under `dash`.

## Optional

- Name finding 8 (the command keeps running after a `SIGKILL` to the recorded pid) in Notes as known and out of scope.
- Moving the reporter into node removes the shell question but holds one node process (tens of MB) per agent for its whole run, and it needs its own proof that an inherited `SIGTERM` ignore survives `exec`. I would not choose it.

## Open questions

- Q1 (EOF on `SIGKILL`, on macOS and Linux, with a child that inherits the descriptor): yes on both, measured, provided the command runs with the write end closed (`3>&-`) and the reporter and outer shell keep no write end. Without the close, the finding waits for the command's last descendant (finding 3).
- Q2 (a builtin that waits without a process start in `sh` and `dash`): none exists in `dash`; `read -t` is bash-only. Use the held descriptor, and keep a 1 s external-`sleep` poll only as the fallback for a failed FIFO.
- Q3 (how the test counts processes): a PATH shim that logs each start of `sleep`, `cat`, `date`, `rm` and `mkfifo`, with the agent's command calling `/bin/sleep` by absolute path, compared between a 1 s and a 4 s run. The count is independent of load; a process-table sample is not.
