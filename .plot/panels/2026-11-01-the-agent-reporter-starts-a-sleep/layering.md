# Layering juror — the-agent-reporter-starts-a-sleep

Position: amend

The plan puts the fix in the right layer by default: it changes only the `sh -c` string that `continuation.ts` builds, and it adds no shipped script and no node process. Through the layering lens that is the smallest correct place, and the plan should say so as a decision rather than leave three layers open as "candidate mechanisms". The held-descriptor wait works on macOS `/bin/sh` for all three shapes (natural exit, direct `SIGKILL`, group `SIGTERM`), measured below, so the bounded-poll candidate and any move into a script or into node can be dropped. The plan needs amendments on four points: it must decide the mechanism and the layer, it must name the second per-agent poll loop (the AgentMonitor's 1 s nap) that it leaves in place, it must state why the dispatch path's parent `wait` does not transfer, and its test must count every exec, not only `sleep`.

## Findings

1. **medium — the plan leaves the layer undecided, and only one layer costs nothing.** Evidence: plan `## Design › Approach` lists "Bounded builtin poll" and "Held descriptor" and defers the choice to Open Questions; `continuation.ts:1391-1399` on origin/main holds the whole wait in one TS template string. I compared the three possible homes. (a) The TS-built string: the change is about four tokens in the existing string, adds no file, adds no line that `scripts/check-shell-lines.sh` counts (it counts `.sh` under `skills/` only, header lines 9-18), and adds no spawn site. (b) A shipped script (for example a `plot-agent-reporter.sh`): it grows shipped shell, which `check-shell-lines.sh` refuses unless the same change removes an equal count, and it adds a script name that the board would have to reach through `PLOT_SCRIPT_DIR`, which is the crossing the CI step "One place reaches a script" ratchets (`ci.yml:1460-1480`). (c) A node reporter: it is one process start per agent rather than 20 per second, but it keeps a resident node process (tens of MB) per agent for the whole `Worker bound`, it needs a bundle and a launcher, and it still cannot `wait` on a non-child, so it would poll `process.kill(pid, 0)` on a timer — the same shape as today, moved into a heavier process. It also gains nothing for the one case the reporter exists for (`SIGKILL` → `137`). So (a) is the answer; the plan should state it and drop (b) and (c).

2. **medium — the held descriptor works on macOS; I measured it.** Evidence: a probe in my scratch directory (`.../scratchpad/jl/exp/probe.sh`) ran the plan's shape under `/bin/sh` on Darwin 24.6: the outer shell runs `mkfifo f; exec 3<>f 4<f; rm f`; the agent subshell closes fd 4 and runs its command as `( exec 3>&-; cmd )`; the reporter closes fd 3, keeps `trap '' TERM`, and blocks on `read _ <&4`; the outer shell then closes both and exits. Results: natural exit → reporter wrote `done rc=0`, agent ppid 1; direct `kill -9` to the recorded pid → `done rc=137` while the command's own child (`sleep 30`) was still alive, so the child did not hold the write end; group `SIGTERM` → `done rc=143` from the agent's own trap, and the reporter survived. The reporter started zero processes while it waited; the whole mechanism costs two one-time execs (`mkfifo`, `rm`). Opening both ends in the OUTER shell before either fork matters: if the reporter opened the FIFO path itself, an agent killed before that open would leave the reporter blocked in `open` forever. I did not run Linux `dash`; `exec 3<>fifo` (read-write open of a FIFO) is defined on Linux and worked on macOS, but POSIX leaves it unspecified, so the slice must prove it on CI's Linux runner.

3. **medium — a second per-agent poll loop stays, and the plan does not name it.** Evidence: `skills/plot/scripts/plot-monitor-subject.sh:193-202` (`plot_monitor_wait`) naps `sleep 1` and then calls `plot_monitor_subject`, whose body (`:102` onward) runs `$(cat "$pid_file" | tr -d ...)` — so each second costs `sleep`, `cat` and `tr` execs, about 3 per second per agent. `plot-agent-monitor.sh:565` runs that loop for every agent, on the dispatch path and on the continue/restart path (`Ide` in the board bundle starts `monitors.start`). My count of short-interval poll loops in shipped code that start a process per poll, from `git grep -nE "sleep 0\.[0-9]|sleep [0-9]"` over `skills` and `packages/*/src` on origin/main: (i) `continuation.ts:1398`, 50 ms, per continued agent, whole run — the plan's subject; (ii) `plot-monitor-subject.sh:198`, 1 s, per agent on both paths, whole run — not covered; (iii) `plot-board-verify.sh:42`, 0.1 s, at most 100 passes, once per verify; (iv) `plot-boardctl.sh:454` and `:553`, 0.5 s, bounded by 40 passes and `wait_bound*2`; (v) `plot-fleetctl.sh:571`, 0.5 s, bounded by `wait_bound`. Only (i) and (ii) scale with agents times run time. The plan's "one of several sources" names the board request path and the fleet scan but not (ii), which is the next-largest per-agent source and lives in shipped shell. The plan should name it as a follow-up issue, not fold it in: (ii) is a different script with a corpus-held twin (`desk-manifest.corpus.test.ts`), and its fix shrinks shipped shell, which is a different review.

4. **low — the plan states why `wait` is unavailable, but not why the dispatch path can use it.** Evidence: `plot-dispatch.sh` `start_worker` (the single-quoted `sh -c` near line 1542) ends with `wait "$agent"; rc=$?` — a parent wait, no poll, so the dispatch path has no equivalent of this loop. The continuation path differs because `continue-route.test.ts:2743` asserts `ppidOf(pid) === '1'` for the recorded pid, and ad509c157 records that a waited-on process cannot also have ppid 1. On the dispatch path the recorded agent's ppid is the wrapper, not 1. So the two starters hold different contracts for the same `.plot-worker.pid`. The plan is right to keep the continuation contract, but it should say in one line that the dispatch path is out of scope because it already waits, so a reader does not look for a second fix there.

5. **low — two implementations of one wrapper contract, undeclared.** Evidence: `reporterTail` (`continuation.ts:1376-1389`) writes the same `gone`/`clear` WorkerMonitor line that `start_worker` writes after its `wait` (`plot-dispatch.sh:1457-1470`); the comment at `continuation.ts:1354-1366` says so. `CLAUDE.md` › *A Shell Script Asks The Domain* allows a duplicate only when a test holds the pair. The e2e tests `monitors-attached` and `monitors-end` hold the two paths to the same outcomes, which is close to that. This plan does not need to change it, and it must not add a third copy (for example a node reporter with its own line writer).

6. **low — the continuation spawn is invisible to the spawn ratchet.** Evidence: CI step "One place reaches a process" (`ci.yml:1400-1416`) greps `\b(spawn|spawnSync|execFile|execFileSync)\s*\(` outside `adapters/`; running that grep over origin/main gives 11 lines (= `allowed=11`), and `continuation.ts:1391` is not one of them, because it calls `spawnFn(` (aliased at `:1353`). `continuation.ts` lives in `packages/fleet/src/shared/`, not `adapters/`. The plan does not move this spawn, which is correct; it must not add a second spawn site for a reporter, because the gate would not see that either.

7. **low — the test as worded can pass with the defect still present.** Evidence: plan Requirement 4 and Open Question 3 propose a `PATH` shim named `sleep`. A shim for `sleep` alone passes if the loop moves to another exec (for example `while kill -0 ...; do cat /dev/null; done` or a `$(date)` per poll). The test also must not use `sleep` as the agent's `Worker command`, or the shim logs the agent's own start.

## Amendments I require

- A1. Decide the mechanism and the layer in `## Design`: the held descriptor, inside the existing `sh -c` string in `continuation.ts`, with no new shipped script, no node reporter and no new spawn site. Give the reason in one line each (findings 1 and 6).
- A2. Specify the descriptor shape that has no open-order race: the outer shell opens the FIFO read-write and read-only before it forks (`mkfifo; exec 3<>f 4<f; rm f`), the agent closes the read end and runs `cmd` with the write end closed (`( exec 3>&-; ${cmd} )`), the reporter closes the write end and keeps `trap '' TERM`, and the outer shell closes both before it exits. The FIFO path lives in the worktree or `$TMPDIR` and is removed right after the open.
- A3. Name the AgentMonitor nap loop (`plot-monitor-subject.sh:193-202`, about 3 execs per second per agent, both paths) in `## Motivation` as a remaining per-agent source, out of scope, with a follow-up issue number.
- A4. Add one line to `## Design` that the dispatch path (`start_worker`) already uses a parent `wait` and is out of scope, and why the continuation path cannot (`continue-route.test.ts:2743`, ad509c157).
- A5. Make the test count every exec, not only `sleep`: put a shim directory first on `PATH` that logs the name of each of `sleep`, `cat`, `date`, `kill`, `mkfifo`, `rm`, `tr`, run an agent whose command does not exec any shimmed name for 1 s and for 3 s, and assert the two logs hold the same entries. Add the existing three shapes (natural exit, `exit N`, direct `SIGKILL` → `137`, group `SIGTERM` → `143`) repeated at least 20 times each in one test, so the race fixes are proven by repetition and not by one green CI run.
- A6. Run the slice's tests on CI's Linux runner and on macOS before merge, because `exec 3<>fifo` is not POSIX (finding 2).

## Open questions

- **Does a blocking read on a descriptor held only by the agent subshell return EOF on `SIGKILL`, given the child inherits it?** Yes on macOS, when the child runs with the write end closed (`( exec 3>&-; cmd )`): measured `done rc=137` with the child still alive (finding 2). Linux is unmeasured; require it on CI (A6). Open both ends in the outer shell before forking, never in the reporter (A2).
- **Which builtin waits without a process start in `sh` on macOS and on Linux, if the bounded poll is chosen?** None that is portable: `read -t` is not in `dash`, and bash 3.2 has no `sleep` builtin. A builtin poll would need `bash` instead of `sh`, which changes how `Worker command` is interpreted. Recommendation: do not choose the bounded poll; the held descriptor needs no interval and no builtin.
- **How does the test count processes?** A `PATH` shim directory that logs every shimmed command name, compared between a short and a long agent run, not a process-table sample: a sample depends on load and on timing, and a shim log does not (A5).
