# Testability juror — every-plan-reference-shows-its-issue

Position: amend

The two user rules are testable, and the data to prove them is already on the client: every plan-carrying fleet row, slice and sprint member in the saved payloads resolves to a card, and the card carries the issue keys. The plan cannot be approved as written because it names no proof. It has no test table, no gate for "every surface uses the one component", and it misses one of the four href helpers (`planHref` in `lib/plan.ts`) plus the StoryModal rewrite and three `location.assign` sites. A grep ratchet proves rule (ii) cheaply. Rule (i) cannot be proven by grep, because the rogue sites render `{card.title}`, `{m.slug}` and `{panel.plan}`; it needs one catalogue browser test that finds plan names by their TEXT, not by their markup. With those two proofs, a domain table test, and a named list of the existing tests that change, the plan is buildable. Checked against `origin/main` at `251b2abfc`.

## Findings

1. **high — No proof exists for "every surface uses the one component".** The Changelog promises one rendering on every surface, and the plan names no test or gate that fails when a site builds its own. Measured with `git grep -n "/plan/" origin/main -- packages/board/src/app`: the `/plan/<file>` href is constructed at 9 non-comment sites — `lib/tuple-row.ts:491`, `:1301`, `:1517`; `lib/agent-rows/rows.tsx:372`; `lib/plan.ts:15`; `components/StoryModal.tsx:16`; `App.tsx:952`, `:965`, `:980`. A ratchet is feasible: one script or one vitest source test counts `` `/plan/${ `` outside the domain rule and fails above zero (the `App.tsx` router fallbacks either call the domain rule too or are named as the only allowed exception).
2. **high — Rule (i) has no mechanical proof, and grep cannot give one.** The sites that drop the prefix render raw fields: `PlanCard.tsx:373` `{card.title}`, `StoryModal.tsx:310` `{card.title}`, `SprintModal.tsx:203`/`:213` `{m.slug}`, `AgentPanelFacts.tsx:401` `panel.plan`, `AgentList.tsx:2694` `{r.branch || r.plan || r.repo}`, `plan-level-row.tsx:171` `issues: []`. A future site that prints `{x.slug}` is indistinguishable by grep from any other string. The proof that works: one browser test over a catalogue state where a plan has issue `1089`; it collects every leaf element whose text contains that plan's slug or title, and asserts that each sits inside the component's attribute (e.g. `[data-plan-ref]`) and starts with `1089: `. This finds a rogue site by what a reader sees. Adding the file moves the browser-test count that `test/integration/stubbed-tests-start-no-board.test.ts:438-445` records, so the commit must update that ledger.
3. **medium — The plan misses a fourth href helper and two more sites.** `planHref` (`lib/plan.ts:13-16`) is used by `PlanCard.tsx:343`, `PlanModal.tsx:45` and `StoryModal.tsx`, and `test/unit/plan.test.ts` asserts it 6 times, including the Windows-separator basename case (`:21`). `StoryModal.tsx:10-16` rewrites a path to `/plan/<slug>.md` on its own. `PlanModal.tsx:44-46` names the plan as `Plan: ${card.title}` and `Plan: ${card.slug}`. The plan's list of removed helpers (`planLink`, `planNameLabel`, the slice row, `tupleFromPlan`) must add `planHref` and the StoryModal rewrite, and the Windows case must move into the domain table rather than be lost.
4. **medium — The label rule is a board function today, not a domain property.** `planNameLabel` lives at `packages/board/src/app/lib/tuple-row.ts:1278` and is tested in `packages/board/test/unit/a-plan-row-names-its-ticket.test.ts:84-99`. Requirement 4 needs it in `packages/domain/src/rules/` as an arrow with factual TSDoc, and those tests must MOVE to `packages/domain/test/`, not be duplicated. The click outcome is already a domain rule: `planLinkClick` (`packages/domain/src/rules/plan-link-click.ts:26`) returns `open`/`wait`/`navigate`. "Opens the plan the same way" is then provable as: every reference uses one click handler that calls `planLinkClick`. Today `PlanLink` (`rows.tsx:372-374`) opens with `target="_blank"` when `onOpenPlan` is absent, which is a second open mode the test must exclude.
5. **medium — One factual claim in the issue is false and it shapes Open Question 2.** The issue says `PlanLink` without `onOpenPlan` opens "a GitHub file in a new tab". It opens the board's own `/plan/<file>` in a new tab (`rows.tsx:372-374`). `git grep -n "blob/" origin/main -- packages/board/src/app` returns nothing: no surface links a plan file on the git host today. So Open Question 2 does not choose between two existing targets.
6. **medium — The client already holds every issue key the rules need; the payload needs no change.** Measured on the saved payloads (`board.json`, `fleet.json`) with `node -e`: 596 cards, 298 with `issues`, 0 duplicate slugs. 44 of 51 fleet rows name a plan; all 44 resolve to a card by `planFile`. All 44 slices resolve by slug. All 14 sprint members resolve by slug. 75 of 77 `StoryPlanRef`s resolve; 2 do not. The plan head already does this lookup (`rows.tsx:654` `card?.issues ?? 7. **medium — Existing tests assert the old texts and hooks, and the plan names none of them.** Counted with `git grep`: `test/unit/tuple-row.test.ts` has 37 lines on plan links (e.g. `:469` `{ what: 'plan', href: '' }`); 6 selectors in 5 browser files depend on `data-tuple-link="plan"` (`agents-tab.browser.test.ts:727`, `plan-link-click.browser.test.ts:272`, `plan-row-names-its-ticket.browser.test.ts:85`/`:87`, `row-withholds.browser.test.ts:279`, `tuple-row.browser.test.ts:577`), so the shared component must keep that attribute; `agents-tab.browser.test.ts:2469`, `:2474`, `:4810` assert exact `/plan/` hrefs; `plan-link-click.browser.test.ts` has 9 `/plan/` lines on the click contract; `plan-row-names-its-ticket.browser.test.ts:93` asserts `1089: one-ticket`. `test/unit/agent-list.test.ts:3398` is a source gate whose `ROW_NAVIGATION` list allows the literal `` href={`/plan/ ``; that allowance must go in the same change, or the gate keeps permitting a hand-built anchor.
8. **low — Notes misdescribe the related plan.** `2026-10-17-a-planned-issue-shows-its-plan.md` writes `plan:*` labels and a link comment on the TRACKER issue; it does not add a plan reference to a board issue row. The plans are still complementary. Also, the domain already has a `planLink` in `ports/tracker.ts` and `rules/plan-issue-comment.ts` (the tracker comment's link); "remove `planLink`" must name `lib/tuple-row.ts:486` only.
9. **low — The inferred plan on an issue row already satisfies rule 5.** `rows.tsx` `IssueRowView` passes `{ what: 'plan', label: inferredPlanName(issue.title), href: '' }`, and the row's own name carries the issue number. One table row keeps it: a reference with no file gives no href.

## Open questions

- Which name does a reference show? Recommendation: the slug, prefixed — `1089: <slug>` — on every surface, with the title in the element's `title` attribute. One format gives one equality assertion; a surface that also wants the title (the Planning card body) prints it outside the reference. `plan-row-names-its-ticket.browser.test.ts:93` already asserts this format.
- Which link target is standard? Recommendation: the in-app `/plan/<file>` route, with the click decided by the existing `planLinkClick` rule (modal on a found card, otherwise navigate), same tab, and no `target="_blank"`. No surface links the git host today (finding 5), so this changes no current destination except the new-tab mode.
- Does each payload carry the issue keys? Recommendation: no payload change; the client resolves keys from the cards through one shared, unit-tested lookup. Measured: 44/44 rows, 44/44 slices and 14/14 sprint members resolve; 2 of 77 story refs do not and need the table's fallback row. This avoids schema churn in `AgentRow`, `Slice`, `StoryPlanRef` and `SprintMember` and the fixture updates in `test/catalogue/` that a schema change would force.
