## Open Questions

- **Port in a workflow.** Let `readWorkerReadings` take the ports, as `readDeskReadings` (`plan-walk-desks.ts:68-72`) already does. Correctness does not depend on the placement. Correctness depends on what the corpus compares (see Finding 1).
- **21 pid checks, 55 sources.** Keep the measured split as a slice 1 deliverable. A different split changes no slice only if every source traces to a caller that slice 1–3 replaces. Add one rule: an untraced source that stays after slice 3 is named in the PR, not absorbed.
- **`Date.parse` against `_plot_lstart_epoch`.** The answer is no for a non-English locale. The dispatcher records `pidStartedAt` with `ps -o lstart=` in the operator's locale (`plot-dispatch.sh:1510`, no `LC_ALL=C`). Measured here: `LC_ALL=de_CH.UTF-8 ps -o lstart=` prints `Mo.  9 Nov. 13:14:40 2026`; `Date.parse` reads that, but reads `Di.  3 März 13:14:40 2026` as `NaN`, while `LC_ALL=de_CH.UTF-8 date -j -f "%c"` reads it as 1772540080. The shell parses the `%c` form; the TypeScript copy does not. A worker in a German locale, started in March, May, October or December, reads `stale`, so `agentState` answers `ended`. Neither the en_US operator machine nor the C-locale runner shows it. Add localized `pidStartedAt` rows (de, fr, every month) to the 12 recorded pairs. Make the dispatcher stamp `pidStartedAt` under `LC_ALL=C` (no added line), and make `pidIsCurrent` read an unparseable recorded start the way the shell does.
- **Slice 4 and `childOnCore`.** Keep a CPU reading. `childOnCore` is the only `idleNow` arm that keeps a silent long build alive (`idle-now` rule: `pid`, `spoken`, `silence`, `childOnCore`, `treeQuiet`). A Bash tool call that runs `pnpm test` for 20 minutes writes nothing to the transcript, nothing to `.plot-worker.log`, and often nothing that `git status` lists. With the log reading alone, the idle watch ends that prompt when `monitorEndsWorker` is set (`worker-loop.ts:1260-1284`). Hold the previous `table()` sample in the loop and compare the subtree CPU time across idle checks: 1 `ps` per check, no 400 ms wait, same meaning. Change the Done-when row from "starts no `ps`" to "starts 1 `ps`".
- **Deleting `plot_worker_activity`.** Do not delete it in this plan. Its one caller is a measuring tool (`plot-quiet-stretch.sh:120`), and the shell-lines gate passes without the deletion.
- **`PLOT_AGENT_PROCESS` in fleetd.** No new risk. Today fleetd sources the script in its own environment, so the shell reads fleetd's value already. The TypeScript copy must read the same variable with the same default `claude`, and the same `PLOT_AGENT_GRACE_SECONDS` default 30 (see Finding 2).

## Findings

1. **The free-agent arm is lost, and the planned corpus cannot see it.** `plot_worker_state` answers `running` for an orphaned wrapper whose `.plot-worker.freewait` names the pid, only when the manifest's `startedAt` is set (`plot-worker-state.sh:1271`). `plot_worker_readings` has no freewait field, `AgentStateReadings` has none, and `agentState` has no such arm (`rules/agent-state.ts`): it sends `orphaned` to `taskState`, which answers `finished`, `waiting` or `stalled`. The existing `agent-state.corpus.test.ts` passes only because no free-wait desk exists when it runs. Slice 1 replaces `processesShell.workerState`, which calls `plot_worker_state` and is correct today, with `readWorkerReadings` plus `agentState`. A free agent then reads `finished` in fleetd, `reap.ts`, `release-claim-reader.ts` and `restart-command.ts`. The planned constructed "free-wait record" desk compares against `plot_worker_readings`, which does not read the file, so it passes. Required: add the arm to the domain (a reading field and an `agentState` step, with the `startedAt` condition), and make the slice 1 corpus compare the final `ProcessReading` (state, pid, code) of `processesFiles.workerState` against `plot_worker_state` on every constructed desk. The readings-against-readings comparison stays as a second block.
2. **`agentAlive` omits the grace window.** `plot_worker_agent_alive` answers `unaskable` (exit 2, which reads `live`) for a wrapper younger than `PLOT_AGENT_GRACE_SECONDS` (default 30, `plot-worker-state.sh:977`, `:1011-1014`). The plan's `agentAlive` names only the subtree `comm` match. Without the grace, every new dispatch reads `orphaned` and then `finished` or `stalled` for up to 30 s. Add the grace to the rule (elapsed from the table's `startedAt`), and add a corpus desk younger than the grace and one older than it. Note that a constructed `orphaned` desk needs a process older than the grace, or the same `PLOT_AGENT_GRACE_SECONDS=0` on both sides.
3. **A shared table read races with `kill -0`.** In the shell, `ps` runs microseconds after `kill -0`, and an empty `ps` answer reads `stale` (`:352-353`). With one table per pass and `workerState(worktree, hasPr)` unchanged (`ports/processes.ts`), the table is memoised in the adapter and read seconds before some desks. A worker started after the table read answers `kill -0` and has no row, so the copied rule reads `stale` and the agent reads `ended`. A new agent spawned after the read reads `orphaned`. State the memo lifetime, and define "pid alive, no row" as a re-read of the table once, then `unaskable`, never `stale`. Add a test with a pid started after the table read.
4. **Bundle paths come from the wrong tree.** The shell reads each desk's own `packages/board/build.mjs` per call (`plot-desk-dirt.sh:85-98`, "a desk's `build.mjs` may differ from `main`'s"). Slice 3 reads one `build.mjs` per process. A desk that edits the build reads dirty in one and clean in the other. Read the bundle list per desk, or record the difference as a decision. Also keep the asymmetry: `quietSeconds` calls the filter with no worktree, so no bundle exclusion applies there (`:637`).
5. **The Dirt Done-when row cannot pass as written.** `quietSeconds` needs HEAD's committer time, and it runs `git log -1 --format=%ct` today (`trees-git.ts:375`) besides `git status`. "Each start 1 `git`" means 2 for `quietSeconds`, or a dropped HEAD time, which makes the tree read quieter than it is: a false `idle`. Change the row to 2 `git` for `quietSeconds`.

Compare the final state word, pid and code of `processesFiles.workerState` against `plot_worker_state` on constructed desks that include a free agent, a wrapper inside the grace window and a pid started after the table read. A readings-only comparison passes over Findings 1–3, and each of them ships a false `finished` or `ended` that a caller acts on.
