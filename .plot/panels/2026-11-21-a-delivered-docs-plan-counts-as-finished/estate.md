## Open question `[question-release-counts-docs]`

**Recommendation: count the plan as delivered on the release cards, as the plan does.** Three estate facts support this answer. First, `docs-live-on-merge` (`release.ts:296-297`) only decides whether `/plot-release` writes a Released record. It does not say that the merged code is missing from the tag. Second, PR #3630's `releaseGroup` draws its bar from `sprintBarOf` per sprint, and `sprintBarOf` reads the same `slicesByPlan`. A separate set for the release side would therefore need a second path in `releaseCards` and also in the new group, and the group would then show a bar that differs from the targeted card for the same sprint. Third, `delivery-view.test.ts:170` already asserts that the person card and the sprint card show equal bars. With the other answer, the plan must close that equality on the release side. Record the answer in the Design and close the question before approval.
