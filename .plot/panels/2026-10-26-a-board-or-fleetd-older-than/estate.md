## Summary

The skew is real and the evidence holds. The plan's design is pointed at the wrong signals, though. Slice 1 adds a "stale spawner" hint to a refusal that legitimate non-writers hit far more often, and the hint cannot tell those cases apart. Slice 2 compares a bundle with itself on disk. That flags staleness about eight times a day in this repository, and it never fires for an adopting repository whose plugin moved to a new version directory. Prior art the plan does not cite (`loop-restart.ts`, the `BoardStatus` entries, the fleetctl `BUNDLE MISSING` arm) already settles two of its four open questions. One cited role (implement) no longer uses the marker on `main`.

## 2. The approach against the code

- **The wording lives in the domain, not the entry (read).** The refusal text is `mainCheckoutWriteRefusal` at `packages/domain/src/rules/main-checkout-write.ts:391`. `gate.ts:534` only calls it. `packages/domain/test/main-checkout-write.test.ts` is its test. The plan says slice 1 "changes one message in `packages/board/src/server/entry/gate.ts`". That is wrong, and the open question about domain vs entry is already answered by the code: domain.
- **The gate cannot attribute the cause (read).** `gatesMainCheckout` (`main-checkout-write.ts:32-33`) reads only `PLOT_UNATTENDED === '1' && marker !== '1'`. Four current, up-to-date spawns set `PLOT_UNATTENDED=1` and leave the marker unset by design: idea `board/src/server/idea.ts:725`, interrogate `interrogate.ts:490`, auto-verify `fleet/src/shared/auto-verify.ts:500` and auto-design `auto-design.ts:757` (ran grep). Two more set it empty: desk launches at `plot-dispatch.sh:1558` and `continuation.ts:1116`. Every refusal those agents get is correct. If the refusal says "a spawner older than the gate is the likely cause", it misleads the most common reader. **Amend:** add a spawn-contract reading that the gate can compare. Put an integer constant in the domain (for example `SPAWN_CONTRACT = 1`) and have every unattended spawn export it (for example `PLOT_SPAWN_CONTRACT`). The gate names a stale spawner only when that variable is absent or lower than its own constant, and gives the spawner's value. Old spawners lack the variable, so this detects the current gap too. The constant moves only when a spawner-gate env contract changes, as #2317 and #2646 did.
- **The comparison across two code sources (read).** The gate runs from the installed plugin (`hooks/hooks.json` → `${CLAUDE_PLUGIN_ROOT}/skills/plot/scripts/plot-gates.sh`; `installed_plugins.json` names `cache/plot-marketplace/plot/2.28.1`). In this repository the board and fleetd run the checkout's bundle. Both `package.json` and the plugin say `2.28.1`, yet `main` carries #2740 and later. A semver comparison is therefore undefined here. A bundle hash compares only within one source. A domain contract integer is the one comparison that holds across both sources, and across adopting repositories.
- **Slice 2 compares the wrong pair for adopting repositories (read).** `plot-board-probe.sh:300-330` resolves a plugin board from `marketplaces/` and falls back to the newest-mtime `cache/<version>/` copy. `plot-fleetctl.sh:118` runs `$script_dir/board/plot-fleetd.mjs`, and the unit bakes that path in (`supervisor_bundle_path`, `:219`). After a plugin update the old `cache/<version>/` directory stays (four versions sit there now). The file the process started from does not change, so "start bundle vs bundle on disk" stays equal for ever. The reading must compare against the bundle the probe or fleetctl would resolve **now**, not against the started path.
- **Slice 2 is too noisy in this repository (ran).** `board-server.mjs` changed in 56 commits between 2026-10-20 and 2026-10-27, and `plot-fleetd.mjs` changed in 49. A hash or mtime comparison reads `stale` most of every day. Operators learn to ignore a signal like that. The contract integer above flags only a contract change. A plain "bundle differs" reading can still ship as evidence, but it should not carry the word `stale`.
- **Prior art the plan does not cite (read).** `packages/domain/src/rules/loop-restart.ts` already compares `loadedHash` with the on-disk content hash (`pinnedHash`, `runningHashNow`), read through `refs.hashFilesSync` in `packages/fleet/src/server/entry/worker-loop.ts:346-372`. That answers the "content hash or mtime" question: content hash, the estate's existing choice. The board already renders status entries from domain rules (`checkoutHealthStatus`, `packages/domain/src/rules/checkout-health.ts`, returning a `BoardStatus`). A staleness entry belongs there, which answers the "banner or --status only" question. `plot-fleetctl.sh:823-828` already prints `BUNDLE MISSING` in the running arm. A staleness line goes beside it and reuses `supervisor_bundle_path`.
- **Hash cost (ran `ls -la`).** `board-server.mjs` is 2.35 MB and `plot-fleetd.mjs` is 0.62 MB. Hash once at start. On a read, re-hash only when size or mtime changed. The status payload is polled, so the plan must state this.
- **fleetd has no HTTP status (read).** `plot-fleet --status` is shell. fleetd must therefore record its loaded identity somewhere fleetctl can read: a state file under `.plot/state/`, or the unit's argv plus a hash recorded at start. The plan does not say where. Under "A Decision Reads The Index" this is a recorded reading, not a verdict, so it is allowed. The plan should still name the file and its single writer.

## 3. Safety

- Neither slice kills, restarts or refuses a spawn. Leaving automatic reload and spawn refusal out is correct. `the-board-does-not-reload-its-bundle` and `board-stop-kills-continued-agents` (memory) show that a restart while continued agents run kills them.
- **Path to refused work (read).** Slice 1 as written puts the stale-spawner hint in front of every desk worker and every idea, interrogate, verify and design agent that hits the refusal. The existing text tells them to resolve `plot_desk_root` and retry, and that works. A hint that names "restart the board and fleetd" invites an unattended agent to write `PLOT-BLOCKED` and wait for an operator. That stalls a slice that would have succeeded. The contract-integer form removes this path, because the hint appears only when the spawner really is older.
- Slice 2's status read is read-only. It must not block `/api/board` on a 2.35 MB hash per poll (see the cost note above).

## 5. New defects and gates

- **`scripts/check-shell-lines.sh`** ratchets shipped shell lines against the merge base. A staleness line in `plot-fleetctl.sh` (1374 lines) or `plot-boardctl.sh` (574 lines) has to remove at least as many lines elsewhere. Better: put the comparison in a domain rule reached through a bundle, as `board/plot-old-label.mjs` does for `oldLabelAction`, so the shell only prints. "Reduce shell, grow the domain" points the same way. The plan says nothing about this.
- **`scripts/check-decision-count.sh`.** A staleness comparison written in shell adds a *decision* to a README row. A comparison in a bundle keeps the row's kind as it is.
- **Layering.** The domain must not hash files. Pass hashes in as readings (the `loop-restart` shape), and let the adapter (`refs.hashFilesSync`) read them. "Every rendered state is a domain property" requires the staleness entry to come from a domain rule plus a `packages/board/src/contract/schema.ts` field, not from a `.tsx` decision.
- **Bash 3.2.** Any new fleetctl or boardctl code must pass `scripts/check-bash32-syntax.sh`. A hash in shell would need `shasum` on macOS and `sha256sum` on Linux. That is one more reason to do it in the bundle.
- **Adopting repositories.** The contract integer is project-agnostic and travels with the plugin. A "same path on disk" comparison does not, as section 2 shows.
- **Arrow functions** in every new domain rule (`packages/domain/**`), and TSDoc without narration. Domain-package rules from CLAUDE.md.
- **Gate observation (ran, incidental).** A read-only `sed -n` over `plot-dispatch.sh` was refused by the 2.28.1 controller gate as "a controller-owned action". The gate also matches a read of the script, not only a run of it. That is outside this plan's scope but is the same family of contract defect.
