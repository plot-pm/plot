# Juror verdict: layering

Position: amend
Evidence: Read the plan, issue #2906 (`gh issue view`), DESIGN-delivery-loop.md, sibling plans #2903, #2898, #2900 and #2901 (grep), `rules/ending-action.ts`, `rules/fresh-agent.ts`, `ports/fresh-agent-record.ts`, `rules/dead-claim.ts`, `rules/claim.ts:77`, `rules/restart-offer.ts`, `workflows/dispatch-verbs.ts:124-259`, `workflows/dispatch.ts:42`, `board/src/server/restart.ts`, `fleet/src/shared/restart-command.ts`, `fleet/src/server/entry/restart-command.ts:89`, `fleet/src/server/entry/registryd.ts:641-1200`, and the readers of `Claim stale after`. Ran `pnpm install` in the worktree, then a scratch vitest probe (`juror-2906-layering/overlap.test.ts`, 3 of 3 passed) that feeds dead-desk readings to the real `endingAction`, `restartWorker` and `restartOffered`.

## (a) Problem statement

- **Wrong rule cited for the person stop.** `rules/fresh-agent.ts` decides nothing. It only composes the prompt text (`freshAgentAnswer`, fresh-agent.ts:52-75). The "second failure asks a person" decision is in `endingAction` (`rules/ending-action.ts:320-370`): `priorFreshSessions > 0 ? 'needs-a-person' : 'start-fresh'` at :351, :354 and :361. The tick acts on that verdict by writing a `PLOT-BLOCKED.md` marker (`registryd.ts:1121`, `:1177`). The probe confirms it: `corrections-spent`, `turn-limit`, `holding-work` and `bound`/`unreadable`/`quiet` with work each answer `needs-a-person` at `prior=1`. That is six ending reasons, while the plan names only "the fresh session failed".
- **`dispatch.ts:42` is a type comment.** The unattended refusal is decided in the domain workflow `restartWorker` (`dispatch-verbs.ts:194-199`), which reads `unattended: boolean`. That boolean comes from `process.env.PLOT_UNATTENDED` at three call sites: `board/src/server/restart.ts:68`, `fleet/src/server/entry/restart-command.ts:89` and `restart-stopped-command.ts:103`. "The controller reads `PLOT_UNATTENDED`" is therefore half right. The place to change is the domain reading, not a controller.
- **The issue does not cite the restart controller path.** fleetd lives in `packages/fleet`, and `restartBranch` (`fleet/src/shared/restart-command.ts`) is in the same package. The board's HTTP route (`restart.ts`) is not the path fleetd should take, because CLAUDE.md lists `restart` among the four actions that run without a board.

## (b) Approach, against the layering lens

1. **Two parallel rules on one population break "one rule, one answer".** `endingAction` already answers every desk that is unregistered, plan-named, not main and has no manifest (`freshAgentCandidateTrees`, registryd.ts:659). `deadClaims` (`dead-claim.ts:55`) answers claimed branches with no live holder. The plan adds `freshSessionFailedFixer` and `deadDeskRestart` beside them, and neither names a precedence. The probe shows the collision. A dead desk with no PR and no marker gets `release-claim` from `endingAction` for `nothing-done` and for `bound`/`unreadable`/`quiet` with nothing beyond the claim. For a first `bound` with work it gets `start-fresh`. For a second fresh-session ending it gets `needs-a-person`. `deadDeskRestart` answers `restart` for every one of those desks. In one tick, fleetd would release a claim and restart the same branch, or start a fresh session and a restarted worker on one desk. That gives two writers on one branch, which the spec's *One writer per branch* forbids. The fix in domain terms is to add verdicts to `endingAction` (`start-fixer`, `restart`) in place of the `needs-a-person` arms they replace, so that one table stays exhaustive and testable from readings. Do not add a second rule that the tick has to reconcile.
2. **The restart rule bypasses the outright-person endings.** `NEEDS_PERSON_ENDINGS` (`ending-action.ts:217-224`) exists because a restart does not fix `unstarted`, `spend-limit`, `run-limit`, `checks-unanswered` or `permission-denied`. `deadDeskRestart` reads only the worker state, PR and marker, so it restarts a spend-limited or permission-denied desk on every tick until a marker appears. After a person or the #2901 unblocker removes the marker, it restarts the desk again. The rule must read the ending reason, and it has no restart count, so a crash-looping desk restarts without a bound. Spec *Stalls* says the loop must not "loop silently".
3. **`failed` is already a handled state.** A worker that exited non-zero with no ending gets `unreadable` from `killedWorkerEnding` (`ending-action.ts:632`), and `endingAction` then answers it. Adding `failed` to the restart population gives the same desk a second mechanism: `restartWorker` launches the ordinary dispatch worker, while `start-fresh` continues through `continue`. The plan should measure which desks fall through every existing rule today, for example `none` with no ending and no manifest, and restrict the restart arm to that measured population.
4. **"No pull request" cannot be read from the index.** CLAUDE.md, *A Decision Reads The Index*, says the index never answers `pr: 'none'`. The selection rule can therefore only say "no MERGED or OPEN row is known", and the controller must confirm. It does: `restartBranch` re-asks `hostShell(...).prState` (restart-command.ts ~:67) and `restartWorker` refuses `reached-review` and `pr-unanswerable` (dispatch-verbs.ts:208-219). That part is right and the plan should state it. One cost is missing from the plan. A desk whose open PR the index has not seen is refused on every tick, with one host call per tick. Record the refusal (the `refused-slices` port already has this shape: a set that a person or a later event clears), or key a back-off on it, so a refused restart is not re-asked every pulse.
5. **The fixer slice duplicates #2903's arm 4.** #2903 builds `slice-pr-next` "CI red, desk dead or corrections spent → start fixer" with a per-PR attempt file. A `corrections-spent` desk has a red PR, so both rules select the fixer for the same PR. The plan has to split the population. The PR-loop rule (#2903) owns every desk with a PR. `endingAction`'s second-fresh arm answers `leave` (handed to the PR loop) where a PR exists, and `start-fixer` only where none exists. For the no-PR case, #2903's per-PR attempt file has no key. The plan must name the key (plan plus branch, as `FreshAgentRecord` uses) or say that a no-PR desk gets a restart instead.
6. **The caller-identity lift belongs to #2898.** Slice `feature/fleetd-caller-identity` in #2898 already lifts `restart`'s unattended refusal for fleetd. This plan's Approach describes building the lift again. It should only consume it. In domain terms, the lift belongs in `restartWorker`'s readings, where a caller reading replaces `unattended: boolean`, and is not an env check in a controller.
7. **The marker write is still live.** If `needs-a-person` stays for any of the six endings, the tick writes `PLOT-BLOCKED.md`, and #2901's unblocker answers it through `continue` while a fixer runs. The plan must say that the `start-fixer` verdict replaces the marker write. Today `applyFreshAgentDecisions` has no third arm for it (registryd.ts:1146-1186).
8. **Things that are right.** No new shell, and the ratchet holds. Agent starts go through the `agent-run` adapter. The decision stays pure. The vocabulary rule holds: process states live on the worker, and the ending reason is an agent fact.

## (c) Slices

- Order is right: nothing starts before #2898 and #2903 merge. The two slices are **not** independent, though. Both change `endingAction`'s table and `applyFreshAgentDecisions` (once they are folded in as (b)1 asks), so they conflict in `ending-action.ts` and `registryd.ts`. Serialise them (restart waits on fixer), or cut one slice for "the table gains `start-fixer` and `restart`" and one for "the tick applies them".
- Missing: the board row's domain property, which the Board-impact comment promises. No slice builds it.

## (d) Open questions

- **Restart as a fixer attempt.** No, but it needs a count of its own. Record restarts per slice, for example as rows in `fresh-agents.tsv` with a kind column, or in a sibling record. After one restart that dies again, answer `start-fixer` or notify. Without a count the arm loops (see (b)2).
- **Where the attempt count lives.** #2903's file is keyed per PR, and a no-PR desk has no key. The plan must name a key (plan plus branch). Otherwise, for a desk with a PR, it should hand off to #2903 and keep no count.
- **The no-worker bound.** The premise is wrong. `Claim stale after` (24 h) is read only by `plot-reconcile-scan.sh:374`, and neither fleetd nor the reaper reads it. The domain's launch-race bound is `ORPHANED_CLAIM_AGE_MS = 60_000` (`rules/claim.ts:77`), which `deadClaim` and `orphanedClaims` share. Reuse that bound, so that both rules name the same branches on the same readings, as `dead-claim.ts` already argues.
- **`elsewhere`.** No. `restartOffered('elsewhere')` is false (probe), and `restartWorker` refuses `no-worktree`.
- **New question 1.** Why is `stalled` excluded? `restartWorker` and `restartOffered` accept it (dispatch-verbs.ts:169, restart-offer.ts:2). Name the reason or include it.
- **New question 2.** Which of the six fresh-session endings earn a fixer when the desk has no PR (`turn-limit`, `holding-work`, `bound`)? The fixer role is defined as "commits on the PR's branch" (spec, *Role agents*).

## (e) Tests

- Domain unit (`packages/domain/test/rules-ending-action.test.ts`): extend the table with `start-fixer` and `restart`. Add one exhaustive property test over ending × prior × fixerAttempts × PR × marker × worker state, which asserts exactly one verdict and that `NEEDS_PERSON_ENDINGS` never answer `restart`.
- Domain unit (dispatch-verbs test): `restartWorker` with the fleetd caller reading is not refused as `unattended`, and every other unattended caller still is. This belongs to #2898's slice, and this plan only depends on it.
- Fleet unit (`packages/fleet/test/unit/fresh-agent-tick.test.ts`): `start-fixer` starts through a fake `agent-run`, writes no marker and appends one attempt row. `restart` calls a fake `restartBranch`, records a `reached-review` refusal, and the next tick makes no second host call.
- No e2e. A browser test only for the board row once the domain property exists.

## Amendments

1. Cite `endingAction` (`ending-action.ts:351/354/361`) and the marker write (`registryd.ts:1177`) as the person stop, not `fresh-agent.ts`. Cite `restartWorker` (`dispatch-verbs.ts:194`) for the refusal, not `dispatch.ts:42`.
2. Fold both decisions into `endingAction` as new verdicts that replace `needs-a-person` arms, with one exhaustive table. Do not add two parallel rules. Name the precedence against `deadClaims` and `release-claim`.
3. Hand every desk with a PR to #2903's `slice-pr-next` fixer arm. This plan's `start-fixer` covers only desks with no PR, keyed by plan plus branch.
4. The restart arm reads the ending reason, never restarts a `NEEDS_PERSON_ENDINGS` desk, carries a restart count with a bound, and uses `ORPHANED_CLAIM_AGE_MS` rather than `Claim stale after`.
5. State that selection reads only a terminal or known row from the index, and that `restartBranch` re-asks the host. Record refusals so a refused restart is not re-asked every tick.
6. Drop the caller-identity lift from this plan's Approach, because #2898 builds it. Serialise the two slices, or re-cut them by table and tick.
