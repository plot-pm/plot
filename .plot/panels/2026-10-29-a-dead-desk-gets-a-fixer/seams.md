Position: amend

Evidence: Read the plan, issue #2906 (`gh issue view`), DESIGN-delivery-loop.md, and the Design and Slices sections of all nine sibling plans (#2898, #2899, #2900, #2901, #2902, #2903, #2904, #2905, #2907). Read `rules/fresh-agent.ts`, `rules/ending-action.ts`, `ports/fresh-agent-record.ts`, `rules/restart-offer.ts`, `rules/dead-claim.ts`, `rules/claim.ts:77`, `workflows/dispatch.ts:30-55`, `workflows/dispatch-verbs.ts:124-260`, `board/src/server/restart.ts:68`, `fleet/src/server/entry/restart-command.ts:89`, `fleet/src/shared/restart-command.ts`, `fleet/src/server/entry/registryd.ts:1000-1065`, `plot-reconcile-scan.sh:374`. Ran: a vitest probe (scratch dir `juror-2906-seams/probe.test.ts`, rooted outside the worktree) that called `endingAction`, `restartOffered` and `restartWorker` on the plan's two target desks. Output: `endingAction` with `priorFreshSessions: 1` answers `needs-a-person` for all six of `corrections-spent`, `turn-limit`, `holding-work`, `bound`, `quiet` and `unreadable`; `restartOffered` is true for `stalled`, `failed`, `ended`, `none`; `restartWorker` with `unattended: true` refuses `unattended`, and with `unattended: false` on an `ended` desk with no PR decides `worker-start`. One earlier probe attempt wrote a test file into the worktree's `packages/domain/test/` and trashed it in the same command; `git status` of the worktree is clean.

## (a) Problem statement

- **The "second failure asks a person" decision is not in `rules/fresh-agent.ts`.** That file only composes the fresh session's prompt (`freshAgentAnswer`, fresh-agent.ts:52). The decision is `endingTableAnswer` in `rules/ending-action.ts:349-362` (`priorFreshSessions > 0 ? 'needs-a-person' : 'start-fresh'`), applied by fleetd's `freshAgentDecisions` in `fleet/src/server/entry/registryd.ts:1012-1063`, which writes a `PLOT-BLOCKED` marker (`markerText`, `escalate`). The plan should name the rule it changes.
- **The fresh-agent record cannot say "the fresh session failed".** `ports/fresh-agent-record.ts:4-18` holds one row per *start* (`plan`, `branch`, `worktree`, `at`, `runUrl`), never an outcome. "Failed" is derived: a second ending on a slice whose row count is above zero. The plan's "a rule reads the desk's fresh-agent record … where the fresh session has failed" therefore needs the ending reading too, which is exactly what `endingAction` already takes.
- **"Second failure" covers six ending reasons, not one.** Probe output above: `turn-limit`, `holding-work`, `bound`, `quiet` and `unreadable` reach `needs-a-person` the same way as `corrections-spent`. The plan does not say which of the six get a fixer. A `turn-limit` or `bound` desk may have no PR, and the design's fixer "commits on the PR's branch".
- **Cited locations.** `dispatch.ts:42` is a comment on the `'unattended'` member of the `DispatchRefusal` union in `packages/domain/src/workflows/dispatch.ts`, not in the board. The refusal itself is `dispatch-verbs.ts:194-198`. Two entry points read `PLOT_UNATTENDED` into that reading: `board/src/server/restart.ts:68` and `fleet/src/server/entry/restart-command.ts:89`. The plan names only the board one.

## (b) Approach — seams with siblings

1. **Duplicate deliverable: the restart controller's unattended lift.** #2898's slice `feature/fleetd-caller-identity` builds "`continue`, `restart` and `merge` lift the unattended refusal for that caller only". This plan's Changelog line 2 and Approach ("It lifts that refusal only for fleetd's identity") claim the same change. Owner: #2898. This plan should only *call* `restart` with the identity and assert it is accepted. The lift belongs in `restartWorker`'s readings (`dispatch-verbs.ts:124-136`) so both entries agree; that is #2898's to say.
2. **Overlap with #2903 arm 4.** #2903 builds "CI red, desk dead or corrections spent → start the fixer (same two attempts)" in `rules/slice-pr-next.ts`. A `corrections-spent` desk whose fresh session also failed and whose PR is red matches both that arm and this plan's `freshSessionFailedFixer`. Two rules then start a fixer for one slice, and one-writer-per-branch is no longer held by one rule. Worse, #2903's arm as written fires the moment corrections are spent, before the fresh session that `endingAction` starts; the design's *A dead or stuck desk* section orders it fresh session first, then fixer. Owner of the fixer start: #2903's `slice-pr-next` arm, with "desk dead" defined to include "its one fresh session already ran". This plan's fixer slice then shrinks to changing `endingAction`'s second-failure verdict from `needs-a-person` to a new verdict (for example `hand-to-loop`) that writes no marker and leaves the fixer start to `slicePrNext`.
3. **Unnamed collision with #2901 (unblocker).** Today the second failure writes a `PLOT-BLOCKED` marker (registryd.ts:1052-1060). Once #2901 lands, `unblockerDue` sees that marker and starts the unblocker, which answers through `continue` — a third session on the desk — while this plan starts a fixer on the same branch. Two writers on one branch, which the design forbids. The plan must state that the second-failure arm stops writing the marker, and #2901 must know the marker no longer arrives from that path. Neither plan names the other.
4. **Collision between this plan's own two slices, and with existing rules.** A desk whose second fresh session ended reads `ended` or `failed` (plot-worker-state.sh:1276, 1389). If it has no PR, `deadDeskRestart` answers *restart* on the same tick that the fixer slice (or today `needs-a-person`) answers for it. A `turn-limit` desk with `priorFreshSessions: 0` and no PR reads `start-fresh` from `endingAction` and *restart* from the new rule. A claimed branch with only claim commits reads `deadClaim` → release (`rules/dead-claim.ts:35-40`) and *restart*. The plan names no precedence. Proposal: `deadDeskRestart` answers only where the desk has no ending file, or where `endingAction` answers `leave`, and never where `deadClaim` is true.
5. **Restart has no bound.** The design gives fixers two attempts; the plan's OQ1 says a restart is not a fixer attempt, and nothing else counts restarts. A desk that dies on every start is restarted on every tick. #2899's stall rule only notifies and holds nothing. The plan needs a restart budget (recorded per slice, readings-as-values), or a statement that a restart is counted as a fresh session in `fresh-agents.tsv`.
6. **Run log not named.** The design's *Stalls* section says fleetd records one line per loop step; #2899 builds that log, and #2900 and #2901 list #2899 as a prerequisite. This plan's two steps (fixer start, restart) write no run-log line and do not name #2899. #2899's stall rule 2 ("spent both fixer attempts on the same finding") cannot see a fixer this plan starts unless it logs.
7. **Prerequisites misattributed.** The plan says #2903 supplies "the fixer runner". #2903 builds the rule arms and the attempts file only, and lists "the `fixer` role definition itself" as out of scope. The runner (`feature/agent-run-takes-a-role`) and `fixer.md` (`feature/role-agent-definitions`) are #2898's. The attempts file is #2903's slice `feature/a-high-finding-is-fixed-before-rule`; this plan reads it, which matches #2903's "written by one place".
8. **Which restart route fleetd calls.** The plan names `packages/board/src/server/restart.ts`. fleetd must not need a running board; the board-free route is `fleet/src/shared/restart-command.ts` (`plot-restart-command.mjs` in CLAUDE.md). The plan should name that one and say both entries read the same caller field.
9. **States.** The plan lists `failed`, `ended`, `none`. `restartOffered` (`rules/restart-offer.ts:2`) and `restartWorker` also accept `stalled`. Reuse `restartOffered`, or say why `stalled` is excluded (a stalled tree holds uncommitted work, dispatch-verbs.ts:146-154, which is a fair reason to leave it to a person).
10. **Layering and shell ratchet.** No issue found: both rules can be pure readings-as-values rules in `packages/domain/src/rules/`, and the calls go through existing adapters.

## (c) Slices

- **Over-waiting.** "No slice below starts before both merge" makes the restart slice wait on #2903, which it does not use. The restart slice needs only #2898's `feature/fleetd-caller-identity`. The fixer slice needs #2898's runner and definitions, and #2903's `feature/a-high-finding-is-fixed-before-rule`. Name branches, not plans, in `<!-- waits: -->` markers.
- **Missing.** No slice builds the board domain property the board-impact comment promises; either add it to a slice or drop the claim.
- **Possibly out.** If finding (b)2 is adopted, the fixer slice becomes a change to `endingAction` plus registryd's application of it, not a new rule — smaller, and it should say so.

## (d) Open questions

- **OQ1 (restart counts as fixer attempt?):** Agree no. But then a separate restart bound is required (finding b5).
- **OQ2 (which record holds fixer attempts):** #2903 owns it — its rule slice builds "a per-PR fixer attempts state file". Closed; name the branch.
- **OQ3 (how long before restart):** The premise is wrong. `Claim stale after` (24 h on this repo) is read only by `plot-reconcile-scan.sh:374`, not by a reaper; the fleet's dead-claim bound is `ORPHANED_CLAIM_AGE_MS = 60_000` (`rules/claim.ts:77`). Reusing 24 h would leave a dead desk idle for a day. Reuse the 60 s launch-window bound or a manifest/pid start time.
- **OQ4 (`elsewhere`):** Agree no; `restartOffered('elsewhere')` is false (probe).
- **New:** Which of the six second-failure endings get a fixer, and what happens to a no-PR desk among them (fixer has no PR; restart would loop)?
- **New:** What happens after two fixer attempts on a *red-CI* PR (not a HIGH)? #2903's ticket path is for HIGH findings and a red PR cannot merge. Owner should be #2903 or #2899's stall rule; this plan should say which.
- **New:** Does the second-failure path still write `escalations.tsv` and the `PLOT-BLOCKED` marker? If yes, #2901 answers it too.

## (e) Tests

- Domain unit (`packages/domain/test/rules-ending-action.test.ts`): each of the six endings with `priorFreshSessions: 1` answers the new verdict instead of `needs-a-person`, and no marker text is composed for it.
- Domain unit for `deadDeskRestart`: each of `stalled/failed/ended/none` × {PR none, PR open, PR unanswerable, blocked marker, ending file present, deadClaim true, within launch window}; assert precedence against `endingAction` and `deadClaim` on shared fixtures so the arms disagree.
- Domain unit (`workflows-dispatch-verbs.test.ts`): `restartWorker` refuses `unattended` for an unattended caller without fleetd's identity, and decides for fleetd's — this test is #2898's; this plan only re-asserts it at the fleet tick.
- Fleet unit (`packages/fleet/test/unit/fresh-agent-tick.test.ts`, `restart-command.test.ts`): the tick writes no `PLOT-BLOCKED` marker on a second failure, starts the fixer once across two ticks, and restarts a dead desk at most the budget's number of times.
