# Layering juror: jenkins_sha_runs through jen

Position: amend

## Summary

The direction is right. One transport for Jenkins (`jen`) inside `plot-host.sh`, the one script that reaches a host CLI, removes a second Jenkins transport (`curl -u`) and two helpers. The plan's line numbers and "only caller" claims are true. Three layering decisions are wrong or missing: the plan keeps a budget/slot bracket that the `jen` wrapper already applies, it drops the `.env` credential source with no replacement, and it understates the test and doc surface that the removed transport leaves behind.

## Findings

1. **Double bracket (HIGH).** The plan says "the `host_slot_take` / `budget_record_call` bracket around each request stay[s]" (Design › Approach). `plot-host.sh:3905-3915` defines a `jen()` shell function that already calls `host_slot_take jenkins ''`, `command jen`, `host_slot_give` and `budget_record_call jenkins ''`. A `jen -I "$slug" api …` call inside `jenkins_sha_runs` resolves to that wrapper, so with the bracket at `plot-host.sh:2066` and `:2068` kept, every request records two Jenkins calls in the budget ledger. The slot side is latent today: `budget_reading` (`plot-host.sh` `*)` arm) records Jenkins with basis `unknown`, so `host_concurrency_bound` returns 1 and no slot is taken. Once Jenkins records basis `predicted` (the `ci-limit` arm at `plot-host.sh:5966` already says `limit 60, predicted`), the bound is `max(1, 60*4/3600)` = 1, the outer bracket holds slot 0 under `$$`, the inner wrapper in the `$(…)` subshell sees slot 0 held by a live `$$` (`budget_slot_held`, `plot-budget.sh:900`), and waits `PLOT_SLOT_WAIT_MAX_S`=30 s before it proceeds. That is 30 s per path, two paths per branch, per bound row. The wrapper is the one place that meters `jen`; the explicit bracket must go.

2. **The `.env` credential source disappears (HIGH).** `jenkins_rest_credential` (`plot-host.sh:1922-1929`) reads `JENKINS_USER`/`JENKINS_API_TOKEN` from the environment, then from `plot_env_file` (the worktree's or the main checkout's `.env`), then the keychain. The `.env` arm is a delivered requirement: `docs/plans/2026-10-16-the-agent-s-ci-wait-never.md:50` ("Without it, no Linux machine reaches gap 1's fix"). `jen` reads the environment and its own secret store (`jen --help`: keychain on macOS, env-only elsewhere) and never a repository `.env`. Removing the helper without a replacement makes a Linux agent that holds its pair only in `.env` lose Jenkins status. The layering-correct fix follows `jira_load_env_file` (`plot-host.sh:3088-3095`): when both vars are unset, read them through `plot_env_file` and `export` them so `jen` sees them in its environment. `plot_env_file` and `read_env_var` keep their Jira callers (`plot-host.sh:3067`, `:3091`, `:3093`), so this adds no parser. The plan must either name this export or state the regression and accept it.

3. **Helpers that lose callers.** `jenkins_resolve_host` (`:1954`) and `jenkins_rest_credential` (`:1922`) have exactly the call sites the plan names (`:2055`, `:2058`); I confirmed no caller in `packages/`, `scripts/` or other skills. `plot_env_file`, `read_env_var` and `jenkins_job_url_path` keep callers. The `security` keychain lookup keyed `jenkins-user:<host>` goes with the helper, which is correct: `jen` owns its keychain.

4. **The refusal names a variable the plan removes.** `plot-host.sh:2088` prints `Jenkins did not answer for '$host'`. With `host` resolution removed, the plan must say the refusal names `$slug` (or the instance). An unattended agent will otherwise keep `host` assignment code alive only to feed this message.

5. **Docs that describe the old transport (MEDIUM).** The plan names only the comment above `jenkins_sha_runs`. These also state the curl/basic-auth transport and become false: the `NO CREDENTIAL IS *CANNOT BE ASKED*` paragraph and `curl failure` wording in the same block (`plot-host.sh:1987-1990`, `:2044`); `build-jenkins.ts:78-89` TSDoc ("`runForSha` ASKS JENKINS' REST API", "THE CREDENTIAL IS NOT THE KEYCLOAK BEARER … A machine with no keychain entry answers `unaskable`"). `plot-config.sh:250` stays true unchanged, which answers the plan's third open question.

6. **Test surface is larger than "references both helpers" (MEDIUM).** `test/reconcile/host.test.mjs` stubs `curl` in 25 places (`makeCurlAnswering` at `:2993`, the `:2860` and `:3997` fixtures) and sets `JENKINS_USER`/`JENKINS_API_TOKEN` in about 20 env blocks. The shared `makeJenStub` (`:2660-2705`) answers `auth`, `job view` and `job list` and exits 0 with no output for anything else, so after the change every one of those tests reads "Jenkins did not answer" rather than failing on a missing helper. Eight tests assert credential behaviour that no longer exists: `:3029`, `:4495`, `:4516`, `:4998`, `:5263`, `:5409`, `:8471`, `:8589`. The slice must say: add an `api` arm to `makeJenStub` that records argv and answers a per-path body (including exit 1 with the status on stderr for the 404/302/401 cases, per `jen api --help`), migrate the curl fixtures to it, and delete or rewrite the credential tests (keeping one that proves the `.env` export from finding 2). `packages/domain/test/pr-status.test.ts:112-125` parses the `read from the environment` notice; the notice keeps a meaning only if finding 2's export prints it.

7. **Timeout is dropped.** `curl --max-time 30` (`:2067`) bounds each request today. `jen api` has no timeout flag (`jen api --help`), and the `jen()` wrapper adds none. Other `jen` calls share this, but `jenkins_sha_runs` runs once per bound PR row. The plan should state whether it accepts an unbounded wait or names a bound.

8. **One transport, one gate.** `scripts/check-host-cli-callers.sh` checks callers outside `plot-host.sh` and is unaffected. `curl` stays in `plot-host.sh` for Jira (`:3113`), so the plan's "Plot reaches Jenkins only through `jen`" is the correct, narrower claim. The shell-lines ratchet (`check-shell-lines.sh`) only gains room: the change removes about 25 lines even with finding 2's export. Nothing in the change needs bash 4. The Bitbucket arm (`plot-host.sh:4939`) reaches `jenkins_sha_runs` through `jenkins_bind_rows` and inherits the fix with no change.

## Rubric answers through this lens

1. It fixes #3061 for the proxied case by construction. For the unproxied case it depends on `jen` working without a Keycloak bearer on a non-Quatico instance; the plan's table claims HTTP 200 but the Motivation says the path "passed testing on an instance without a proxy, where plain basic auth works", which reads as a `curl` result. The plan should name the `jen api` run on the unproxied instance and its verification command.
2. Line claims `:2047`, `:2055`, `:2058`, `:1776` and `plot-config.sh:250` are true on `main` (worktree file identical to `main`). The "bracket stays" claim is wrong per finding 1.
3. See findings 2, 5, 6, 7.
4. `jen api` exits 1 on HTTP 400 or above and prints the status and the body head to stderr (`jen api --help`, jen 0.4.0). `2>/dev/null` plus `|| true` leaves stdout empty, which fails `has("builds")` and keeps exit 4 (`unaskable`, `checksLookup: broken`) — honest. A 302 is below 400: whether `jen` follows it and prints the login HTML with exit 0 is unverified; either way the HTML fails `jq -e .`, so `branch_answered` stays unset and the refusal stays "did not answer". jen 0.4.0 ships `api`; 0.2.0 is unverified.
5. Missing decisions for a Sonnet agent: drop the bracket or call `command jen` (finding 1); the `.env` export (finding 2); what the refusal names (finding 4); the stub shape and which credential tests go (finding 6); the timeout (finding 7).
6. Not yet: no test named fails before the change, and the stub needs an `api` arm. A stubbed `jen` that answers the builds body only when its argv is `api <path>` and records the argv covers the proxied case, because the proxy is invisible past `jen`. A test that `curl` is never invoked (a `curl` stub that fails loudly) proves the transport moved.

## Amendments required

1. Remove the explicit `host_slot_take`/`host_slot_give`/`budget_record_call` lines around the request and let the `jen()` wrapper meter it. Add a test that one `runs-for-sha` records exactly one Jenkins ledger line per path.
2. Keep the `.env` credential source: before the first `jen api`, when `JENKINS_USER` and `JENKINS_API_TOKEN` are both unset, export them from `plot_env_file` the way `jira_load_env_file` does, and print the source notice. Or state the Linux regression explicitly and get it approved.
3. Name the refusal text after `host` is removed (`for instance '$slug'`).
4. List every doc site to rewrite: the comment block `plot-host.sh:1971-2045` (transport and credential paragraphs) and `packages/domain/src/adapters/build/build-jenkins.ts:78-89`.
5. Specify the test migration: an `api` arm in `makeJenStub`, the 25 `curl` fixtures moved to it, the credential tests listed in finding 6 deleted or rewritten, and a `curl` stub that fails if called.
6. State the timeout decision for `jen api`.
