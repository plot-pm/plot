# Seams juror — fleetd's fixer and main-repair agents never start

Position: amend

The diagnosis is right and the command fix is right: on `origin/main` the only production builder that hands `--agents` a path is `roleCommand`, and only two production starts reach it, the fixer (`auto-fixer.ts:383`) and main-repair (`repair-role.ts:133`). Both run the fragment through `agentRunCommand`, which runs `bash -c '<fragment> "$@"' _ <prompt>` (`agent-run-command.ts:65`), so `--agents "$(cat '<file>')"` expands; I ran that exact runner shape once with Claude Code 2.1.316 and the fixer answered "OK". Three statements in the plan are false on main, and two of them change the slice: the reviewer does not share `roleCommand` and the unblocker has no production start; a failed start is not left in flight but spends the correction budget (all 32 recorded attempts are settled, 15 of 19 PRs are exhausted, 3 of them still open); and `repair-role.ts` does not return `'failed'` for a start that dies, it returns `'started'` and the episode's only attempt is recorded `ended`. The budget seam reaches a third reader the plan does not name, `auto-ticket.ts`, which accepts a HIGH on an exhausted record. The plan needs these corrections and a split into two slices so the one-line command fix lands first.

## Open questions

- Q1 (does the runner use a shell?): Yes. `agentRunCommand` runs `env -u PLOT_REPO_ROOT bash -c '<fragment> "$@"' _ <prompt>` (`agent-run-command.ts:65`), and both role callers are hard-wired to it (`auto-fixer.ts:615`, `repair-start-world.ts:53`). I ran that exact shape with `--agents "$(cat '.plot/state/fixer/3023.agents.json')"` on Claude Code 2.1.316 and the fixer answered "OK". Keep `$(cat)`: the JSON is 1.2 KB against an `ARG_MAX` of 1 MiB, it keeps the file as the one carrier that the SDK path also reads, and it keeps the role prompt out of the logged command. Inline `singleQuote(json)` also works and is the fallback if a reviewer wants the fragment self-contained.
- Q2 (how is a dead start detected?): By the run's own end: non-zero exit (`end: unstarted`) plus the CLI's startup refusal line in the run's appended output, held as a named harness pattern (A6). Not by a timer and not by the absence of an agent event, which plain `-p` text output does not emit. The attempts record needs a field for it: an optional `start: 'failed'` on the attempt, decoded as absent on old records.
- Q3 (does a failed start spend a correction attempt?): No. It records a failed start and holds that head until it moves (A3). The existing records: the three open PRs with exhausted records (#3012, #3021, #3022) stay exhausted under the new rule, because their old attempts carry no failed-start field. The plan states that a person moves those three files aside after slice 2 lands; the slice does not rewrite records it cannot tell apart.
- Q4 (real-CLI test in CI?): Local only, skipped when `claude` is absent, and the fake CLI is the gate. CI has no `claude` and no token, and a real run costs money and time on every PR. The fake must reproduce the real refusal line from the live log so the two agree.
