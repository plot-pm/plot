## (a) Problem statement

The motivation is measured: times, exit code 143, the pulse fields and the two controller refusals (plan.md:21-26). The gap it names is real: `--restart` has no endpoint and no bundle, and the controller gate deliberately leaves it ungated because it has none (controller-gate.test.mjs:328-340).

One stated fact is wrong, and it changes which problem is right. plan.md:30 says "a worker that a person or `--stop` ended ... no rule answers it", and Open Question 2 (plan.md:46) says `ending-action.ts` "has no row for an ending that `--stop` writes". Both are false. `plot-dispatch.sh --stop` writes `{"reason":"stopped","actor":"operator"}` (plot-dispatch.sh:1882-1887), `stopped` is in `EndingReasonSchema` (ending.ts:161), and `endingAction` answers `leave` for it by design (ending-action.ts:149, and `killedWorkerEnding` respects it at :625). The comment at plot-dispatch.sh:1882-1885 states the intent: "A PERSON'S STOP IS RECORDED AS ONE, so the supervisor's tick leaves the desk alone."

So the defect behind the 2026-10-27 measurement is narrower than "no rule": `plot-fleetctl.sh --stop` stops every agent through `plot-dispatch.sh --stop` (plot-fleetctl.sh:1296), so a fleet-wide pause is recorded with the same reason, actor and detail as a person's deliberate stop of one slice. The supervisor cannot tell them apart, and `leave` is correct for one and wrong for the other. The plan must restate this; otherwise route 2 and Q2 are designed against a missing row that exists.

## (b) Does the approach solve it without a new defect

Route 1 (controller action) closes the controller gap and is the right shape. Two risks need a sentence each in the Approach:

1. Duplicate rule. The plan's domain rule "accepts only ... `failed` or `ended` and whose desk exists" (plan.md:38) is a second implementation of `handover_refusal` (plot-dispatch.sh:1028-1072), which also refuses an open or merged PR first, a live loop, a running worker and a `PLOT-BLOCKED` marker, and accepts `stalled` and `none`. The plan's rule names no PR check. The script's comment (plot-dispatch.sh:1934-1949) records why the PR goes first: five of five `failed` desks held a PR. A domain rule without it would admit a desk the script then refuses, so the endpoint returns a script failure where it should return a named refusal. CLAUDE.md *A Shell Script Asks The Domain* allows the duplicate only when declared, with a corpus test at `packages/domain/corpus/`. The plan says neither. Either the domain rule carries the full refusal set and a corpus test pairs it with `handover_refusal`, or the script asks the domain and its shell copy goes.
2. Narrower than the script. Excluding `stalled` and `none` (accepted at plot-dispatch.sh:1957-1960) is either deliberate or an accident; the plan must say which.

Route 2 as written (plan.md:39) restarts "the workers that `--stop` stopped", but `--stop` leaves no record that distinguishes its stops from a person's earlier `plot-dispatch.sh --stop` of the same branch. A `--start` that restarts every `stopped` desk would undo a person's decision. That is a new defect unless `--stop` first records its own stops (a distinct `actor`/`detail`, or a list file) and `--start` reads only those. Route 2 also competes with `--start N` for the machine bound (plot-fleetctl.sh:1220-1226); the plan does not say whether restarts count against N.

## (d) Open questions a person must decide before approval

1. Route 1 only, or route 1 plus a fleet-stop fix? Recommendation: both, but route 2 reworded as "a fleet stop records itself as one, and the tick restarts it", built in the domain, not as new restart logic in plot-fleetctl.sh. Route 1 alone leaves every `--stop`/`--start` cycle needing a manual restart per desk.
2. Q2 restated: should a `stopped` ending written by `plot-fleetctl.sh --stop` answer `leave` like a person's stop, or a restart on the next `--start`? Recommendation: a distinct actor or detail and a restart; a person's single-slice stop keeps `leave`.
3. Q3, which states route 1 accepts: the script's set (`failed`, `ended`, `stalled`, `none`), or the plan's (`failed`, `ended`)? Recommendation: the script's set, with the PR-first refusal, so the domain and the script agree and a corpus test can hold them together. `finished` with unlanded work stays out; that is the tick's `start-fresh` row.
4. Duplicate or delegate: does the domain rule duplicate `handover_refusal` under a corpus test, or does `plot-dispatch.sh --restart` ask the domain and drop its shell copy? Recommendation: delegate; it lowers the shell count, which the ratchet rewards.
5. Does a fleet restart count against `--start N`? Recommendation: yes, restarts first, so the machine bound holds.
