# Juror verdict: failure modes and safety

Position: amend
Evidence: Read `skills/plot/scripts/plot-dispatch.sh` `--restart` end to end (1898-1995), `handover_refusal` (1028-1067), `reached_review` (1760-1771), `start_worker` (1109-1305), `--stop` (1824-1896); `plot-worker-state.sh` `plot_worker_state` (1196-1371); `plot-fleetctl.sh` `--stop` (1249-1300); `packages/domain/src/workflows/dispatch-verbs.ts` `restartWorker` (123-235); `packages/domain/src/rules/continue-target.ts` (1-165); `packages/domain/src/rules/ending-action.ts` (12-150, 618-640); `packages/fleet/src/shared/continue-lock.ts` (1-165); `packages/fleet/src/server/entry/registryd.ts` (1105-1180). Ran `plot_worker_state` in a sandbox under `scratchpad/juror-safety/` on three hand-built desks: exit 143 + dead pid reads `failed`; dead pid + no exit file reads `ended`; a pid file naming a live unrelated process (no manifest, wrapper file present) reads `running`.

The plan names a real gap and the right route (a controller), and the script it reaches already refuses the worst cases (live worker, live loop, PR, marker). But the plan's own refusal list is narrower than the script's, it ignores an existing domain rule, and it does not name the per-desk lock that `continue` and fleetd already use. Those are amendments, not a reason to reject.

## (a) Problem statement

The facts are measured and dated (plan lines 21-26): exit 143 at 15:06, the pulse row's three words, the two controllers and what each refused. I confirmed the mechanism: `plot-fleetctl.sh:1297` calls `plot-dispatch.sh --stop` per branch; `--stop` signals the process group (`plot-dispatch.sh:1866-1873`), writes a `stopped` ending (`:1887`), and keeps desk and claim (`:1888-1890`). The exit file then holds 143 and `plot-worker-state.sh:1363` reads `failed` (sandbox desk1 reproduces it). `endingAction` answers `leave` for `stopped` (`ending-action.ts:147-149`), and `continueTarget` refuses `no-question` first (`continue-target.ts:141`). So no controller reaches a new worker. The problem is the right one.

One factual gap: the plan says "nothing a master agent may call reaches it" but does not mention that the domain already holds `restartWorker` (`dispatch-verbs.ts:177`) with zero production callers (only `packages/domain/test/workflows-dispatch-verbs.test.ts`). The slice will either reuse it or write a second rule; the plan must say which.

## (b) Does the approach introduce a new defect?

Route 1 is safe only if the controller keeps every refusal the script has, and adds the lock the script lacks. As written it does not.

1. **The plan's rule omits three refusals the script makes.** Plan line 38 accepts "a claimed slice whose worker reads `failed` or `ended` and whose desk exists". `handover_refusal` also refuses an open or merged PR (`plot-dispatch.sh:1031-1040`), a live desk loop whatever the state word (`:1046-1052`, #1450), and a `PLOT-BLOCKED` marker (`:1058-1064`). The PR row is the measured one: five of five `failed` desks held a PR (`:1934-1945`). If the domain rule decides on the state word alone and the script re-refuses, the decision is made twice and the controller reports the script's refusal as an unnamed failure. The rule must carry all of them by name.
2. **`restartWorker` has no loop reading.** `RestartReadings` (`dispatch-verbs.ts:124-131`) holds branch, tree and PR only; the #1450 live-loop refusal lives in shell alone. A controller built on `restartWorker` as it stands would accept a desk whose loop sleeps on checks or a usage limit (state `stalled`/`finished`, loop alive) — the plan's failed/ended filter hides this today, but the rule is the one place the refusal should live. Add a `DeskLoop` reading, as `continueTarget` already has (`continue-target.ts:84`).
3. **No per-desk lock: two starters can both pass the check.** `--restart` reads state and loop, then calls `start_worker`, with no lock between (`plot-dispatch.sh:1954-1993`; no `flock`/`mkdir` lock in the file). `/api/continue` and fleetd's `start-fresh` serialise on `.plot-worker.continue.lock` (`continue-lock.ts:39`, `takeContinueLock` 145-165) for exactly this race (#1357: "two callers ... can both pass the live-loop check before either has spawned"). A restart controller that does not take that lock races (i) a second restart from the board and the bundle, (ii) a master agent's continue, and (iii) fleetd's `start-fresh` on a `bound`/`unreadable` ending — which reads `ended`, the very state route 1 accepts. The manifest `start_worker` writes before the spawn (`:1258`) makes fleetd's next tick answer `leave` (`ending-action.ts:29-34`), but that covers only a tick that lands after the write. Result: two loops on one desk, one tree, one branch.
4. **Host failure fails open.** `reached_review` returns "no PR" on a transport failure, offline, or backend `none` (`plot-dispatch.sh:1760-1770`). `--release` already treats that as wrong for an irreversible act (`:2042-2054`). For an operator typing `--restart` it is tolerable; for a controller that a master agent calls during a host outage it restarts work already under review. The domain reading should be `true | false | 'unanswerable'`, as `PrOpenReading` already is (`ending-action.ts:119`), and `unanswerable` refuses.
5. **A stale ending outlives the restart.** `start_worker` removes `.plot-worker.exit` (`:1205`) but not `.plot-worker.ending.json`; the only writer in the script is `--stop` (`:1887`). After a restart the desk still says `stopped`. If the new worker is then killed without writing an ending, `killedWorkerEnding` returns `null` because an ending exists (`ending-action.ts:632`), so fleetd keeps answering `leave` and the crash is masked as a person's stop. The restart should move the prior ending aside (or the slice should prove the loop overwrites it at start).
6. **Pid reuse refuses safely, but the refusal's advice is not safe.** After a stop the loop removes its manifest, so `plot_worker_state` falls back to the bare pid file and `kill -0` alone (`plot-worker-state.sh:1212-1219, 1241-1244`). My sandbox desk2 (pid file naming an unrelated live `sleep`) read `running`. A restart therefore refuses `worker-alive` — the safe direction — but its message says "stop it first: `plot-dispatch.sh --stop`" (`:1055`), and `--stop` sends SIGTERM to that pid's whole process group (`:1866-1873`). A master agent that follows the advice signals an unrelated process. The controller's `worker-alive` refusal on a desk with no manifest `startedAt` should say the pid is unverified and not route to `--stop`. (The issue's own stranded branch is `bug/the-reaper-reads-a-reused-pid-as-a-live-worker`, the same class.)
7. **Session and tree are handled correctly.** `start_worker` mints a fresh session per launch (`:1252`, `:1373-1375`), so a restart never resumes the old session id. The tree is inherited unchanged; nothing cleans, resets or stashes (`:1965-1977`). Uncommitted work is not lost. A local HEAD behind `origin` (another machine pushed) makes the new worker's push fail non-fast-forward rather than overwrite; acceptable, but the restart does not fetch first.

Route 2 has its own defect. `plot-fleetctl.sh --stop` produces the same ending record as a person's deliberate `plot-dispatch.sh --stop` (`:1887`, actor `operator`, detail `plot-dispatch --stop`). `--start` cannot tell "the fleet stopped this" from "a person stopped this on purpose", so route 2 as stated restarts desks a person meant to leave stopped. It needs its own record (for example `fleetctl` writing `detail: fleet-stop` or a stop list) before `--start` may act on it.

## (c) Slices

- Missing: the slice should state that it reuses and extends `restartWorker` (`dispatch-verbs.ts:177`) rather than writing a new rule, and adds the `DeskLoop` and an `unanswerable` PR reading.
- Missing: the controller takes `takeContinueLock` on the desk across read-decide-spawn, the same lock `continueOnDesk` and fleetd use. Without it the slice adds a race, not a route.
- Missing: the adapter's contract with the script. If the adapter shells to `--restart`, the script's refusals must map to named domain refusals, and a test must hold that a refusal the domain did not predict is reported as a defect, not passed through as a generic error.
- Missing: clearing or archiving the prior `.plot-worker.ending.json` on a successful start, with a test that a restarted-then-killed worker gets `killedWorkerEnding`'s `unreadable` ending.
- Missing: the controller gate change. The plan says "the gate lists the action and its receipt" (line 38) but no slice owns `plot-gates.sh`/receipt work; the gate today refuses `plot-dispatch.sh` without a receipt (observed in this session when a grep named the script), and the bundle must leave the receipt the gate reads.
- Missing: a refusal under `PLOT_UNATTENDED=1` or not? `plot-needs-design.mjs` refuses unattended; the plan does not say whether a fleet agent may restart a sibling's desk. It should refuse there.
- Order: route 2 (if chosen) depends on a distinguishable stop record and should be its own slice after route 1, not folded in.

## (d) Open questions for a person

1. Route 1, route 2, or both? Either route 1 only, or route 1 plus route 2. Recommend route 1 now; route 2 only as a later slice after `fleetctl --stop` writes a stop record distinct from a person's `--stop`.
2. Should fleetd restart a `failed`/`stopped` slice by itself? Either yes (new `endingAction` row) or no (leave stays; a person or master agent calls the controller). Recommend no: a `stopped` ending is a person's decision by construction (`ending-action.ts:147-149`), and auto-restart on a five-second tick is what `plot-dispatch.sh:1907-1910` warns against.
3. Which states are restartable? Either `failed`/`ended` only, or the script's set (`stalled`, `failed`, `ended`, `none`). Recommend the script's set, gated by the same PR, loop and marker refusals: `stalled` is the state that holds 324 unfinished lines (`:1965-1967`), and narrowing it makes the controller weaker than the verb it replaces. `finished` stays excluded.
4. Host unreachable during the PR check: either proceed (today's `reached_review`) or refuse `pr-unanswerable`. Recommend refuse for the controller.
5. Lock: either the restart takes `.plot-worker.continue.lock` (one lock per desk for every starter) or a new restart lock. Recommend the existing lock; two locks on one desk do not exclude each other.

## (e) Position

amend. The direction is sound and the underlying verb already protects uncommitted work and never resumes a stale session. Before approval the plan should name `restartWorker` as the rule to extend, require the per-desk continue lock, carry the PR/loop/marker refusals (PR read as fail-closed), clear the stale ending on start, fix the `worker-alive` advice for an unverified pid, and drop or defer route 2 until a fleet stop is distinguishable from a person's stop.
