## Walkthrough result (2026-08-15)

Run against `main` in a throwaway repo, following `docs/fleet-user-test.md`.
Fifteen items verified by executing them, not by reading.

**One defect found and fixed** ([#94](https://github.com/plot-pm/plot/pull/94)):
a worker that had *completed* its job was reported as `dead`, which reads as a
crash — a healthy fleet looking failed. It surfaced only because this was the
first time a real worker was ever started; every automated test runs
`--no-start`, which is precisely the gap that let it ship. `--status` now
distinguishes running / finished / failed / ended, and the first test that
starts an actual process pins it.

**Confirmed by execution:** the wave transition on real merged work, the merge
queue predicting a collision *against the branch ahead of it* rather than
against main, fan-out to two concurrent workers, claim exclusivity, the reaper,
and the phase gate.

**Three items remain unverified**, all requiring a human in a live session
rather than a script. They are ergonomics and adoption, not correctness, and a
defect in any of them is fixable in a patch release:

- whether an agent actually follows the prose (`/plot-dispatch` dry-running and
  *asking* before it fans out) — a rule, not a gate, and only observable in a
  real session
- `/plot-init` applied end-to-end in a repo that is not this one — its
  detection is tested, its application is not
- whether the four-phase map matches how the work feels in practice
