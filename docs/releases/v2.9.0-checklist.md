# Endgame Test — v2.9.0

**The board learned to tell the truth about itself.** Twenty-four plans landed
in this release, and almost all of them changed something you can *see*. This is
a guided tour of that: open the board, walk the six stops below, and tick what
holds.

You do not need to have read any of the plans. Every step says where to look,
what to do, and what you should see — and links the plan it came from if you
want the argument behind it.

**Roughly 45 minutes.** Stops 1–3 are the heart of it; if you only have twenty
minutes, do those.

---

## Before you start

```bash
nvm use              # Node 24 — pnpm crashes on 26
pnpm install         # if node_modules is missing
pnpm build:board     # ALWAYS — a stale artifact fails in reassuring ways
pnpm board           # then open http://localhost:7777
```

Three things worth knowing before you are confused by them:

**Read the real estate, not the mock.** `PLOT_BOARD_MOCK` renders one row of
every kind and is wonderful for a screenshot, but it is a fixture: it cannot
show you a *wrong* row, which is exactly what you are hunting. Leave it unset.
([a-mock-row-shows-what-the-tuple-still-gets-wrong](../plans/2026-08-20-a-mock-row-shows-what-the-tuple-still-gets-wrong.md))

**The board serves the branch it is running from.** If the design looks old or a
row looks stale, check the branch name in the header before filing a bug — you
may be looking at a different worktree.
([the-board-says-which-branch-it-serves](../plans/2026-08-22-the-board-says-which-branch-it-serves.md))

**Folding is remembered.** `Quiet` and `Done` start folded, and your choice is
saved in the browser. Two steps below depend on `Done` being folded — if you have
already opened it, fold it again before those.

## Stop 1 — Do the sections keep to their subject?

*The sprint's headline. Seven defects here were reported from a running board and
none was caught by a test — they are all about what a human sees.*

The Agents tab has six sections: **Working**, **Waiting on you**, **Waiting on a
machine**, **Not started**, **Quiet**, **Done**.

- [ ] **Working lists people-shaped work, not branches.** Every row names an
      agent session actually running. A branch nobody is touching belongs
      elsewhere.
- [ ] **Waiting on a machine lists machines** — builds, pipelines. A running
      agent is *not* a machine; if you see one here, that is the bug.
      ([every-section-has-one-subject](../plans/2026-08-20-every-section-has-one-subject.md))
- [ ] **Not started holds nothing already started.** No `wip`, no `claimed`, no
      merged work.
- [ ] **Unfold Done. It holds finished work only** — no `Released` rows, no
      `Discovery` rows, no half-finished waves. Done is the *release scope*:
      what has landed but not yet shipped.
      ([done-holds-what-is-still-yours](../plans/2026-08-23-done-holds-what-is-still-yours.md))
- [ ] **Nothing in Done pulses or shows a live worker.** A finished row should not
      claim activity just because its worktree still has an untidy file.
- [ ] **One wave appears in exactly one section.** Find a plan whose waves span
      two sections and confirm no wave is listed twice.
      ([the-wave-is-a-thing-the-board-can-hold](../plans/2026-08-23-the-wave-is-a-thing-the-board-can-hold.md))

> **Fold Done again before Stop 4.**

## Stop 2 — Does a row tell you the truth about itself?

*Before this release a row could say `eligible` while being unstartable. This is
the fix that most changes day-to-day use.*

- [ ] **No row anywhere says `eligible`.** Rows now say one of four things:
      **`start work`** · **`needs a brief`** · **`waiting on approval`** ·
      **`someone is on it`**.
- [ ] **Count the `start work` rows against the size of Not started.** The defect
      being fixed measured **26 rows saying `eligible` where about 5 were
      actually startable** — so if nearly every row says `start work`, the verdict
      is not being computed. A handful is the healthy shape.
- [ ] **Pick one `start work` row and sanity-check it**: is its plan approved, is
      the branch unclaimed, does a brief exist? All three should be true.
      ([the-row-says-whether-you-can-start-it](../plans/2026-08-23-the-row-says-whether-you-can-start-it.md))
- [ ] **`start work` is coloured; the other three are not.** This deliberately
      overrides an older rule that tinted more rows — if everything is coloured,
      the colour has stopped meaning anything.
      ([a-startable-wave-says-so](../plans/2026-08-22-a-startable-wave-says-so.md))
- [ ] **No row cites a closed pull request.** A withdrawn PR is over; the branch
      may well still be alive and heading for a new one.
- [ ] **A merged branch reads `merged`** — even one whose ref still exists on the
      remote.
      ([a-resurrected-ref-does-not-hide-a-merge](../plans/2026-08-23-a-resurrected-ref-does-not-hide-a-merge.md))
- [ ] **A finished worker reads as finished**, not as waiting for an answer
      nobody asked it for.
      ([a-marker-is-a-file-not-a-mention](../plans/2026-08-23-a-marker-is-a-file-not-a-mention.md))
- [ ] **Long plan and issue names use the width the row has** instead of clipping
      early while the branch column hogs the space. Find the longest name on the
      tab and check it is not cut off with room to spare beside it.
      ([the-name-track-holds-the-name](../plans/2026-08-22-the-name-track-holds-the-name.md))

## Stop 3 — Can you drive the workflow from the board?

*This release moved real lifecycle actions onto the board. They run actual Plot
commands, so treat them as live.*

Actions live on the **plan head** — the row that names the plan, above its waves.
Look for **⋯** where the menu is collapsed.

**How every action behaves — worth learning once:**

1. Click once: the button **arms**, turns amber, and rewrites itself to name the
   consequence (something like `merges PR #146?`).
2. Click again to confirm. The label becomes `approving…` / `delivering…` /
   `creating…` with a spinner.
3. If the command refuses, **its own message appears on the card** — read it,
   that is the point.

- [ ] **The arming step works and is legible.** Click one action once, read the
      armed label, then click elsewhere to cancel it. Nothing should have run.
- [ ] **A Draft plan offers `Approve`** on its plan head in *Waiting on you* —
      and no branch row pretends to offer it.
      ([a-plan-moves-through-the-sections](../plans/2026-08-22-a-plan-moves-through-the-sections.md))
- [ ] **`Commission design` sits beside `Approve`** — the two answers to one
      question, in one place.
- [ ] **An approved, unstarted plan offers `Implement` and `Dispatch`.**
      ([an-approved-plan-offers-its-two-starts](../plans/2026-08-22-an-approved-plan-offers-its-two-starts.md))
- [ ] **A plan whose waves have all merged offers `Deliver`,** and reaches
      **Testing** without anyone running `/plot-deliver` by hand.
      ([done-means-delivered](../plans/2026-08-21-done-means-delivered.md))
- [ ] **A refused action explains itself.** Find an action that is dimmed and
      hover it — the tooltip should say *why*, not just be grey.
- [ ] **An unsliced wave (one holding several branches) says so** and offers
      `Slice this wave`, rather than sitting blocked with no reason given.
      ([a-wave-is-one-branch](../plans/2026-08-21-a-wave-is-one-branch.md))
- [ ] **An issue offers `Create plan`.**

## Stop 4 — Does the fleet report itself honestly?

- [ ] **Not started carries an auto-dispatch switch.** Toggle it off and on;
      while on, eligible waves of approved plans start by themselves.
      ([approval-hands-the-work-to-agents](../plans/2026-08-22-approval-hands-the-work-to-agents.md))
- [ ] **Working carries a parallel-agents stepper** (default 3), reading
      **`N parallel agents · M working`**. Check **M matches the agents you can
      actually see running** — not the registry's size.
      ([the-board-says-how-many-workers-are-free](../plans/2026-08-24-the-board-says-how-many-workers-are-free.md))
- [ ] **Finish or kill a worker and watch M fall.** A finished worker's lingering
      process must not keep occupying a slot.
- [ ] **The blocked mark finds its wave — the fun one.** Find a wave marked
      *blocked by* something, where the blocker has finished into **Done**.
      **Leave Done folded**, then click the mark. It must either open Done and
      flash the row, or tell you the wave's name and that it is off screen.
      **It must never do nothing.** Try it from more than one section: this fix
      had two halves and a single-section check can pass over a live defect.
      ([the-blocking-wave-is-found-wherever-it-is](../plans/2026-08-23-the-blocking-wave-is-found-wherever-it-is.md))
- [ ] **A relaunched agent updates its entry** instead of leaving the board
      naming a process that already exited.
      ([the-registry-names-a-live-agent](../plans/2026-08-23-the-registry-names-a-live-agent.md))

## Stop 5 — Do plans read correctly?

- [ ] **The Kanban columns are Discovery · Design · Development · Testing ·
      Released.** *Testing* is the new name for delivered-but-not-shipped — it
      describes what happens in it, which is what you are doing right now.
- [ ] **A plan head says how many waves it holds** — `N waves · M elsewhere`.
      N is what you can see under that head; M is the rest of the plan. A plan
      wholly in one section has no `elsewhere` clause at all.
      ([a-split-plan-says-it-is-split](../plans/2026-08-23-a-split-plan-says-it-is-split.md))
- [ ] **A plan head is a plan head, not a branch row** — it names the plan and
      carries the plan's actions.
      ([a-plan-row-is-not-a-branch-row](../plans/2026-08-17-a-plan-row-is-not-a-branch-row.md))
- [ ] **A Draft plan claims no approvals.** Open a plan still in Draft: no wave
      head should report work as landed or awaiting approval.
      ([a-draft-plan-claims-no-approvals](../plans/2026-08-23-a-draft-plan-claims-no-approvals.md))
- [ ] **A plan reports both a phase and a status** — what a person decided, and
      what its branches measure. *Every wave has landed* should be statable
      without pretending somebody delivered it.
      ([a-plan-has-a-phase-and-a-status](../plans/2026-08-23-a-plan-has-a-phase-and-a-status.md))
- [ ] **An interrogated plan says so.** Open a plan that went through
      `/challenge-the-plan` and find its round count.
      ([an-interrogation-leaves-a-record](../plans/2026-08-22-an-interrogation-leaves-a-record.md))

## Stop 6 — Is the board quiet when nobody is using it?

*Before this release an idle board made ~3,700 GitHub calls an hour and burned a
5,000/hour budget in about 78 minutes.*

- [ ] **Leave the board open and untouched for 30 minutes, then run
      `gh api rate_limit`.** GraphQL use should be in the low hundreds per hour,
      not thousands.
      ([the-scan-asks-once-per-pulse-not-once-per-branch](../plans/2026-08-23-the-scan-asks-once-per-pulse-not-once-per-branch.md))
- [ ] **An exhausted budget degrades gracefully:** the banner says so and names
      the reset; PR-dependent groups say they may be incomplete rather than
      silently showing zero.

*(This is the one stop you can start and walk away from — kick it off before
Stop 1 and read the result at the end.)*

## The estate behind the board

Run from a **checkout of main**, not from a copy of the script:

```bash
./skills/plot/scripts/plot-reconcile-scan.sh | tail -2
```

- [ ] **`attention=0` and `drift=0`.** These are the two that gate.
- [ ] **`merged_not_delivered=0`.**
- [ ] **`sprint_drift` read by a human.** Section 9 is brand new in this release
      and has never been reviewed — it reported **27** findings on its first real
      run. They look like naming drift rather than release defects, but nobody
      has actually read them.
- [ ] `pnpm test`, `pnpm run test:reconcile`, `pnpm run test:board` green.

> **Two traps that cost real time — don't repeat them.**
> An **all-zero footer** means you ran a *copy* of the scan (it finds its helpers
> relative to its own path), not that the estate is clean. The tell is that
> counters no merge could have changed zero at the same moment.
> And **`auto-dispatch-spawn.test.ts` fails under full-suite load and passes
> alone** — re-run that file by itself before believing it.
