# Release Checklist — v2.9.0

Sprint: [`the-board-tells-the-truth-in-every-section`](../sprints/active/2026-W35-the-board-tells-the-truth-in-every-section.md)
— Must **8/8**, Should **9/9**, Could **4/7**.

**17 plans reach this release.** They are listed at the bottom for provenance;
this checklist does not walk them one by one, and the reason is the whole point
of the sprint.

## What this checks, and what it does not

Automated coverage is **104 test files** — 69 unit, 35 browser — including the
eighteen section rules the sprint set out to make executable. CI proves the
mechanics. Re-running them here would prove nothing new.

**Verify what the tests cannot.** The sprint's own success condition is not a
green suite; it is:

> a board a reader opens after the release containing **no row its section
> forbids**

That is a judgement about what a person sees, made by a person who did not write
the code. Every item below is one of those.

**Method:** open the board (`pnpm board`) against this repo's real estate — not
`PLOT_BOARD_MOCK`, which is a fixture and cannot show a wrong row. Read each
section as a reader would, and tick only what you have actually looked at.

## 1. Every section admits only what belongs in it

The sprint's subject. Seven defects were reported from a running board and none
was found by a test.

- [ ] **DONE holds finished work only** — no `RELEASED` rows, no `DISCOVERY`
      rows, no incomplete waves. Expand it; it is folded by default.
- [ ] **No row in DONE wears an activity mark or a live worker state.** A
      finished row reports neither a pulse nor a worker.
- [ ] **WORKING lists agents, not branches.** Every row names a session. A
      branch nobody is working is somewhere else.
- [ ] **WAITING ON A MACHINE lists machines.** An agent is not a machine; a
      running worker belongs in WORKING.
- [ ] **NOT STARTED holds nothing already started.** No `wip`, no `claimed`, no
      merged work.
- [ ] **One wave appears in exactly one section.** Pick a plan whose waves span
      DONE and NOT STARTED and confirm no wave is in both.

## 2. A row says something true about itself

- [ ] **A plan head's wave count adds up.** `N waves · M elsewhere`: N is what
      you can see under that head, M is the rest of the plan. On a plan wholly
      in one section there is no `elsewhere` clause at all.
- [ ] **A row states whether you can start it** — `start work`, `needs a brief`,
      `waiting on approval`, `someone is on it`. **No row says `eligible`.**
      Count the `start work` rows: it should be far fewer than the rows in NOT
      STARTED, and each should be genuinely startable.
- [ ] **A `start work` row is coloured and the others are not.** This overrides
      an older rule deliberately; if every row is coloured, the tone means
      nothing.
- [ ] **No row cites a closed pull request.** A withdrawn PR is an ended
      artifact; the branch may still be live.
- [ ] **A merged branch reads `merged`,** even one whose ref still exists.
- [ ] **The header names the branch the board is serving.** With several
      worktrees open, this is what tells a stale-looking board from a broken one.

## 3. The controls tell the truth about the fleet

- [ ] **`N parallel agents · M working`** — M matches the agents you can
      actually see running. Not the registry's size; the ones doing work.
- [ ] **The blocked ⓘ finds its wave.** Click it on a blocked wave whose blocker
      has completed into DONE — **leave DONE folded first**. It must open that
      section and flash the row, or say the wave's name and that it is not on
      screen. **It must never do nothing.**
- [ ] **A plan head's actions match its phase.** A Draft plan offers Create PR
      and Approve; an approved one offers Implement and Dispatch.

## 4. The host is not being drained

The board made ~3,700 GitHub calls an hour before this release and exhausted a
5,000/hour budget in about 78 minutes.

- [ ] **Leave the board open and idle for 30 minutes, then check
      `gh api rate_limit`.** GraphQL consumption should be in the low hundreds
      per hour, not thousands.
- [ ] **The board recovers from an exhausted budget** rather than compounding
      it: when the limit is spent the banner says so and names the reset, and
      PR-dependent groups say they may be incomplete rather than showing zero.

## 5. The estate agrees with itself

- [ ] `plot-reconcile-scan.sh` reports **`attention=0`** and **`drift=0`**.
- [ ] Every plan in this release carries a `Delivered:` record, not just the
      phase.
- [ ] `pnpm test`, `pnpm run test:reconcile`, `pnpm run test:board` green on the
      release commit.
