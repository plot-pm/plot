# Every Delivery row keeps its actions in one ⋯ menu in the last column

> Mine in mode `mine` keeps a row that is assigned to the reader or whose plan is the reader's; every Delivery row with an action has one ⋯ menu in a fixed last column that lists a fixed set of actions, disabled with its reason where it cannot run; every existing row control has a named new place; You rows start with a verb, Work items is one grid with status pills, Release delivery plan rows unfold to their slices, and the fleet's switches live only in the Fleet section.

## Changelog

- With Mine on in its lenient mode, a row, agent or ticket shows when it is assigned to you or its plan is yours, and a row whose owner is unknown still shows. The strict mode keeps today's narrower rule.
- Every Delivery row with an action has one ⋯ menu in the last column, at the same position in every group and section. A row with no action keeps an empty last cell of the same width. The menu lists the same actions for every row of a kind; an action that cannot run now is listed disabled with its reason, never hidden, and the ⋯ itself never shows disabled while it lists an item. An action that asks for confirmation today still asks, and a destructive action asks too.
- The plan row's approve, deliver, implement, dispatch and reslice buttons, the slice line's Start work button and the Tickets row's *Plan it ›* move into the row's ⋯.
- You rows start with what to do: verb, object, consequence ("Interrogate · plan X · 3 slices wait · 2h"). The loose branches under Unblock group into one row ("Release or delete · 2 loose branches · 36–37 days old"), and its ⋯ lists each branch with its own actions; every other You row stays one row per item. The verb opens the same choice as ⋯. The group-wide delete of all loose branches is removed: each branch is deleted on its own.
- Work items is one grid: item, plan, status, by, age, ⋯. Status shows as pills with a coloured dot and whole words, and it is never cut; the branch segment of the item tuple gives way.
- Each Release delivery plan row unfolds to its slices: slice name, PR and branch, state and ⋯.
- The fleet's switches show as real switches at the top of the open Fleet section, also when the fleet is stopped, and the "turn on ›" links open the Fleet section before they scroll to them.

**Shared rules for every slice:**

- **No change to the controllers or their refusals** (spec non-goal). ⋯ items call the existing board routes (`packages/board/src/server/index.ts:290-497`): `approve`, `deliver`, `implement`, `dispatch`, `continue`, `restart`, `reslice`, `interrogate`, `needs-design` (which moves a plan to Design; no board route starts a design run), `release-claim`, `loose-delete`, `registry/drop`, and Create plan (`CreatePlanButton`). No route is added.
- **Release approval is not a row action** (operator decision, 2026-11-20). It stays only in the header's Release group (plan 4). No You row reads "Approve release", and `placeDelivery` keeps sending release items to `releases` and to no section (`packages/domain/src/rules/delivery-placement.ts:434-437`), so the `release-approval` reason of `YOU_GROUP_OF` (`delivery-placement.ts:215`) reaches no row.
- **No hidden UI.** An action that cannot run is listed disabled with its reason (for example "Delete branch — claimed, release it first"). No action is reachable only on hover. The ⋯ trigger is never disabled while it lists a disabled item.
- **Every rendered state is a domain property** (CLAUDE.md). Each row's verb, verb tone, object, consequence, grouping, menu items, disabled reasons and status pill is a domain or view property with a unit test; browser tests only prove it is seen. New domain code is arrow functions with factual TSDoc. A function the builder rewrites in `menus.tsx`, such as `menuState` (`menus.tsx:250`), becomes an arrow, because the rule follows the diff.
- **Scope and Mine** (operator decision, 2026-11-20). Mine applies to You, Work items and Fleet rows, and to Tickets. Mode `off` shows every row; in the `release` scope that keeps today's unnarrowed rows (`selection` is `[]`, `packages/domain/src/rules/delivery-scope.ts:25-27`). Mode `mine` shows a row that is assigned to the reader or whose plan is the reader's, and keeps today's rows of unknown owner. Mode `strict` keeps today's narrower rule. The first slice of this plan builds that rule (below); every slice of this sprint that shows or counts Mine waits on it. In `my-sprint` scope the rows narrow to the sprints `deliveryScope` returns (operator decision, 2026-11-20; `delivery-scope.ts:56-65`). In the `release` scope under Mine `mine` or `strict`, a row of a plan in no active sprint says "no sprint": in a You row's consequence, and as a grey status pill in a Work items row. Today's sprint filter is `rowInSprintSelection` (`packages/domain/src/rules/sprint-selection.ts:117`, applied to the Delivery rows at `AgentList.tsx:832`), with `NO_SPRINT` (`:2`), `rowIsSprintExempt` (`:83`) and `showsSprintSlug` (`:141`). `rowSprintMembership(item, activeSprints)` is built on `inAnyActiveSprint` and `rowIsSprintExempt` beside them and adds only the "no sprint" answer, by the You rows slice with a unit test per cell of {`release`, `my-sprint`} × {`off`, `mine`, `strict`}.
