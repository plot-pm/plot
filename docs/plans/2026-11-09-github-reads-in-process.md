# GitHub reads in-process

> fleetd reads GitHub over Node's HTTPS client inside the `host` connector adapter, not through one `plot-host.sh` process tree per question: the open PR listing, the `--state all` and merged deltas, the issue read and the default-branch re-ask. The partial-answer contracts stay, every rule copied out of `plot-host.sh` is a declared duplicate with a corpus test, a gate holds the second transport to `packages/domain/src/adapters/host/`, and both transports charge one budget.

## Changelog

- On a GitHub repository, fleetd asks GitHub for pull requests, issues and the default branch's CI runs from inside its own process. An idle fleetd pass starts no `bash`, `gh`, `jq` or `node` process for these reads, and the answers, the completeness claims and the rate-limit record stay the same.
- A new CI gate refuses an HTTPS request to a host from any file outside `packages/domain/src/adapters/host/`.

Board impact: none on the plan format, the template, the helper scripts or the `docs/plans` layout. The board reads the same `prs`, `issues` and `defaultBranch` readings over the channel; `plot-host.sh` keeps every op for the shell consumers and the merge path.

## Motivation

fleetd asks GitHub through `plot-host.sh` today, and each question starts a process tree. Three paths in `packages/fleet` reach it:

| Read | Caller | Route today |
|---|---|---|
| The scan's listing: `pr-list --state open --rich`, then `--state all` with or without `--since` | `readGithubListing`, `packages/fleet/src/shared/fleet-scan.ts:522-536`; one call at `:491` | `Scripts.hostSaid(['pr-list', …])` |
| The PR index refresh and its re-ask of open rows | `packages/fleet/src/shared/pr-refresh.ts:1426-1441`, `:1563-1566` | `Scripts.hostSaid(['pr-list', …])` |
| The merged set and its `--since` delta | `mergedBranches`, `packages/fleet/src/server/entry/registryd-main.ts:883`, `:903`, `:945` | `Host.prList` → `host-shell.ts:454` → `plot-host.sh pr-list` |
| The issue read | `refreshIssueIndex`, `packages/fleet/src/shared/issue-refresh.ts:446`, `:523`, `:527`, `:536` | `Tracker` → `tracker-github.ts:143-152` → `tracker-shell.ts:311` → `plot-host.sh issue-list` |
| The default-branch re-ask | `packages/fleet/src/shared/default-branch-refresh.ts:130`, `:286` | `Build.runsForSha` → `build-shell.ts:194-195` → `plot-host.sh runs-for-sha` |

One `pr-list` call starts `bash` for `plot-host.sh` (6,064 lines), `gh`, several `jq`, `sed` and `awk` processes, and one `node` for the page count (`plot-host.sh:3321`). The story's 30-second sample of fleetd's direct children names `plot-host.sh pr-list` per state among about 160 children. The census rows S4 (an idle fleetd pass) and S6 (one PR whose CI turns green) read 1099.5 and 2671 `execve` on the sprint head with 5 open PRs (story, *Measures*). S4's target is 0 outside the safety-net pass, and the host reads are one of the five sources Phase 5 names.

Counted in `census-head.jsonl` (CI run 42595561157, artifact `census-report-head`), the images of a `plot-host.sh` call are about 180 per idle pass on the 0-desk GitHub fixture (16 % of S4) and about 246 on the 3-desk fixture (10 %). The default-branch re-ask runs once per half `Checks wait` (1800 s) and appears in no S4, S5 or S6 sample, so moving it removes nothing from those rows. Three host-side starts stay after this plan: `spend-rate` through `plot-host.sh` (`registryd-main.ts:486`, `pr-refresh.ts:701`, `fleet-scan.ts:317`; about 2.5 trees per idle pass), `node plot-merger-token.mjs` (1 per pass) and `node plot-issue-source.mjs` (1 per 2 passes). `spend-rate` stays a `plot-host.sh` call in this plan: its 3 call sites are named residue, and a later plan moves them to a `BudgetRecord` read.

The risk is high and silent. Two partial-answer contracts decide whether a missing row means "no PR" or "not read": the `.list-complete` whole-page claim (`renderScanListing`, `packages/domain/src/rules/scan-listing.ts:142-151`; `wholePage` reads the shell's `page complete` notice at `:259`) and the refusal to fold a delta when a carried OPEN row is absent from both answers (`foldScanListing`, `scan-listing.ts:292`). The shell states both on stderr (`pr_list_report_truncation` and `pr_list_report_complete`, `plot-host.sh:3313-3349`). A second transport that drops a notice reads every truncated page as whole, and nothing fails.

## Design

This plan depends on `the-snapshot-entity` (delivered). `triggers-replace-the-tick` depends on this plan. It shares `packages/fleet/src/server/entry/registryd-main.ts` with `liveness-token` (this plan moves `mergedBranches`, `:883`; that plan changes the worker reading in the same file), and the second to merge rebases. It shares no source file with `refs-from-files`, `one-cat-file-batch`, `desk-probes-in-domain` or `node-worker-wrapper`; every one of them, `liveness-token` included, this plan included, changes census counts and may touch the census fixture under `packages/fleet/test/census/` (`stub-host.ts`, `sandbox.ts`), so the second to merge rebases its fixture change and states its own measured delta. The AgentMonitor's per-desk `plot-host.sh pr-state` call (`plot-agent-monitor.sh:257-264`) stays: `liveness-token` ends those loops.

### Approach

**A typed read first, then a second transport behind it.** The fleet's callers read `pr-list` stdout and stderr through `Scripts.hostSaid`. An HTTPS adapter cannot produce a shell's stderr notices without imitating them, so the first slice gives the read a type and moves the callers to it, with the shell still answering.

**Slice 1: the seam (no transport change).**

- `ports/host.ts` gains `prListing(query)`. The query names `state` (`open`, `all`, `merged`), `limit`, `since`, `rich` and `richOpen`. The answer is a `PrListing`: the rows, and for each asked state one completeness word, `whole` or `possibly-truncated`, and the refusal kind on a failed call. `host-shell.ts` answers it from `plot-host.sh pr-list`, and reads the per-state notices into the completeness words with the patterns `scan-listing.ts:259` and `:390` use today.
- `readGithubListing`, the PR index refresh and `mergedBranches` call `prListing`. `foldScanListing` and `foldPulseListing` take the completeness word instead of reading notice text. The Bitbucket arm keeps `hostSaid`: Phase 7's `bitbucket-reads-in-process` moves it.
- A failed `PrListing` answer carries the kind and the host's wait, and `said` holds the connector's words verbatim, so `refusalKind` (`rules/refusal.ts:59`) and `hostReaction` (`pr-refresh.ts:488`) classify it as they classify the shell's text today. The callers pass the kind and the wait to `reactionTo`. `Host.observe` alone does not suffice: it acts only on `throttled` (`ports/host.ts:376-392`).
- **A refused credential is its own kind.** `HostRefusal.kind` (`ports/host.ts:88`) gains `auth` beside `throttled`, `secondary` and `failed`, and the board's `RefusalKind` (`rules/refusal.ts:26`) gains `auth` beside `quota`, `secondary` and `outage`. The backoff does not retry an `auth` refusal: a wait does not repair a token, so `reactionTo` answers it with no retry time, and the next read runs only on the next trigger. The board shows an `auth` refusal as "sign in", with the fix from `said`, and never as `outage`. In this slice the shell route answers `auth` where `gh` exits on a `401`.
- Every existing contract and fleet test passes unchanged. This slice moves no census row.

**Slice 2: the client, its credentials, its budget and its gate.**

- `adapters/host/github-api.ts` is the one module that opens a connection to the GitHub API. It takes the base URL from `GITHUB_API_URL` (default `https://api.github.com`), as `skills/plot/scripts/plot-github-app.mjs:24` does, and the repository from the `origin` remote, as `gh_origin_slug` does (`plot-host.sh:2560`).
- **The API host.** The client derives the API host from the `origin` remote, as `gh` does, so a GitHub Enterprise origin reads its own API and not `api.github.com`. `GITHUB_API_URL` overrides it.
- **Credentials.** The reads run as the identity `gh` runs as today. The client takes the token from `GH_TOKEN` or `GITHUB_TOKEN`, and otherwise runs `gh auth token --hostname <host>` once at start. Where no person is signed in to `gh` (a server, a CI runner), fleetd reads with `GH_TOKEN` or `GITHUB_TOKEN`; this plan adds no `Reader app` key.
- **The budget account is the token's login.** The client asks `GET /user` once per token, on the first request after it reads a token, and charges every ledger entry to that login. A `gh auth switch` followed by a refreshed token therefore charges the new user, and a cached token keeps charging the user whose window it spends. The shell's `budget_account` (`plot-host.sh:3513-3534`, the first `user:` in `hosts.yml`) keeps its rule for the shell appenders; while both name the same person, both write one key. A `GET /user` that fails charges the account `unknown`, as `budget_account` does with no `hosts.yml`, and the client asks again with the next token. On a `401` with a token from `gh` it runs `gh auth token --hostname <host>` once more and retries the request once, so a person's `gh auth login` takes effect with no fleetd restart. A token from `GH_TOKEN` or `GITHUB_TOKEN` gets no refresh, because `gh auth token` returns the same variable. A second `401`, or the first on an environment token, is a refusal of kind `auth`. Its `said` names the token source and the fix, for example `GitHub refused the token from gh auth token (401 Bad credentials); run gh auth login`, or the variable and the unit file that sets it. That process runs in answer to a trigger (start, a refused credential), which *Target Shape* allows. The token travels in a request header only, never in argv, a file or a log line, as `plot-github-app.mjs:12-14` states for the App flow.
- **The App keys stay with their writes.** `Review app`, `Merger app` and `Writer app` sign `plot/review` statuses, merges and pushes (`plot-commit-status.mjs`, `plot-merger-token.mjs`, `plot-push-writer-app.mjs`). The client never reads with one of them: each App installation has its own rate window, and a read charged to it would spend the review or merge identity's budget. A fourth App key for reads waits for a repository that needs one.
- **Budget and slots.** Every request takes a host slot through the `Slots` port with the account and bound `host_slot_take` uses (`plot-host.sh:3849-3873`), and appends one `BudgetEntry` through the `BudgetRecord` port (`ports/budget.ts`, `adapters/budget/budget-file.ts`), the ledger `plot-host.sh` writes as `budget.tsv`. The bucket and the window come from `X-RateLimit-Resource`, `-Limit`, `-Remaining` and `-Reset`, so each in-process entry has the basis `actual`, where `gh pr list` records a guess from its argv (`gh_bucket_of_argv`, `plot-host.sh:3560`). A `403` or `429` with a secondary-limit message maps to the `LimitObservation` `secondary`, and an exhausted window to `throttled`, through `Host.observe`, and `said` holds GitHub's response `message` verbatim, so `refusalKind` reads the same words it reads from `gh` today.
- **The client rotates `budget.tsv`.** `budget-file.ts:145` performs no rotation, and after the cutover fleetd's reads are the largest appender. The client applies `budget_rotation_due` (`plot-budget.sh:207`) before it appends, as `rules/budget-rotation.ts`, a declared duplicate of the shell rule. `packages/domain/corpus/budget-rotation.corpus.test.ts` runs both over the same ledger sizes, ages and clock values and names both answers on a disagreement. The shell appenders keep their copy.
- **Proxies.** The client honours `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY` as `gh` does: it passes a proxy agent built from them for every request, and a host that `NO_PROXY` names goes direct. A machine behind a proxy reads in-process as it reads through `gh` today.
- **A bound per request.** Each request ends after 30 s with no complete answer. GitHub's GraphQL server stops a query at 10 s, so 30 s never cuts an answer the server still sends, and a stalled socket releases its slot and the pass within one bound. A timeout answers kind `failed`, which the board shows as `outage`; its `said` names the request and the bound, for example `no answer from api.github.com within 30 s (graphql, page 2)`. A timeout on page 2 or later is a walk refused mid-way, and the completeness rule below applies. The client claims the host slot, and `withHostSlot` (`pr-refresh.ts:804`) stops wrapping `prListing`, so one question holds one slot and not two. One pass holds no more requests in flight than the `Slots` bound: without the 100–300 ms process start in front of each request, the reads of a pass arrive closer together, and the secondary limit counts concurrency.
- **`actual` lines change shell routing.** `gh pr list` records basis `unknown` for `graphql` (`budget_reading`, `plot-host.sh:3610-3619`); the client records `actual` with the real remaining value. Two shell rules read it: `graphql_budget_spent` (`:2391`) sends `pr-state` to REST at remaining 0, and `host_concurrency_bound` (`:3818`) turns a slot bound on. A contract row holds the first.
- **The gate.** `scripts/check-host-https-callers.sh` refuses `node:https`, `undici`, `api.github.com`, `GITHUB_API_URL` and a global `fetch(` call in `packages/*/src`, matched by the pattern `(^|[^.[:alnum:]_])fetch\(`, so that no `.` or word character precedes it. The gate applies the pattern outside `packages/domain/src/adapters/host/`. `packages/board/src/app/` is exempt by name: its 27 matches in 16 files ask the board's own server by a relative path (a plain `fetch(` grep finds 29 matches in 17 files there, because it also counts member calls and longer names). The `Trees` port declaration `fetch(path, branch)` in `packages/domain/src/ports/trees.ts:637` is exempt by name, and so are the member calls `Trees.fetch` that the pattern skips. The scripts that already reach GitHub over HTTPS (`plot-github-app.mjs` and its three callers) are named exceptions, each with its write. Measured in this worktree with that exact pattern: 1 hit outside `adapters/host/` and `app/` (`packages/domain/src/ports/trees.ts:637`), which the named exemption removes, so the gate reports 0 on this tree. A contract test runs the gate over a fixture tree with one violation per pattern. The domain purity gate (`ci.yml:1416-1425`) already refuses `https` outside `adapters/`; the new gate narrows it to `adapters/host/` and adds the fleet and board packages.
- **The census sees the new transport.** A `PATH` stub cannot see an in-process request. `packages/fleet/test/census/stub-host.ts` gains a local HTTP server that serves the same recorded answers as the stub `gh`, and the census sandbox sets `GITHUB_API_URL` to it and `GH_TOKEN` to a fixture value. The story planned this for Phase 7 (*Phase 1*, fixtures bullet); GitHub moves first.

**Slice 3: the PR reads in-process.**

- `adapters/host/github-pr-listing.ts` answers `prListing` for a GitHub backend. It sends the GraphQL queries `gh pr list` sends today for the open rich listing, the `--state all` listing and the merged listing, with the same fields, the same `updated:>` search for `--since` (exclusive, `plot-host.sh:4562-4575`) and the same `--limit`. It keeps the split read of `--rich-open` (`plot-host.sh:4620-4655`): the open rows rich, the terminal rows plain with the absent values. The decision of 2026-11-05 stands: the read stays unconditional GraphQL at today's cadence, the `--state all` delta, the merged delta and the issue read included, so the corpus feeds one recorded request to both transports. A GraphQL refusal reaches the same backoff as the shell's (Slice 1). A move of the deltas to REST needs its own plan and corpus. The merged listing keeps `--limit 500` (`registryd-main.ts:900`), 5 pages of 100 per full read.
- **Completeness.** A state's page is `whole` only when every page of the walk answered, the last page reports `pageInfo.hasNextPage: false`, and the row count is below the limit. The row-count rule alone, which `pr_list_report_truncation` applies to GitHub (`plot-host.sh:3322-3327`) and `pagePossiblyTruncated` holds in the domain (`packages/domain/src/rules/listing-page.ts:51`), is safe for `gh` only because `gh pr list` is all-or-nothing (`pr_list_call`, `:921`). An in-process walk refused on page 3 of 5 holds fewer rows than the limit, and that rule would call it `whole`. A walk refused on any page is never `whole`. It answers the rows of the pages read, the completeness word `possibly-truncated` for that state, and the refusal: `lastRefusal()` holds the kind and the verbatim message. This is the shape `hostSaid` already gives exit 7, and `mergedBranches` already reads it (`registryd-main.ts:918`). `foldScanListing`'s refusal of an absent carried OPEN row does not change: it reads rows, not the transport.
- **The declared duplicates.** Three jq programs in `plot-host.sh` decide what a rule reads: `CHECKS_OF` (`:713`, the check rollup to `green`, `pending`, `failing` or `none`, and `ciChecks` without `plot/review`), `MERGEABLE_OF` (`:725`) and the row projection of the listing arm. They become `rules/checks-of.ts`, `rules/mergeable-of.ts` and `rules/github-pr-row.ts`, arrow functions over values. The shell keeps its jq copies for `pr-state` and the shell consumers.
- **The corpus.** `packages/domain/corpus/github-pr-listing.corpus.test.ts` feeds one recorded GitHub answer to both transports: the GraphQL response to the stub server for the in-process adapter, and the `gh pr list --json` output recorded from the same request to a stub `gh` for `host-shell.ts`. It compares every row field by field, and the completeness word per state. The recorder is a script that captures both with `GH_DEBUG=api`; the corpus tier runs with no host token (`packages/domain/corpus/no-host-token.ts`), so the test reads recordings only. The recordings hold each shape `gh`'s flattening touches: a `CheckRun` and a `StatusContext`, `ACTION_REQUIRED`, a `plot/review` context (`plotReview`, `plot-host.sh:4790`), `mergeable: UNKNOWN`, a draft, a merged row, a listing of more than 100 rows and a `--since` search answer. Each fixture records the `gh` version, because a `gh` upgrade can change the query the fixture stands for. `checks-of.corpus.test.ts` runs `jq` with `CHECKS_OF` and `MERGEABLE_OF` and the TypeScript rules over the same rollups. A disagreement names both answers and the PR, as *A Shell Script Asks The Domain* requires.
- **"Differs" covers every field a rule reads.** `recordReading` compares the `prs` reading by content (`packages/domain/src/rules/snapshot-record.ts:35`), so a field the in-process row omits can never mark a change. `PrIndexRowSchema` holds 22 fields (`packages/domain/src/entities/pr-index.ts:30`). A unit row per field changes that field alone in one recorded answer and asserts that the in-process read yields a different `prs` reading, so that `recordReading` reports `changed: ['prs']`. The corpus then holds that the shell sets no field the in-process row leaves absent.

**Slice 4: the issue read and the default-branch re-ask.**

- `tracker-github.ts`'s four reads (`issueListOpen`, `issueListClosed`, `issueListChanged`, `issueListInbox`) call the client, as `trackerGitHost` is built over the host connector (`CLAUDE.md`, *A connector is a kind of adapter*). The query is the one `gh issue list` sends (`plot-host.sh:5472`), with the same page token and the same `issue-list` exit outcomes: an empty list, a failed question and `unaskable` stay three answers. The issue writes stay in `plot-host.sh`, where `issue-writes-have-a-rest-route` moves them to REST.
- `build-actions.ts`'s `runsForSha` calls the client with the request `gh run list --branch <b> --limit <n> --json headSha,conclusion,…` sends (`plot-host.sh:5156`), `GET /repos/{owner}/{repo}/actions/runs`, and applies the newest-first, first-match rule of `run-for-sha` (`plot-host.sh:5142`). That rule is a declared duplicate with a corpus row.
- Both reads answer a refusal with the kind, the host's wait and GitHub's verbatim message, as the PR listing does.
- Both reads keep the `Tracker` and `Build` ports. Only the adapter's transport changes, and a Bitbucket, Jira or Jenkins repository runs the shell route as before.

**Slice 5: the cutover and the measurement.**

- fleetd's composition root picks the in-process reads when `Host.backend()` answers `github`, `CI` is not `jenkins`, and the client resolves a token; the shell reads otherwise. A GitHub repository with `CI: jenkins` keeps the shell route until Phase 7 moves Jenkins: the GitHub `pr-list` arm overlays Jenkins colours on the checks (`plot-host.sh:4583-4600`), and GitHub's `statusCheckRollup` alone would read `none` on every row.
- fleetd logs the transport, the reason for it and the token source (`GH_TOKEN`, `GITHUB_TOKEN` or `gh auth token`, never the token) once at start, publishes the transport with its heartbeat, and `/plot-fleet --status` prints it. A fallback to the shell is never silent.
- `PLOT_HOST_TRANSPORT=shell` forces the shell reads for one fleetd process. It is a rollback switch while the corpus is young, and `triggers-replace-the-tick` removes it. A person sets it as an `EnvironmentVariables` entry in the fleetd unit (`skills/plot/units/com.plot-pm.fleetd.plist`, or the systemd unit) and reloads fleetd through `plot-fleetctl.sh`; `/plot-fleet --status` confirms it. The census runs with the switch unset.
- A green per-source census row `P5: an idle fleetd pass on GitHub starts no plot-host.sh pr-list or issue-list` (`census-rows.ts`, `green: true` from this slice) reads the strace tree by argv, and a stub-server count holds that in-process requests per idle pass do not exceed the baseline request count. S4 is a strict row with no `green` flag until Phase 8 (`census-rows.ts:42-48`), so without P5 no gate holds the saving.
- The census rows S4 and S6 run on the GitHub fixture against the merge base, and the slice records both numbers in the story's *Measures*. The expected delta is about 150–250 fewer `execve` per idle GitHub pass, and about 20 `pr-list` calls in 2 passes to 0. The PR states how many `execve` each read removed.
- The board's own reads (`plot-pr-reader.mjs` with no fleetd) take the same composition, so a board with no fleetd also reads in-process.
