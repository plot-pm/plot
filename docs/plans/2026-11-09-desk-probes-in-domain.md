# The desk probes read from files

> fleetd and the board read each desk's worker state, dirt and activity with TypeScript readers behind the `Processes` and `Trees` ports, and decide with the domain rules that exist today. No per-desk `bash -c . plot-worker-state.sh` probe remains in `packages/*/src`; each reader that copies a shell reading is a declared duplicate with a corpus test against `plot-worker-state.sh`.

## Motivation

The census counts what desks cost an idle fleetd pass. On CI run 42595561157 (PR #3277, 2026-11-09), S4 on GitHub reads 1124.5 `execve` per pass with 0 desks and 2585.5 with 3 desks: 1461 per pass, about 487 per desk, come from desks. Bitbucket with 3 desks reads 2676. S5 (one desk commit) reads 2587 and S6 (one PR turns green) 2696, both with 3 desks.

The census report names commands, not callers. Per pass, these commands appear only when desks exist (half of the two recorded passes in `census-report-head`):

| Command | 0 desks | 3 desks | Source in `plot-worker-state.sh` |
|---|---|---|---|
| `dirname plot-worker-state.sh` | 1 | 56 | load time, `:98` and `:196`: one per `source` |
| `bash plot-config.sh` | 86 | 147 | `plot_manifest_dir_for` (`:178`) at load time |
| `sed` with a `\1` capture | 0 | 126 | manifest field reads (`:257`, `:289-291`) |
| `date` | 0 | 105 | `_plot_lstart_epoch` (`:301-304`) and the manifest epoch (`:368`); up to 5 per call on Linux |
| `cut` | 1 | 103 | the reading splits in `plot_worker_state` (`:1216-1218`, and `:1423-1425` in `plot_worker_readings`) |
| `ps` | 0 | 21 | `plot_pid_is_current` (`:352`) |
| `grep ^PLOT-BLOCKED`, `ls` | 0 | 6, 6 | `plot_worker_blocked` (`:445`) |

So fleetd sources the script about 55 times per pass for 3 desks and evaluates the pid reading about 21 times, 7 per desk. The TypeScript callers that source it per desk:

- `processesShell.workerState` (`packages/domain/src/adapters/processes/processes-shell.ts:168`), reached from `readDeskReadings` (`packages/domain/src/workflows/plan-walk-desks.ts:94`) on every scan, from the unblock world (`packages/fleet/src/server/entry/registryd-main.ts:1258`), from `release-claim-reader.ts:63`, `restart-command.ts:77`, `auto-fixer.ts:372` and the board's `reap.ts:401`.
- `treesGit.dirtyPaths` (`packages/domain/src/adapters/trees/trees-git.ts:326`) and `treesGit.quietSeconds` (`:365`), both `bash -c . plot-worker-state.sh`, reached from `readDeskReadings` (`plan-walk-desks.ts:97-98`), `registryd-main.ts:618`, `:1489`, `:2150` and the agent's own loop (`packages/fleet/src/server/entry/worker-loop.ts:646`, `:1274`).
- `bashLiveness` (`packages/fleet/src/shared/registry.ts:1147`), one sourced batch per registry read, and `bashCleanliness` (`:1319`), one inline `bash` program per batch that runs `git status`, `grep` ×5, `sed`, `cut` and `git rev-list` per desk. The board passes it at `packages/board/src/server/fleet.ts:3202`; both run through `execFile` at `registry.ts:510`.

The decision is already in the domain: `agentState` (`packages/domain/src/rules/agent-state.ts`) takes the readings `plot_worker_readings` prints, and `packages/domain/corpus/agent-state.corpus.test.ts` holds it against `plot_worker_state`. `deskManifest` and `deskWaitsFree` are domain rules with corpus tests too. What stays in the shell is the gathering: the manifest and pid files, the start-time check, the agent-alive table walk, the `PLOT-BLOCKED*` glob, the dirty filter and the exit record.

This is the paused Phase 4 of `the-shell-holds-no-behavior` (archived 2026-11-09), whose per-desk scripts the story took over.

## Design

This plan depends on `the-snapshot-entity` (delivered): every reading lands in the snapshot's `workers` and `deskFiles` keys through `recordReading`. `liveness-token` depends on the *Worker readings* slice, because it replaces the start-time column that slice reads. `triggers-replace-the-tick` depends on this plan. `refs-from-files` (this sprint) changes `treesGit` for `Trees.list` and ref reads; the *Dirt* slice changes `dirtyPaths` and `quietSeconds` in the same file, `trees-git.ts`, so whichever merges second rebases. `one-cat-file-batch`, `github-reads-in-process`, `node-worker-wrapper` and `sprint-prs-run-ci` share no file with this plan.

### Approach

**Placement under *The Layering Rule*.** The readers are adapters, and the adapter gathers: `processesFiles` reads one desk's files and the process table and hands the values to the rules. The rules that copy a shell reading live in `packages/domain/src/rules/` and take values. No rule or workflow gains a port, so `CLAUDE.md`'s *A note on shape* stands unamended. Each copied reading is a declared duplicate under *A Shell Script Asks The Domain*: `plot_worker_state` runs once per desk per shell pass in `plot-dispatch.sh` and `plot-fleetctl.sh`, so the shell keeps its copy and a corpus test holds the pair. On a disagreement the branch stops.

**Slice 1: worker readings (largest share: the sources, `sed`, `date`, `cut`, `ps`).**

- `Processes` (`packages/domain/src/ports/processes.ts:37`) gains `table()`: one process-table reading per call, rows of `pid`, `ppid`, `startedAt` (epoch ms), `comm` and CPU time. A new adapter `packages/domain/src/adapters/processes/processes-table.ts` implements it with one `ps -A -o pid=,ppid=,lstart=,time=,comm=` under `LC_ALL=C`. The start-time check needs the table until `liveness-token`. `processesFiles` holds one table per pass: the first `workerState` call of a `readDeskReadings` call or a registry batch reads it, every later call of the same pass reuses it, and the next pass reads a fresh one. The memo belongs to the `processesFiles` instance, so a site that constructs one per call reads one table per call. A failed `ps` answers `failed` for the pass, and fleetd logs `process table unreadable` with the `ps` exit code; it never answers `stale` per desk.
- **The trace comes first.** Before it changes a reader, slice 1 adds a spawn-spy inventory under the census driver that records every `ps` and every sourcing of `plot-worker-state.sh` per pass with its full argv and caller, as `refs-from-files` does for `rev-parse`. Slice 1's PR traces the 21 `ps` checks and the 55 sourcings per pass for 3 desks to their callers, names each caller that reads `ended` or `orphaned` for a desk, and names any source that no slice of this plan replaces. The census diff adds sources the table in *Motivation* omits: `grep` 392 per pass (the manifest loop at `:257` costs one `grep` and one `sed` per manifest file per call), `tr` 88, bare `git` 69, `bash` 64, and about 80 per pass from the host chain, which no slice touches.
- `pidIsCurrent(recorded, startedAtMs)` in `packages/domain/src/rules/pid-current.ts` copies `plot_pid_is_current` (`plot-worker-state.sh:347`): within 3 s of `pidStartedAt` on either side, else at or after `startedAt` less 3 s, else nothing to check. `agentAlive(table, pid, nowMs)` in the same file copies `plot_worker_agent_alive` (`:1002`): `unaskable` for a wrapper younger than `PLOT_AGENT_GRACE_SECONDS` (default 30, `:977`, `:1010-1014`), with the age taken from the table's `startedAt`; otherwise `present`, `absent` or `unaskable` from the subtree's `comm` against the agent process name. The dispatcher records that name in the desk manifest as `agentProcess`, from its own `PLOT_AGENT_PROCESS` (default `claude`, `plot-worker-state.sh:921`). fleetd reads it from the manifest, and logs the value once per desk when it first reads the desk. A manifest written before this plan has no `agentProcess`, and fleetd reads it as `claude`. Without the grace every new dispatch reads `orphaned`, then `finished` or `stalled`, for up to 30 s.
- **A pid that `signalZero` finds alive and the table does not hold never reads `stale`.** The table is read before some desks' pid files, so a worker started after the table read has no row; the shell reads `ps` at check time and has no such gap (`:352-353`). The reader takes one fresh reading of that pid's start time; a pid still without a start time reads `unaskable`.
- **The recorded start time can be localized.** The dispatcher writes `.plot-worker.pid.startedAt` and the manifest's `pidStartedAt` from `ps -o lstart=` in the operator's locale (`plot-dispatch.sh:1510`, no `LC_ALL`). Under `de_CH.UTF-8` that prints `Di.  3 März 13:14:40 2026`, which `Date.parse` reads as `NaN`, while `_plot_lstart_epoch`'s `date -j -f "%c"` fallback reads it in a German reader's locale. A TypeScript parse that fails reads `stale`, so `agentState` answers `ended` for a running worker. Slice 1 makes the dispatcher stamp both values under `LC_ALL=C` on the existing line (no added line), and the corpus holds localized recorded strings against `_plot_lstart_epoch`; on a disagreement the branch stops. A desk dispatched before the change keeps its localized string until it ends.
- `readWorkerReadings(worktree, table)` in the adapter `packages/domain/src/adapters/processes/processes-files.ts` gathers the `AgentStateReadings` fields with no process and hands them to `agentState` as values: the manifest through `deskManifest`, the `.plot-worker.pid` and `.plot-worker.pid.startedAt` fallback, `.plot-worker.wrapper.pid`, `.plot-worker.exit` (absent `null`, unreadable `''`), `.plot-worker.freewait` through `deskWaitsFree`, the `PLOT-BLOCKED*` marker through the `Desk` port, `signalZero` for `kill -0`. The `Agent registry` directory is resolved once per process, not once per desk (`plot_manifest_dir_for`, `:178`, costs one `bash plot-config.sh` per call today). On a `readDeskReadings` pass, `dirty` and `unpushed` come from that pass's own reads (`plan-walk-desks.ts:94-98`), so no desk pays a second `git status` and `git rev-list`. A caller outside that pass (`restart-command.ts`, `release-claim-reader.ts`, `auto-fixer.ts`, `reap.ts`) has the adapter read them only for a desk whose liveness is not `live`, as `plot_worker_task_state` does.
- **The free-agent arm moves into the domain.** `plot_worker_state` answers `running` for an orphaned wrapper whose `.plot-worker.freewait` names the pid, only when the manifest's `startedAt` passed `plot_pid_is_current` (`plot-worker-state.sh:1299`). `AgentStateReadings` has no such field and `agentState` sends `orphaned` to `taskState` (`agent-state.ts:144`), so a free agent would read `finished`. `AgentStateReadings` gains a `waitsFree` reading and `agentState` gains the arm with the same `startedAt` condition; `agent-state.corpus.test.ts` gains a free-wait desk.
- `processesShell.workerState` is replaced by `processesFiles` (`packages/domain/src/adapters/processes/processes-files.ts`), whose `workerState` calls `readWorkerReadings` and `agentState`. The six callers above keep their signature. `processesShell` keeps `childrenOf`, `uptimeSeconds` and `startedAt` for the callers that need one pid, and stops implementing `workerState`, so the type checker lists every site that still passes it as `Processes`. On `1b7f8ec6e` `processesShell(` is constructed at 21 sites; those that reach `workerState`, directly or through `readDeskReadings`, are `scan-walk.ts:317`, `:339`, `refs-git.ts:410`, `fleet.ts:3323`, `reap.ts:657`, `:1724`, `registryd-main.ts:578`, `:852`, `:1253`, `:3180`, `agent-run-for.ts:82`, `auto-fixer.ts:738`, `release-claim-reader.ts:57` and `restart-command.ts:77` (`packages/fleet/src/shared/`). Each constructs `processesFiles` instead.
- `packages/domain/corpus/worker-readings.corpus.test.ts` compares `readWorkerReadings` with `plot_worker_readings` field by field on every desk of this estate (`production.ts`, `readDesks`) and on constructed desks: no manifest, a reused pid, a wrapper file with no agent older than the grace, a wrapper 5 s old with no agent yet, an exit file holding `abc`, a free-wait record with and without a proven `startedAt`, and a pid started after the table read. A second block compares the final `ProcessReading` (state, pid, code) of `processesFiles.workerState` with `plot_worker_state` on the same desks; a readings-only comparison passes over the free-agent arm, the grace and the table race. A third block holds `pidIsCurrent` against `plot_pid_is_current` over 12 recorded start-time pairs plus localized recorded strings (de and fr, every month, a single-digit day), with `_plot_lstart_epoch` run under the recording locale and under `LC_ALL=C`. A row runs `agentAlive` with `PLOT_AGENT_PROCESS` unset.

**Slice 2: dirt (the `bash`, `grep` and `cut` per desk).** `deskDirtFilter(porcelain, worktree, bundlePaths)` in `packages/domain/src/rules/desk-dirt-filter.ts` copies `plot_worker_dirty_filter` (`plot-worker-state.sh:543`) with the three patterns `PLOT_WORKER_RECORD`, `PLOT_EDITOR_LEFTOVER` (`:391`) and `PLOT_TOOL_SCRATCH` (`:409`) and the root `?? PLOT-CORRECTION.md` exemption. `treesGit.dirtyPaths` runs one `git --no-optional-locks -C <desk> status --porcelain` and filters in process. `treesGit.quietSeconds` runs that `status` with `-uall` plus the `git log -1 --format=%ct` it runs today (`trees-git.ts:373`), 2 `git` in all; dropping the HEAD time would read the tree quieter than it is. The bundle paths come from each desk's own `packages/board/build.mjs`, read per desk as `plot-desk-dirt.sh:85-98` does, because a desk that edits the build declares its own bundles. `quietSeconds` applies no bundle exclusion, as `plot-worker-state.sh:637` calls the filter with no worktree. `treesGit.markers` (`trees-git.ts:304`, `bash -c ls | grep`) reads the directory with `readdirSync`. The corpus test `packages/domain/corpus/desk-dirt-filter.corpus.test.ts` holds the filter against `plot_worker_dirty` on every desk of this estate and on a constructed porcelain corpus (renames, quoted paths, nested `PLOT-CORRECTION.md`, each scratch directory).

**Slice 3: the registry path.** `/plot-fleet --status` prints the board's state of each desk beside its own: `plot-fleetctl.sh --status` asks the TypeScript reading through a bundle once per operator command, and a desk whose two states differ shows both with the word `differs`. The slice removes an equal number of shell lines elsewhere, so `check-shell-lines.sh` passes. `bashLiveness` (`registry.ts:1147`) becomes one `readWorkerReadings` per worktree over one shared `table()`, and keeps its contract: one failure answers an empty array and the batch reads `unknown`. `bashCleanliness` (`:1319`) becomes `deskClean(dirty, unpushed)` in `packages/domain/src/rules/desk-clean.ts` over `deskDirtFilter` with the bundle paths from each desk's own `packages/board/build.mjs`, and `Trees.unpushedCommits`. A worktree that cannot be read stays `false`, as today. A reader failure that answers `unknown` for the batch logs its reason. The `execFile` at `registry.ts:510` then serves `plot-config.sh` alone. A parity test runs the old inline program and the new rule over the same 20 constructed worktrees before the program is deleted, in the same PR.

**Slice 4: activity from the worker log.** `Processes.activity` (`processes-shell.ts:225`) samples `ps -o pid=,ppid=,time= -ax` twice, 400 ms apart, per call; its one production caller is the agent's own loop (`worker-loop.ts:1273`, `childOnCore`). `logActivity(before, after)` in `packages/domain/src/rules/log-activity.ts` answers `working` when `.plot-worker.log`'s size or mtime moved between two readings and `idle` when neither moved, as the story decides (2026-11-05: "The working/idle activity reading comes from file events on the worker log"). Until Phase 8 arms the watch, the reading is a `statSync` at each idle check, with the previous reading held in the loop. **Slice 4 keeps a CPU reading from `table()`.** `childOnCore` is the last `idleNow` guard before `idle` (`rules/sample.ts:179`), `idle` ends the prompt with exit 124 while `PLOT_MONITOR_ENDS_WORKER` defaults to `1` (`worker-loop.ts:1602`, `:2600`), and one tool call that runs longer than the 900 s window (`IDLE_WINDOW_SECONDS`, `:121`) can leave the log still. The CPU delta compares the subtree's CPU time in the held table against a fresh one, with no 400 ms wait. The log leads: an idle check reads the log first, and reads the CPU delta (one `ps`) only when the log is still. A moving log answers `working` with no `ps`. The idle verdict's inputs (log size and mtime, the CPU delta) go into `.plot-worker.ending.json`, so an idle ending can be told from a `Worker bound` ending, which also exits 124. `plot_worker_activity` and `plot_worker_cpu_centis` stay: their one caller is `plot-quiet-stretch.sh:120`, and deleting them removes 0 census processes. The census desks carry no `.plot-worker.wrapper.pid` and do not run the agent loop (`packages/fleet/test/census/sandbox.ts:301-315`), so S4, S5 and S6 do not see this slice; a spawn-spy test on `idleVerdict` does. If the CPU reading stays beside the log reading as a fallback, `activity.corpus.test.ts` stays for it; it is retired only if no CPU reading copies `plot_worker_activity`.
